# 物理子系统参与人员与个人敏捷看板工程设计

## 文档状态
修订2；业务规则已确认，落盘文档待复核。
确认依据：用户确认“创建时按系统/部署单元带出系统参与人员，后续可改”，补充“负责人默认系统负责人，后续可改”，并同意“管理者可以查看所有任务执行情况，但不能越权执行”。

## 方案比较
1. 系统成员执行系统全部任务：实现简单，但无法表达任务级分工，未选。
2. 创建时默认带入，任务独立维护，实时校验系统资格：已选，复用现有任务负责人、参与人和检查项。
3. 系统人员与任务持续全量同步：维护少，但会覆盖已调整分工并扩大权限，未选。

## 规则和不变量
- 有效系统参与人=当前系统负责人∪显式成员；按租户、项目、物理子系统隔离，部署单元继承所属系统。
- 系统负责人可以为空的历史记录不擅自补负责人。生成任务时负责人必须合法且非空，预览阶段提示补齐后才能提交。
- 任务负责人单选必填，任务参与人多选。按系统/部署单元生成时分别取系统负责人和有效系统成员。
- 每个生成任务可独立覆盖默认值，后端生成提交时重新校验目标和人员，不能信任预览快照。
- 负责人自动参加任务。改负责人后，新人入列，旧人默认保留为普通参与人，可再移除。
- 不绑定系统的公共任务使用项目范围的显式分工，默认负责人沿用公共任务配置；配置缺失时必须在预览补齐，不能擅自选择全项目人员。
- 新增系统成员不回填旧任务；修改系统负责人不覆盖旧任务负责人。
- 系统成员退出立即撤销资格。仍担任未完任务或未解决阻塞负责人者须先移交；并发请求在事务内重新校验，不让退出与执行竞态形成越权。
- 存量任务保持名单，不合法人员只向管理视图标识待处理，普通查询和执行失败关闭；不能为修复数据自动扩大系统名单。

## 权限矩阵
所有规则先满足认证、RBAC、租户与项目数据范围，再进行对象授权。
| 动作 | 普通人员 | 授权管理者 | 审批/办理人员 |
| --- | --- | --- | --- |
| 维护系统参与人 | 系统负责人且有维护权限 | 有系统人员管理权限 | 不因流程身份获得 |
| 查看个人看板 | 本人负责/参与且系统资格有效的任务 | 同普通人员 | 同普通人员 |
| 查看计划全貌和检查项 | 仅本人任务 | 授权项目/计划内全部 | 不因流程身份获得 |
| 修改任务负责人/参与人、日期和依赖 | 有分派/计划管理权限才可操作 | 保留现有角色对应管理范围 | 无默认权限 |
| 启动、完成检查项、重新打开检查项 | 系统资格∩任务人员∩操作权限 | 完全相同，无管理员豁免 | 无默认权限 |
| 取消/恢复任务、检查项、计划 | 保留原管理职责限制，不因参与而获得 | 依原对象层级管理权限，原因必填 | 无默认权限 |
| 发起资源申请 | 本人参与系统的部署单元 | 同普通人员，不能凭管理角色申请其他系统 | 不因审批/办理身份获得申请权 |
| 编辑/提交资源申请 | 同时是合法申请人及系统参与人 | 不默认可编辑他人申请 | 只执行分配的流程动作 |
| 工单审批/资源办理 | 有对应流程分配才可处理 | 不以管理角色绕过流程 | 可按分配履职，不要求加入系统 |

管理权限沿用已验证的角色、项目范围和计划职责；实施时映射现有权限码，不凭名称新增超级权限。
管理者可管理不代表可以直接改完成状态；检查项状态改变仍由专用业务命令完成。

## 数据和接口设计（候选契约，非已存在API）
- 新增架构模块人员关系存储，唯一约束建议为租户+项目+系统+用户，保存显式成员；负责人参与关系从负责人字段合并计算，避免两份负责人事实。
- 系统人员读取返回 ownerUserId、explicitParticipantUserIds、effectiveParticipantUserIds、版本和可维护能力；更新显式名单携带版本，负责人不得通过成员接口修改。
- 任务覆盖参数为 ownerUserId、participantUserIds；生成预览覆盖以模板任务及目标类型/目标ID组合标识，不能用展示顺序作为身份。
- 任务生成提交同一事务验证负责人、名单、目标项目归属；候选任务人员更新命令亦校验版本，并原子保证负责人在名单中。
- 服务端计算 canView、canManage、canExecute 等对象能力，前端不推断管理员执行权；具体DTO字段和路由在T1冻结，不与现有接口伪装混用。
- 个人查询默认 view=mine；management 必须独立鉴权，不能靠客户端参数放大范围。分页、计数和搜索条件在数据库查询中应用，不能取一页后过滤。
- 现有检查项 complete/reopen、任务启动接口复用业务状态机，PlanEngine 的管理员执行放行必须消除；计划管理授权与任务执行授权分开。
- 资源申请所有明细验证部署单元到系统的归属，关联工单从任务发起也同样校验。
- 查询/执行只能从服务端认证上下文取得租户和操作者；跨项目或不可见对象沿用统一不存在语义，已可见对象无动作权限返回禁止，版本冲突返回冲突并刷新。
- 用户停用、退出项目、系统成员移除都使资格失效；旧完成历史保留。列表批量查询名单，避免逐卡片查询人员。

## 看板、状态和交互
直接替换 PlanDetailPage.vue 中原有“看板”页签内容，保留现有入口和计划上下文，不新增菜单、独立看板页面或跨计划聚合。所有看板数据固定当前 planId；默认“与我相关”，管理者可在同一看板内切换“全部任务”，切换需服务端管理权限校验。
四列：未开始=NOT_STARTED；已开始=IN_PROGRESS；已完成=COMPLETED；阻塞=BLOCKED或WAITING_PRECEDING。
已取消单独筛选，不计已完成；活动任务显式阻塞优先于未开始/已开始分列；已完成仍存在活动阻塞时作为状态一致性错误检测，不在界面静默纠正。
卡片显示系统/部署单元、计划、负责人、检查项完成数、日期及阻塞提示。检查项继承任务权限，不额外建人员模型。
不实现自由拖拽改状态；启动、完成、重开均走有权限校验的业务动作，依赖不满足不能通过看板绕开。
不可见前置任务只显示“前置条件未满足”，不返回其名称、检查项、人员和明细ID。
复用交付示范中心工具栏、卡片、详情抽屉及公共UI和语义主题变量。示范中心是展示模块，不能直接提供本业务任务状态规则；只新增本模块四列容器，不修改公共UI。
桌面1280×800及以上四列有界滚动；手机375×812、390×844、430×932为状态页签+单列卡片，页面不横向滚动。
手机表单单列，抽屉接近全宽并保留边距；高度不超过视口安全区，标题/操作固定，内容独立纵向滚动。
卡片主操作为详情，高频执行在详情中呈现；取消等危险动作放更多菜单并确认。加载、空、失败重试、无权限、只读、提交中、未保存和版本过期都明确反馈。
切换项目清理选择、查询缓存与旧响应；异步旧请求不能覆盖新项目结果。

## 补充权限入口
- 部署单元维护：原架构维护角色∩系统资格；不得将参与人等同架构师。
- 环境实例和资源明细：普通人员按系统范围，办理/运维人员按已有职责范围，不自动新增全局权限。
- CLB/DNS/证书等工单：申请目标按系统资格，办理保持原流程职责；关联现有工单须同时有任务权限和工单可见性。
- 网络访问申请：源端系统参与资格为准；目标由允许申请目录和审批约束，非要求加入目标系统。不可见目标只暴露审批所需的允许目录信息。
- 附件、评论、活动、报告、时间视图、通知跳转继承对象权限；通知发送和点击分别检查，旧消息不是永久授权。
- 公共字典、共享规范和模板不附加系统成员限制。
- 跨业务模块使用统一参与查询/校验公开契约，但需独立公共能力范围和Owner审批；本轮仅描述，不修改其他模块。

## 迁移、安全、运维与回退
追加迁移建立关系存储，不修改历史SQL；旧系统有效参与人先仅含负责人。旧任务名单保留，做资格差异报告和人工移交，不自动吞掉问题。
提前确认系统负责人及项目资格异常量，不能上线后才发现所有执行者被锁。审计保存操作者、对象、变更前后人员、原因和时间，不删除历史行为归属。
成员撤销不取消已批准申请；旧草稿禁止继续编辑/提交，进行中流程按原审批办理职责继续，申请侧交接由管理流程处理。
专项复核覆盖授权、迁移和公共能力影响。遇权限漏洞先关闭相关执行入口，不能以回滚旧版宽权限作为默认恢复手段。
