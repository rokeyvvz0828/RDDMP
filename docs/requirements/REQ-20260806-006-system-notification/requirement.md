# 系统消息通知公共能力

## 目标

在平台层提供统一、可复用的站内消息通知能力，使需求、研发、测试、版本、迁移、投产、工作流和后续业务模块可以通过稳定契约向指定用户发布消息，用户可在全局顶栏查看并管理自己的通知。

## 实施范围

- 在 `platform/system` 提供公开的 Java 消息发布接口，发布命令包含幂等事件标识、业务类型、业务主键、接收用户、标题、内容、级别、来源和可选站内路由。
- 消息按租户和用户隔离，重复事件不重复生成通知；接收用户必须是同租户有效用户。
- 追加 Flyway 迁移，新增通知主表和用户通知状态表，支持未读查询和按创建时间排序。
- 提供当前认证用户的通知列表、未读数、单条已读和全部已读接口，不接受客户端传入用户身份。
- 在应用顶栏增加消息铃铛和消息抽屉，覆盖加载、失败、空、未读、全部已读和站内跳转状态。
- 提供业务模块接入文档，明确契约、幂等、路由、安全和事务边界。

## 非实施范围

- 不接入短信、邮件、企业微信、推送平台或 WebSocket 实时通道。
- 不实现通知模板管理、用户订阅偏好、批量运营消息和附件。
- 不允许通知动作跳转到外部 URL，不允许业务模块直接写通知数据表。
- 不修改现有业务流程，只提供后续按需接入的公共能力。

## 验收

1. 同一租户、业务类型和事件标识重复发布时只产生一条通知，多个接收用户分别拥有独立已读状态。
2. 用户只能查询和更新自己的通知，未读数、单条已读和全部已读结果一致。
3. 非法站外路由、空接收人、跨租户或无效用户被服务端拒绝。
4. 顶栏消息入口在桌面和移动布局可达，加载、空、失败、未读和已读状态可辨识。
5. Maven 测试、前端生产构建、治理检查、Flyway 迁移和真实浏览器流程通过。

## 回退

回退应用代码和前端入口；数据库表保留但停止写入，后续通过单独补偿迁移删除测试数据或表，不回改已发布 Flyway 文件。
