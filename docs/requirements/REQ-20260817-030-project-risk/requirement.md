# 项目风险管理

## 业务目标

在项目详情中提供“项目风险”页签，项目成员可查看项目风险，项目负责人或超级管理员可维护风险信息，并通过参数管理维护风险枚举值。

## 本次实施

- 在项目计划页签后新增项目风险页签。
- 新增风险编号规则并纳入项目设置，默认 `{PROJECT_CODE}-R{SEQ:3}`。
- 新增风险列表、三段式新增/编辑表单、删除功能和项目范围权限校验。
- 风险字段按“问题上报”“进展跟踪”“升级与解决”三部分展示。
- 项目阶段、紧急程度、上报问题级别、当前状态、关注等级、是否升级、当前问题级别从参数管理读取。
- 提出组织/组、涉及组织/组复用组织树；日期字段统一使用年/月/日控件和 `yyyy-MM-dd` 数据格式。
- 新增数据库表、字段注释、权限节点和默认枚举示例。

## 本次不实施

- 不引入业务表单元数据能力，不依赖 `biz_form_*` 表。
- 不改变项目成员可见范围、计划和项目角色业务规则。
- 不实现风险流程审批、通知、附件或外部系统同步。

## 数据与权限

- 风险数据归属 `platform/system`，通过 `projectId + tenant_id` 查询并执行项目访问校验。
- 读取复用项目查看权限；新增、修改、删除分别使用项目风险权限节点的对应动作。
- 所有写操作记录审计，编号由服务端按项目设置规则生成，忽略客户端传入编号。

## 验收标准

1. 项目详情在项目计划后显示项目风险页签，列表支持加载、空状态、失败和删除确认。
2. 新增/编辑表单按三块展示全部字段，枚举来自参数管理，组织来自组织树，日期为年/月/日。
3. 项目设置可保存风险编号规则，创建风险后编号按规则服务端生成且不可由前端覆盖。
4. 非项目成员无法访问风险数据；无对应动作权限时后端返回明确的“查看/新增/修改/删除项目风险权限”错误。
5. 数据库迁移、后端测试、前端构建、差异检查和浏览器验收通过。

## 回退

回退本需求新增的 V43 迁移、项目风险后端接口、前端风险页签和账本文件；不修改历史迁移。
