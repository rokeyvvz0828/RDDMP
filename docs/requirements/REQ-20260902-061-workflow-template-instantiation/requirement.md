# 工作流模板实例化与人员边界

## 业务目标

将可复用的流程结构与可执行流程明确分离：全局模板只描述流程结构，不绑定具体人员；项目流程从模板创建后，只能配置当前项目成员或项目角色；存量平台级工作流继续正常执行。

## 本次实施

- 定义范围调整为 `PLATFORM`、`TEMPLATE`、`PROJECT` 三类。
- 追加 V135，将存量 `GLOBAL` 定义迁移为 `PLATFORM`，保持现有发布、启动和业务绑定能力。
- `TEMPLATE` 不绑定项目，不允许配置具体用户或角色，不允许发布、启动、恢复为发布态或绑定业务。
- 模板审批节点使用结构占位符；发起人节点可保留 `STARTER`，抄送节点使用无具体用户的模板占位。
- 项目流程只允许使用 `PROJECT_MEMBER`、`PROJECT_ROLE` 和 `STARTER`，并沿用现有项目成员与角色校验。
- 定义列表按“本项目流程、全局模板、平台流程”分区；默认显示本项目流程。
- 支持从模板创建项目流程：复制结构、清空人员占位、绑定当前项目，并要求重新配置项目人员后保存和发布。

## 本次不实施

- 不修改历史 V134，不修改 Flowable `ACT_*` 表。
- 不自动把存量平台级用户/角色节点改写为项目节点。
- 不改变具体业务模块对工作流编码和审批场景的选择规则。
- 不允许模板作为运行时定义参与任何实例匹配。

## 业务规则

1. `PLATFORM` 和 `TEMPLATE` 的 `project_id` 必须为空，`PROJECT` 必须绑定当前用户有权访问的项目。
2. `PLATFORM` 保留现有 `USER`、`ROLE`、`STARTER` 配置和运行能力。
3. `TEMPLATE` 审批节点只能使用 `TEMPLATE_PLACEHOLDER` 或 `STARTER`，不得保存具体人员或角色主键。
4. `TEMPLATE` 抄送节点只能保存模板占位标记，不得保存具体用户主键。
5. 发布、启动、按编码启动、业务绑定目录和恢复操作必须排除或拒绝 `TEMPLATE`。
6. 业务按编码启动优先选择当前项目的 `PROJECT` 定义，其次回退 `PLATFORM`，永不选择 `TEMPLATE`。
7. 从模板创建仅复制定义内容，不复制定义主键、版本、发布状态或运行实例。

## 验收标准

1. 存量 `GLOBAL` 数据经 V135 变为 `PLATFORM`，原发布流程仍可查询、启动和审批。
2. 模板编辑器不能选择具体用户或角色；绕过前端提交具体人员时后端拒绝。
3. 模板不能发布、启动、按编码匹配或出现在可绑定流程目录中。
4. 项目流程只能选择当前项目成员和项目角色，跨项目数据继续由后端拒绝。
5. 从模板创建项目流程后结构保留，人员占位被清空并要求配置，保存结果属于当前项目。
6. 定义列表默认展示本项目流程，可切换查看全局模板和平台流程，分页总数与当前分类一致。
7. 后端聚焦测试、全量回归、前端构建、治理和范围检查全部通过。
8. 桌面与 `375x812`、`390x844`、`430x932` 视口可完成分类查看和模板实例化，无页面级横向溢出。

## 权限、数据与回退

- 后端权限是最终边界，前端显隐不代替范围和人员校验。
- 数据库仅追加 V135；应用回退时保留 `PLATFORM` 值，旧版应用不得在迁移后重新部署。
- 代码回退需同步发布兼容 `PLATFORM` 的版本；如需物理回退，另行追加迁移，禁止修改已执行迁移。
