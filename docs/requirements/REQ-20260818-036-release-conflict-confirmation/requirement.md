# 重复申请确认交互修复

## 业务目标

申请人发现同窗口重复申请后，可以明确选择“仍创建新申请”，弹窗立即关闭并继续提交审批；同一冲突事实未变化时，不应再次弹出相同确认。

## 本次实施

- 将“仍创建新申请”从单条历史申请卡片移到弹窗底部，与“暂不处理”并列并作为主操作。
- 点击后立即关闭冲突弹窗，使用当前 `conflictToken` 直接提交已保存的申请。
- 当前冲突令牌未变化时，后续提交错误不得被误判为新的重复申请冲突。
- 仅当服务端返回的冲突令牌发生变化时，重新打开弹窗并要求再次确认。
- 保留“取消旧申请”和“修改旧申请”的现有卡片级操作。

## 本次不实施

- 不修改后端冲突接口、提交接口、状态机或数据库。
- 不持久化用户的冲突确认决定；刷新页面后可以重新确认。
- 不调整移动端业务布局；沿用现有响应式行为。

## 验收标准

1. “仍创建新申请”位于弹窗底部“暂不处理”右侧，使用主按钮样式。
2. 点击“仍创建新申请”后弹窗立即关闭，按钮 loading 阻止重复提交。
3. 提交携带已确认的 `conflictToken`，成功后申请进入审批中且不会再次出现相同弹窗。
4. 非冲突类 `409` 显示原始业务错误，不重新打开重复申请弹窗。
5. 冲突事实变化导致新令牌时重新打开弹窗，并显示“历史申请信息发生变化”。
6. “取消旧申请”“修改旧申请”“暂不处理”行为保持兼容。
7. 前端生产构建、范围检查和桌面浏览器真实路径验收通过。

## 回退

仅回退本需求对两个 Vue 文件的修改，恢复卡片内“仍创建新申请”和原有冲突处理逻辑；无数据补偿或数据库回滚。
