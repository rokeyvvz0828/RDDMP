# 需求与架构管理操作列样式统一

## 业务目标

需求人员和架构人员在桌面列表及架构移动卡片中使用操作入口时，操作列应与实际操作数量匹配，并遵循仓库当前“高频操作直接展示、低频及危险操作进入更多菜单”的公共样式，避免超宽空白、按钮拥挤和样式不一致。

## 范围

### 本次实施

- 调整需求差异、存量需求、系统清单的操作列宽度、图标、间距和操作入口视觉层级。
- 调整逻辑子系统、物理子系统桌面表格及移动卡片的操作图标、间距和一致性。
- 复用 `UiDataTable`、Element Plus 按钮与下拉菜单、语义主题变量及交付示范中心既有模式。

### 本次不实施

- 不修改后端、API、数据库、权限编码、审计或业务数据。
- 不修改按钮显示条件、权限判断、状态判断、确认弹框、业务处理函数和服务调用。
- 不修改公共 UI 组件、全局样式或其他业务模块。
- 不重构需求管理完整移动端列表。

## 现状与规则

- 当前入口：需求管理的需求差异、存量需求和系统清单，以及架构管理的逻辑子系统和物理子系统列表。
- 需求差异操作列固定宽度为 `380px`，少量操作状态下存在大面积空白；其他列表的操作层级和图标不统一。
- 所有操作继续使用原有 `v-if`、权限计算、状态判断、确认弹框和点击处理函数；本次仅调整模板入口与局部 CSS。
- 前端权限显隐只改善体验，后端授权边界保持不变。
- 不涉及外部系统、附件或敏感信息。

## 接口与数据

- API/事件契约：不变。
- 数据 Owner：不变。
- 数据库迁移与存量兼容：不涉及数据库变更。
- 输入输出：只调整现有行操作的视觉呈现，不新增字段或请求。

## 验收标准

1. 需求差异直接展示修改记录、符合现有条件的审批记录和提交评审；编辑、删除按现有条件进入更多菜单，操作列不超过 `280px`。
2. 存量需求直接展示阶段推进、修改记录；阶段记录、编辑、删除进入更多菜单，所有动作仍调用原处理函数。
3. 系统清单直接展示编辑，删除进入更多菜单，确认与错误反馈不变。
4. 逻辑和物理子系统统一展示带标准图标的详情、编辑、更多入口，删除权限和删除确认不变。
5. 操作容器不换行、间距稳定；`1280x800` 无文字遮挡或无意义超宽列。
6. `375x812`、`390x844`、`430x932` 无页面级横向溢出，架构移动卡片操作可达。
7. 浅色和深色主题下固定列背景、文字和危险操作语义可读。

## 测试与发布

- 必须执行：`git diff --check`、`npm --prefix web run build`、当前任务范围检查和治理检查。
- 浏览器验收：需求差异、存量需求、系统清单、逻辑子系统和物理子系统；桌面 `1280x800`，移动 `375x812`、`390x844`、`430x932`，并检查浅色和深色主题。
- 上线验证：确认固定列滚动无透底、按钮不换行、更多菜单可达且原操作结果不变。
- 回退：恢复本需求修改的四个前端文件即可，无数据补偿。
- 风险与人工复核：由模块 Owner 复核状态组合下操作可见性未变化。
