# 项目级角色权限与系统权限维护

## 业务目标

系统管理员集中维护权限目录，项目负责人在项目角色中配置业务页面权限；同一成员切换顶部项目后，导航、按钮和服务端接口权限必须切换为其在目标项目中的有效权限。

## 范围

### 本次实施

- 系统设置以“权限维护”替换原角色权限配置，维护权限目录。
- 项目设置的项目角色支持按菜单勾选业务权限。
- 新增项目角色权限持久化、存量初始化和项目上下文服务端鉴权。
- 项目切换时刷新个人权限与动态路由，并处理无权页面。

### 本次不实施

- 不允许项目角色授予系统设置权限。
- 不重构 JWT 格式，不恢复输入项配置能力，不改变业务数据模型。

## 现状与规则

- 当前 `sys_role_permission` 提供全局权限，项目角色仅维护成员关系，项目切换不会刷新有效权限。
- 系统权限继续由系统角色控制；项目业务权限由当前项目角色控制，多角色取并集。
- 项目负责人和 PM 拥有当前项目全部业务权限；存量其他角色初始化查看权限；新角色默认无权限。
- 服务端必须验证认证、RBAC、租户、项目成员和实体归属，权限写操作必须审计。
- 不涉及外部系统、附件或敏感信息。

## 接口与数据

- 新增权限目录维护接口及项目角色权限读写接口。
- 项目业务请求携带 `X-Project-Id`，登录资料与动态路由按当前项目计算。
- 数据 Owner 为 platform/system；security 只消费有效权限查询契约。
- 追加 Flyway 迁移创建项目角色权限关系并初始化存量角色，不修改历史迁移。

## 验收标准

1. 系统管理员可维护权限目录，已被角色引用的权限不可删除。
2. 项目负责人可在项目角色抽屉中配置业务权限，不能选择系统权限。
3. 同一成员切换两个权限不同的项目后，菜单、路由、按钮和后端接口同步变化。
4. 多角色权限取并集；项目负责人和 PM 兜底全权限；新角色默认无权限。
5. 缺少或伪造项目上下文、跨项目角色或跨租户请求均被服务端拒绝。
6. 保存和切换失败可恢复，重复提交受控，桌面与手机布局可用。

## 测试与发布

- 执行 system、security、boot 聚焦测试和 Maven 回归；执行前端构建、治理和范围检查。
- 使用本地测试项目 A/B 完成 API 与真实浏览器权限切换验收。
- 上线后核对迁移角色权限数量、管理员系统权限、普通成员项目差异权限和审计记录。
- 回退应用时恢复系统角色业务权限读取；新增关系表保留，必要时追加补偿迁移。
- 风险与人工复核人：system/security/infrastructure Owner 与前端 Owner。
