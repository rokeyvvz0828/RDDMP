## 业务目标

在架构模块中提供可审计、失败保守的网络访问判定能力：用户输入来源、目标、协议、端口和申请时间范围后，系统只能给出“需要申请”或“不需要申请”两个结论。

当现有有效关系完整覆盖本次访问条件，或显式免申请规则完整覆盖本次访问条件时，系统返回“不需要申请”。其他情况，包括输入缺失、规则未知、覆盖不完整、端口或地址无法解析、时间范围无法确定、系统异常，均返回“需要申请”。

同时，网络访问关系的开通、修改、续期和关闭必须通过新的访问申请及平台工作流完成。既有已开通关系不得由页面或 API 直接编辑或删除；已下线实例不自动关闭历史关系，但历史关系需要展示风险，且已下线实例不得用于新的访问申请。

## 范围

### 本次实施

- 新增网络访问判定服务和 HTTP API，结论固定为“需要申请”或“不需要申请”。
- 新增严格覆盖计算：端点集合、地址、协议、端口范围和有效期必须全部被现有有效关系或免申请规则覆盖。

- 扩展访问申请动作类型：开通、修改、续期、关闭。
- 扩展访问关系生命周期：成功开通形成新关系；成功修改或续期形成替代关系并通过申请关闭旧关系；成功关闭通过申请关闭目标关系。
- 接入平台工作流：只有工作流成功完成后，才能创建、替换或关闭访问关系。

- 前端在现有“网络访问关系”页面内增加判定入口、生命周期申请入口、风险提示和必要的免申请规则维护入口。

## 现状与规则

### R1：判定输入与二值输出

判定请求必须包含：

- 来源端点：沿用 09 的 `NetworkEndpointCommand`，支持内部部署实例集合和外部地址。
- 目标端点：沿用 09 的 `NetworkEndpointCommand`，支持内部部署实例集合和外部地址。
- 协议：沿用现有 `AccessProtocol` 枚举。
- 端口：支持单端口、逗号分隔端口、闭区间端口范围。
- 有效期类型：`LIMITED` 或 `LONG_TERM`。
- 开始时间：必填。
- 结束时间：仅 `LIMITED` 必填；`LONG_TERM` 必须为空。

判定响应必须包含一个稳定结论：

- `NEEDS_APPLICATION`：需要申请。
- `NOT_REQUIRED`：不需要申请。

响应可以包含判定依据、原因码和覆盖关系编号，但不得引入第三种业务结论。

### R2：严格失败保守策略

以下情况一律返回“需要申请”：

- 输入缺失或格式非法。
- 来源或目标端点无法解析为当前可用端点集合。
- 端口无法解析、端口越界、范围反转或端口集合为空。
- 协议未知或不在白名单。
- 有效期缺失、结束时间不晚于开始时间，或长期有效提交了结束时间。
- 没有命中的免申请规则，且没有完整覆盖的有效访问关系。
- 只覆盖部分来源、部分目标、部分端口、部分协议或部分时间范围。
- 历史快照缺少必要字段，导致无法证明覆盖。
- 运行异常或数据库读取异常。

### R3：端点解析与覆盖语义

- 内部端点以当前租户、物理子系统、环境、部署单元和部署实例解析；新申请只能选择 `ACTIVE` 实例。
- 外部端点以启用状态的外部地址记录解析。
- 请求端点集合必须被关系或规则完整覆盖，不能因为同一部署单元新增实例而自动扩大历史关系覆盖范围。
- IPv4 地址按规范化单 IP 或 CIDR 判断包含关系，复用现有 `NetworkCidr` 能力。
- 域名和无法用 CIDR 表达的外部地址默认只允许精确匹配；不做通配符推断。
- 历史关系快照中的端点身份和地址值均作为覆盖证据；任一必要证据缺失时按未覆盖处理。

### R4：端口、协议与时间覆盖

- 端口覆盖要求请求端口集合完全落入关系或免申请规则的端口集合。
- 协议覆盖要求精确匹配；若现有枚举定义了全协议值，只有显式全协议值才能覆盖其他协议。
- `LIMITED` 请求必须被起止时间完整覆盖。
- `LONG_TERM` 请求只能被长期有效关系或长期有效免申请规则覆盖，不能被有限期关系覆盖。
- 长期关系和长期申请不使用遥远日期占位，数据库结束时间保持 `NULL`。
- 对 09 存量关系，若缺少有效期类型，则按 `valid_until IS NULL` 推断为长期，否则推断为有限期；无法推断时按未覆盖处理。

### R5：免申请规则

为了让“所有适用规则明确无需申请”可执行，本批次新增最小免申请规则台账：

- 规则归属 `business/architecture`，只表达“无需申请”，不表达真实防火墙策略。
- 规则至少包含来源网络分区、目标网络分区、协议、端口范围、有效期类型、启停状态和说明。
- 规则不命中、停用、时间不覆盖、端口不覆盖或协议不覆盖时，都不构成免申请证据。
- 外部地址相关规则本批次默认不启用通配能力；外部访问通常需要已有关系覆盖或新申请。

### R6：申请动作与关系生命周期

访问申请新增动作类型：

- `OPEN`：开通访问。审批成功后创建一条新 `ACTIVE` 关系。
- `MODIFY`：修改关系。必须指定一条当前 `ACTIVE` 目标关系；审批成功后通过申请关闭旧关系，并创建替代关系。
- `RENEW`：续期关系。必须指定一条当前 `ACTIVE` 目标关系；审批成功后通过申请关闭旧关系，并创建新的续期关系。
- `CLOSE`：关闭关系。必须指定一条当前 `ACTIVE` 目标关系；审批成功后关闭目标关系，不创建新关系。

既有已开通关系不可直接编辑或删除。现有直接关闭接口和前端直接关闭按钮需要废弃或改为引导创建关闭申请。

### R7：平台工作流

- 提交访问申请必须调用平台工作流，使用独立业务类型和流程定义代码。
- 只有工作流成功完成时，业务服务才能创建、替换或关闭访问关系。
- 退回、拒绝、撤销、终止不形成或变更访问关系。
- 申请需要记录当前流程实例、流程版本、轮次、回执、提交快照和生命周期历史。
- 流程定义迁移只创建草稿或基础定义；真实提交前仍需确保流程已发布并部署。

### R8：下线实例风险

- 实例下线不自动关闭历史访问关系。
- 访问关系列表和详情需要展示是否包含已下线实例、下线实例数量和可审计的风险摘要。
- 新建、修改、续期申请不得选择已下线实例。
- 如果历史关系包含已下线实例，用户可以发起关闭申请或修改申请处理风险。

### R9：权限、数据范围与审计

- 查看判定、关系和规则需要 `architecture:network-access:view`。
- 创建和提交访问申请需要 `architecture:network-access:apply`。
- 维护免申请规则、处理审批模拟入口、管理关系生命周期需要 `architecture:network-access:manage`。
- 所有写操作必须在服务端执行认证、RBAC、租户隔离、实体授权、并发版本检查和操作审计。
- 前端权限只控制可见性，不能替代服务端校验。

## 接口与数据

### 判定 API

```text
POST /api/architecture/network-access/decision
```

请求字段：

```json
{
  "source": {"kind": "MANAGED", "physicalSubsystemId": 1, "environmentId": 2, "deploymentUnitId": 3, "instanceIds": [10, 11]},
  "target": {"kind": "MANAGED", "physicalSubsystemId": 4, "environmentId": 5, "deploymentUnitId": 6, "instanceIds": [20]},
  "protocol": "TCP",
  "ports": "443,8443-8445",
  "validityType": "LIMITED",
  "validFrom": "2026-09-01T00:00:00+08:00",
  "validUntil": "2026-12-31T23:59:59+08:00"
}
```

响应字段：

```json
{
  "decision": "NEEDS_APPLICATION",
  "needsApplication": true,
  "basis": "STRICT_REQUIRED",
  "reasonCodes": ["NO_COVERING_RELATION"],
  "coveringRelationNos": []
}
```

### 访问申请 API

- `actionType`：`OPEN`、`MODIFY`、`RENEW`、`CLOSE`。

- `validityType`：`LIMITED` 或 `LONG_TERM`。

提交、撤销、审批事件和流程事件需要统一进入生命周期服务。直接关系关闭 API 不再直接关闭关系。

## 验收标准

1. 用户输入完整来源、目标、协议、端口和时间范围后，判定 API 只返回“需要申请”或“不需要申请”。
2. 输入缺失、规则未知、覆盖不完整、端口异常、时间异常、历史快照不可证明覆盖或服务异常时，判定结果均为“需要申请”。
3. 现有有效关系完整覆盖所有来源、目标、协议、端口和时间范围时，判定结果为“不需要申请”。
4. 显式免申请规则完整覆盖所有来源、目标、协议、端口和时间范围时，判定结果为“不需要申请”。
5. 长期有效关系和申请不使用遥远日期占位；长期请求不能被有限期关系覆盖。
6. 修改、续期和关闭只能通过新的访问申请办理；页面不提供直接编辑或直接删除已开通关系。
7. 工作流未成功完成时，不创建、不替换、不关闭访问关系。
8. 审批成功的开通申请创建新关系；审批成功的修改或续期申请形成替代关系并关闭旧关系；审批成功的关闭申请关闭目标关系。
9. 历史关系包含已下线实例时，列表和详情显示风险；新申请无法选择或提交已下线实例。
10. 受保护接口完成服务端认证、RBAC、租户隔离、实体授权、审计和并发版本检查。
11. 前端桌面和移动视口均可完成判定、发起申请、查看风险、创建关闭申请和查看详情。
12. 单元测试、真实 MySQL Flyway 迁移、平台工作流集成路径、前端构建、权限审计检查和浏览器旅程均有可复核证据。
