# 平台业务接入、附件与内部电子签名

## 业务目标

完善业务模块接入平台工作流、统一待办已办、持久附件和内部电子签名的公共能力，使版本发布控制以及后续需求、测试、投产等模块能够通过稳定契约复用平台能力，不读取平台私有表，也不在业务模块复制流程、附件和签名实现。

## 本次范围

- 工作流按稳定流程编码解析当前已发布版本并启动实例。
- 工作流实例保存业务类型、业务标题、业务主键、业务轮次、项目展示快照、详情路由和业务数据摘要。
- 工作流状态变化生成持久、可重试、至少一次投递的业务生命周期事件。
- 首页工作台展示“我的待办”和“最近已办”，支持跳转业务详情。
- 工作流节点可配置内部电子签名，审批人使用当前登录身份点击确认签署。
- 新增独立 ccb-attachment 平台模块，提供临时上传、业务绑定、权限检查、预览、下载、受控删除、审计和孤立文件清理。
- 页面提供临时 Mock 项目切换和项目展示数据，为后续正式项目上下文保留替换接口。
- 继续复用现有站内通知发布能力，不重复建设通知中心。

## 本次不做

- 正式项目管理、项目成员权限和服务端项目数据范围实现。
- 在正式环境使用 Mock 项目数据作为授权依据。
- 外部 CA、短信、邮件、企业微信、生物识别或密码二次验证。
- 具备法律效力的数字签章。
- 版本发布控制业务表、申请状态、纳基和报表实现。
- 外部消息总线或跨系统事件集成。
- 制品文件上传和制品仓库管理。

## 核心规则

### 按编码启动

- 租户内流程编码唯一。
- 业务模块只提交固定编码，平台解析该编码当前已发布版本。
- 未找到、未发布、版本损坏或模型校验失败时不得创建流程实例。
- 启动成功固定定义 ID 和版本号，后续重新发布不影响运行实例。
- 现有按 definitionId 启动接口继续兼容。

### 业务上下文

- businessType、businessKey、businessTitle、actionPath 和 businessRound 必填。
- projectRef、projectName 在 Mock 阶段用于展示，不作为服务端授权依据。
- actionPath 只能是站内绝对路由，不允许外部 URL、协议相对地址、反斜杠或换行。
- dataDigest 保存业务模块提交的规范化数据 SHA-256 摘要，用于绑定审批轮次和签名。

### 生命周期事件

- 事件类型至少包含 STARTED、RETURNED、APPROVED、REJECTED 和 TERMINATED。
- 业务状态变化和事件记录必须在同一数据库事务内完成。
- 每个事件具有全局稳定 eventId；投递语义为至少一次，消费者必须幂等。
- 平台记录每个订阅者的投递状态、次数、错误和下次重试时间。
- 事件乱序或重复不能造成业务状态倒退。
- 旧兼容流程和 Flowable 流程都必须产生同一格式的事件。

### 工作台

- 首页显示当前用户最多五条待办和五条最近已办。
- 展示业务标题、业务类型、项目名称、当前节点、发起人、到达或处理时间和状态。
- 点击使用 actionPath 进入业务详情；完整列表仍保留在工作流菜单。
- 工作台无数据、加载中、失败和无权限状态均有明确呈现。

### 内部电子签名

- 由工作流审批节点配置 signatureRequired。
- 要求签名时，审批操作必须显示确认框，明确当前账号、审批动作和签署含义。
- 用户不重新输入密码，仅使用当前有效登录身份点击确认。
- 服务端从认证主体取得签署人，不接受客户端传入签署人身份。
- 签名绑定流程实例、任务、业务轮次、业务数据摘要、审批动作和意见。
- 签名记录写入后不可修改或物理删除，并在流程时间线和业务详情中展示。
- 未确认签名、令牌失效、任务不属于当前用户、流程轮次不一致或实例摘要缺失时拒绝审批；客户端不提交待签摘要。

### 持久附件

- 上传先生成 TEMP 附件，业务保存成功后由业务服务通过公开契约绑定。
- TEMP 附件仅上传人可访问；BOUND 附件通过业务类型对应的 AttachmentAccessPolicy 校验。
- 平台保存附件名称、类型、大小、对象键、上传人、业务绑定和审计信息，不向业务前端暴露对象键。
- 预览复用 kkFileView；不支持预览的文件仍可按权限下载。
- 已绑定附件的解除绑定或删除必须由业务模块先完成业务状态授权。
- 超过保留期且未绑定的 TEMP 附件由幂等任务清理。
- 删除使用逻辑状态并清理对象存储，失败时保留可重试记录。

### Mock 项目

- 前端项目上下文通过独立 Store 和 Provider 暴露，业务页面不得直接硬编码项目数组。
- 当前项目保存在本地浏览器，仅用于展示和本地联调。
- 工作台可以按 Mock 项目筛选，但该筛选不是安全边界。
- 正式项目模块接入时替换 Provider，不改变业务页面消费接口。

## 权限与安全

- 工作流公开 Java 契约只供服务端业务模块调用。
- 待办、已办、详情和审批操作校验当前用户的任务关系。
- 附件所有接口校验租户、当前用户、附件状态和业务访问策略。
- 签名、生命周期事件和附件操作写入审计。
- 客户端提供的用户、租户、项目权限、对象键和签署人字段均不可信。

## 验收标准

1. 业务模块可按固定流程编码启动当前已发布版本，异常时零实例写入。
2. 两类流程运行路径都生成统一、持久、可重试的生命周期事件。
3. 重复和乱序事件不会造成消费业务状态倒退。
4. 工作流监控可以查询失败或 DEAD 的事件投递，并由授权管理员重新执行。
5. 首页工作台正确展示待办已办业务上下文并跳转站内详情。
6. 要求签名的节点只有当前任务办理人确认后才能审批，并生成不可变签名记录。
7. 不要求签名的现有流程行为保持兼容。
8. 附件完成 TEMP、绑定、授权预览下载、受控删除和孤立文件清理。
9. Mock 项目可在页面切换，且没有被后端当作正式授权依据。
10. 现有按 ID 启动、流程设计器、待办已办、通知和临时文件预览功能无回归。
11. 平台模块测试、全量 Maven 测试、前端构建、Flyway、治理检查和桌面浏览器验收通过。

## 风险与回退

- 数据库只追加 V35 和 V36 迁移，不修改历史迁移。
- 回退应用版本时保留业务事件、签名和附件元数据，不执行生产 DROP。
- 新增字段允许旧实例为空，旧 API 和旧流程继续可用。
- 新附件入口可关闭，但已绑定附件保持只读可追溯。
- 事件投递异常不得回滚已经完成的流程状态，通过重试恢复。
