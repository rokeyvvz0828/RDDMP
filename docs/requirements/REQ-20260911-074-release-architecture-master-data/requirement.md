# 配置管理接入架构物理子系统与交付单元主数据

## 状态和授权

2026-09-11 用户确认配置管理版本申请接入架构管理中的物理子系统和交付单元，并确认以下规则：

- 新建申请只允许选择当前项目下启用的物理子系统及其启用交付单元。
- 编辑草稿时，原选择已停用则保留快照展示，但保存或提交前必须重新选择有效主数据。
- 已提交、审批中和已完成申请继续使用配置管理持有的历史快照。
- 架构交付单元制品类型统一为 `IMAGE`（镜像）和 `BINARY`（二进制），不在配置管理建立二次映射。
- 既有 `容器/压缩包/脚本` 数据通过追加迁移分别转换为 `IMAGE/BINARY/BINARY`，旧字典项停用。

用户已确认推荐的“配置管理端口 + Boot 适配器 + 架构公共只读查询契约”设计并要求实施。需求状态为 ready。

## 业务目标

版本申请人从配置管理新建或编辑申请时，直接选择当前项目在架构管理中维护的真实物理子系统和交付单元；服务端重新校验项目归属、启用状态和父子关系，并使用可信主数据生成申请快照，替代前端静态 Mock。

## 本次范围

- 架构交付单元制品类型字典收敛为 `IMAGE/BINARY`，追加 Flyway 数据迁移。
- 架构模块公开面向业务引用的最小只读查询契约，按租户和项目查询启用物理子系统及其启用交付单元。
- 配置管理定义主数据消费端口并提供配置管理权限下的只读选择接口。
- Boot 模块组装配置管理端口与架构查询契约，不建立业务模块私有实现依赖。
- 版本申请创建、草稿保存和更新时由服务端校验并规范化物理子系统、交付单元快照。
- 版本申请抽屉移除静态 Mock，按当前项目异步加载并联动物理子系统和交付单元。
- 覆盖加载、空、失败、无权限、停用快照和移动端状态。

## 非目标

- 不修改已提交、审批中或已完成申请的历史快照。
- 不把配置管理业务规则放入架构模块，不允许配置管理直接读取 `arch_*` 表。
- 不调整投产窗口、审批流程、需求选择、文件介质、投产基线和生产版本规则。
- 不新增跨项目选择，不授予配置管理用户架构维护权限。
- 不修改历史 Flyway 文件 `V212__delivery_unit_artifact_type.sql`。

## 数据与权限规则

1. 数据 Owner 为 `business/architecture`；配置管理只读引用，配置申请表继续保存编码和名称快照。
2. 所有选择查询和写入校验必须执行登录校验、配置管理权限、项目访问权限及 `tenant_id + project_id` 隔离。
3. 物理子系统必须未删除且状态为 `ACTIVE`。
4. 交付单元必须未删除、状态为 `ACTIVE`、归属所选物理子系统，且制品类型只能为 `IMAGE` 或 `BINARY`。
5. 前端提交的编码、名称和制品类型不可信；服务端按 ID 读取真实主数据并覆盖快照字段。
6. 原 Mock 草稿或已停用主数据可按申请快照反显，但不得再次保存或提交。

## API 契约

- `GET /api/release/master-data/physical-subsystems?projectId=...&keyword=...&page=...&size=...`
- `GET /api/release/master-data/physical-subsystems/{subsystemId}/delivery-units?projectId=...&keyword=...&page=...&size=...`

接口只返回选择所需字段并使用配置管理申请权限，不要求调用者持有架构管理页面权限。

## 验收标准

1. 当前项目存在启用架构数据时，版本申请抽屉可查询物理子系统并在选择后查询其交付单元。
2. 切换项目或物理子系统后清除不属于新上下文的选择，不发生请求乱序覆盖。
3. 新建、保存草稿和更新均拒绝不存在、停用、跨项目或父子关系错误的数据，且数据库无部分写入。
4. 服务端忽略伪造的编码、名称和制品类型，保存架构主数据返回的可信快照。
5. 架构交付单元新值只能为 `IMAGE/BINARY`；存量容器、压缩包、脚本值按确认映射迁移，旧选项不再用于新增维护。
6. 已停用历史草稿能看到原快照与“已停用”提示，但保存和提交被前后端共同阻止；非草稿历史申请展示不变。
7. 仅有配置管理申请权限且能访问项目的用户可读取选择数据；无项目权限、跨租户和未认证请求被拒绝。
8. 后端模块测试、Flyway 检查、治理检查和前端构建通过；桌面及 375/390/430 像素移动视口下无整页横向溢出或不可达操作。

## 风险与回退

- 追加迁移会规范化共享字典与存量交付单元，需在发布前备份相关字典和交付单元数据。
- 回退代码后历史申请不受影响；迁移数据如需恢复，使用发布前备份补偿，不回改历史迁移。
- 基线后端测试在当前受限沙箱中因 Mockito/Byte Buddy 无法附加 JVM 而失败，必须在允许进程附加的环境复验。
