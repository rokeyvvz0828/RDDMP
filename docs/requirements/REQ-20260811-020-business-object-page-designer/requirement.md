# 业务对象页面设计器重构

## 业务目标

重启现有表单视图设计器，形成稳定的“业务对象 -> 页面集合 -> 页面角色 -> 字段布局”配置路径。设计器应让研发人员先选业务对象，再按列表、详情、新建、编辑、审批配置页面；新建和编辑页面内部选择单页表单或分步表单，避免把两者误认为同级业务页面。

## 本次实施

- 为 `biz_form_view` 追加页面集合、页面角色和表单模式字段，兼容历史 `view_type` 数据。
- 服务端校验页面角色与表单模式组合，返回规范化的页面角色和模式。
- 设计器左侧以业务对象和页面树组织工作流；列表页优先作为业务入口。
- 列表、详情、新建、编辑、审批共用当前业务对象的字段主列表；列表字段只能来自已纳入表单字段集合的字段。
- 新建/编辑页面支持单页表单或分步表单；分步配置沿用现有步骤表。
- 视图属性按页面角色显示：列表显示列宽、固定列、筛选、排序和移动端模式，表单显示分区、栅格和字段属性，详情/审批默认为只读。
- 补充项目管理业务对象 Mock 页面集合，确保首次启动可以直接看到设计示例。

## 不实施

- 不创建动态 Vue 路由，不把数据库配置转换成任意组件路径。
- 不修改既有业务模块页面、业务 CRUD、工作流引擎或菜单权限模型。
- 不删除历史 `view_type`、V35/V36 迁移或旧视图数据。

## 验收标准

1. 设计器能展示项目管理业务对象及列表、详情、新建、编辑、审批页面。
2. 新建/编辑页面的模式只允许 `single` 或 `wizard`，列表/详情/审批不能选择表单模式。
3. 列表、详情、表单、审批页面都只能从同一业务对象字段主列表引用字段；列表引用不可用字段时服务端拒绝。
4. 历史 `form/detail/list/approval/wizard` 视图仍可查询，并能映射到新页面角色。
5. 前端在 375x812、390x844、430x932 和 1280x800 视口无页面级横向溢出，核心配置路径可操作。
6. 前端构建、治理检查、Flyway 检查和 system 模块测试通过。

## 回退

停止读取新增页面字段并回退应用版本即可；保留追加迁移和历史数据，不删除任何 V35/V36 数据。
