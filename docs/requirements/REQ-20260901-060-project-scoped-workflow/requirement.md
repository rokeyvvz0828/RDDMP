# 工作流按项目维度管理

## 业务目标

工作流定义、业务绑定、流程实例和审批人员应具有明确的项目归属。项目成员只看到有权访问的项目流程和实例，项目流程只能选择本项目成员与项目角色，审批任务在执行时再次校验项目权限。

## 本次实施

- 流程定义支持 `GLOBAL`（租户模板）与 `PROJECT`（项目流程）两种范围；存量定义迁移为 `GLOBAL`。
- 项目流程必须绑定真实项目主键，定义查询返回当前项目流程和租户全局模板，并明确展示范围。
- 流程实例新增真实 `project_id`；业务启动在创建首批任务前固化项目主键，项目编号和名称继续作为历史快照。
- 审批人来源增加“项目成员”和“项目角色”；项目流程保存、发布和启动时校验人员、角色均属于对应项目。
- 流程定义、监控、详情、待办和审批操作执行项目访问校验；无项目权限的用户不能通过直接接口读取或处理。
- 项目成员被停用或移除前检查该项目中的待办任务；存在待办时阻断并提示先转交、撤销或终止流程。
- 工作流编辑页使用顶层项目上下文加载项目流程、项目成员和项目角色；切换项目后重新加载。
- 全局流程及无法回填项目的历史实例保持租户级兼容，不伪造项目归属。

## 不实施

- 不改变具体业务模块对审批场景的判定规则。
- 不把项目组织树作为审批授权或数据权限来源。
- 不自动迁移全局用户/角色审批节点为项目成员/项目角色节点。
- 不修改 Flowable 自带 `ACT_*` 表，不修改历史 Flyway。
- 不引入跨租户项目共享。

## 业务规则

1. `PROJECT` 定义必须有 `project_id`，`GLOBAL` 定义必须没有 `project_id`。
2. 项目流程的创建、编辑、发布、取消发布、归档、恢复和删除仅允许超级管理员、项目负责人或项目 `PM` 角色成员操作。
3. 项目成员可查看本项目流程定义和实例；全局流程沿用现有平台工作流权限。
4. `PROJECT_MEMBER` 保存用户主键，用户必须是项目有效成员；`PROJECT_ROLE` 保存项目角色主键，运行时解析该角色下的有效项目成员。
5. 项目流程的抄送用户同样必须是项目有效成员。
6. 项目实例的任务查询、详情和审批操作必须同时满足任务归属与项目访问权限。
7. 业务启动时先解析项目、校验定义范围并写入实例项目上下文，再创建首批任务。
8. 存量实例根据 `project_ref = pm_project.project_code` 回填；无法唯一匹配的记录保持 `project_id` 为空。

## 验收标准

1. 当前项目成员可以看到该项目流程和全局模板，看不到其他项目流程；无权限直接访问返回禁止访问。
2. 新建项目流程后，审批节点只能选择当前项目成员和角色；跨项目人员或角色在服务端被拒绝。
3. 项目业务启动生成的 `wf_instance.project_id` 在首批 `wf_task` 产生前已写入，两个执行引擎的审批人解析结果一致。
4. 失去项目权限的用户即使仍持有任务 ID，也不能读取上下文或提交审批。
5. 有待办任务的项目成员不能被停用或移除；待办处理或流程终止后可以操作。
6. `V134` 成功迁移定义和实例数据，存量全局流程及无项目历史实例继续可查询。
7. 工作流后端、系统后端、组合层测试、全量 Maven 测试、前端构建、治理与范围检查通过。
8. 桌面、`375x812`、`390x844`、`430x932` 视口下，范围选择、项目标签和人员配置可用，无页面级横向溢出。

## 权限、数据与审计

- 后端继续执行现有 RBAC，并叠加项目成员/管理权限和实体归属校验。
- 项目数据由 `platform/system` 拥有；`platform/workflow` 通过公开契约访问，`platform/boot` 负责组合，禁止形成 Maven 循环依赖。
- 工作流定义和实例生命周期审计保持现有机制，项目范围作为被审计对象上下文。
- 数据迁移只追加 `V134`，应用回退时保留新增可空列和绑定表。

## 回退

回退本需求 Java、Vue、TypeScript 和契约代码；数据库新增列和表保留，旧应用忽略新增列。需要物理回退时另行追加迁移，禁止修改 `V134`。
