# 需求管理平台（新建项目 + 存量项目）

## 业务目标

依据 2026-08-16 会议纪要重构需求管理平台，替代已删除的旧需求管理实现。平台提供两大业务模块：

1. **新建项目（0~1 项目）**：各项目组针对自身系统做差异分析，形成需求差异清单（对应《附件1：需求分析差异清单》），支持在线填写与上传 Excel 自动解析；每条差异走「待评审 → 评审中 → 已评审」审批流，评审通过后项目组成员不可修改；同一项目全部差异评审完成后一键形成基线，差异可维护开发状态、测试状态。
2. **存量项目（常态化需求管理）**：按《蒙商常态化需求管理表-需求管理基线-业务组填写》sheet 字段维护存量需求，按需求提出、需求对接、工作量评估、立项、软需、投产等阶段推进，每个阶段有状态；支持在线提交与上传解析。

贯穿要求：每一条数据都有完整改动记录（谁改的、什么时间改的、改了什么），列表行内提供「修改记录」入口，点击弹出小窗口展示历史记录。

## 范围

### 本次实施

- 新建项目主数据（项目编码、项目名称、项目类型、启动时间、状态、说明）。
- 需求差异清单：按附件1 的 24 个字段建模（序号、事业群、业务板块、业务组、需求编号、分类、名称、涉及系统、金科做法、差异类型、蒙商作法、差异描述、蒙商分析部门、蒙商分析人、金科分析人、适配方式、处理状态、协同组、解决方案、是否专题、上升决策层级、决策结论、蒙商确认部门、金科确认人），枚举值按附件1 list sheet 维护。
- 差异生命周期：待评审 → 评审中 → 已评审/已退回；**单条提交评审**，走平台审批流，审批人**按角色路由**；评审通过后锁定不可修改；退回回待评审。
- 基线：同一项目全部差异已评审后「形成基线」，生成基线版本快照并整体锁定；本期不做基线后变更流程。
- 差异扩展字段：开发状态（未开始/开发中/已完成/已上线）、测试状态（未开始/测试中/已通过），作为差异上的状态字段维护。
- 存量项目常态化需求：按《需求管理基线-业务组填写》sheet 的 8 个阶段列组字段建模（需求提出、需求对接、工作量评估、立项、软需、投产、需求状态及备注、需求变更信息），每个阶段有状态（未开始/进行中/已完成），阶段推进采用状态确认、**不走审批流**。
- 录入方式：在线填写 + 上传文件自动解析（模板下载、逐行校验、校验报告、确认导入）。
- 系统清单主数据（req_system）：系统编号、名称、事业群、逻辑子系统、业务组件、业务领域、产品视图、投产点、状态、引入/保留等，供两模块选择与校验。
- 统一改动记录（req_change_log）：所有业务数据的新增、修改、状态流转均记录操作人、时间、字段、旧值、新值、来源；「修改记录」弹窗查看历史。
- 表单与页面样式：复用平台现有 UI 组件与交付示范中心设计，按 `design-h5.md` 完成移动端适配。

### 本次不实施

- 配置管理模块（参数实例化、菜单/岗位/角色/权限实例化内容、参数模板转数据库脚本工具），另立需求。
- 基线后差异变更流程；已基线数据修改需另立需求。
- 不打通研发/测试模块，开发/测试状态仅作为差异上的状态字段。
- 不新增客户/项目以外的组织维度；演示与 mock 数据中的客户名称一律脱敏（如「XX银行」），人员使用虚构姓名，不出现真实姓名、电话等个人信息。
- 不接入外部需求/工单/维普/PAMS 系统；需求编号一期手工登记或从基线导入。
- 存量项目阶段推进不走审批流；不实现评审会签/签字。

## 现状与规则

- 数据来源：`docs/demand` 目录下《附件1：蒙商银行-需求分析差异清单_板块(组名)_物理子系统 V0.2》与《蒙商常态化需求管理表-0710-2050(1)》作为模板结构、枚举口径与样例参考；具体客户名称、人员姓名与电话必须脱敏后方可用于初始化与演示数据，源文件不入库、不提交。
- 差异状态：待评审 / 评审中 / 已评审 / 已退回；评审通过即锁定，项目组成员不可编辑删除。
- 差异枚举：事业群、业务板块、业务组、分类（功能/流程/产品/批处理/报表/岗位/菜单/核算/其他）、差异类型（无差异/金科有-蒙商无/金科有-蒙商手工/蒙商有-金科无/双方作法有差异）、适配方式（按原型/参数配置/业务清理/少量改造/保留现状）、处理状态（双方已确认/待行方确认/待架构确认/跨组沟通/待决策）、上升决策层级（版块内/总体组/领导小组）、是否专题（是/否）。
- 存量需求阶段：需求提出 → 需求对接 → 工作量评估 → 立项 → 软需 → 投产；需求状态取值（需求分析/业需修订/业需评审通过/立项中/软需编制/软需评审通过/已投产/需求终止）。
- 需求编号：新建项目格式为「组件物理子系统编号+三位序号」（如 `W01812-001`）；存量项目按维普需求编号格式（如 `JG-W0332C-240507-001`）。需求编号先不强制校验，导入时仅提供格式提示，不做硬性拦截。
- 权限：项目组成员（维护本项目待评审差异）、评审角色（审批流按角色路由）、存量需求按业务组数据范围维护、管理员/统筹（项目管理、系统清单、基线、阶段确认）；受保护接口在服务端校验认证、RBAC、数据范围与实体授权；写操作记录操作人、对象、动作、前后值与 trace ID。
- 附件：差异清单 Excel、业需/软需文档通过平台文件预览/附件能力上传与预览，业务代码不得暴露底层存储路径。

## 接口与数据

- 新增业务模块 `server/src/modules/requirement`（Maven artifact `ccb-requirement`，包名 `com.ccb.requirement`），内部按新建项目、存量项目两个业务域组织，依赖 `shared/common`、`platform/infrastructure`、`platform/security`、`platform/workflow`、`platform/file-preview`。
- 审批流：新建项目差异评审按固定流程编码 `requirement.diff.review` 接入平台 workflow，审批人按角色路由，审批状态通过业务生命周期事件回写（幂等）。
- 数据 Owner：业务需求管理模块；表前缀 `req_`，全部含 `tenant_id`、软删除与审计字段。
- 核心表：`req_project`、`req_difference`、`req_legacy_requirement`、`req_stage_log`、`req_system`、`req_baseline`、`req_baseline_item`、`req_change_log`、`req_import_batch`、`req_attachment`。
- 数据库迁移：追加式 Flyway（V35 起，旧 V36/V37 已删除），不修改已发布脚本；存量兼容与回退按数据库规约执行。
- 新增模块需同步更新 `governance/modules.yaml`、`docs/architecture/MODULES.md`、根与组合根 `pom.xml`、CODEOWNERS；属于治理与公共能力变更，需 Owner 审批。
- 脱敏输入输出示例：客户名称统一替换为「XX银行」，人员姓名使用虚构姓名，电话使用 `13800000000` 形式。

## 验收标准

1. 新建项目：能创建项目，按系统维护需求差异清单；支持在线逐条新增/编辑与上传附件1 格式 Excel（下载模板 → 逐行校验 → 校验报告 → 确认导入），导入数据状态为「待评审」。
2. 差异评审：单条提交评审走审批流，审批人按角色路由；评审中锁定，审批通过后状态「已评审」且项目组成员不可修改，退回后回到「待评审」并展示退回意见。
3. 基线：同一项目全部差异均为「已评审」时可形成基线，生成基线版本并整体锁定；基线版本可查看。
4. 差异可维护开发状态、测试状态字段。
5. 存量项目：按《需求管理基线-业务组填写》字段维护需求，支持在线提交与上传解析；需求提出、需求对接、工作量评估、立项、软需、投产各阶段可推进并记录状态（未开始/进行中/已完成），阶段推进留痕。
6. 改动记录：每条差异/需求/系统/基线的每次变更均可通过行内「修改记录」弹窗查看历史（时间、操作人、操作类型、字段、旧值、新值），数据与业务变更一致。
7. 权限：匿名 401、越权 403、授权成功；项目组成员仅能修改本组待评审/已退回数据。
8. 全新本地数据库启动后无需人工配置即可看到新建项目、存量项目页面与脱敏演示数据；桌面与 375/390/430 移动视口完成浏览器验收。
9. JDK 17 后端测试、前端构建、治理检查与 Flyway 检查通过。
