# 移除逻辑子系统模型并收敛物理子系统字段

## 业务目标

架构管理不再维护独立的逻辑子系统主数据。架构维护人员在物理子系统工单中直接维护物理子系统编号、可选逻辑子系统文本和业务组件编号；业务组件选项由系统字典统一管理。完成后，用户从架构管理入口只处理物理子系统及其下游部署单元、环境、资源和网络关系，不再看到逻辑子系统列表、详情、选项或变更入口。

## 范围

### 本次实施

- 退役独立逻辑子系统模型：移除逻辑子系统菜单、前端页面、HTTP 接口、选项接口、服务、模型和测试入口。
- 追加数据库迁移，删除逻辑子系统表及逻辑草稿/编号分配等仅服务于逻辑父级模型的结构；存量物理记录在删除前回填可选逻辑子系统文本。
- 将物理子系统的逻辑归属降为一个可选文本字段，新增或变更物理子系统时可以为空，也可以人工填写。
- 为物理子系统新增业务组件编号 `businessComponentCode` 字段，值来自系统字典 `ARCH_BUSINESS_COMPONENT` 的启用项；页面和接口展示字典标签。
- 支持在物理子系统新增工单中自行填写物理子系统编号，由服务端统一转大写、校验格式并保持租户内永久唯一；不再依赖逻辑序号和编号槽位生成物理编号。
- 同步架构模块契约、Mock 数据、前端类型和依赖物理子系统选项的下游页面，保证部署单元、具体环境资源申请、环境部署实例、网络访问和搭建计划继续以物理子系统为主引用。
- 删除或隐藏逻辑子系统相关权限入口，保留必要的历史工单只读显示兼容，不允许再创建或提交逻辑目标工单。

### 本次不实施

- 不把逻辑子系统改成新的系统字典或新的业务主数据。
- 不迁移、删除或重建部署单元、资源申请、环境部署实例、网络访问关系等下游业务数据。
- 不实现跨模块从需求管理系统清单自动同步业务组件。
- 不连接生产库，不执行生产数据清理。
- 不修改平台 system 字典管理页面；仅通过迁移新增业务组件字典分类和基础选项。
- 不引入动态表单元数据、`biz_form_*`、表单 schema 或 `PublishedFormSchemaQuery`。

## 现状与规则

- 当前入口、流程和数据来源：架构模块已有逻辑子系统、物理子系统、部署单元、环境、资源申请、网络和搭建计划能力；物理主记录直接写入已被生命周期工单替代。
- 业务规则和边界：用户确认采用方案 B，硬移除逻辑表和逻辑接口；物理子系统成为架构主数据根对象，逻辑子系统仅作为物理记录的可选文本说明。
- 角色、权限、数据范围和审计：物理子系统沿用 `architecture:view`、`architecture:apply`、`architecture:manage` 以及物理相关查看/变更权限；服务端继续执行认证、RBAC、当前租户过滤、行版本和操作审计。逻辑相关权限不再赋予可见入口。
- 外部系统、附件或敏感信息：不访问外部系统；不处理附件；不使用真实生产数据、真实人员信息、口令、Token、Cookie、证书或未脱敏日志。

## 接口与数据

- API/事件契约：移除 `/api/architecture/logical-subsystems` 和 `/api/architecture/options/physical-subsystem/logical-subsystems`；物理子系统列表、详情、工单草稿、提交和发布接口新增 `code`、`logicalSubsystemName`、`businessComponentCode` 字段。
- 数据 Owner：物理子系统及其下游引用属于 `business/architecture`；业务组件可选项属于 `platform/system` 字典能力，通过架构选项接口白名单读取。
- 数据库迁移与存量兼容：追加新版本 Flyway 迁移，先把原逻辑父级名称回填到物理记录文本字段，再删除外键、逻辑表、逻辑草稿表和逻辑编号分配结构；历史工单主表保留，以避免审计链断裂。
- 脱敏输入输出示例：物理新增草稿可提交 `code: "PHY_PAYMENT"`, `logicalSubsystemName: "支付逻辑域"`, `businessComponentCode: "architecture.business-component.payment"`。

## 验收标准

1. 架构管理菜单、路由、前端页面和后端接口不再提供逻辑子系统列表、详情、创建、编辑、删除、选项或逻辑工单入口。
2. 数据库迁移在空库和已有库均可执行；迁移后不存在活动外键依赖 `arch_logical_subsystem`，且 `arch_logical_subsystem` 与仅服务逻辑模型的草稿/编号表已移除。
3. 迁移前已有物理子系统能在新字段中看到可选逻辑子系统文本；没有逻辑文本的记录显示为空值，不阻塞列表、详情或下游选择。
4. 物理子系统新增工单必须填写物理编号；服务端转大写、校验 2-32 位字母数字连字符下划线，并对当前租户永久唯一，重复或删除后复用返回 409。
5. 物理子系统新增、更新、详情和列表均包含 `businessComponentCode`，仅接受 `ARCH_BUSINESS_COMPONENT` 启用字典项或空值；无效字典值返回 400。
6. 物理子系统页面显示并筛选业务组件编号，移动端卡片和详情抽屉无页面级横向滚动，提交中、失败、无权限、空数据和脏表单状态仍可见。
7. 部署单元、资源申请、环境部署实例、网络访问和搭建计划仍可按 ACTIVE 物理子系统选择和展示，不再依赖逻辑父级字段。
8. 源码、SQL、网络请求和前端类型中没有新增动态表单元数据依赖；不新增生产访问或真实数据。
9. 相关 Maven 聚焦测试、前端构建、Flyway 检查、治理检查、范围检查和 `git diff --check` 有真实结果。
10. 真实浏览器验证覆盖物理子系统列表、详情、申请草稿、提交前校验、业务组件字典、桌面和 375/390/430 手机视口；未执行项不得报告为通过。
