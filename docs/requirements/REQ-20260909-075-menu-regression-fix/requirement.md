# 动态菜单回归修复

## 业务目标

修复项目级角色权限上线后出现的菜单回归：系统设置中的“权限维护”必须显示正确中文；项目管理和系统级菜单作为全局入口，不依赖也不展示顶部项目选择器。拥有任一可访问项目的项目管理权限的用户必须能看到“项目管理”入口。

## 范围

- 追加 Flyway 补偿迁移，使用与 SQL 客户端字符集无关的 UTF-8 字节写回“权限维护”。
- 将项目管理和系统级路由标记为全局路由：进入时不初始化项目上下文，应用壳层不展示顶部或移动端项目选择器。
- 项目管理入口按用户在任一可访问项目中的 `project:project:list` 权限生成，不受当前或未选择的顶部项目影响。
- 登录或恢复会话时，若本地没有有效项目上下文，自动从用户可访问项目中恢复默认项目并刷新项目级菜单。
- 保留项目内业务路由的项目上下文、`X-Project-Id`、数据范围和服务端实体授权。
- 权限维护的所属菜单使用下拉式菜单树；编辑时展开当前菜单的祖先节点，已停用菜单不出现在候选项中。
- 补充路由、动态菜单和迁移回归测试。

## 不变量与非目标

- 不修改已发布的 V201，不手工伪造 Flyway 历史。
- 不改变项目成员、项目角色权限和系统角色权限的数据边界。
- 不允许在任一可访问项目中都没有 `project:project:list` 权限的用户获得项目管理菜单。
- 不修改 JWT、公开 API、项目业务表、项目内数据范围或服务端鉴权。

## 验收标准

1. 菜单 102 的名称为“权限维护”，UTF-8 字节为 `E69D83E99990E7BBB4E68AA4`。
2. 访问 `/projects` 或 `/system/**` 时，不初始化项目上下文，桌面顶部和移动端抽屉均不展示项目选择器；离开后原有已选项目保持不变。
3. 用户在任一可访问项目中具有 `project:project:list` 时，即使顶部未选择项目，动态路由也包含 `/projects`；仅具有其他 `project:*` 权限或没有项目管理权限时不包含该入口。
4. 系统级菜单仍只按系统权限生成，不因当前项目上下文改变；项目内业务菜单、接口数据范围与服务端鉴权保持原规则。
5. Security 聚焦测试、前端生产构建及桌面和移动端浏览器验收通过。
6. 权限目录接口返回菜单状态；所属菜单下拉树仅展示启用菜单，并在编辑时显示当前选择的树路径。
7. `ccb.current_project_id` 缺失时，拥有可访问项目的用户登录或刷新页面后自动恢复一个有效项目上下文，并同时显示项目级菜单；没有可访问项目或项目列表暂时加载失败时，保留系统级菜单和登录态。
