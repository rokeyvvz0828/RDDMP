# 架构管理 - 交付单元

## 状态和授权
业务规则经当前会话确认：2026-09-10 用户提出“开发交付单元功能，放到架构管理菜单下，交付单元归属于物理子系统，需要交付单元名和归属物理子系统，实现增删改查，使用平台统一的抽屉式表单和信息展示，支持关联部署单元，可在详情抽屉关联”，并在复核中确认：

- 逻辑子系统已于 `V147__remove_logical_subsystem_model.sql` 移除，物理子系统是架构主数据根对象，本需求不得重新引入逻辑子系统。
- 关联部署单元只能选择**同一物理子系统**下的部署单元。
- 关联关系**无方向**：从交付单元可查关联部署单元，从部署单元也可查关联交付单元（补充需求）。
- 其余设计取舍（自动编号、状态 ACTIVE/INACTIVE、只做增删改查不做版本快照与导入、软删除 + 引用守卫、复用 `UiFormDrawer`、非目标清单）用户确认无异议。

用户已确认设计文档并要求进入实施计划。ready 表示业务基准明确。

## 业务目标
架构管理员在架构管理菜单下维护交付单元（交付内容的稳定逻辑身份），并把它与同一物理子系统下的部署单元建立无方向关联，使“哪些部署单元承载该交付单元”以及“某部署单元被哪些交付单元使用”都能被直接查询，取代当前交付单元信息只存在于其他模块前端 mock 主数据的状态。

可观察成功结果：用户在架构管理菜单进入“交付单元”，完成新增、查询、修改、删除，并在抽屉内完成关联维护；部署单元详情能看到关联的交付单元。

## 范围

### 本次实施
- 新增交付单元主数据与编号分配：名称、归属物理子系统（创建后不可改）、自动编号、状态、描述、备注、软删除、乐观锁、审计。
- 交付单元分页列表（名称/归属物理子系统/状态筛选）、详情、新增、修改、删除、停用/启用。
- 交付单元与部署单元的无方向关联（仅同一物理子系统）；交付单元详情抽屉与部署单元详情抽屉**都可维护关联**，两侧共享同一份关系数据。
- 架构管理菜单下新增“交付单元”菜单与 `architecture:delivery-unit:view` / `architecture:delivery-unit:manage` 两级权限及角色种子。
- 追加 Flyway 迁移与聚焦测试、前端构建与浏览器验收。

### 本次不实施
- 不修改 `release` 模块的前端 mock 交付单元主数据，不接入其他业务模块。
- 不做交付版本、交付制品、交付映射审批、Excel 导入。
- 不恢复逻辑子系统模型，不调整物理子系统既有契约。
- 不在部署单元的新建/修改表单中增加交付单元选择（关联编辑只在详情抽屉内，避免只改关联也发布新版本）。
- 不新增或修改平台公共组件、公共包与公共 API。

## 现状与规则
- 当前入口：架构管理（菜单 800）下已有逻辑子系统（已删）、物理子系统（802）、部署单元（804、805）。交付单元不存在任何表、菜单或接口。
- 数据来源：物理子系统 `arch_physical_subsystem`、部署单元 `arch_deployment_unit`（均按 `project_id` 隔离）。两个主数据表由架构模块拥有，本需求只新增本模块 `arch_` 表。
- 业务规则：
  - 交付单元归属物理子系统必须存在、未删除且状态为启用；归属创建后不可变更。
  - 交付单元名称在“同租户 + 同项目 + 同物理子系统”内唯一。
  - 编号创建时分配、不可修改、序号永久占用不回收，格式 `DU<物理子系统编号><三位序号>`。
  - 只有同一物理子系统的部署单元才能被关联；该不变量由数据库复合外键保证，服务层同时做显式校验。
  - 部署单元作废时若仍被交付单元关联，拒绝作废（fail-closed）。
- 角色、权限、数据范围和审计：查看沿用 `architecture:delivery-unit:view`（兼容既有 `architecture:view/apply/manage`、`architecture:deployment-unit:view`），写操作仅 `architecture:delivery-unit:manage`；所有请求按 `projectRef` 做项目访问校验；写操作写 `com.ccb.system.capability.SystemOperationAudit`，审计失败不阻断业务结果。
- 外部系统、附件或敏感信息：无外部系统访问、无附件、无敏感数据。

## 接口与数据
- API 契约：`/api/architecture/delivery-units`（列表、详情、新增、修改、删除、停用/启用、覆盖式更新关联），`/api/architecture/deployment-units/{id}/delivery-units`（部署单元反查，只读）。
- 数据 Owner：`business/architecture`。新增表 `arch_delivery_unit`、`arch_delivery_unit_number_seq`、`arch_delivery_unit_deployment_unit`。
- 数据库迁移与存量兼容：仅追加 `V202__create_architecture_delivery_units.sql`，不修改已发布迁移；纯新增表与新增菜单/权限行，不改写存量数据；回退为停用入口 + 回退代码，新表可保留或按发布流程删除。
- 脱敏输入输出示例：`{"name":"统一认证交付包","physicalSubsystemId":12,"relatedDeploymentUnitIds":[31,32]}`。

## 验收标准

1. 在架构管理菜单可见“交付单元”，具备查看权限可进入列表，无权限返回 403 且前端展示无权限态。
2. 新建交付单元必须选择启用物理子系统并填写名称；创建成功后自动获得 `DU…` 编号，编号不可修改。
3. 同一物理子系统内重名被拒绝并给出可读错误；不同物理子系统可同名。
4. 列表支持按名称、归属物理子系统、状态筛选并分页；详情展示编号、名称、归属物理子系统、状态、描述、备注与关联部署单元。
5. 修改名称/描述/备注成功并递增行版本；并发使用旧行版本提交被拒绝；归属物理子系统不可通过任何入口修改。
6. 关联只能选择同一物理子系统下、状态为启用的对侧对象；交付单元详情抽屉与部署单元详情抽屉都可多选保存关联，任一侧保存后另一侧立即可见；已停用的交付单元或已停用/已作废的部署单元不能调整关联。
7. 删除交付单元需二次确认，删除后列表不再展示，其关联同步清理且不影响部署单元主记录；停用后不能新增关联，已有关联保留可见。
8. 写操作产生审计记录；跨项目、越权与未认证请求被服务端拒绝。
9. 桌面与手机视口下加载、空、失败、无权限、提交中状态完整，无横向整页滚动、遮挡或按钮不可达。
