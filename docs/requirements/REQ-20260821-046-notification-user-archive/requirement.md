# 消息通知用户归档

## 业务目标

用户可以将已经阅读和处理的通知从默认通知列表中归档，并在已归档视图中查看或恢复；通知正文、接收关系和业务审计证据必须保留。

## 本次实施

- 仅允许当前用户归档自己已读且未归档的通知。
- 增加“已归档”视图，支持现有分页和业务板块筛选，并允许单条恢复。
- 增加“归档全部已读”，二次确认后仅归档当前用户未归档的已读通知。
- 默认列表、未读列表、未读角标和业务板块汇总排除已归档通知。
- 保留旧 `unreadOnly` 查询参数兼容，新前端使用 `view=ALL|UNREAD|ARCHIVED`。

## 不实施

- 不物理删除通知、接收关系或审计记录。
- 不提供管理员跨用户归档、自动归档、保留期限或定时清理。
- 不改变通知发布、工作流事件内容、业务路由和外部通知渠道。

## 数据与权限

- 归档状态属于 `sys_user_notification`，新增可空 `archived_at`；历史数据默认未归档。
- 所有查询和更新从认证主体读取 `tenant_id` 和 `user_id`，客户端不能指定目标身份。
- 恢复只清空 `archived_at`，保持 `is_read/read_at` 不变。

## 验收标准

1. 归档已读通知后，仅当前用户的活动列表减少，已归档列表增加；其他接收人不受影响。
2. 未读通知归档返回 409 和“请先阅读消息后再归档”，重复归档与重复恢复幂等。
3. 恢复后通知回到全部列表且保持已读，未读角标不增加。
4. 批量归档只处理 `is_read = 1 AND archived_at IS NULL`，返回实际变更数。
5. 三种视图的分页、板块筛选和计数一致，一秒轮询仍只请求未读计数。
6. 后端聚焦测试、前端构建、Flyway 启动、治理检查和桌面/移动浏览器验收通过。
