# 版本申请文件介质

## 业务目标

版本申请除普通交付单元外，还可以登记一个或多个文件路径。文件介质与普通交付单元共享审批、冲突确认、投产基线、生产版本、统计、权限和审计链路。

## 必须行为

1. 版本申请提供可同时选择的“交付单元”和“文件介质”，至少选择一种；新建默认选择交付单元。
2. 文件介质允许添加多条，每条只填写一个文件路径，不填写版本号或选择制品类型。
3. 文件介质归属申请所选物理子系统，后端固定保存为交付单元 `FILE`、名称“文件介质”、制品类型 `FILE`，版本号为空。
4. 文件路径去除首尾空格后不能为空，最长 1024 字符，不允许控制字符；同申请内不得重复。
5. 非应急申请按同一窗口和相同规范化路径判断重复，沿用取消旧申请、修改旧申请或继续创建新申请；历史已准出路径再次申请时识别为追加申请。
6. 审批准出后，每条路径独立进入承接窗口的投产基线，可分别维护投产成功、投产失败或未投产。
7. 投产成功的文件介质进入生产版本，按物理子系统和路径展示最近成功记录、投产时间和来源申请，版本号显示“无版本号”。
8. 申请详情、冲突弹窗、投产基线、生产版本和统计分析区分交付单元与文件介质。
9. 存量普通交付单元行为、现有权限、审批状态、乐观锁、修订历史、状态事件和投产审计保持不变。
10. 桌面及规定手机视口中，版本申请抽屉无页面级横向溢出，新增、删除、保存和提交操作可达。

## 非目标

- 不访问、上传、校验或预览路径对应的真实文件。
- 不增加文件版本、校验和、文件大小、主机、环境或目录浏览。
- 不建设项目、物理子系统或交付单元主数据服务。
- 不改变审批流程、窗口规则、版本类型或菜单权限。

## 验收标准

1. 仅交付单元、仅文件介质和混合申请均可保存、编辑、提交和查询。
2. 多条路径独立保存，空路径、重复路径、超长路径和控制字符被服务端拒绝。
3. 同窗口相同路径触发完整冲突提示，不同路径不触发；确认继续创建后可正常提交。
4. 两条文件路径准出后在投产基线显示为两行，维护其中一条不影响另一条。
5. 文件路径投产成功后出现在生产版本中，结果回改后能回算上一条成功记录。
6. 存量申请和普通交付单元回归通过，无权限用户不能绕过后端权限。
7. Flyway、发布模块测试、全量测试、前端构建、真实接口和规定视口浏览器验收通过。

## 回退

源代码可按本需求范围回退。Flyway 迁移不做降版本；已执行迁移的环境通过后续补偿迁移处理。存在文件介质业务数据时，不允许回退到无法读取该数据的旧应用版本。
