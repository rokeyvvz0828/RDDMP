# 字段治理与视图设计器基础能力

## 业务目标

建立“字段主列表 -> 业务表单字段集合 -> 表单/列表/分步视图”的稳定配置链路。平台提供公共设计器和元数据能力，各业务模块继续独立维护菜单、前端路由、页面组件、后端服务和业务数据。

## 范围

### 本次实施

- 在现有 `biz_form_*` 能力上新增表单视图、列表视图、分步步骤和页面 Block 的持久化模型。
- 增加字段引用校验：视图只能引用当前业务范围已登记的字段；列表视图只能引用已纳入业务表单字段集合的字段。
- 提供视图配置查询、保存、发布和引用校验 API，保持现有输入项配置 API 兼容。
- 增加前端元数据类型和视图设计基础入口，表单设计器不再把任意临时字段作为正式配置来源。
- 记录租户、权限、审计、版本和回退边界，并补充可重复加载的 Mock 视图数据。

### 本次不实施

- 不创建具体业务模块的菜单、业务主表或业务 CRUD 服务。
- 不实现跨模块通用动态业务路由，不允许数据库配置任意 Vue 组件路径。
- 不把表单、列表、分步表单和页面 Block 合并为万能脚本引擎。
- 不修改既有已发布迁移，不删除或重命名现有 `biz_form_*` 字段。

## 现状与规则

- 当前 `biz_form_scope`、字段、规则、选项和值表已存在，表单设计器仍是浏览器内存原型。
- `biz_form_field_definition` 作为当前业务范围的字段集合；视图通过字段 ID 引用它。
- 设计器可以复用公共组件，但业务模块菜单、路由、业务页面和后端服务保持模块内独立。
- 服务端最终校验字段归属、视图类型、租户、权限和字段引用，前端限制不能作为安全边界。

## 接口与数据

- 新增 `/api/system/form-metadata/scopes/{scopeId}/views` 查询和保存视图配置；发布时生成包含字段引用、步骤和 Block 的版本快照。
- 新增 V35 Flyway 迁移，创建 `biz_form_view`、`biz_form_view_field`、`biz_form_view_step`、`biz_form_view_step_field`、`biz_form_page` 和 `biz_form_page_block`，并为字段定义增加业务字段可用标记。
- 所有写接口使用现有认证、RBAC、租户上下文、统一响应、审计和软删除约定。
- 既有 V32/V33/V34 数据保持可读，回退通过停止使用 V35 视图层并恢复应用版本完成。

## 验收标准

1. 视图只能引用当前 `scope` 的字段；跨 scope、停用或不存在的字段保存失败。
2. 列表视图引用的字段必须属于业务表单字段集合；服务端拒绝不满足约束的配置。
3. 表单、列表、分步和页面 Block 配置能查询、保存、发布并生成版本快照。
4. 既有输入项配置查询、保存、发布和 Mock 加载不回归。
5. 前端构建、后端 system 模块测试、治理检查和 Flyway 检查通过。
6. 设计器基础入口不产生任意组件路径，不向业务菜单动态注入未登记的前端路由。

## 测试与发布

- 必须执行：`mvn -pl :ccb-system -am test`、`mvn test`、`npm --prefix web run build`、治理检查、Flyway 检查和视图引用 API 验证。
- 浏览器验证输入项配置和表单设计器原型仍可访问，设计器空状态、字段选择、发布和移动端布局可观察。
- 发布前由 Owner 复核 V35 表结构、视图引用约束和公共前端类型；禁止直接连接生产环境。
- 回退保留 V35 表和历史数据，应用回退到只读取 V32/V33/V34 能力，不物理删除配置。
