# 投产管理独立菜单与测试数据

## 业务目标

投产管理保留父级目录，五项投产功能作为独立子菜单呈现，不再在页面内部使用 Tabs 或横向菜单切换。为投产管理提供可直接验收的本地测试数据，并按项目隔离。

## 本次实施

- 保留“投产管理”父级目录及现有五个子菜单：投产演练计划、投产时序、投产回退时序、投产问题分析及跟踪、投产组织。
- 五个子路由直接展示各自业务内容；移除投产管理页面壳中的内部 Tabs/横向导航。
- 保留顶部项目切换栏。切换项目后当前子菜单重新加载当前项目数据，不能残留上一个项目的列表、表单或详情状态。
- 追加 `V124__release_operations_demo_data.sql`，为至少两个虚构测试项目各写入五项投产功能数据。
- 测试数据覆盖演练方案、环境搭建说明、多轮演练、普通时序、回退时序、问题分析跟踪、多个投产组及项目成员。
- 测试迁移可重复执行，不删除 V123 及用户手工新增的业务记录；使用固定测试前缀和固定测试主键保证幂等。

## 不实施

- 不取消“投产管理”父级目录，不把五项功能提升为顶级菜单。
- 不修改投产管理表结构、后端业务 API、权限编码和既有 V123 迁移。
- 不改变既有配置管理中的投产窗口、版本申请、投产基线、生产版本和审批流程。
- 不写入生产数据，不使用真实个人信息；测试成员只引用仓库已有的演示用户。

## 验收标准

1. 左侧导航显示“投产管理”父级目录及五个独立子菜单；点击任一子菜单直接进入对应页面，页面内不存在重复的 Tabs/横向菜单。
2. `/release-operations` 会跳转到当前用户有权限的第一个子菜单；五个子路由的权限和现有菜单权限保持一致。
3. 至少两个测试项目各有完整投产管理数据：演练方案/环境/三轮演练，普通时序/四条明细，回退时序/三条明细，三条不同状态或优先级的问题，以及两个投产组和组内成员。
4. 切换两个测试项目时，五个子菜单的数据只对应当前项目；刷新页面后测试数据仍可读取。
5. V124 可重复执行且不会产生重复测试记录、删除 V123 或影响测试项目下用户手工新增的记录。
6. 前端构建、后端相关测试、Flyway 检查、治理/范围检查、差异检查和桌面/手机浏览器验收均记录真实结果。

## 数据和回退

追加 `V124__release_operations_demo_data.sql`，只为固定测试项目和固定测试主键补齐缺失数据。V124 不修改历史迁移，不清理非本任务固定 ID 的业务记录。应用回退时保留迁移和测试数据，必要时关闭投产管理菜单权限或回退前端入口。
