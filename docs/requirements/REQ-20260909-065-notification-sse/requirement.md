# 通知中心改用 SSE 实时刷新

## 业务目标

将通知中心每秒查询未读数改为服务端事件驱动，降低空闲请求和数据库查询开销，同时保持跨页签、抽屉列表和断线场景下的消息状态及时一致。

## 本次实施

- 页面初始化查询一次未读数，之后由 SSE 通知事件触发未读数刷新。
- 抽屉打开时，收到事件同步刷新通知列表和业务板块统计。
- 使用 30 秒有效、单次消费的一次性票据建立 SSE，不在 URL 中暴露 JWT。
- 页面隐藏时断开连接，恢复可见时重新申请票据并连接。
- SSE 失败按 1、2、5、15、30 秒重连；持续失败后启用 60 秒兜底轮询，连接恢复即停止轮询。
- 服务端每 25 秒发送心跳，连接约 10 分钟后由客户端重新申请票据续连。
- 发布、已读、全部已读、归档、恢复和批量归档仅在事务成功提交且数据实际变化后广播。
- 容器 Nginx 与宿主 Nginx 对 SSE 端点关闭缓冲并延长读取超时。

## 本次不实施

- 不引入 WebSocket、Redis Pub/Sub 或消息中间件。
- 不改变通知接收人、租户隔离、项目归属、已读和归档业务规则。
- 不修改数据库结构、测试数据或生产部署。
- 不把访问 JWT 放入查询参数。

## 验收标准

1. 页面空闲时不再每秒请求 `/api/notifications/unread-count`，正常 SSE 连接期间仅有初始查询和事件触发查询。
2. 无效、过期和重复使用的票据均无法建立流；合法票据只能建立当前租户、当前用户的连接。
3. 通知数据事务回滚时不广播；实际写入成功后同一用户所有在线页签收到失效事件。
4. 页面隐藏时连接关闭，恢复可见后自动连接；失败重连和 60 秒兜底轮询符合约定。
5. SSE 经本地 Vite 代理和两层 Nginx 配置时不缓冲，25 秒心跳可到达客户端。
6. system/security 聚焦测试、前端生产构建和治理检查通过。

## 权限、数据与审计

- 票据签发端点必须认证；流端点仅精确放行 GET，并以单次票据恢复租户和用户边界。
- 票据仅保存在当前进程内存，随机生成，不写数据库、不记录日志，30 秒后失效。
- SSE 数据只表示“通知状态可能变化”，不包含消息正文、用户信息或业务数据。
- 保持现有通知查询与写操作审计边界，不新增审计日志噪声。

## 测试与发布

- 后端：票据单次消费、过期拒绝、用户隔离、心跳/广播清理、事务提交与回滚。
- 前端：`npm --prefix web run build`，浏览器检查请求频率、可见性切换、抽屉刷新和控制台。
- 回归：`mvn -pl :ccb-system,:ccb-security,:ccb-boot -am test`、治理检查和 Nginx 配置检查。
- 回退：回退本需求提交即可恢复原通知逻辑；无数据库补偿。
