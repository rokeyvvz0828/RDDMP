# 修复工作流生命周期、编辑器、历史与电子签名

## 业务目标

流程管理员需要安全管理已发布流程、顺畅编辑流程图并追溯历史；审批人需要在配置要求时，以当前登录身份完成平台内部电子签名。修复后，流程归档不破坏运行中实例和历史数据，常见的串行节点插入不再要求人工删除连线，低分辨率下保存操作始终可达。

## 范围

### 本次实施

- 草稿流程保留删除能力；已发布流程改为归档，并支持管理员填写原因后恢复发布。
- 增加流程历史版本和定义更新记录查询、展示及历史流程图只读查看。
- 优化“从此处添加节点”，在零出边时追加，在单出边时自动插入节点并重建连线。
- 调整流程编辑弹窗和画布高度，使标题、内容和底部保存操作适配视口。
- 将用户任务节点现有电子签名开关改为明确的“需要电子签名：是/否”，复用已实现的同意、拒绝、退回服务端校验和签署留痕。
- 通过追加 Flyway 迁移修复工作流 JSON schema 与定义、版本元数据不一致的问题，并同步修正本地演示数据源。

### 本次不实施

- 不接入第三方 CA、证书、印章图片、短信验证或外部电子签名系统。
- 不重构现有 Flowable 引擎、业务模型编译器或完整工作流模块架构。
- 不修改尚未进入 `main` 的配置管理业务模块代码。
- 不支持从多出边网关节点自动猜测插入分支；该场景继续要求选择具体连线。

## 现状与规则

- 当前 `DELETE /api/workflows/definitions/{id}` 对所有流程执行软删除。已发布流程会停止新发起且运行实例仍保留，但定义详情和版本入口一并消失，语义不清。
- 已发布流程只能归档，归档后禁止新发起，不影响运行中实例、历史实例、历史版本和更新记录；管理员可填写原因恢复发布，恢复时不生成新版本。
- 草稿流程可删除。已归档流程不可编辑、发布、取消发布或删除。
- 用户任务和抄送节点保持单入边、单出边约束。右键从单一路径节点添加用户任务时，系统自动插入；多分支网关不自动选择分支。
- `V34__repair_workflow_model_schema_versions.sql` 只修复元数据，不操作节点和连线。该迁移已经执行，禁止修改；本次通过后续迁移修复存量不一致。
- 电子签名配置只属于用户任务节点，默认“否”。配置为“是”时，同意、拒绝、退回必须由当前登录人点击确认签署；加签、转办、委托和抄送不要求签名。`rokey` 已有签名服务、`wf_signature` 和业务审批确认，本次复用并补齐配置体验及回归验证。
- 电子签名是平台内部身份确认，不具备第三方 CA 数字证书效力。

## 接口与数据

- 生命周期接口：新增归档和恢复发布接口；删除接口仅接受草稿。
- 历史接口：新增版本列表、指定版本详情和定义更新事件列表。
- 审批接口：复用现有 `signatureConfirmed`，后端继续依据发布版本中的节点配置校验。
- 数据 Owner：`platform/workflow` 负责定义、版本、事件和签署凭据；`platform/infrastructure` 只负责追加迁移和本地演示数据同步。
- 数据库迁移：复用 V35 已有签署表，只追加 V42 schema 元数据修复迁移；不修改 V34、V35 或本地已执行的 V40/V41。
- 现有 `wf_signature` 保存签署人、账号快照、实例、任务、动作、时间和业务数据摘要，不保存口令、Token 或证书私钥。

## 验收标准

1. 已发布流程不能删除，只能填写原因归档；归档后不能新发起，但运行中实例可继续处理，历史数据仍可查询。
2. 管理员可以填写原因恢复已归档流程，恢复后继续使用归档前版本且可以新发起，不产生额外版本。
3. 草稿流程仍可删除，非草稿调用删除接口得到明确业务错误。
4. 在具有一条后续连线的节点上执行“从此处添加节点”，系统自动把原连线替换为两条连线，流程可校验、保存和发布。
5. 在受支持桌面和小视口中打开流程编辑器，底部“保存流程”始终可达，页面不产生整体横向滚动。
6. 流程详情可以查看全部版本、指定历史流程图以及创建、修改、发布、取消发布、归档和恢复记录。
7. 用户任务可以明确配置是否需要电子签名；发布后配置随版本冻结。
8. 需要签名的同意、拒绝、退回请求继续不能绕过后端校验；配置改造后确认签署和不可变签署凭据查询无回归。
9. 新增迁移执行后，JSON `schemaVersion=2` 的定义和版本元数据均为 2，本地演示数据同步后不再写回错误值。
10. 聚焦后端测试、全量后端测试、前端生产构建、治理检查、差异检查和浏览器验收达到交付门禁。

- 后端聚焦测试：使用 JDK 17 执行 `mvn -pl :ccb-workflow -am test`。
- 后端全量测试：使用 JDK 17 执行 `mvn test`。
- 前端构建：`npm --prefix web run build`。
- 浏览器：验证归档/恢复、历史页签、自动插入、弹窗操作可达和签署确认；检查桌面及 `375x812`、`390x844`、`430x932` 视口。
- 数据库：在隔离本地库执行新增 Flyway 迁移，并查询 schema 元数据不一致数量为零。
- 上线验证：抽查一个草稿、一个已发布定义和一个运行中实例，再验证归档、恢复及签署审计。
- 回退：回退应用代码；保留 V35 既有签署表、签署记录和 V42 修复后的 schema 元数据。不得回滚或修改已经执行的 Flyway 脚本。
- 风险与人工复核人：平台公共工作流和数据库迁移属于高风险变更，由平台 Owner `rokeyvvz0828` 专项复核。
