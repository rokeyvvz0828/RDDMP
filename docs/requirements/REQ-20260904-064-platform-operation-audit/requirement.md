# 平台全局操作审计日志

## 业务目标

平台管理员需要统一追踪关键业务操作；项目负责人和项目管理员需要查看自己负责项目的操作记录。日志应能回答谁在何时、从哪个 IP、对哪个模块和业务对象执行了什么操作、结果如何，同时不得保存业务正文或敏感值。

## 范围

### 本次实施

- 自动记录已认证请求中的新增、修改、删除、审批、导入和导出操作。
- 显式记录用户/角色/权限/组织成员、系统参数、工作流审批详情、附件预览下载、迁移结果失败详情以及审计日志本身的敏感查询。
- 登录成功和失败继续使用 `sys_login_log`，在统一审计页面提供独立页签。
- 操作日志记录模块、操作类型、业务对象、结果、耗时、IP、User-Agent、Trace ID、项目快照和修改字段名。
- 页面和 API 最多查询最近 30 天；操作日志与登录日志保留 180 天，定时清理并记录单条汇总结果。
- `SUPER_ADMIN` 查看全租户操作及登录日志；项目负责人或项目 `PM` 角色成员只查看其管理项目的操作日志；普通用户无菜单和查询权限。

### 本次不实施

- 不记录普通列表、看板统计、健康检查、轮询和选项查询。
- 不保存请求体、响应体、密码、Token、文件内容、签名 URL、审批意见正文或字段修改前后值。
- 不根据前端自报项目请求头建立项目归属；无法从可信路径、查询参数或服务端上下文确认时项目字段为空。
- 不替换工作流、测试、附件等领域已有的专用审计表。
- 不建设外部日志平台、消息队列或合规归档系统。

## 现状与规则

- 当前 `sys_login_log` 已记录登录结果、IP 和 User-Agent；`sys_operation_log` 仅有操作者、操作码、方法、路径、结果和 Trace ID 等基础字段。
- 现有通用操作日志写入分散在 system、workflow、project 和 `SystemOperationAudit`，全局拦截必须通过请求上下文合并语义，避免同一 HTTP 请求重复落库。
- 自动采集默认覆盖 `POST/PUT/PATCH/DELETE`，预览、校验、轮询和内部回调按集中策略排除；`GET` 仅命中敏感查询策略时记录。
- 项目管理权限按 `pm_project.owner_id` 或有效项目角色 `PM` 判断，不能仅依赖前端菜单显隐。
- 审计落库失败不得改变原业务请求结果，但必须输出带 Trace ID 的受控错误日志。

## 接口与数据

- `GET /api/system/audit/operations`：分页查询近 30 天操作日志，支持日期、模块、类型、结果、项目和关键字筛选。
- `GET /api/system/audit/logins`：仅超级管理员分页查询近 30 天登录日志。
- `GET /api/system/audit/projects`：返回当前用户可查询的审计项目范围。
- 数据 Owner：`platform/system`；全局 HTTP 适配器位于组合根 `platform/boot`。
- 追加 `V156__platform_operation_audit.sql` 扩展日志字段、索引、菜单和权限，不修改历史迁移。
- 存量操作日志新增字段允许为空，查询时兼容旧记录。

## 验收标准

1. 成功和失败的关键写请求各产生一条操作日志，包含操作者、模块、类型、结果、耗时、IP、User-Agent 和 Trace ID。
2. 修改操作只保存字段名集合；日志中不出现密码、Token、审批意见、请求正文、文件内容或签名 URL。
3. 已有手工审计与全局拦截合并为单条记录，非 HTTP 场景仍可使用原 `SystemOperationAudit` 落库。
4. 普通 GET、健康检查、轮询、选项和预览校验不记录；确认的敏感 GET、附件预览下载和导出会记录。
5. 超级管理员可查看全部操作和登录日志；项目负责人或 `PM` 仅看到其管理项目操作日志；普通用户菜单不可见且接口返回 403。
6. 查询日期默认最近 30 天，传入更早日期仍被限制为最近 30 天；180 天以前的数据由每日任务删除并产生一条汇总审计。
7. 审计页面桌面与 `375x812`、`390x844`、`430x932` 可完成筛选、分页和详情查看，无页面级横向溢出。
8. Flyway、后端聚焦测试、全量 Maven 测试、前端构建、治理与任务范围检查通过。
