# 项目投产日历

## 业务目标

项目成员在项目详情内维护独立的投产日历，以月历方式集中查看本项目的投产安排，不依赖配置管理投产窗口数据。

## 范围

### 本次实施

- 项目详情增加“投产日历”页签，并将现有项目详情页签样式调整为借鉴配置管理投产窗口的导航样式。
- 项目成员查看、新增、编辑和删除本项目的多条日历安排；每条安排包含标题、投产日期范围和备注，同一日期最多归属一条有效安排。
- 新增项目级日历表、服务端 CRUD 接口、成员实体授权、乐观锁与操作审计。
- 桌面端提供月历；移动端提供按日期分组的条目列表，并完整覆盖加载、空、失败、无权限和提交中状态。

### 本次不实施

- 不复用、同步或修改配置管理的投产窗口、版本申请、投产基线和生产版本数据。
- 不支持时分秒、重复规则、状态流转、提醒、附件、审批、跨项目汇总或外部日历同步。
- 不修改项目计划、项目角色、工作流或已有页签的业务规则。

## 现状与规则

- 当前入口为项目详情 `ProjectView.vue`，页签状态由 `?tab=` 维护。
- 日历数据归项目模块所有，按 `tenant_id` 与 `project_id` 隔离。
- 项目成员均可维护，服务端必须验证登录身份、项目成员关系、租户范围、实体归属与乐观锁；前端显隐不能替代校验。
- 创建、更新、删除均保留操作审计；删除采用逻辑删除。

## 接口与数据

- 新增项目日历列表、创建、更新、删除接口，列表按当前项目和指定月份返回。
- `pm_project_release_calendar` 允许同一项目存在多条有效记录；记录包含 `release_start_date` 和 `release_end_date`，开始日期等于结束日期表示单日安排，范围内每一天都属于该条安排。
- 服务端拒绝与已有有效记录日期范围重叠的创建或编辑请求，因此同一项目同一日期最多一条安排；不重叠的日期可以继续维护。
- 追加迁移 `V218__project_release_calendar_date_range.sql`，将既有 `release_date` 数据回填为相同的开始/结束日期；不修改已发布迁移，回退应用代码时保留表与历史数据作为只读证据。
- 不传递生产数据、密钥、Token 或外部系统凭据。

## 验收标准

1. 项目详情可通过 `tab=release-calendar` 打开投产日历，其他页签功能和路由行为保持不变。
2. 项目成员可创建、编辑、删除多条含标题、投产日期范围和备注的安排；刷新后数据持久化回显，单日和跨月范围均可保存，日期不重叠的安排可以并存。
3. 非项目成员与跨租户请求在服务端被拒绝，且不能读取或修改条目。
4. 同时编辑同一条目时，旧版本提交被拒绝且前端提示刷新。
5. 桌面月历和 375x812、390x844、430x932 视口均无页面级横向溢出；移动端使用按日期分组列表。
6. 新页签样式与配置管理投产窗口导航一致，同时保留项目模块现有主题变量与可访问性。
7. 月历查询返回与当前月份相交的范围记录，范围内每一天显示该安排；跨月范围在相邻月份均可查看。
8. 项目概览按日期显示投产安排；日期框直接显示投产标题，不使用悬浮框展示详情；服务端拒绝同一项目日期范围重叠的新增或编辑请求，保证每日最多一条安排。

## 测试与发布

- 必须执行：项目服务聚焦测试、迁移集成测试、前端构建、治理与范围检查、桌面及规定移动视口浏览器验收。
- 上线验证：以项目成员身份完成新增、编辑、删除和刷新；以非成员身份验证拒绝访问。
- 回退：回退本需求的应用代码和前端页签；不回滚已发布 Flyway 迁移，不删除已写入日历数据。
- 风险与人工复核人：平台系统 Owner 复核成员授权、审计与迁移；项目 Owner 复核交互和数据范围。
