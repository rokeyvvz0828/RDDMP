# 投产演练复用架构环境管理

## 业务目标

移除投产管理中重复维护的“投产演练环境”，让项目成员仅在架构管理的环境管理中维护环境，并在投产演练轮次中选择该项目的有效架构环境。

## 范围

### 本次实施

- 移除投产演练环境菜单、前端路由、页面、前端 API、后端 CRUD、权限和私有持久化模型。
- 演练轮次改为选择项目级 `arch_environment`，服务端通过架构模块公开只读契约验证环境属于当前项目且为 ACTIVE。
- 扩展架构模块已存在的 `ReleaseMasterDataQuery` 与投产模块适配端口；投产模块不得直接访问 `arch_` 表。
- 追加 Flyway 迁移，清空旧私有环境、演练轮次、演练步骤与关联问题，删除私有环境表，并逻辑下线旧菜单和权限。
- 架构环境删除时增加投产演练引用检查；被演练引用时拒绝删除。

### 本次不实施

- 不迁移或保留旧投产演练环境、旧演练轮次、步骤或关联问题。
- 不修改架构环境的创建、编辑、停用、资源申请和资源实例业务规则。
- 不新增独立的环境同步、复制或外部资源部署能力。

## 现状与规则

- 投产管理当前将 `rel_release_drill_round.environment_id` 指向私有 `rel_drill_environment`，并提供 `/release-operations/environments` CRUD。
- 架构管理的 `arch_environment` 已按项目、租户、状态维护环境主数据；投产演练只能选择当前项目的 ACTIVE 环境。
- 用户确认旧数据无需兼容：删除私有环境时，同时清空所有依赖该旧引用的演练轮次、步骤和关联问题。
- 演练读写保留投产模块的项目成员授权、RBAC、乐观锁与审计；架构模块保持其自身环境权限与数据范围。

## 接口与数据

- 架构公开契约新增项目有效环境查询与按 ID 校验投影；投产模块通过自身 `ReleaseArchitectureDirectory` 消费。
- 演练轮次 HTTP 请求继续使用 `environmentId`，其语义改为 `arch_environment.id`；响应回显环境名称、编码与类型。
- 新增 `V217__release_drill_use_architecture_environment.sql`；清理旧数据后删除 `rel_drill_environment`，保留 `rel_release_drill_round.environment_id` 列用于架构环境 ID。
- 迁移逻辑下线菜单 1006、其权限及角色授权；不修改已发布的历史迁移。

## 验收标准

1. 投产管理菜单与路由中不再出现“投产演练环境”，旧路由不可进入维护页面。
2. 新建或编辑投产演练轮次仅列出当前项目 ACTIVE 架构环境，保存的 `environmentId` 必须通过服务端项目、租户与状态校验。
3. 跨项目、不存在或停用架构环境均被拒绝；无可选环境时前端显示明确提示并禁用新建轮次。
4. 迁移后旧私有环境、旧演练轮次、步骤和关联问题均被清空，且私有环境表已删除。
5. 架构环境被投产演练引用后删除被拒绝；投产演练读取仍显示环境名称、编码和类型。
6. 菜单、权限、迁移、投产与架构聚焦测试、前端类型检查/构建和桌面/移动浏览器路径通过。

## 测试与发布

- 必须执行：Flyway 迁移集成、投产演练服务/API 权限测试、架构环境引用删除测试、前端构建、治理与范围检查、桌面与规定移动视口浏览器验收。
- 上线验证：以项目成员身份在架构环境管理创建有效环境，在投产演练创建轮次；验证停用、跨项目和删除引用均被服务端拒绝。
- 回退：回退应用代码后不恢复已删除的历史投产演练数据；数据清理是用户确认的不可逆动作。若需恢复，仅从迁移前数据库备份恢复。
- 风险与人工复核人：发布与架构模块 Owner 复核跨模块公开契约、迁移清理范围、菜单权限和引用检查。
