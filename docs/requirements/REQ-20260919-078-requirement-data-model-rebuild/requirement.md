# 需求管理数据模型重构（需求-物理子系统统一建模）

> 跨模块说明：本需求只改 `business/requirement`、`platform/infrastructure` 迁移与需求管理前端页面，**不改 `business/development`**。与 REQ-20260919-077（权限重建）同批实施，因为数据范围、收回、流转与开发来源契约都建立在本模型之上。

## 业务目标

新建项目与存量项目当前是两张结构完全不同、且各自绑定需求自建系统清单的表；开发管理读取需求数据时只认存量表。业务上两者的真实差异是"一条需求关联几个物理子系统"：新建项目按物理子系统维度提出（1 条需求 = 1 个物理子系统 = 1 个开发任务），存量项目一条需求关联多个物理子系统（每个子系统 1 个开发任务）。

本需求把两者统一为一条主表 + 需求-物理子系统关联行，为开发管理提供稳定的只读来源。

可观察的成功结果：

- 新建项目差异只能选 1 个物理子系统（取自架构管理），存量需求可挂多个（主责 1 + 协同若干）。
- 系统主数据不再由需求管理自建，统一取架构管理物理子系统。
- 需求管理侧已按开发管理所需的口径准备好数据：新建差异在"全部评审完 + 形成基线"后成为可开发来源，存量在"到软需阶段且立项已完成"后成为可开发来源。
- 开发管理现有读取契约形状不变，仍可编译运行（新建项目来源待开发管理侧放开后启用）。

## 范围

### 本次实施

- 新主表 `req_requirement`（`requirement_kind = NEW_PROJECT_DIFF | LEGACY`）承载两页共用字段。
- 新关联表 `req_requirement_system`（需求 ↔ 架构物理子系统，`system_role = LEAD/CHANGE/TEST`，含系统负责人，不含系统人员）。
- 拆出 `req_difference_detail` / `req_legacy_detail` 承载各自专有字段；统一 `req_flow_log`；合并 `req_legacy_deliverable`。
- 约束：新建差异恰好 1 行系统；存量 1..N 行且 `LEAD` 唯一；存量创建不校验系统，离开"需求对接"阶段前必须齐备。
- 系统主数据改造：通过 `com.ccb.requirement.integration` 新增只读接口 + `platform/boot` 适配器，委托架构 `PhysicalSystemDirectoryQuery`。
- `RequirementDevelopmentQuery` **实现**改造：数据来源切换为新表，契约 record 形状保持不变；本次仍只返回存量来源，避免触发开发侧 `source_type='LEGACY'` 约束。
- 前端：新建差异"涉及物理子系统"必填单选；存量系统行去掉"系统人员"，只保留系统负责人；页签重组（系统与协同事项→需求对接、工作量表→工作量评估、软需文档→软需）。
- 需求数据 `project_id` 统一为 `pm_project.id`。
- 差异序号服务端自动生成。
- 不作数据迁移与兼容：清空需求业务数据并按新结构重建演示数据。

### 本次不实施

- 开发管理任何代码与表结构（含 `dev_task` 来源类型约束放开）。
- 需求管理权限数据重建（属 REQ-20260919-077，同批实施但独立范围）。
- 交付件与文档上传能力。

## 业务规则

1. 涉及系统一律取架构管理物理子系统；需求侧保存 `physical_subsystem_id` 与编码/名称快照。
2. 新建项目差异按物理子系统维度提出，系统行恰好 1 行，创建时必填。
3. 存量需求系统行 1..N，其中主责恰好 1 行；创建时不强制，离开需求对接阶段时必须齐备。
4. 开发来源生效条件：新建差异需"项目内无待评审/评审中差异，且该差异已纳入基线"；存量需求需"已到软需阶段且立项阶段已完成"。
5. 系统人员不再保留，系统行只维护系统负责人。

## 接口与数据

- 新增只读接口（requirement → boot 适配）：按项目与关键字查询架构物理子系统。
- `RequirementDevelopmentQuery.search/find`：契约不变，实现改读新表；`SourceSystem.systemCode` 语义为架构物理子系统编码。
- 新增迁移：建主表/关联表/详情表/统一流转日志/交付件表，清空并重建演示数据。

## 验收标准

1. 新建差异必须且只能选 1 个物理子系统；存量需求可挂多个并区分主责/改造/测试，主责唯一。
2. 存量创建无需填系统；推进"需求对接"时若缺主责或协同，拒绝并提示。
3. 系统下拉数据来自架构物理子系统，需求管理不再维护系统清单。
4. 开发管理仍能编译运行，读取存量需求的契约输出与改造前语义一致。
5. 需求数据 `project_id` 为 `pm_project.id`，切换项目即切数据。
6. 差异序号由系统生成且项目内唯一。

## 回退

回退本次代码与迁移；测试库重新执行模型重建迁移并重建演示数据。
