# 项目计划分组

## 目标

项目负责人可以在项目计划页创建项目级分组，并将主计划拖入分组；主计划下的全部子计划随主计划一起归属分组。

## 范围

- 项目计划增加分组归属，已有计划默认显示在“未分组”。
- 计划页支持新建、重命名和删除分组。
- 主计划可拖动到分组行，后端事务性更新主计划及全部后代计划。
- 页面显示中文提示“可以拖动主计划进行分组”。
- 分组删除时只允许将其中计划移入“未分组”，不删除计划。
- 移动端保留“移动到分组”操作，避免依赖触摸拖拽。

## 非目标

- 不支持分组嵌套。
- 不改变主计划/子计划的 `parent_id` 层级和编号规则。
- 不新增独立权限码，复用项目计划查看、新增、修改、删除权限和项目实体授权。

## 验收条件

1. 新建分组后，分组出现在项目计划树的一级，刷新页面后仍存在。
2. 主计划拖入分组后，主计划和全部子计划显示在该分组下，数据库中的 `group_id` 一致；子计划不会被拆散。
3. 主计划可从一个分组移动到另一个分组或未分组。
4. 子计划不能作为分组拖拽源，也不能单独改变分组归属。
5. 删除分组后，计划仍存在并显示在未分组区域。
6. 无项目修改权限时，分组写操作和移动接口返回无权限，前端不展示写操作。
7. 计划页在桌面端支持拖拽，在移动端提供可用的分组选择操作且无横向布局溢出。
8. 后端测试、前端构建和 `git diff --check` 通过。

## 验收反例

- 只修改前端状态，刷新后计划回到原分组。
- 拖动主计划后子计划仍留在旧分组。
- 删除分组连带删除计划。
- 通过构造请求将其他项目的计划移动到当前项目。
