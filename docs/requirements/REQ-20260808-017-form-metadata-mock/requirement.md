# REQ-20260808-017 输入项配置契约收敛与 Mock 数据

status: ready

## 业务目标

检查输入项配置相关契约的一致性，明确各文件职责和当前实现边界，并为首个业务范围提供可重复加载的 Mock 配置，确保研发人员启动本地环境即可查看真实配置结构。

## 本次实施

- 收敛业务表单元数据契约与 Mock 数据契约的重复表述，明确工作区编辑、发布快照和历史版本语义。
- 扩展本地 Mock 同步器的 `biz_form_*` 白名单和测试覆盖。
- 在 `mock/mock-data.json` 中加入虚构的“交付工单”范围、分区、字段、规则、选项、扩展值和发布快照。
- 更新本任务的需求范围和 `.ai-control` 验收证据。

## 本次不实施

- 不修改业务表单 API、前端页面和已有表结构。
- 不新增独立的草稿 revision 编辑 API。
- 不把 Mock 数据用于生产初始化或生产数据迁移。

## 业务规则

1. Agent 负责随业务功能交付初始化元数据，系统设置仅作为审阅、纠偏、发布和应急维护入口。
2. Mock 只使用虚构内容和高位保留 ID，必须保留租户字段并可幂等 upsert。
3. 已发布配置快照指向完整的 scope/section/field/rule/option 配置；扩展值保存字段定义引用和必要的展示名称快照。

## 验收标准

1. Mock 数据 JSON 可解析，包含交付工单完整元数据链路和至少一条实体扩展值。
2. `MockDataInitializer` 接受全部 `biz_form_*` 表，非法表或列仍被拒绝。
3. JDK 17 下基础设施测试、前端构建、治理检查和 Flyway 检查通过。
4. 记录当前实现的运行时风险和本地启动验证方式。

## 回退

将 `MOCK_DATA_ENABLED` 设为 `false` 可停止本地同步；回退代码时保留已发布 Flyway 表，不手工删除数据库对象。
