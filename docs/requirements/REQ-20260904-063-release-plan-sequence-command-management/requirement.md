# 投产方案时序与指令分层维护

## 业务目标

投产方案时序图中的 `P1`、`P2` 等对象是独立的时序节点；每个时序节点下可以维护多条指令。参考图片只用于表达视觉层级，不增加图片中的其他业务字段。

## 必须实施

- 正向和回退时序均按独立时序节点展示，节点编号为 `P1`、`P2` 等并按序排列。
- 时序节点支持新增、编辑、删除；时序名称和说明可维护。
- 每个时序节点下支持新增、编辑、删除多条指令；指令保留时间范围、负责人、状态、说明和乐观锁行为。
- 移除时序图底部横向时间线及其时间节点/标签；指令时间只作为时序和指令内容展示。
- 现有投产方案数据迁移为一个时序节点对应一条历史指令，存量方案仍可查看和维护。
- 保留项目切换、权限校验、空/失败/只读/提交中状态。

## 不实施

- 不恢复已移除的独立投产时序菜单。
- 不改变投产演练、环境、问题跟踪和投产组织业务。
- 不依赖 `biz_form_*` 元数据能力。

## 数据与权限

- 在投产模块追加方案时序表，方案指令追加时序归属字段并取消原先“每个方案和类型只能有一个指令序号”的约束。
- 追加迁移将每条历史方案指令转换为对应时序节点，历史指令序号归一为该时序下的第 1 条指令。
- 新增时序和指令接口沿用投产方案项目成员校验、RBAC、实体范围和 rowVersion 校验；时序删除同时软删除其指令。

## 验收标准

1. 正向和回退抽屉显示多个 P 节点，每个节点有独立名称、编辑/删除和新增指令操作。
2. 一个 P 节点可同时显示多条指令，指令可新增、编辑、删除且数据刷新后保留。
3. 页面不再渲染底部时间线；不同视口下阶段列不会造成页面级横向溢出。
4. 历史数据能通过追加迁移正常读取，后端服务测试、前端构建、差异检查和浏览器验收通过。

## 回退

回退本任务前端、投产模块契约/服务/存储变更和追加迁移；不修改上一轮已发布迁移。
