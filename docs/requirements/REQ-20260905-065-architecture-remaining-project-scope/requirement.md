# 架构管理剩余业务按项目隔离

## 业务目标

在 `REQ-20260905-064` 已完成物理子系统、部署单元、环境管理、资源申请、环境部署实例和搭建计划项目化的基础上，将架构管理中仍按租户共享的网络专项工单、网络分区及网段、网络访问全链路和架构决策全部接入顶部当前项目。

不同项目之间的数据、编号、关联、流程实例、通知、附件和操作权限必须相互隔离。架构规范、搭建计划模板、环境类型及平台字典继续保持租户级共享。

## 范围

### 本次实施

- 网络专项工单及其历史、流程轮次和流程回执绑定项目。
- 网络分区、网段、外部网络地址绑定项目。
- 网络访问申请、申请历史、流程轮次、流程回执、访问关系和豁免规则绑定项目。
- 架构决策事项及其材料、评审、参与人、行动项、结论、发布意图、替代关系、编号序列、流程轮次和回执绑定项目。
- 所有目标业务接口显式要求 `projectRef`，并通过 `ProjectAccessService` 解析可信项目主键。
- 所有查询、写入、唯一性、关联、工作流回调、通知跳转和附件访问限定认证租户与可信项目。
- 历史数据全部归入项目编码 `RDDMP-PLATFORM`；不复制到其他项目。
- 编号、编码、名称和地址唯一性调整为项目内永久唯一，不同项目允许重复。
- 网络分区与部署单元、资源申请、环境部署实例之间的引用增加同项目约束。
- 将新增业务表纳入 `ArchitectureProjectDeletionGuard`，存在数据时阻止项目删除。
- 更新虚构 Mock 数据，以至少两个项目和重复业务编号验证隔离。

### 租户共享能力

- 架构规范及其版本、条款等现有共享数据。
- 搭建计划模板及模板版本。
- 环境类型及平台字典。
- 工作流定义模板；业务流程实例必须绑定项目。

### 本次不实施

- 不提供跨项目共享、复制、转移或合并网络、决策数据。
- 不把租户共享能力改为项目私有。
- 不新增项目级架构角色，继续使用项目成员资格与现有架构 RBAC 组合授权。
- 不重复实现工作流项目权限，不修改 Flowable `ACT_*` 表。
- 不重命名现有 Java 包、数据库表或 API 根路径。
- 不修改已发布 Flyway 迁移。
- 不访问生产系统或使用真实敏感数据。

## 核心规则

- 所有目标接口强制接收 `projectRef`；创建和编辑 DTO 不接收 `tenantId` 或 `projectId`。
- 服务端依次校验认证、RBAC、租户、项目访问权和实体项目归属。
- 网络分区、实例、访问关系、工单、决策和结论禁止跨项目引用。
- 实体不存在或不属于当前项目时，列表不返回，详情返回 `404`。
- 跨项目关联返回 `400`；项目访问权不足返回 `403`；项目仍有架构数据时删除返回 `409`。
- 项目切换不改变已有业务记录或流程实例的项目归属。
- 工作流定义保持租户共享，业务实例使用 `WorkflowBusinessContext.projectRef/projectName` 固化项目。

## 编号与唯一性

以下字段改为项目内永久唯一，不同项目允许重复：

- 架构决策编号。
- 网络专项工单编号。
- 网络访问申请编号。
- 网络访问关系编号。
- 网络分区编码和名称。
- 外部网络地址。

架构决策编号序列按 `(tenant_id, project_id, seq_year)` 独立计数。软删除数据仍占用同一项目内的业务编号或名称。

## 数据与迁移

- 追加 `V158` MySQL 8.4 Flyway 迁移，不修改 `V156`、`V157` 或更早脚本。
- 目标主表及可独立查询、审计、回调的子表增加 `project_id`。
- 迁移采用增加可空列、按租户唯一活动 `RDDMP-PLATFORM` 回填、完整性校验、改为非空、重建索引和约束的顺序。
- 存在待迁移数据但找不到唯一活动默认项目时迁移失败。
- 父子关系及跨业务引用使用 `tenant_id + project_id + id` 约束，迁移前发现跨项目或无法确定归属的数据时失败关闭。
- 工作流轮次、回执及幂等约束包含项目维度。

## 工作流、通知与附件

- 网络专项工单、网络访问申请和架构决策流程实例全部绑定业务项目。
- 流程启动后校验返回实例项目；生命周期消费者再次校验租户、项目、业务实体、轮次和实例一致性。
- 历史进行中流程随业务数据归入 `RDDMP-PLATFORM`；无法匹配业务实体的流程形成迁移阻塞报告，不静默伪造归属。
- `LocalSeededWorkflowPublisher` 继续发布租户级共享流程定义；必要时仅调整种子业务上下文和示例数据，使新业务实例携带项目。
- 通知事件和跳转链接携带 `projectRef`，但服务端仍需重新校验访问权。
- 附件上传、预览、下载和删除校验附件、业务实体与当前项目一致，不允许跨项目复用附件 ID。
- 业务事件、工作流事件和通知事件包含租户、项目、业务类型和业务 ID，项目纳入幂等键。

## 前端交互

- 页面自动使用顶部当前项目，不增加第二个项目选择器。
- 目标 API 使用现有项目化请求封装；无当前项目时不发送业务请求。
- 切换项目时取消或忽略旧请求，清空列表、详情、分页、选中项和缓存，并关闭业务弹层后重新加载。
- 新增、编辑、提交、审批和发布期间发生项目切换时终止操作，要求在新项目重新执行。
- 工作流和通知跳转携带 `projectRef`；旧链接缺失项目时引导选择项目，不自动查询全部项目。
- 网络分区、网段、部署单元和环境实例等关联选择器只加载当前项目数据。
- 页面复用交付示范中心、公共 UI 和语义主题，按 `design-h5.md` 完成桌面及移动端验收。

## 验收标准

1. 四类业务及关键子数据均具有非空项目归属，查询和写入限定 `tenant_id + project_id`。
2. 两个项目可创建相同决策编号、工单编号、申请编号、关系编号、分区编码、分区名称和外部地址；同一项目重复及软删除后复用被拒绝。
3. 任意列表、详情、创建、更新、删除、提交、审批、发布和直接 ID 访问均不能越过当前项目。
4. 网络分区与部署单元、资源申请、环境部署实例之间不存在跨项目引用。
5. 网络访问申请、关系、豁免规则和相关分区、实例只能属于同一项目。
6. 架构决策材料、评审、参与人、行动项、结论、发布意图和替代关系不能跨项目。
7. 三类业务工作流上下文、流程实例、轮次、回执和生命周期回调与业务项目一致。
8. 通知和附件不会泄露其他项目业务摘要、详情或文件。
9. 历史数据只迁入 `RDDMP-PLATFORM`；默认项目缺失或不唯一时迁移明确失败。
10. 项目存在任一新增项目化业务数据时，`ArchitectureProjectDeletionGuard` 阻止删除。
11. 架构规范、搭建计划模板、环境类型和平台字典保持租户共享。
12. 顶部切换项目后页面无旧项目列表、详情、表单、选择项或延迟响应残留。
13. `1280x800`、`375x812`、`390x844`、`430x932` 及明暗主题下无页面级横向溢出。
14. 聚焦测试、真实 MySQL/Flyway、工作流集成、前端构建、治理、范围检查和浏览器 UAT 均有真实证据。

## 测试与发布

- 后端覆盖双项目正负矩阵、无项目参数、无访问权、跨项目 ID、同项目唯一性、删除保护和生命周期项目不一致。
- 数据库覆盖空库、既有库、默认项目缺失、跨项目脏数据、非空列、唯一索引和组合外键。
- 前端覆盖项目切换、请求失效、缓存清理、关联选择器、工作流和通知跳转及四视口明暗主题。
- UAT 使用两个项目创建重复编号，验证列表、详情、流程、通知、附件和关联选择器互不可见。
- `projectRef` 强制化属于接口契约变更，数据库、后端和前端作为同一发布批次上线。
- 上线前完成数据库备份和迁移预检查；迁移失败时停止发布，不通过删除约束绕过。
- 已执行 Flyway 不反向修改；应用失败时回退整批应用，并按发布方案恢复备份或追加补偿迁移。
