# 投产演练管理模型重构

## 业务目标

将投产演练从单方案、项目级正向/回退时序模型调整为可复用的多方案、多环境、多轮演练模型，使每轮演练都能追溯其方案、环境、执行步骤和问题。

## 必须实施

- 移除“投产时序”和“投产回退时序”菜单及前端路由入口；保留旧接口作为兼容入口，不再暴露菜单。
- “投产演练计划”支持当前项目维护多个投产方案，每个方案包含正向和回退两类有序步骤，覆盖原时序和回退时序能力。
- 新增“投产演练环境”菜单，当前项目可维护多个环境；每个环境维护环境名称、沿用数据线专项环境、基础架构部署、硬件、网络开通、中间件、组件和数据库检查。
- 新增“投产演练”菜单，当前项目可维护多轮演练；每轮必须关联一个投产方案和一个投产环境，并可维护有序演练步骤、负责人、计划时间、状态、结果和说明。
- “投产问题分析及跟踪”中的问题可选定并展示关联的演练轮次，轮次只能来自当前项目。
- 顶部项目切换后，所有投产页面只读取当前项目的数据；旧数据通过追加迁移回填到默认方案/环境，不能丢失。

## 不实施

- 不删除历史表和历史接口，不修改已发布 Flyway 脚本。
- 不改变投产窗口、版本申请、投产组织、附件和其他业务模块的职责。
- 不新增动态表单元数据依赖，不写入生产数据或真实个人信息。

## 业务规则

- 方案名称在同一租户和项目内唯一；环境名称在同一租户和项目内唯一。
- 方案步骤类型只能是 `NORMAL` 或 `ROLLBACK`，同一方案和类型内按序号唯一。
- 演练轮次编号在同一项目内递增；方案和环境必须属于同一项目且未删除。
- 演练步骤属于一个轮次，按序号展示并支持乐观锁更新。
- 删除方案或环境前若被演练轮次引用，服务端拒绝删除并返回可理解的冲突提示；删除轮次时其步骤级联逻辑删除。
- 问题关联轮次必须属于当前项目；取消关联允许保存为空。

## 权限、数据和审计

沿用 `release-operations:access` 父权限；新增页面权限为 `plan`、`environment`、`drill`、`issue`、`organization` 的 view/manage。所有接口校验认证主体、租户、当前项目有效成员和实体归属；新增/修改/删除保留 `created_by`、`updated_by`、`row_version` 和逻辑删除字段。

## 验收标准

1. 左侧投产管理仅显示投产演练计划、投产演练环境、投产演练、投产问题分析及跟踪、投产组织五项菜单，不显示两条旧时序菜单。
2. 一个项目可创建至少两个方案，每个方案可维护正向与回退步骤，刷新后顺序和数据保持。
3. 一个项目可创建至少两个环境并维护全部环境检查字段；环境列表按当前项目隔离。
4. 演练轮次创建时方案或环境缺失、跨项目或已删除时服务端拒绝；合法轮次可新增、编辑、删除多个步骤。
5. 问题新增/编辑可关联当前项目演练轮次，列表展示轮次；切换项目后不得显示其他项目轮次。
6. 旧项目的旧方案、时序、时序明细、轮次和问题数据在迁移后可继续读取；迁移只追加且可重复执行不产生重复演示数据。
7. 后端相关测试、前端构建、Flyway、治理、范围和差异检查通过；桌面及 `375x812`、`390x844`、`430x932` 视口无页面级横向溢出和新增控制台错误。

## 回退

按本任务文件边界回退应用代码并保留已执行迁移；如需关闭功能，隐藏新菜单权限即可。不得删除已执行迁移或业务数据。
