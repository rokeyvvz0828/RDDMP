# 通知消息展示所属项目

## 业务目标

全局消息通知中心中的每条消息应明确展示其所属项目，帮助用户在不切换当前项目的情况下判断消息来源；不属于具体项目的平台消息应明确展示为平台全局范围。

## 本次实施

- 通知发布和查询契约增加可空的项目标识与项目名称快照。
- 项目标识和项目名称必须同时存在或同时为空；为空表示平台全局消息。
- 工作流待办通知和审批结果通知携带工作流实例已有的项目上下文。
- 新增 Flyway 迁移，为通知表增加项目快照字段，并按稳定工作流事件标识回填现有工作流通知。
- 通知抽屉在业务板块/来源与标题之间展示项目归属；项目消息显示 `所属项目：项目名称`，平台消息显示 `所属范围：平台全局`。
- 桌面和移动端使用同一信息层级，长项目名称可换行且不产生页面级横向滚动。

## 不实施

- 不按当前项目过滤消息、业务板块、未读数或归档数据。
- 不改变通知接收人、租户隔离、角色权限、已读和归档规则。
- 不从通知标题、路由或业务主键推断项目。
- 不为没有可靠项目关系的既有业务通知补造项目归属。
- 不修改项目切换、配置管理或工作流审批状态逻辑。

## 业务规则

1. `projectRef` 与 `projectName` 必须成对提供；仅提供其中一个时拒绝发布。
2. 项目字段是消息产生时的展示快照，后续项目改名不反向修改历史消息。
3. 同一幂等事件重复发布时保持首次固化的正文、接收人和项目快照。
4. 工作流待办从 `wf_instance` 读取项目上下文；审批结果从生命周期事件上下文读取。
5. 历史回填仅使用工作流稳定事件 ID 关联已有上下文，无法可靠关联的消息保持平台全局。

## 验收标准

1. 发布并查询项目消息时，接口返回成对的 `projectRef/projectName`，通知抽屉显示 `所属项目：<项目名称>`。
2. 平台消息返回两个空项目字段，通知抽屉显示 `所属范围：平台全局`。
3. 仅提供一个项目字段、项目标识超过 64 字符或项目名称超过 128 字符时，服务端返回明确参数错误且不写入通知。
4. 工作流待办和审批结果通知均携带工作流上下文中的项目快照；原有 13 参数发布调用保持源码兼容。
5. `V133` 可在当前 MySQL 数据库成功执行，并为可可靠关联的历史工作流通知回填项目上下文。
6. 后端聚焦测试、前端生产构建、范围检查、桌面和 `390x844` 通知抽屉验收通过，无文字遮挡、页面级横向溢出或控制台错误。

## 权限、数据与审计

- 通知中心继续按认证用户的租户和接收关系查询，不增加客户端身份参数。
- 项目字段仅用于归属展示，不作为新的授权依据。
- 发布审计和通知正文审计边界保持不变。
- `sys_notification` 新增两个可空快照字段；迁移只追加，不修改历史迁移。

## 回退

应用代码可按本需求文件范围回退。数据库列为可空，应用回退后可保留；若必须物理回退，需另行评审追加迁移，不直接修改或删除 `V133`。
