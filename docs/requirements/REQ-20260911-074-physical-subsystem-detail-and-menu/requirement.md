# 物理子系统详情抽屉、节点号字段与架构菜单分组

## 业务目标

让架构人员在同一屏内按业务语义快速读取物理子系统事实，补齐安全节点号与文件传输节点号两个技术属性，并把架构管理入口按架构资产、环境、架构决策三类业务域分组，降低菜单查找成本。

## 范围

### 本次实施

- 物理子系统详情抽屉改为表格样式（`el-descriptions border`），并分四个栏位：
  - 基本信息：系统编号、系统简称、英文名称、发布状态。
  - 归属信息：负责人、负责团队、所属事业群。
  - 技术信息：部署平台、开发框架、系统运行时间、系统级别、安全节点号、文件传输节点号、灾备模式。
  - 描述：所属逻辑子系统、业务组件编号、系统描述、备注。
- 物理子系统新增 `securityNodeNo`（安全节点号）与 `fileTransferNodeNo`（文件传输节点号）两个可选自由文本字段：
  - 物理子系统变更申请草稿与物理子系统详情同时承载。
  - 表单使用输入框录入，不做字典校验；提交后进入审批快照并覆盖提交摘要。
  - 数据库追加 Flyway 迁移，为 `arch_physical_subsystem` 与 `arch_subsystem_physical_draft` 增加列。
- 架构管理（`/architecture`）下的菜单拆分为三个子目录：
  - 架构资产管理：物理子系统、架构子系统变更工单、部署单元、部署单元初始化导入、交付单元。
  - 环境管理：环境管理、资源申请、环境部署实例、环境搭建计划、搭建计划模板、网络分区、网络访问关系、网络专项工单。
  - 架构决策管理：架构决策、架构规范。
  - 仅调整 `parent_id` 与追加目录菜单，不改路由、组件路径和权限代码；按既有子菜单授权逐目录授予角色可见性。
- 列表表格与详情中的状态字段统一使用标签展示，并在标签内显示同色状态指示灯：物理子系统发布状态、架构子系统变更工单状态，桌面表格与移动卡片一致。指示灯为 `UiStatusTag` 的可选能力，默认关闭，不影响既有页面。

### 本次不实施

- 不改变物理子系统的编号规则、状态机、审批流程、权限代码和项目隔离规则。
- 不把安全节点号、文件传输节点号纳入字典、唯一性校验或跨系统同步。
- 不改写已发布 Flyway 迁移，不重命名现有路由、组件路径、API 路径、Java 包或数据表。
- 不新增、删除或重命名既有架构菜单项名称（“环境管理”分组与其下“环境管理”页面保持同名，见“已知问题”）。

## 现状与规则

- 物理子系统事实由 `arch_physical_subsystem` 维护，只能通过 `arch_subsystem_change_application` 审批后由 `SubsystemPublicationService` 发布写入。
- 前端详情抽屉组件 `SubsystemDetailDrawer.vue` 当前仅被物理子系统页使用，采用自定义 `dl` 网格，无分栏。
- 菜单来自 `sys_menu` + `sys_role_menu`；`AuthService.routes` 以 `parent_id == 0` 为根逐层挂载，因此新增目录必须同时补齐角色可见性。
- 数据范围仍为“当前项目”；新字段不改变任何查询过滤条件。
- 审计沿用现有变更历史与提交快照；新字段进入提交摘要（canonical）以保证提交后不可静默改写。

## 接口与数据

- API：物理子系统详情/列表响应新增 `securityNodeNo`、`fileTransferNodeNo`；变更申请草稿请求/响应新增同名字段。字段可空，最大长度 64。
- 数据 Owner：`business/architecture`，表 `arch_physical_subsystem`、`arch_subsystem_physical_draft`。
- 数据库迁移：V204 为两表增加 `security_node_no VARCHAR(64) NULL`、`file_transfer_node_no VARCHAR(64) NULL`，并追加架构菜单三组目录；V205 将架构规范从架构资产管理移入架构决策管理。存量行保持 `NULL` 兼容。
- 脱敏示例：`{"securityNodeNo":"SN-0012","fileTransferNodeNo":"FT-0031"}`。

## 验收标准

1. 物理子系统详情抽屉使用带边框表格分四栏展示，字段与分组和本需求一致，空值显示 `—`。
2. 变更申请表单与只读详情均出现“安全节点号”“文件传输节点号”输入框，可保存草稿、提交并再次打开后原值回显。
3. 审批发布后物理子系统详情展示新值；未填写时显示 `—`；超过 64 字符被服务端拒绝。
4. 架构管理下出现“架构资产管理”“环境管理”“架构决策管理”三个分组，原有菜单项分别归入对应分组（架构规范在架构决策管理），菜单名、路由、权限与原有行为不变。
5. 物理子系统与变更工单的列表表格、移动卡片和详情中的状态字段均以标签展示，并在标签内显示与状态同色的指示灯；未使用指示灯的既有页面外观不变。
6. 目标 Maven 模块测试、Flyway 迁移检查、前端生产构建与真实浏览器桌面/移动视口验收通过。

## 测试与发布

- 必须执行的测试：`mvn -pl :ccb-architecture -am test`、`node scripts/check-flyway-migrations.mjs`、`npm --prefix web run build`。
