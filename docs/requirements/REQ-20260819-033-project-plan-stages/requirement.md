# 项目计划阶段与分组重构

## 业务目标

项目计划需要按固定的七个项目生命周期阶段组织，阶段内再维护计划分组，分组内维护主计划及其子计划，便于按阶段查看、维护和执行项目计划。项目自身不再维护独立的“项目阶段/计划阶段”字段，项目阶段仅在风险上报场景中作为风险属性保留。

## 范围

### 本次实施

- 使用现有 `PLAN_PHASE` 参数类别维护七个计划阶段：立项、需求、设计开发、数据迁移、测试与验收、培训及投产演练、投产上线。
- 项目计划阶段只能使用上述七个固定参数，停用其他历史计划阶段参数；项目级 `pm_project.phase` 字段及其接口、页面展示和 Mock 数据移除。
- 计划分组增加阶段归属，创建分组时必须选择阶段。
- 项目计划页按“阶段纵轴 → 月份横轴 → 主计划时间条”展示；点击主计划后在弹框中查看和维护子计划，分组维护保留独立入口。
- 主计划继续支持新增子计划；主计划拖入分组时，主计划及全部子计划一起移动并同步阶段。
- 计划字段沿用现有字段，包括计划编号、名称、描述、负责人、阶段、牵头方、配合方、状态、日期和进度；阶段由参数阶段决定，计划表单不再手工编辑阶段。
- 服务端校验阶段有效性、父子计划阶段一致性、分组阶段一致性、日期范围和项目/租户范围。
- 追加 Flyway 迁移，新增表字段和参数数据均提供中文注释；历史迁移不修改。

### 本次不实施

- 不新增独立的项目阶段 CRUD 表；阶段仍由参数管理维护。
- 不改变计划编号规则、项目权限、项目成员和角色模型。
- 不改变计划已有字段语义，不新增移动端专用业务分支。

## 验收标准

1. 项目计划页展示七个阶段，阶段顺序与参数管理顺序一致；无计划阶段显示空状态，不污染其他阶段。
2. 新建分组必须选择阶段，分组显示在对应阶段下；同一项目不同阶段可以使用同名分组。
3. 新建主计划和子计划仍可使用现有字段；子计划默认继承父计划阶段，服务端拒绝阶段不一致的子计划。
4. 长按主计划整行拖入目标分组后，主计划及全部后代计划归入该分组并统一为分组阶段；非主计划不可拖动。
5. 非法阶段、无效分组、跨项目分组、日期逆序和越权请求均由服务端拒绝，前端显示中文错误。
6. 既有项目计划和分组经 V46/V47 兼容迁移后仍可查看、编辑和删除；项目响应不再返回项目级 `phase`/`phase_name`；V43-V46 历史迁移内容不变。
7. 后端项目测试、前端构建、Flyway 检查、治理检查和 `git diff --check` 通过；桌面和 375px 页面无页面级横向溢出。

## 数据与兼容规则

- `pm_project.phase` 不再作为项目契约字段使用，V47 追加迁移删除该历史字段。
- `pm_project_plan.phase` 继续保存计划阶段参数键，仅允许七个固定阶段。
- `pm_project_plan_group.phase` 保存分组阶段参数键。
- V46 将历史 `ANALYSIS`、`DEVELOPMENT`、`DELIVERY` 计划阶段映射到七阶段中的兼容阶段，并为历史分组按已有主计划阶段回填阶段；无阶段数据回填为 `PLAN_INITIATION`。
- V47 固化七个 `PLAN_PHASE` 参数，停用其他计划阶段参数，清理不在七阶段内的历史计划阶段，并删除 `pm_project.phase`。
- 计划归组时同步主计划及全部子计划的 `phase` 与目标分组阶段，移出分组时保留当前阶段。

## 验证与回退

- 验证命令：`mvn -pl :ccb-system -am test`、`npm --prefix web run build`、`node scripts/check-flyway-migrations.mjs`、`node scripts/check-all-governance.mjs`、`git diff --check`。
- 回退应用代码时保留 V46/V47 迁移数据；不得删除或修改已执行迁移。V47 删除的项目级历史阶段字段不恢复，必要时关闭计划阶段入口并保留计划数据只读。
