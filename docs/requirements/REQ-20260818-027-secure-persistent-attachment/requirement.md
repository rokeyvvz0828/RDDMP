# 安全持久附件与大型文件传输平台能力

## 业务目标

建设可被业务模块复用的持久附件平台能力，安全处理最大 5GB 的非结构化文件、断点续传、摘要、病毒扫描、预览、Range 下载和对象清理，使业务模块不接触 MinIO 对象键或自行实现文件安全边界。

## 范围

### 本次实施

- 建立独立 `ccb-attachment` 平台模块，复用 infrastructure 的 MinIO 能力、security 认证和 file-preview 的 kkFileView 适配。
- 提供分片上传会话、短期分片地址、暂停/继续、完成、取消和过期会话清理。
- 服务端完成后流式计算 MD5 与 SHA-256，不信任客户端摘要或 multipart ETag。
- 接入 ClamAV 异步扫描；扫描通过前对象保持隔离，命中风险文件进入 `QUARANTINED`。
- 提供受控预览、支持 HTTP Range 的下载、对象彻底清理和可重试失败状态。
- 提供公开附件契约与访问策略 SPI；平台模块不反向依赖具体业务模块。
- 支持环境级租户/项目配额配置、单文件 5GB 上限和每用户 20 个并发上传限制。

### 本次不实施

- 不实现项目、目录、标签、备注、收藏、审核、外链、回收站或迁移包业务规则。
- 不开放匿名上传，不接受客户端提交任意远程 URL，不暴露长期 MinIO 地址或持久凭据。
- 不实现跨租户或跨项目存储去重。

## 现状与规则

- 当前 `platform/file-preview` 仅保存临时预览对象，不是持久资产或大型文件上传服务。
- 现有 `REQ-20260814-022` 已设计持久附件模块但当前分支尚未实现；本需求进入 `ready` 前必须由 Owner 决定合并、替代或调整该需求，避免平行实现。
- 文件状态为 `UPLOADING -> SCANNING -> READY`；扫描异常进入 `SCAN_FAILED`，风险文件进入 `QUARANTINED`。
- 非 `READY` 文件不得预览、下载、绑定审核或对外分享。
- MinIO 桶保持私有，短期地址只能由后端签发，客户端不得构造对象键。

## 接口与数据

- 上传 API 提供会话创建、分片签发、状态查询、完成和取消；完成、取消操作支持幂等键。
- 附件 API 提供元数据查询、预览授权、Range 下载和受控彻底清理。
- 附件表保存附件 UUID、文件名、大小、类型、MD5、SHA-256、私有对象键、状态、上传人和时间；上传会话保存分片生命周期和过期时间。
- 数据 Owner 为 `platform/attachment`；业务模块只持有附件 ID。
- 外部依赖为本地/受控 MinIO、ClamAV 和 kkFileView，不连接生产文件系统或外部任意地址。

## 验收标准

1. 最大 5GB 文件可分片上传、暂停、继续、取消和完成，失败分片可单独重试。
2. 完成后服务端流式计算 MD5/SHA-256，摘要、大小和类型与持久对象一致。
3. ClamAV 通过前文件不可访问；测试病毒样本被隔离且不进入预览、下载或业务绑定路径。
4. 下载支持 HTTP Range，预览仅允许受控来源，不泄露对象键和持久凭据。
5. 过期会话和未完成分片可幂等清理；对象删除失败保留可重试状态。
6. 跨租户、无访问策略、过期地址、伪造 MIME、超限和并发超额请求被拒绝并审计。
7. 附件模块、预览模块、全量 Maven、治理及容器运行检查通过。

## 测试与发布

- 必须执行附件模块单元与集成测试、MinIO/ClamAV/kkFileView 容器测试、上传和 Range 下载 API 测试、安全边界测试、`mvn test` 和治理检查。
- 上线前验证 5GB 等价分片场景、失败重试、扫描隔离、过期会话和对象清理监控。
- 回退应用时停止新上传、扫描和清理任务，保留附件元数据与对象，不执行生产 `DROP` 或批量对象删除。
- 风险包括平台公共能力、对象存储、恶意文件处理、供应链镜像和大文件资源耗尽；需 infrastructure、security 和 platform Owner 专项复核。
