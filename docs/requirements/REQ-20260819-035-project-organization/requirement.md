# 项目组织架构维护

## 目标

在项目详情的“项目组织架构”页签中维护独立于系统组织架构的项目组织树，并将项目成员挂接到项目机构、将项目角色关联到项目成员。

## 必须需求

- R1：每个项目拥有独立的项目组织树，项目组织节点包含名称、编码、上级节点、排序号、启用状态和逻辑删除状态。
- R2：支持新增、编辑和删除项目组织节点；删除有下级节点或仍挂接成员的节点时拒绝操作并给出中文提示。
- R3：项目成员在新增或编辑时必须可以选择所属项目机构；每个项目成员在当前项目中归属一个项目机构，机构为空时表示“未分配机构”。
- R4：项目组织架构页签左侧展示项目组织树，选择节点后右侧成员列表按机构过滤；选择“全部机构”展示全部成员。
- R5：项目角色维护支持直接勾选当前项目成员，保存后通过现有成员-角色关系维护角色成员关联。
- R6：角色关联人员必须是当前项目的有效成员；项目成员变更机构不影响其角色关联。
- R7：接口和数据库校验项目归属、租户边界、项目访问权限和现有项目成员/角色权限，写操作保留审计日志。

## 约束与验收

- 保持现有中文界面、前后端分离契约和项目组织架构页签入口。
- 项目组织树与 `sys_org` 完全独立，不读取、不写入系统组织架构数据。
- Flyway 仅追加 `V50` 迁移，不修改已发布脚本；历史项目成员机构为空可兼容展示。
- 桌面端采用左树右维护区，375px 手机视口切换为上下布局，不产生页面级横向溢出。
- 验收包含后端测试、前端类型检查和构建、迁移检查、差异检查及接口/页面运行态检查。
