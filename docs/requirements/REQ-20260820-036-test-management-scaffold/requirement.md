# 测试管理模块目录与空白列表脚手架

## 业务目标

研发与测试人员能够从系统 Sidebar 进入一级“测试管理”，按测试类型和业务页面三级导航到对应的空白 CRUD 列表，为后续测试公告板、方案、范围、案例、缺陷、报告和统计能力提供稳定入口。

## 范围

### 本次实施

- 建立前端 `test-management` 业务模块目录，并按应用组装测试、用户测试、非功能测试、安全测试、营业日管理划分子目录。
- 在动态菜单中建立“测试管理”一级菜单；应用组装测试、用户测试、非功能测试、安全测试四个二级目录各包含测试公告板、测试方案、测试范围、测试案例、测试缺陷、测试报告、分析统计七个三级页面。
- 营业日管理作为二级目录，包含日历概览、日历安排、跑批需求、测试环境管理四个三级页面。
- 为 32 个叶子入口提供统一的空白 CRUD 列表：标题、关键词筛选、新增、编辑、删除入口、空状态和分页占位。
- 复用交付示范中心、`UiPageHeader`、`UiToolbar`、`UiDataTable` 和语义主题变量，覆盖桌面与移动端布局。
- 为管理员角色初始化菜单访问与 create/read/update/delete 操作权限。

### 本次不实施

- 不建设测试管理业务表、后端 CRUD API、真实数据持久化或业务审计。
- 不定义测试方案、范围、案例、缺陷、报告、统计和营业日的正式字段模型。
- 不实现批量导入导出、流程审批、附件、图表或跨模块集成。
- 不修改现有页面、公共 UI 组件或现有菜单行为。

## 现状与规则

- 当前入口、流程和数据来源：Sidebar 由 `/api/auth/routes` 返回的动态菜单树生成；前端通过 Vue Router 映射页面组件。
- 业务规则和边界：四个测试域使用相同的七类页面；营业日管理使用四个日历及环境类页面；空白列表数据仅存在于当前页面内存，刷新后清空。
- 角色、权限、数据范围和审计：管理员获得菜单及 CRUD 占位权限；本次没有真实写 API，因此不产生业务审计记录，前端权限入口不代表未来后端授权。
- 外部系统、附件或敏感信息：不涉及。

## 接口与数据

- API/事件契约：不新增业务 API；复用现有 `/api/auth/routes` 菜单契约。
- 数据 Owner：当前仅为前端演示状态；后续各页面需求分别确定正式数据 Owner。
- 数据库迁移与存量兼容：追加一条 MySQL 8 Flyway 菜单迁移，不修改历史迁移；只新增菜单、角色菜单和权限记录。
- 脱敏输入输出示例：页面允许创建虚构的“名称/说明”临时记录，不接收生产数据。

## 验收标准

1. Sidebar 出现一级“测试管理”，展开后结构和顺序与本需求指定目录一致，32 个叶子入口均可点击且 URL 唯一。
2. 每个叶子入口进入统一空白列表，展示正确的测试域和页面名称，并提供关键词筛选、新增、编辑、删除及分页占位。
3. 新增和编辑可在页面内创建或修改虚构临时记录；删除必须二次确认；刷新页面后恢复空列表，明确提示当前为脚手架。
4. 页面使用现有公共组件和主题变量，在 1280x800、375x812、390x844、430x932 视口无页面级横向溢出，移动端操作可达。
5. 新模块路径在治理模块清单和 CODEOWNERS 中登记；Flyway、治理检查、前端构建和真实浏览器路径验证均有实际证据。

## 测试与发布

- 必须执行的测试：治理检查、Flyway 迁移检查、前端生产构建、目标路由与菜单数据库检查、桌面及三种手机视口浏览器验收。
- 上线验证：登录管理员账号，展开测试管理，抽查四个测试域的三级入口和营业日管理，验证空列表 CRUD 占位交互。
- 回退或补偿：回退需求提交；若迁移已应用，新增补偿迁移将相关菜单和权限标记删除，不修改已发布 V51。
- 风险与人工复核人：新增模块边界、动态菜单和 Flyway 属高风险变更，由 `rokeyvvz0828` 复核。
