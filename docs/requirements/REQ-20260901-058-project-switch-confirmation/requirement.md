# 项目切换确认与页面刷新

## 业务目标

用户通过顶部或移动端项目选择器切换项目时，需要先明确确认，避免误操作。确认后系统保存目标项目并整页刷新，使所有页面数据重新进入目标项目上下文。

## 范围

### 本次实施

- 桌面顶部、侧边布局头部和移动端抽屉中的项目选择器使用相同的确认交互。
- 弹窗展示目标项目名称，并明确提示当前页面将重新加载。
- 取消切换时保持当前项目和选择器显示不变。
- 确认切换时先保存目标项目，再执行浏览器整页刷新。

### 本次不实施

- 不修改项目列表、项目成员、权限或数据范围规则。
- 不修改项目上下文 Store 的公共行为。
- 不修改接口、数据库、路由结构或页面业务逻辑。
- 不新增样式，复用 Element Plus 现有确认弹窗和选择器能力。

## 现状与规则

- 当前三个项目选择器直接调用 `projectContext.select`，没有二次确认，也不会整页刷新。
- 仅用户主动操作选择器时触发确认；详情直链等程序化项目同步继续直接使用 Store，不弹窗。
- 确认期间禁止重复触发项目切换。

## 接口与数据

- API/事件契约：无变化。
- 数据 Owner：项目上下文继续由 `useProjectContextStore` 管理。
- 数据库迁移与存量兼容：无数据库变化。
- 敏感信息：无。

## 验收标准

1. 在任一项目选择器中选择其他项目时，弹窗显示目标项目名称、刷新提示、确认切换和取消操作。
2. 点击取消后不保存目标项目、不刷新页面，选择器恢复当前项目。
3. 点击确认切换后保存目标项目并整页刷新，刷新后目标项目保持选中。
4. 桌面布局、顶部布局和移动端抽屉行为一致，且不影响程序化项目同步。

## 测试与发布

- 必须执行：前端生产构建、目标文件差异检查、桌面与 390x844 浏览器交互验收。
- 上线验证：选择另一项目分别验证取消和确认，确认刷新后项目名称及页面数据属于目标项目。
- 回退：回退 `AppLayout.vue` 的项目切换处理器和选择器绑定即可。
