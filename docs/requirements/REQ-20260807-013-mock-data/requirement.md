# REQ-20260807-013 Mock 数据自动维护

status: ready

## 目标

为 RDDMP 建立统一的本地 mock 数据源，覆盖当前平台的系统管理、工作流、AI、消息通知和交付示范能力，并为后续业务模块提供可扩展的数据登记方式。项目以 local profile 首次启动时自动加载数据，后续启动继续幂等同步，便于研发人员快速查看页面和接口功能。

## 实施范围

- 新增版本化的 `mock/mock-data.json`，按功能域、数据表和功能目录组织虚构数据。
- 新增基础设施层 mock 数据同步器，读取 classpath 中的数据文件，对声明的数据表执行白名单校验和幂等 upsert。
- 新增 mock 数据状态表，记录数据集版本、校验摘要和最近同步时间。
- local profile 默认开启 mock 数据同步，生产和非 local profile 默认关闭。
- 新增维护契约和启动说明，要求新增业务功能在同一数据文件中登记 mock 场景。

## 非目标

- 不修改既有业务 API、包名、模块边界或 Flowable 引擎表。
- 不在生产环境自动写入演示数据。
- 不上传真实附件、不调用外部 AI、不保存真实凭据。
- 不将交付示范中心的纯前端会话状态强行改造成后端业务数据。

## 业务规则

1. 只有 `local` profile 且 `ccb.mock-data.enabled=true` 时执行同步。
2. 数据文件是 mock 数据的唯一维护源，数据集按 `datasetKey` 和 `datasetVersion` 标识。
3. 只能同步 loader 白名单中的表和字段；数据文件引用未知表或字段时启动失败并给出明确错误。
4. 同一主键重复启动必须更新为文件内容，不产生重复数据；缺少的数据库默认字段由数据库默认值补齐。
5. mock 数据使用保留的高位 ID 和 `MOCK_`/`mock-` 标识，避免与现有演示迁移数据冲突。
6. 关闭 `MOCK_DATA_ENABLED` 后，启动器不清理、不覆盖人工数据。

## 验收标准

- 首次 local 启动后，系统、AI、通知和工作流列表能读取到 mock 数据。
- 同一数据集重复启动不产生重复行，修改数据文件版本后能更新对应行。
- 非 local profile 或关闭开关时不执行 mock 同步。
- 未授权表/字段会被拒绝，数据文件中不存在真实凭据和生产数据。
- `mvn test`、前端构建、治理检查和 Flyway 检查通过。

## 回退

关闭 `MOCK_DATA_ENABLED` 即可停止后续同步；删除本次新增代码、V31 迁移和 mock 文件可回退本需求。已被 mock 数据同步更新的本地行需要通过数据库备份或本地重建恢复。
