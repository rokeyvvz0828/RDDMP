# 本地固定业务流程自动发布修复

## 业务目标

修复本地环境中物理子系统变更工单和资源申请工单提交时报“流程编码未发布或不存在”的问题。两个固定流程在 Flyway 中仍只预置草稿，但 local profile 启动后必须通过平台正式发布能力完成 BPMN 编译和 Flowable 部署，使工单可直接提交。

## 范围与规则

- 本地启动时检查 architecture.subsystem.change 和 architecture.resource-request。
- 草稿流程调用现有 WorkflowService.publish 发布；已发布流程幂等跳过。
- 流程缺失、状态异常、操作用户缺失或部署失败时，本地应用启动失败并报告具体原因。
- 仅 local profile 默认启用，可通过环境变量关闭或覆盖流程编码；其他 profile 不自动发布。
- 不修改历史 Flyway，不伪造 PUBLISHED、deployment_id 或 Flowable 表，不绕过工作流网关、权限和审计。
- 同步修复因 Flyway 迁移重编号而陈旧的架构模块 MySQL 集成测试版本基线，并统一网络准入迁移测试的项目数据库排序规则。
- 仅修改测试代码，不借此调整迁移内容、业务实现或数据库结构。

## 验收标准

1. 本地启动器对两个草稿流程各调用一次平台发布服务。
2. 已发布流程不会重复发布。
3. 任一固定流程缺失时启动器失败。
4. ccb-boot 聚焦测试、架构提交服务回归、治理、范围和 git diff --check 通过。
5. 三个迁移集成测试类通过，`mvn -pl :ccb-boot -am test` 不再因陈旧迁移版本或测试数据库排序规则失败。
