# 项目风险抽屉与进展评论

## 业务目标

将项目风险维护从大弹窗调整为右侧抽屉，并将问题上报、进度描述、问题跟踪分成可理解的操作模式，支持项目成员持续记录风险进展。

## 本次实施

- 新增、编辑风险时只显示“问题上报”第一部分。
- 风险操作列提供“编辑、进度描述、问题跟踪、删除”操作。
- “进度描述”模式中第一部分只读，展示按创建时间倒序排列的评论，并允许当前可进入项目风险页的用户发表评论。
- 评论使用现有 `UiUserIdentity` 展示头像和姓名，后端持久化评论作者和内容。
- “问题跟踪”模式维护第三部分“升级与解决”，保存后刷新风险数据。
- 追加 Flyway 迁移创建项目风险评论表，接口遵循现有项目租户和访问范围校验。

## 本次不实施

- 不新增评论独立权限，不改变项目可见范围和风险维护权限。
- 不修改已发布 Flyway 脚本，不引入通知、附件、审批或动态表单元数据。

## 数据与权限

- 评论归属 `tenant_id + project_id + risk_id`，作者取服务端认证用户，不信任客户端作者字段。
- 评论读取和发表复用项目查看权限与项目成员/超级管理员访问校验；风险第三部分修改继续使用项目风险修改权限和项目负责人校验。
- 评论新增保留项目风险操作审计记录。

## 验收标准

1. 新增/编辑风险打开右侧抽屉，只能看到并提交第一部分；不出现第三部分编辑控件。
2. 进度描述打开同一抽屉，第一部分所有控件只读；评论按 `created_at DESC, id DESC` 展示，头像姓名组件和评论内容可见，发表评论后置顶且不重复提交。
3. 问题跟踪打开同一抽屉，只显示第三部分，可保存关注等级、问题级别、升级和解决日期/方案。
4. 非项目成员不能读取或发表评论；项目成员不需要新增评论权限即可发表；原有风险增改删权限边界保持不变。
5. V44 迁移、后端聚焦测试、前端构建、范围检查和浏览器桌面/移动视口验收通过。

## 回退

回退本需求新增的 V44、评论接口、抽屉模式和账本文件；保留并不修改 V43 历史迁移。
