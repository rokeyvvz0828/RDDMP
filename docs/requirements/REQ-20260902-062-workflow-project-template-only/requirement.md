# 工作流仅保留全局模板与项目流程

## 业务目标

工作流管理员只维护“全局模板”和“本项目流程”。存量平台流程安全复制为无具体人员的模板，并且只为“平台能力升级项目”生成待配置项目草稿；历史和运行中实例继续使用原定义。

## 范围

### 本次实施

- 定义页移除“平台流程”入口和重复的当前项目标签。
- 11 条存量 `PLATFORM` 定义复制为 `TEMPLATE` 草稿，具体用户、角色和动态办理人配置统一改为人员占位。
- 仅项目 `RDDMP-PLATFORM`（ID `910000000003001`）生成同编码 `PROJECT` 草稿。
- 项目草稿允许保存未解析占位，但发布前必须全部配置为有效项目成员或项目角色。
- 新启动优先选择当前项目同编码已发布流程；不存在时才兼容回退旧 `PLATFORM`。
- 工作流管理 API 不再列出或允许新建、编辑、发布存量 `PLATFORM` 定义。

### 本次不实施

- 不物理删除或原地改写存量 `PLATFORM` 定义。
- 不修改 Flowable `ACT_*` 表、历史实例定义主键或版本。
- 不为其他项目自动生成流程，不自动推断旧用户/角色到项目成员/角色的映射。
- 不迁移运行中实例，不改变具体业务模块的流程编码。

## 现状与规则

- 当前定义页展示 `PROJECT`、`TEMPLATE`、`PLATFORM` 三个分区并重复显示当前项目。
- 当前共有 11 条有效 `PLATFORM` 定义、23 个历史实例和 10 个运行中实例。
- 模板不可发布或运行；项目定义必须绑定可访问项目，人员配置由后端校验。
- 全局模板的维护沿用工作流管理权限；项目流程沿用项目访问和管理权限。
- 存量平台定义仅作为隐藏兼容数据，禁止从管理入口继续维护。

## 接口与数据

- `GET /api/workflows/definitions` 仅接受 `PROJECT` 或 `TEMPLATE` 管理范围，并返回项目草稿是否待配置人员。
- `POST /api/workflows/definitions` 仅创建 `PROJECT` 或 `TEMPLATE`。
- 发布接口对项目占位、项目成员和项目角色执行最终校验。
- `WorkflowGateway.startByCode` 和 `startByDefinitionId` 在存在当前项目同编码已发布流程时选择项目流程，否则兼容旧平台流程。
- 追加 `V136`，复制数据并使用独立确定性主键区间；不修改 V134、V135。

## 验收标准

1. 定义页桌面和手机视图只显示“本项目流程”“全局模板”，不显示重复项目标签或平台流程文案。
2. 11 条存量平台定义均有同编码模板草稿，模板 JSON 不含具体用户、角色主键或动态办理人配置。
3. 仅 `910000000003001 / RDDMP-PLATFORM` 生成 11 条项目草稿，其他项目没有迁移生成数据。
4. 待配置项目草稿可保存，列表有明确提示；存在占位时发布失败，配置有效项目成员或角色后可发布。
5. 按编码和显式定义 ID 发起时，同编码项目流程优先；无已发布项目流程时旧平台流程仍可兼容启动。
6. 迁移前后的旧平台定义、版本、23 个历史实例及其定义引用不变，10 个运行中实例可继续查看和审批。
7. MySQL 8.4 迁移、工作流聚焦测试、全量后端测试、前端构建、治理和范围检查通过。
8. 桌面及 `375x812`、`390x844`、`430x932` 视口无页面级横向溢出，双分区和待配置操作可达。
