# 投产问题详情、维护抽屉与双视图

## 目标与确认

项目成员在 `/release-operations/issues` 查看问题详情，维护人员通过抽屉新增和编辑，并按需要在卡片与列表之间切换。

用户已确认详情抽屉、分区维护抽屉、共用筛选分页、桌面默认列表/手机默认卡片方案，并在查看落盘实施计划后回复“确认”。模块 Owner 来自 `governance/modules.yaml`，不代表额外 Owner 审批。

## 必须需求

- R1：两种视图均能点击问题标题或详情按钮打开只读详情抽屉。展示编号、标题、优先级、状态、演练轮次、负责人、发现/关闭/更新时间及问题描述、分析结论、处理措施、跟踪记录；缺失值有明确空值显示。
- R2：新增和编辑由弹窗改为右侧抽屉，分区呈现原有字段，正文可滚动，底部取消/保存可达。保留编号与标题必填、关闭状态必须填写关闭时间、保存中禁重、失败保留输入及原有数据提交契约。
- R3：工具栏使用有提示与可访问名称的图标分段控件切换卡片和列表。两视图共用当前页数据、筛选、页码和分页大小，切换视图不触发新查询，不清空条件。
- R4：首次进入桌面默认列表、手机默认卡片；用户主动选择后不因窗口缩放被覆盖。手机卡片单列、表单单列，手动选择列表时只允许表格局部横滚。375x812、390x844、430x932 及桌面无页面级横向溢出，浅深主题可读。
- R5：有查看权限的只读用户可打开详情，新增/编辑/删除仅向 `release-operations:issue:manage` 用户显示。项目切换不得留下旧问题详情；加载、空、错误重试、无权限、取消删除和服务端分页语义保留。

## 边界

仅修改 `web/src/modules/release/components/ReleaseIssueTrackingView.vue` 及本需求文档和前缀账本。不改投产方案、其他投产菜单、公共组件、共享 CSS、路由、API、后端、数据库或依赖；不提交、不推送、不切分支。保护当前工作区既有改动。

现有 `ReleaseIssueDto` 已包含详情全文和显示名称，详情直接使用服务端返回的当前记录，不新增详情 API。保留 `ReleaseIssueWrite`、projectId、rowVersion 及成员/轮次选项来源，不更改权限和审计规则。无附件、迁移、外部系统或生产访问，不读取 `.env`。

## 验收与回退

以实施计划中 R1-R5 场景矩阵为准，运行 `git diff --check`、前端构建、治理和范围检查；实际浏览器验证两种视图、详情/新增/编辑、筛选分页、取消删除、项目切换和桌面/手机布局。缺少测试账号或可用工具时，明确记录未测项，不宣称独立验收通过。

发布后检查该路由及原 API 请求。回退仅撤销本需求组件和文档改动，无数据补偿；保留其他任务未提交内容。独立人工复核待验收阶段，不冒充已获批准。
