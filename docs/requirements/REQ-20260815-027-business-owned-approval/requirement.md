# 业务详情内审批与工作流职责收敛

## 目标

消除版本申请详情与审批操作割裂的问题。工作流平台继续负责任务编排、权限、动作、电子签名和审计，但业务审批判断及操作必须发生在配置管理的完整版本申请详情页。首页工作台和任务中心只聚合、索引并跳转业务工单，工作流管理模块只保留流程定义和流程监控。

## 必须范围

1. 新增配置管理业务详情路由 `/release/applications/:applicationCode`，统一承载版本申请详情、交付单元、需求、附件、审批进展、流转日志和审批操作。
2. 版本申请列表、首页待办、首页已办和通知使用同一业务详情路由；待办携带 `taskId`，已办携带 `instanceId` 或可定位审批轮次的信息。
3. 当前登录人拥有有效待办时，无论从任务中心还是版本申请列表进入，业务详情页都自动显示审批意见、当前身份确认签署、同意、退回和拒绝操作。无 `taskId` 时由服务端按业务类型、申请单号、当前租户和当前登录人解析本人待办；无权限、无本人待办、已处理、失效或结束任务只读展示。
4. 首页“查看全部”进入 `/workbench/tasks` 任务中心。任务中心提供待办和已办列表、分页、项目过滤及业务跳转，不允许直接审批。
5. 工作流菜单移除“待办审批”和“流程已办”，工作流管理页面不再提供业务审批按钮，仅保留流程定义、流程配置和流程监控。
6. 旧 `/workflow/inbox`、`/workflow/done` 路由跳转到任务中心；旧 `/workflow/review/:taskId` 在能够定位业务单号时兼容跳转业务详情，否则回到工作台并提示。
7. 工作流平台提供指定任务上下文查询和按业务标识解析当前用户待办的能力，返回业务标识、业务路由、实例、节点、任务类型、状态、允许动作、签名要求及当前用户处理资格。查询和决策均由服务端校验租户、待办人、任务状态和权限。
8. 工作流决策仍调用 `/api/workflows/tasks/{id}/decision`；业务前端不得模拟服务端授权，也不得直接访问工作流私有表。
9. 工作流实例 `action_path` 使用稳定业务地址 `/release/applications/{申请单号}`，首页和任务中心在导航时安全附加任务或实例参数。
10. 新增 Flyway 迁移下线菜单 `202`、`204` 及对应角色菜单关系，不修改已发布迁移；保留待办、已办和决策后端接口作为平台公共能力。
11. 当前配置管理业务数据继续使用可替换 Mock Provider；正式配置管理 API 接入后保持路由、任务上下文和审批动作契约不变。
12. Web 与 `375x812`、`390x844`、`430x932` 视口均能查看完整工单并完成当前用户允许的审批操作，不产生页面级横向溢出。

## 关键规则

- 业务详情是审批上下文和操作界面的唯一所有者。
- 工作流平台是任务状态、允许动作、待办人、电子签名和流程审计的唯一事实源。
- 首页与任务中心是跨业务聚合入口，不复制业务详情和审批表单。
- 流程监控用于管理员观察与审计，不提供业务审批操作。
- 审批操作成功后留在业务详情页并刷新申请状态、审批进展和流转日志。
- 任务已被其他人处理、流程轮次变化或重复提交时，服务端拒绝操作，页面刷新为最新只读状态。
- 没有完整业务详情时不得执行审批判断。

## 非目标

- 不在工作流平台实现版本申请字段、附件和业务规则展示。
- 不让任务中心成为第二套业务审批页面。
- 不实现正式配置管理后端或替换当前项目、子系统、交付单元和需求 Mock Provider。
- 不删除待办、已办、任务决策、流程监控等平台后端能力。
- 不新增独立移动端应用或第二套 H5 业务规则。

## 验收标准

1. 动态菜单中工作流仅显示流程定义和流程监控，不显示待办审批和流程已办。
2. 工作流管理页面及任务中心均没有同意、退回、拒绝等业务审批按钮。
3. 首页待办、已办、任务中心及版本申请列表均能进入同一版本申请业务详情。
4. 有效待办人可以在完整业务详情中签署并同意、退回或拒绝；其他用户和失效任务不能操作。
5. 审批成功后不离开业务详情，状态、进展和日志同步更新；重复提交不会产生重复动作。
6. 历史工作流地址得到安全兼容，不形成空白页、404 或继续进入通用审批弹框。
7. 指定任务上下文、业务待办解析和决策接口具备租户、登录人、任务状态和允许动作校验，并有正常、越权、无本人待办、已处理和不存在测试。
8. Flyway、Maven、前端构建、治理、`git diff --check` 及规定视口浏览器验收通过。

## 回退

前端可恢复原工作流菜单路由和独立审批页；数据库通过新的前向迁移恢复菜单关系，不回滚或修改既有 Flyway；工作流公共接口保持向后兼容，因此业务详情审批可独立回退。
