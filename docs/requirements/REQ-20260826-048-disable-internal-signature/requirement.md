# 暂停使用平台内部电子签名

## 业务目标

当前内部电子签名仅增加一次登录身份确认，用户感知与普通审批差异不足。现阶段暂停新签名配置和签署要求，使审批继续按原有意见与动作完成，同时保留历史签名证据以便审计和未来恢复能力。

## 范围

### 本次实施

- 流程设计器不再展示“需要电子签名”配置。
- 工作流任务上下文统一返回不需要电子签名。
- 审批决定不再要求签名确认，也不新增签名记录。
- 保留现有签名字段、接口兼容、数据库表和历史签名查询。

### 本次不实施

- 不删除或修改历史签名记录。
- 不删除数据库表、API 字段或流程定义中的存量 `signatureRequired` 配置。
- 不增加手写签名、密码复核、CA、印章或第三方签署平台。
- 不修改审批动作、任务授权、流程状态和业务模块逻辑。

## 现状与规则

- 入口：流程定义中的审批节点配置，以及业务详情页审批操作。
- 暂停期间，即使历史流程版本保存了 `signatureRequired=true`，运行时也必须按不需要签名处理。
- 审批仍必须校验当前办理人、任务状态、允许动作和业务数据范围。
- 历史签名数据继续只读返回，不进行数据迁移。

## 接口与数据

- API 字段 `signature_required` 和 `signatureConfirmed` 保持兼容；前者固定返回 `false`，后者被忽略。
- 数据 Owner：`platform/workflow`。
- 数据库无变更，`wf_signature` 历史记录保留。

## 验收标准

1. 审批节点配置中不再出现“需要电子签名”。
2. 带有存量 `signatureRequired=true` 的任务上下文也返回 `signature_required=false`。
3. 同意、拒绝、退回在未提交签名确认时可以继续执行，且不新增签名记录。
4. 历史签名查询仍返回既有记录，公开请求和响应字段不删除。
5. 工作流聚焦测试、前端构建、全量后端测试和范围检查通过。

## 测试与发布

- 必须执行：`mvn -pl :ccb-workflow -am test`、`mvn test`、`npm --prefix web run build`、治理与范围检查、`git diff --check`。
- 上线验证：检查流程节点配置无签名选项，审批详情无签名确认项，审批动作可正常提交。
- 回退：恢复节点配置入口和运行时签名校验；数据库及历史记录无需补偿。
- 风险与人工复核人：平台工作流审计行为变化，由模块 Owner `rokeyvvz0828` 复核。
