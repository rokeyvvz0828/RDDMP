# REQ-20260807-014 业务表单元数据规约与数据模型

status: ready

## 目标

参考 `2guan/RADAR` 的输入项配置设计，为 RDDMP 建立统一的业务表单元数据规约和 MySQL 数据模型，使后续业务功能可以通过配置管理字段、分区、布局、选项、列表展示、筛选、统计维度和状态规则，同时保持核心业务表稳定。

## 实施范围

- 新增 `docs/integration/business-form-metadata-contract.md`，定义接入规则、字段类型、状态规则、接口契约、查询安全和移动端要求。
- 新增 Flyway `V32__business_form_metadata.sql`，创建 scope、section、field definition、field rule、field option、field value、config revision 七类平台表。
- 不新增业务页面、动态表单 API 或业务模块字段；本需求只建立公共设计和持久化基础。

## 非目标

- 不把现有业务表迁移为 EAV。
- 不修改现有 Java 包名、模块边界、业务逻辑、工作流表或既有迁移。
- 不在本需求中实现系统设置页面、后端 CRUD、前端动态渲染和历史业务字段回填。

## 业务规则

1. 核心字段继续落在业务主表，扩展字段使用值表。
2. 字段定义与字段值分离；字段定义使用稳定 `field_key`，字段中文名称不可作为主键。
3. 状态/角色/表达式规则必须通过稳定编码匹配，服务端负责最终校验。
4. 配置发布保存完整快照，业务值不因配置版本变化而被覆盖。
5. 多值字段用 `ordinal` 保存顺序，值列必须与 `value_type` 匹配。
6. 扩展字段的列表、筛选、排序和统计能力必须经过元数据白名单。
7. 外部引用遵循系统字典、人员、组织、附件等公共契约。

## 验收标准

- 规约明确说明配置层级、字段属性、值类型映射、接入步骤、服务端校验和回退方式。
- Flyway 迁移只新增七类表及必要索引，无修改既有迁移、既有业务表或数据。
- 所有新表包含租户隔离、软删除或版本状态、审计时间字段和查询索引。
- 迁移文件符合 `V<number>__description.sql` 命名和追加规则。
- 治理检查与 Flyway 检查通过。

## 回退

本需求只增加新表和规约；回退应用时停止读取新表，数据库保留空表和配置快照，后续按正式数据库回退流程处理，不手工删除生产表。
