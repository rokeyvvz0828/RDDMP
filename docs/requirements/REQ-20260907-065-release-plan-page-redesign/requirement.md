# 投产方案页面重新设计

## 业务目标

项目成员在 `/release-operations/drill-plans` 中选择方案、查看方案信息并维护正向与回退时序。调整信息层级，不改变业务功能。

用户已确认左侧方案目录、右侧详情、抽屉展示 P1/P2 时序的设计，并再次确认了落盘实施计划。模块 Owner 来自模块清单，不代表已取得额外 Owner 审批。

## 范围

- R1：桌面使用紧凑方案目录和较宽详情区域，展示名称、编码、版本、状态及选中反馈；不添加统计块或介绍文案。
- R2：详情保留编辑、删除操作，正向和回退时序使用两个明确入口，展示各自名称、时序数和指令数。
- R3：时序保持抽屉展示，P1/P2 横向排列，每个时序包含多个指令。时序和指令的新增、编辑、删除，时序组名称修改全部保留，不增加日期时间线。
- R4：手机端目录与详情上下排列，仅时序区域局部横向滚动。图标有可访问名称和提示，长文本换行，浅色和深色主题可读。
- R5：项目切换、选中状态、表单字段、时间范围、权限、加载、空、失败、无权限、提交反馈和删除取消行为不变。

不实施：API、后端、数据库、路由、公共组件、其他投产菜单、查询能力扩展、依赖升级、提交或推送。

## 接口与数据

继续调用 `web/src/api/release.ts` 的方案、时序、指令 CRUD 和项目成员选项 API。请求参数、rowVersion、projectId 和响应 DTO 不变。数据归 business/release；无数据库迁移、权限或审计策略变更，无外部访问或附件影响。不读取 `.env` 或生产数据。

## 验收标准

1. 在桌面宽度 1280px 及以上，目录窄于详情；切换两个方案后详情与时序入口对应当前选中方案。
2. 正向和回退入口分别打开正确抽屉，P 编号、名称及所属指令对应服务端数据。
3. 所有原有新增、编辑入口可达，表单字段与原实现一致；三级删除点击取消或关闭不发出删除请求、不显示失败消息。
4. 375x812、390x844、430x932 下页面无横向溢出；时序局部滚动可达末列，抽屉正文可滚动且关闭及表单提交操作可达。
5. 加载、无数据、失败重试、无权限、只读、保存中与长文本场景不丢失；主题切换无不可读按钮。
6. 源码仅修改授权组件，API/请求函数、父级项目切换及其他页面不变，前端构建成功。

## 测试与发布

执行 `git diff --check`、`npm --prefix web run build`、治理与范围检查；浏览器使用本地测试会话验证上述场景，未具备的角色和故障场景如实记录，不伪称通过。

上线检查该路由及两个抽屉、项目切换、现有维护入口。仅回退本需求新增的模板及局部样式，不回退既有菜单改名、不修改已发布 SQL 或数据。独立复核由人工验收完成，本上下文自测不冒充独立观测。
