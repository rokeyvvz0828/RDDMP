# 项目工作台批量统计查询

## 业务目标

降低项目工作台在项目数量增长时的数据库访问次数，消除每个项目重复查询所有者、成员和计划统计造成的 N+1 访问，同时保持现有响应字段、排序、权限和租户隔离。

## 本次实施

- 工作台列表保留原项目主查询和可见范围条件。
- 所有者名称改为一次租户绑定的批量查询。
- 成员数、计划数、完成数和平均进度改为一次项目集合统计查询。
- 保持 `owner_name`、`member_count`、`plan_count`、`completed_plan_count`、`plan_progress` 字段及空列表行为不变。

## 本次不实施

- 不改变项目详情接口的字段或权限行为。
- 不迁移其他 `JdbcTemplate` 查询，不新增缓存、索引、迁移或前端改动。

## 验收标准

1. 工作台返回 N 个项目时，除项目主查询外最多执行一次所有者查询和一次统计查询，不按项目逐行查询。
2. 统计结果、所有者名称、排序、租户条件和项目可见范围与原行为一致；空列表不发起批量查询。
3. 现有工作台和项目权限回归测试通过，公开 API 响应不变。

## 测试与回退

- `mvn -Dnet.bytebuddy.experimental=true -pl :ccb-system -am test`
- 回退 ProjectService 批量装饰逻辑即可恢复原查询路径；无数据库补偿。
