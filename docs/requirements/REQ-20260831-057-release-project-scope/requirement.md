# 配置管理项目维度隔离

## 业务目标

配置管理的投产窗口、版本申请、投产基线、生产版本、统计分析和审批流程配置必须以顶部当前项目为唯一操作范围。用户不得通过修改请求参数、业务编号或记录 ID 读取或操作无权访问项目的数据。

## 本次实施

- 提供统一的项目访问能力，按项目编码解析未删除的 `pm_project` 并校验当前租户和有效项目成员关系；超级管理员保持现有豁免规则。项目生命周期状态与顶部项目列表保持一致，不额外排除已完成或已暂停项目。
- 六个配置管理菜单的列表请求必须携带顶部当前项目，后端拒绝缺少项目范围的查询。
- 详情、历史、冲突、附件、提交、撤回、取消、投产结果和审批流程配置等实体操作，从目标记录反查所属项目并执行服务端项目访问校验。
- 创建和修改时以服务端解析的项目为准，拒绝请求体伪造项目编码、名称或选择其他项目投产窗口。
- 打开版本申请详情或审批固定链接时，先读取申请所属项目；有权限则自动切换顶部项目，无权限则拒绝访问并显示明确提示。
- 切换顶部项目时关闭旧项目弹层并清空旧数据；异步请求返回前再次确认项目，避免旧响应覆盖新项目页面。

## 不实施

- 不引入 `X-Project-Ref` 全局请求头，不把前端当前项目作为服务端授权依据。
- 不把全部页面 URL 改造成 `/projects/{projectRef}/...`。
- 不改变菜单角色权限、审批流程规则、业务状态机和现有数据库结构。
- 不修改其他业务模块的项目隔离实现。

## 验收标准

1. 六个菜单切换顶部项目后只展示新项目数据，旧项目弹层关闭，慢响应不能回写到新项目页面。
2. 普通用户直接请求无有效成员关系项目的列表、详情或写接口时返回 403；超级管理员仍可访问租户内未删除项目。
3. 列表与统计接口缺少项目编码时返回 400，不能退化为租户全量查询。
4. 写请求中的项目字段、投产窗口和目标业务记录不一致时被服务端拒绝，且不产生数据修改。
5. 直接打开有权限的其他项目版本申请链接会自动切换顶部项目；无权限时显示无权访问且不加载详情、审批、附件和历史。
6. 后端项目访问和各域服务测试、前端构建、治理检查及桌面/H5 关键流程验证通过。

## 权限与数据

- 项目访问基于 `pm_project` 与 `pm_project_member`；成员必须 `status = 1` 且未删除。
- 项目菜单/操作权限继续由现有 `release:*` RBAC 权限控制，项目成员关系是额外的数据范围门禁。
- 不新增或修改数据库表，不执行数据迁移。

## 回退

按任务文件边界回退代码和契约变更即可；无数据库迁移和数据清理。回退时保留现有配置管理数据。
