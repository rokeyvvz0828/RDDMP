# 配置管理角色菜单权限

## 业务目标

管理员可以按角色分别授权配置管理六个菜单及其操作权限；用户只看到并访问获授权的菜单，未授权菜单不能通过直接输入地址或调用业务接口绕过。

## 必须行为

1. 配置管理作为父目录，包含投产窗口、版本申请、投产基线、生产版本、统计分析、审批流程配置六个真实子菜单。
2. 每个子菜单拥有独立查看权限；角色授权后，动态菜单、页面页签和直接路由访问保持一致。
3. 新增、修改、提交、撤回、取消、维护结果和维护审批流程等操作继续使用对应动作权限，并在前端隐藏无权限入口、后端拒绝越权请求。
4. 投产基线与生产版本拆分为 `release:baseline:*` 和 `release:production-version:view`，不再共享查看权限。
5. 角色权限保存继续自动保留子菜单及配置管理父目录；只配置某个子菜单动作时，该角色自动具备该子菜单查看能力。
6. 现有拥有配置管理权限的角色迁移后保留等价权限，历史业务数据不变。
7. 页面仅加载当前角色有权使用的数据，不因其他菜单无权而产生 403；版本申请、投产基线和统计分析所需投产窗口选项作为受限业务依赖可正常读取。

## 非目标

- 不新增数据范围、项目级授权或字段级授权。
- 不改变配置管理业务状态、审批规则和已有业务数据。
- 不改变系统角色管理入口的管理员权限。

## 验收标准

1. 角色仅授权一个查看权限时，只出现配置管理父目录和对应子菜单，直接访问其他五个地址会返回工作台。
2. 只读角色可查看授权菜单，但看不到或不能触发该菜单写操作。
3. 写权限角色可完成原有操作；后端权限注解与前端按钮权限一致。
4. 投产基线角色不会自动看到生产版本，生产版本角色也不会自动看到投产基线。
5. `SUPER_ADMIN`、`RELEASE_ADMIN` 迁移后仍具有六个菜单和原有操作权限。
6. Flyway、发布模块测试、前端构建、权限目录与真实浏览器角色验证通过。

## 回退

代码可按本需求文件范围回退；数据库迁移不做降版本，必要时通过后续补偿迁移恢复父菜单和旧权限映射。业务表与业务数据无需补偿。
