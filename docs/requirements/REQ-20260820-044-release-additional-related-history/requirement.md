# 追加申请相关历史申请参考

## 业务目标

审批人在追加申请详情中直接查看本申请所追加的历史申请及实时状态、申请背景和版本变化，避免离开当前工单或依据同窗口无关申请作出审批判断。

## 本次实施

- 仅在追加申请详情展示“相关历史申请”，关系来源固定为当前申请已持久化的 `ADDITIONAL` 关系。
- 按历史申请聚合展示申请单号、实时状态、版本类型、申请人/部门、申请及准出时间、需求编号、申请说明和直接相关版本变化。
- 版本变化使用当前有效交付单元和文件介质重算，过滤当前申请已移除的关系项。
- 历史申请按最近准出时间倒序，申请单号可以打开对应详情。
- 历史数据独立加载；失败或为空不阻断当前详情与审批操作。

## 本次不实施

- 不展示同窗口全部早期申请，不复用动态冲突列表。
- 不在参考区审批、撤销、编辑历史申请，也不重复加载历史附件。
- 不修改追加申请保存、提交、冲突处理、审批状态机或数据库结构。

## 验收标准

1. 普通申请不展示相关历史区块；追加申请始终展示加载、数据、空或失败状态之一。
2. 接口只返回当前租户、当前申请持久关系中的直接历史申请，不包含同窗口无关或后创建申请。
3. 多条关系聚合为一张历史申请记录，状态取当前值，变化只包含当前有效交付项。
4. 申请单号可站内跳转，排序稳定且不返回附件。
5. 接口要求 `release:application:view` 或管理员权限。
6. 历史接口失败时，当前申请详情和审批面板仍可使用，并可局部重试。
7. Release 模块测试、前端生产构建、范围检查和桌面/移动浏览器验收通过。

## 回退

移除新增只读端点、前端请求和详情区块即可；不涉及数据补偿或数据库回滚。
