# **批量作业管理**

## **1. 基本信息**

|              |                              |
| ------------ | ---------------------------- |
| **需求标题**     | 新增"批量作业管理"模块                 |
| **需求类型**     | 新增模块                         |
| **拟新增模块名称**  | 批量作业管理（Batch Job Management） |
| **提出人 / 部门** | 运维团队                         |
| **优先级**      | 高                            |

## **2. 背景与目标**

· 现在有什么问题、痛点或新增需求？生产环境大量批量作业分散在鲁班、百川等调度平台，无统一登记入口；跑批问题通过 ITSM 工单或口头沟通处理，缺乏闭环跟踪；慢作业无系统性标记和分析机制。

· 希望通过本次需求达到什么效果？统一登记批量作业（关联事业群、物理子系统、作业名、作业说明、跑批时间、频次、平台），记录执行时长（秒级）并标记慢作业；两类问题（跑批报错、跑批慢）统一登记，项目组分析原因并反馈处理方案（报错→根因+修复方案；慢→慢因分析+优化方案+计划），形成闭环跟踪。

## **3. 主要使用方式**

· 使用人：运维人员（登记作业、执行记录、标记慢、登记问题）；项目组（反馈处理方案：报错→根因分析+修复方案，慢→慢因分析+优化方案+计划）；平台运维（系统管理员）；合规/审计团队（审计员）。

· 主要操作：运维人员登记批量作业（填写作业名、所属事业群、物理子系统名称、物理子系统编号（自动读取）、作业说明、跑批时间、频次、平台（鲁班/百川））；登记执行记录（执行日期、开始/结束时间、时长秒数、状态）；标记慢作业；登记跑批问题（关联作业、问题描述、发生时间、严重程度）；项目组针对问题提交处理反馈：报错类提交根因分析+修复方案+预防措施，慢类提交慢因分析+优化方案+目标时长+计划起止日期并可更新进度。

· 新模块位置与关联：放在"生产运维管理"菜单下方；关联事业群、物理子系统基础数据、鲁班/百川调度平台。

## **4. 功能要求**

1. 支持批量作业登记：填写作业名、所属事业群、物理子系统名称、物理子系统编号（从已有基础数据自动读取）、作业说明、跑批时间、跑批频次、跑批平台（鲁班/百川）、备注。

2. 支持登记执行记录：记录每次跑批的执行日期、开始时间、结束时间、执行时长（秒级）、执行状态（成功/失败/超时/慢）和错误信息。

3. 支持慢作业标记：时长超过阈值自动标记为"慢"，运维人员也可手动标记；标记后可登记为慢类问题。

4. 支持问题登记与处理反馈：运维人员登记两类问题——报错（关联作业、错误描述、发生时间、严重程度）和慢（关联作业、慢现象描述、当前耗时、慢阈值、严重程度）；项目组提交处理反馈，报错类含根因分析+修复方案+预防措施，慢类含慢因分析+优化方案+目标时长+计划起止日期，可多次补充；慢类支持更新优化进度；运维确认解决后关闭，可重开。

5. 支持按问题类型（报错/慢）分别统计问题量、解决率、平均解决时长和慢优化完成率。

6. 支持统计报表：按事业群、子系统、平台、时间维度统计作业量、问题量（报错/慢分类）、解决率和慢优化完成率，支持导出 Excel。

7. 支持批量导入导出和搜索筛选：按事业群、子系统、平台、频次、状态、是否慢筛选作业列表，支持 Excel 批量导入。

8. 支持站内消息通知：新问题提交后通知对应项目组，处理反馈提交后通知运维人员。

## **5. 流程说明**

· 作业登记流程：运维人员登记批量作业→保存为"正常"状态→（如需）标记为"停用"。

· 问题处理流程（报错/慢统一）：运维登记问题（选报错或慢）→待处理→项目组提交处理反馈→处理中→运维确认解决→已解决→已关闭；已关闭问题可重开。共 5 个状态节点，两类问题共用同一状态机。

· 慢类问题在处理中阶段支持更新优化进度（百分比）和计划状态（已出方案/执行中/已完成/已取消）。

· 留痕：记录每条作业、问题、处理反馈的完整操作链（操作人、动作、时间）；全量操作日志保留 1 年，审计员可只读查看并导出报表。

## **6. 结果与验收**

9. 运维人员可以登记批量作业，填写作业名、事业群、物理子系统名称、物理子系统编号（自动读取）、作业说明、跑批时间、频次、平台（鲁班/百川）。

10. 运维人员可以登记执行记录，记录执行日期、开始/结束时间、执行时长（秒级）和状态，时长超过阈值自动标记为"慢"。

11. 运维人员可以登记两类问题（报错/慢），项目组可以提交对应处理反馈（报错→根因+修复；慢→慢因分析+优化方案+计划），运维确认后关闭，可重开。

12. 支持按问题类型（报错/慢）分别统计问题量、解决率、平均解决时长和慢优化完成率，并可导出 Excel。

13. 支持按事业群、子系统、平台、时间维度统计作业量、问题量、慢作业数和慢优化完成率，并可导出 Excel。

14. 审计员可只读查看全部作业、问题、处理反馈记录及操作日志。

## **7. 补充说明（可选）**

· 参考材料：现有 ITSM 工单流程、鲁班/百川调度平台作业配置文档、事业群和物理子系统基础数据。

· 权限要求：4 个角色（运维人员、项目组、系统管理员、审计员），按 RBAC 模型控制功能权限和数据权限。项目组按物理子系统做数据权限隔离。

· 风险与限制：执行记录由运维人员手动登记，无平台 API 对接；批量导入需控制单次最大行数。
