## 二、公共基础能力与主数据（去重合并）

以下能力在多个需求中重复出现，合并统一定义。各需求章节引用本节，不重复描述。

### 2.1 角色与权限模型

平台统一采用 **RBAC（角色 + 数据范围）** 控制功能权限与数据权限；前端权限不能替代后端校验；受保护写操作需服务端认证、数据范围与实体授权，并保留审计。

各需求涉及角色汇总（按角色做数据权限隔离，项目组类角色通常按物理子系统/事业群隔离）：

| 需求 | 角色 |
|------|------|
| 架构资产（D1） | 应用架构师、数据架构师、技术架构师、安全架构师（初始人员：耿俊辉/洪鹿平/李彪/张恒）、开发人员、业务人员（不可见技术文档） |
| 部署单元资源（D3） | 项目组申请人、项目组负责人、管理员、架构审核人、资源管理员、运维负责人、审计/查询人员 |
| 网络权限（D4） | 申请人（业务开发/运维）、网络工程师（实施）、网络管理员（团队负责人）、系统管理员、审计员 |
| 测试环境搭建（D6） | 测试经理、环境搭建负责人、基础设施运维人员、网络管理员、应用部署负责人、项目经理、管理员 |
| 环境变更（D7） | 变更申请人（测试经理/测试人员/业务方）、变更审核人（测试负责人/运维主管/DBA主管）、变更执行人（运维工程师/DBA）、变更验证人、变更管理员、项目经理 |
| 批量作业（D8） | 运维人员、项目组、系统管理员、审计员 |
| 加密机（D9） | 申请人（项目组/系统经理）、办理人（开发部门/安全资源管理人员，具体待确认）、系统管理员、只读查询角色（可选） |
| 架构决策（D11） | 提报人（项目组/事业群）、实施管理板块审核人员、架构管理板块、参会项目相关负责人、系统管理员 |
| 投产流程（D10） | 农信业务、金科业务、金科开发、农信开发、金科测试、农信测试、金科运维、农信运维、管理员、超级管理员 |

通用权限模式：

- 普通用户只能查看/维护**本人或授权范围**（本部门、本事业群、本物理子系统）内的数据；管理员可查看全量。
- 审计员/只读查询角色：只读查看全部记录并导出报表，不可修改。
- 支持字段级权限（如实施字段与业务申请字段分离：资源管理员可回填实施结果，不得修改业务申请字段）。
- 生产环境相关操作需额外授权与二次确认（D7、D3）。

### 2.2 组织、事业群与机构

- "所属事业群"为各需求通用基础字段，来源于平台组织架构（组织树）。
- 实施机构配置初始值（D10，平台系统设置提供）：北京事业群、上海事业群、广州事业群、成都事业群、厦门事业群、武汉事业群、深圳事业群、大数据中心、交付事业部、基础技术中心、云南农信。
- 业务板块初始值（D10）：对公金融板块、对私金融板块、信贷管理板块、渠道运营板块、计划财务板块、风险管理板块、技术系统。
- 人员字段：优先从用户目录选择，保留人员标识、姓名、所属部门（如 D9 系统经理）。

### 2.3 物理子系统主数据（关键依赖根）

物理子系统是多个需求的数据依赖根（D3/D4/D8/D9 均引用"自动读取、无需手填"）。基础属性：

- 物理子系统编号（规则见 §2.9）、中文名、英文名、系统功能描述、所属应用（预留）、所属事业群
- 安全节点号、文件传输节点号（如有）
- 业务连续性等级（灾备等级）、灾备模式、部署平台、默认网络分区、归属项目组、系统负责人、最终确认人、联系方式

管理规则：

- 同一环境下物理子系统编号唯一（D3）；系统编号/名称提交时判重（D2）。
- 物理子系统下线前必须确认其下所有部署单元均已下线或迁移（D3）。
- 变更流程（D1）：项目提交变更申请（新增/修改/删除）→ 应用架构师审核 → 结果反馈。
- 信息录入方式之一为智能补全（D2，见 §3.2）。

### 2.4 环境清单

环境类型：生产（PROD）、SIT、UAT、性能测试、预生产（PRE-PROD）、灾备演练、数据线、账务线、联机线、批量线等；环境标识如 PROD/SIT/UAT/DATA/ACCT。

环境属性：部署平台、网络分区、灾备模式、业务连续性等级、资源池、可用区/机房；环境状态：规划中、建设中、运行中、冻结、下线、归档。

环境负责人：项目负责人、应用负责人、资源负责人、运维负责人（D3）；环境清单由管理员维护（D7）。

环境使用情况（D5，详见 §6.1）：按系统维度统计计算/存储已用资源、数据库已分配实例/资源/链接/用户名。

### 2.5 附件与文件管理

统一复用平台受控文件能力（MinIO + kkFileView 在线预览），共性要求：

- 支持上传与在线预览；**支持填写 SVN/云盘路径**作为附件的补充形式（D10、D7）。
- 访问控制：技术类文档仅技术人员可见，业务/其他人员不可见，**不支持下载**（D1 部署单元公告、网络规划方案）；审计/验收类附件永久归档可预览下载（D11、D9）。
- 附件大小、格式做上传限制，禁止违规文件；不得上传明文密钥、口令等敏感凭据（D9）；SSL 证书等敏感信息需加密存储（D4）。
- 附件与业务单据（决策单号/申请单号/变更单号）永久绑定，支持随时预览、下载（D11）。

### 2.6 消息通知

统一站内消息通知（平台 notification 能力），可扩展邮件/企业微信（多数需求标注"渠道待确认"）。共性通知场景：

- 提交、要求补充、退回、完成、撤回/驳回等状态流转通知相关角色（D9、D7、D8、D11）。
- 审批/实施待办通知、SLA 超时提醒、超时升级（D3、D7）。
- 通知内容至少包含业务单号、对象名称、动作、当前状态和待办入口（D9）。
- 关键节点自动推送站内通知 + 邮件（D11：单据提交、初审通过、会议发布、决策结果发布）。

### 2.7 审计留痕

- 记录业务对象全生命周期操作链：操作人、动作、时间、意见、状态变化；字段级变更前后值对比（D3、D7）。
- 全量操作日志保留 1 年，审计员可只读查看并导出报表（D4、D8）。
- 历史记录仅允许查看，不允许普通用户删除或覆盖；不可删除，仅管理员可标记作废（需填写原因）（D9、D7）。
- 敏感生产环境数据访问需审计（D3、D7）。

### 2.8 导入导出与通用数据网格

统一列表/台账底层组件能力（D10 定义，全平台适用）：

- **全局检索**：跨机构、跨系统名称多条件全文本模糊检索，输入即搜。
- **标准导入**：Excel/CSV 标准模板 + Schema 解析校验器；支持批量数据清洗；提供"覆盖更新、重复跳过、事务回滚报错"三种冲突控制机制；导入失败定位到行、列、错误原因（D3）。
- **导出**：标准 .xlsx；支持全量导出、勾选导出、当前筛选视图导出三种范围；导出内容与页面筛选结果一致（D3/D4/D6/D7/D8/D9 同要求）。
- **筛选**：按底层数据类型动态匹配过滤器（日期/字符/字典多选），支持组合条件存为常用过滤器。
- **排序**：列头点击排序，支持多字段联合加权排序。
- **列宽**：拖拽调整列宽。

批量导入限制：控制单次最大行数（D8）；支持至少 1 万行数据预校验（D3）；CSV 支持 GB18030 / UTF-8 编码（D3）。

### 3.2 物理子系统信息智能补全（D2）

**背景**：新系统流程存在痛点——系统编号、领域系统简称及中文简称等核心属性依赖架构师线下经验手工分配，效率低、易冲突；申请与审批依赖 Excel 线下传递，协同效率低。

**目标**：申请人在系统申请时输入少量系统功能描述，系统智能生成完整架构信息，申请人调整确认后提交。

**使用人**：系统负责人、架构师。

**功能要求**

1. 核心：架构属性智能生成——录入/选择"物理子系统名称/功能描述"后，系统根据登录用户提取联系人、事业群，基于后台配置的规则智能匹配生成：物理子系统编号、逻辑子系统编号、物理子系统名称、逻辑子系统名称、系统简称、承接组件、业务领域、系统负责人、安全节点编号、文件传输节点编号、系统运行时间、开发平台框架（P2/P8/P10）。
2. 防重校验：提交时与库中已有系统编号、名称判重，提示重复，防止提交重复系统。
3. 架构师干预：受理申请时页面展示推导出的预设结果，架构师可一键确认，也可人工干预修改后提交落库。

**流程**：系统负责人提交申请（状态：待架构师受理）→ 架构师核对/修改 → 发布系统。

**验收**：① 系统负责人可查看通过后的系统信息、安全节点编号；② 架构师可受理新增并完成发布。

> 待确认：智能推导的实现机制（规则引擎 vs AI 模型）及规则维护人（§10-5）。

### 3.3 架构决策全流程管理（D11）

**背景痛点**：架构决策事项线下流转（邮件传《架构决策单》），单据易丢失、进度不可视；无标准化附件与模板下载；会议无线上排期通知（收单后 7 日内组织会议靠人工提醒易超时）；决策意见、风险评估、实施计划无线上载体；决策结果靠人工邮件推送。

**目标**：决策申请、附件上传、模板下载、流转审核、会议排期、决策记录、结果发布线上闭环；强制留存问题分析、备选方案、佐证材料；自动管控 7 个自然日会议时效；决策意见与原单据绑定归档；一键发布结果并支持历史追溯。

**菜单**：一级菜单「架构管理」→ 子菜单「架构决策申请」「决策会议管理」「历史决策台账」。关联：项目人员权限、系统消息通知、附件存储、邮件推送接口；单据/会议/决策结果/附件绑定同一决策单号，可互相跳转。

**功能要求**

1. 《架构决策单》模板在线下载（含背景、现状、需求、争议点、多方案分析、建议栏位）。
2. 在线填报，必填项强制校验：决策事项、问题分析、可选方案、建议内容。
3. 多附件上传（分析材料、流程图、对比文档等佐证资料）。
4. 单据线上流转：提报人提交 → 实施管理板块初审 → 架构管理板块接收，各节点可填写审核意见。
5. 会议创建：录入会议时间、参会人员、议题并发布通知。
6. 时效管控：架构管理板块接收单据起算 7 个自然日，超时未创建会议标红预警。
7. 决策意见编辑：决策建议、理由、风险评估、落地实施计划、下一步行动项。
8. 线上确认：提报方、相关方可线上查看意见并留痕确认。
9. 一键发布决策结果：自动推送通知至全部关联人员，同步邮件外发。
10. 多维筛选：决策单号、项目、提报部门、单据状态、会议时间、决策结果。
11. 全部单据、会议、决策记录支持导出归档。

**流程与状态**

提报人新建决策单（上传附件）→ 提交实施管理板块初审（待初审）→ 初审通过流转架构管理板块（待排会）/ 驳回退回（已驳回）→ 创建并发布会议（会议已安排）→ 会后录入决策意见、相关方线上确认（待发布结果）→ 提交实施管理板块发布结果（决策已办结）。

**审批**：初审为实施管理审核人员，不通过退回修改；决策意见确认为提报方查看确认（无强制审批，留确认记录）；结果发布无需额外审批。

**留痕**：全程操作人/时间/审核意见/修改记录；附件永久关联决策单号；关键节点自动站内通知 + 邮件；会议信息、决策意见、风险评估、行动项全部归档，不可删除。

**验收**

1. 可在线下载模板、完整填报并上传多附件，必填项缺失无法提交。
2. 实施管理板块可线上完成初审流转，状态实时更新，流转轨迹完整可查。
3. 架构管理板块可创建并发布会议，7 日超时自动标红预警。
4. 可录入完整决策意见并与原决策单绑定保存。
5. 可一键发布决策结果，自动通知所有相关人员并同步邮件。
6. 全部历史单据、会议记录、决策结果可按条件筛选、导出；权限隔离（仅本部门/本项目人员可见自身单据，管理员全量）。
7. 所有操作、审核、确认、发布动作均留存操作日志。

> 待确认：邮件外发通道；附件格式/大小限制具体值（§10-6）。

## 四、部署单元与资源管理域（D3，单租户口径）

> **单租户口径调整说明**（依据平台锚定单租户的决策）：
> - "租户（客户）"由**一级隔离边界**降级为**可选业务属性**（租户编号/名称/客户简称/客户全称，用于查询分组与统计维度）。
> - 取消"按租户配置流程模板、审批策略、实施团队"；取消"跨租户复制需权限审核"（如需复制，按普通功能简化）；取消租户级数据隔离。
> - 保留：环境 → 物理子系统 → 部署单元 → 资源清单管理、架构基线、申请审核流程、校验规则、报表看板。客户维度数据上可区分（建议保留字段，为后续升级留余地）。

### 4.1 背景与目标

为支撑生产/测试环境部署单元和资源清单管理，建设在线管理能力，维护不同环境、不同部署线路下的物理子系统、部署单元、资源规格、关联关系、审核流程和实施记录。参考坤元 CMDB、孔明 CMDB 及项目实践痛点。版本记录：2026-08-10 初稿大纲（李彪），2026-08-11 细化。

建设目标：

- 支持按环境隔离管理生产、测试及各类专线环境的部署单元清单。
- 一个物理子系统下维护多个部署单元，按类型和部署形态分别管理。
- 数据库、MQ、共享存储等基础资源/软件作为特殊部署单元纳入统一管理。
- 支持项目组发起新增、变更、扩容、下线等申请，经管理员、架构审核、资源管理员实施。
- 管理流程按环境、部署单元类型、资源类型定制。
- 支持从现有 CSV/Excel 清单导入基础数据，提供版本、差异和审计追踪。

### 4.2 术语与对象关系

- **环境**：租户（客户）下部署资源的二级边界（单租户口径下即部署资源的一级组织维度）。环境类型：生产、SIT、UAT、性能测试、预生产、灾备演练、数据线、账务线等；环境状态：规划中、建设中、运行中、冻结、下线、归档；属性：部署平台、网络分区、灾备模式、业务连续性等级、资源池、可用区/机房；负责人：项目/应用/资源/运维负责人。不同环境各自维护部署单元和资源清单，不得默认共用生产资源。
- **物理子系统**：部署单元的归属实体，一个物理子系统可含多个部署单元。字段见 §2.3。管理规则：同一环境下编号唯一；同一物理子系统在不同环境下可有不同部署单元清单和资源规格；下线前必须确认部署单元已下线/迁移。
- **部署单元**：资源申请、部署、审核、实施和运维管理的最小业务管理对象。字段：名称、简述、类型（WB/AP/DB；MQ、批处理、文件服务、任务执行器、网关、监控代理等统一用 AP 类型）、关联部署单元名称（AP↔DB、AP↔WB 等依赖）、部署形态（容器/虚拟机/物理机）、部署节点数、网络分区、操作系统、JDK、中间件、数据库选型/版本、备注、最终确认人、联系方式。规则：同一环境同一物理子系统下名称唯一；可关联一个或多个部署单元（一对一/一对多/多对多）；不同环境可用不同资源规格/版本。
- **资源清单**：每个部署单元在指定环境下实际申请、审核、实施和运行的资源规格。维度：计算（CPU、内存、节点数）、汇总（总 CPU/总内存 = 单节点 × 节点数 + 总边车）、存储（系统盘、本地磁盘 CBS、共享文件存储 CFS、数据库存储）、边车（SA/NFT/FServer/jobexecutor/appMon，含总边车 CPU/内存、边车内存占比）、平台（部署平台、服务器类型、网络分区、操作系统）、软件（JDK、中间件、数据库选型/版本）。

### 4.3 架构基线（设计态）

- 定位：设计态主数据，不直接代表具体环境运行实例；环境部署单元可关联架构基线版本；同一基线可被多环境引用，环境可在基线基础上差异化配置；环境部署单元保留"基线来源/基线版本"。
- 管理对象：物理子系统基线、部署单元基线、关联关系基线、标准资源基线、边车基线、基线版本和发布记录。
- 基线与环境关联：环境绑定基线版本；环境资源变更记录与基线差异项；基线升级提示受影响环境并支持差异同步建议；环境脱离基线记录原因和审批。
- 基线驱动建环境：基于基线一键新建环境；基于既有环境复制新建；按物理子系统/部署单元范围选择；选择是否复制关联关系、特殊部署单元、边车配置、版本信息；按目标环境模板自动调整资源规格。
- 批量编辑与离线导入：在线批量编辑（按子系统/部署单元调整资源、边车、中间件版本）；导出离线表格编辑后批量导入；导入校验基线引用、环境归属、字段格式、资源计算关系；失败明确到行列。
- 基线审批：项目组提出创建/变更申请 → 管理员审核主数据和范围 → 架构审核人审核设计合理性/标准资源/关联关系/复用方式 → 资源管理员确认可实施性 → 发布基线版本后方可作为环境新建模板。
- 关键规则：基线与环境数据分离存储；基线变更不自动覆盖已存在环境（通过版本升级/差异同步）；环境创建必须明确来源"基线/既有环境"；复制环境保留唯一标识和版本链路；特殊部署单元与普通部署单元统一建模但保留专有属性。

### 4.4 功能需求

**环境管理**：新增、编辑、冻结、下线、归档环境；支持生产/SIT/UAT/数据线/账务线等类型；每环境独立部署单元和资源清单；支持从其他环境复制清单作初始化模板（如生产复制到 UAT 后按测试规格缩容）；环境间差异对比（部署单元数量、资源规格、版本、数据库/MQ 依赖、网络分区）；冻结状态下只允许查询和发起解冻申请。

**物理子系统管理**：新增、编辑、停用、下线；维护编号/简称/名称/事业群/连续性等级/灾备模式/部署平台；查询其下所有部署单元及资源汇总；查看与其他物理子系统的部署单元关联关系；按子系统维度导入导出部署单元清单；下线时自动校验是否存在有效部署单元、有效资源、未完成流程。

**部署单元管理**（全生命周期）：新增、修改基本信息、调整类型/部署形态/节点数/资源规格、维护关联、标记状态（草稿/待审核/待实施/已实施/运行中/变更中/冻结/下线/归档）；复制（同环境内复制、跨环境复制）；批量导入、批量编辑、批量提交审核；查看历史版本和变更记录。

编辑规则：

- 已实施/运行中的部署单元不允许直接修改生效数据，需通过变更申请产生新版本。
- 待审核状态仅申请人可撤回，撤回后回草稿。
- 审核通过未实施前，资源管理员可补充实施信息，但不得修改业务申请字段；如需修改应退回申请人。
- 已下线部署单元不可被新增关联引用。

**特殊部署单元**：

- 数据库：选型（GoldenDB、MySQL 等）、版本、存储容量、部署形态（独占/共享集群、容器化、物理机）、灾备模式（主备/双活/冷备）、关联应用、访问权限说明、客户端/驱动要求。规则：允许多个 AP 关联同一 DB；共用集群标识共用关系/容量/归属；存储扩容单独走资源变更和架构审核；版本变更评估影响范围。
- MQ/中间件：类型（如 IBM MQ）、版本、节点数、主备模式、授权方式、关联应用、网络分区和访问策略。
- 边车：SA/NFT/FServer/jobexecutor/appMon；边车配置与部署单元资源一并申请一并审核；自动汇总总边车 CPU/内存并计算占比；不同环境可配置不同默认边车策略。

**资源清单管理**：单条/批量维护；必填校验；单位统一（G、核、节点数）；资源合计自动计算；规格变更前后对比；按租户(客户)/环境/平台/网络分区/物理子系统/部署单元类型/服务器类型统计；缺失项检查（DB 缺选型、虚拟机缺系统盘、容器缺 CPU/内存/节点数）；异常检查（节点数 0 仍有关联应用、总 CPU 与单节点 × 节点数不一致、存储为空但类型为 DB）。

**关联关系管理**：AP 关联 DB、AP/WB 关联 MQ、WB 关联 AP、批处理关联 DB/MQ/文件服务；手工维护 + 从"关联部署单元名称"批量解析导入；图形化展示子系统下部署单元拓扑；按部署单元查看上游依赖和下游影响范围；下线/迁移/扩容/版本变更提示关联影响；关联对象不存在时提示补录或标记外部依赖。

**查询统计**：按客户/环境/物理子系统/部署单元类型/服务器类型/网络分区/数据库选型/版本/JDK/中间件/操作系统/最终确认人/项目组/资源管理员多维查询。指标：部署单元数量、物理子系统数量、CPU/内存总量、节点总数、CBS/CFS/数据库存储总量、边车 CPU/内存总量、数据库/MQ 特殊部署单元数量。

**版本管理**：每次审核通过并实施完成后生成正式版本；审核中修改作为草稿/待生效版本；查看任意历史版本；版本差异对比；按时间点查看某环境完整资源快照；回滚申请（回滚也必须经过审批）。

### 4.5 申请与审核流程

**申请类型**：新增环境、新增物理子系统、新增部署单元、资源变更、扩容/缩容、数据库/MQ 等特殊部署单元新增或变更、关联关系变更、软件版本变更（JDK/中间件/数据库）、网络分区变更、部署单元迁移、部署单元下线、资源清单批量导入。

**标准流程**：

1. 项目组申请人创建申请，选择环境、物理子系统、部署单元或资源对象。
2. 填写或导入部署单元及资源清单。
3. 系统自动校验（字段完整性、资源计算、命名唯一性、关联关系、必填项、资源异常）。
4. 项目组负责人确认业务必要性和申请范围。
5. 管理员审核基础信息、归属、字段规范、流程模板和数据完整性。
6. 架构审核人审核部署形态、资源规格、灾备模式、网络分区、数据库/MQ 依赖和架构影响。
7. 资源管理员实施资源分配、部署开通、数据库/MQ/存储准备、权限开通。
8. 资源管理员回填实施结果（实际资源规格、实施时间、资源标识、备注）。
9. 运维负责人确认监控、备份、告警、灾备和运行接入。
10. 申请单完成，生成正式版本并更新部署单元及资源清单。

**审批动作**：同意、驳回、退回补充、转办、加签、会签、撤回、作废、暂停、恢复。驳回/退回/作废必须填写原因；架构审核涉及资源压缩或调整记录调整前后规格；实施完成必须回填实施结果。

**流程定制**：按环境配置流程模板（生产强制架构审核和运维确认，SIT/UAT 可简化）；按申请类型配置（数据库扩容由数据库资源管理员实施）；按部署单元类型配置审批人（DB/MQ/网络分区变更必须架构审核）；按资源阈值配置审批规则（CPU/内存/存储超阈值增加容量负责人审批）；支持条件分支、会签、加签、抄送、自动跳过；支持审批 SLA、超时提醒、超时升级；支持流程版本管理，历史申请按发起时流程版本执行。

**流程状态**：申请单——草稿、待项目组确认、待管理员审核、待架构审核、待资源实施、待运维确认、已完成、已驳回、已撤回、已作废。部署单元——草稿、审核中、待实施、已实施、运行中、变更中、冻结、下线、归档。

### 4.6 数据模型（主要实体）

租户(客户)、环境、物理子系统、部署单元、部署单元资源清单、部署单元关联关系、特殊资源配置（数据库/MQ/存储/边车）、申请单、审批记录、实施记录、版本记录、流程模板、用户/角色/组织/权限。

部署单元主数据字段：客户编号/名称、环境编号/名称/类型、物理子系统编号/简称/名称、业务连续性等级、灾备模式、所属事业群、部署平台、部署单元名称/简述/类型、关联部署单元名称、网络分区、服务器类型、操作系统、数据库选型/版本、JDK、中间件、备注、最终确认人、联系方式、状态、版本号、生效时间、失效时间。

资源清单字段：系统盘容量(G)、CBS(G)、CFS(G)、数据库存储容量(G)、CPU、内存、部署节点数、总 CPU（总配额+总边车）、总内存（总配额+总边车）、总边车 CPU（已乘节点数）、总边车内存（已乘节点数）、边车内存占比、是否需要 SA/NFT/FServer/jobexecutor/appMon 边车、资源管理员、实施状态、实施时间、实施备注。

### 4.7 校验规则

- 基础：名称不能为空；同环境下部署单元名称不重复；类型必填；服务器类型/网络分区从配置项选择；生产环境必须填写业务连续性等级和灾备模式；最终确认人和联系方式至少填一项。
- 类型：DB 必填选型和版本（申请存储则填容量）；AP 填 CPU/内存/节点数/JDK/中间件/操作系统；容器填 CPU/内存/节点数并校验边车；虚拟机填系统盘/CPU/内存/节点数/操作系统；物理机填 CPU/内存/节点数或配置说明；MQ 填中间件类型/版本/节点数/主备模式/关联应用。
- 资源计算：总 CPU = 单节点 CPU × 节点数 + 总边车 CPU；总内存同理；边车内存占比 = 总边车内存 ÷ 总内存；节点数为 0 必须说明是否为共用/逻辑资源或仅登记存储；存储/CPU/内存/节点数非负。
- 关联：关联对象不存在提示补录或标记外部依赖；下线部署单元不得作为新关联对象；DB/MQ 被多单元关联展示共用关系和影响范围；删除/下线特殊部署单元前必须解除或迁移所有有效关联。

### 4.8 数据导入导出

导入：GB18030/UTF-8 CSV、Excel；字段映射配置（兼容表头换行字段如"总CPU(总配额+总边车)"）；导入前预检查（新增/更新/冲突/缺失/格式错误）；导入到指定环境；按物理子系统或部署单元增量导入；导入后生成版本记录和导入报告。

导出：按客户/环境/物理子系统/部署单元类型导出；支持当前版本、历史版本、审核中版本、实施后版本；导出字段覆盖原始表格字段并补充客户、环境、流程状态、版本号、申请单号、实施状态等管理字段。

### 4.9 权限需求

按角色和数据范围控制（§2.1）：项目组申请人仅维护本组范围草稿/被退回申请；管理员可审核并维护字典；架构审核人审核架构字段和资源合理性；资源管理员回填实施结果；运维负责人确认运行接入；审计人员只读。支持按环境、项目组、物理子系统授权；字段级权限；流程节点权限；敏感生产环境数据访问审计。

### 4.10 非功能需求

- 易用性：表格化编辑、复制行、批量修改/校验/提交；字段筛选、排序、冻结列、列显隐；从历史环境/版本快速复制；导入错误定位到行列；常用查询响应 ≤ 3 秒；批量导入 ≥ 1 万行预校验；资源统计异步汇总和缓存。
- 安全性：登录认证和统一身份集成；角色/数据/字段权限；敏感操作二次确认；生产环境变更审计。
- 可配置性：部署单元类型、服务器类型、网络分区、环境类型、边车类型、审批流程、资源校验规则、资源阈值和审批策略均可配置。

### 4.11 验收标准

① 可按环境维护独立部署单元和资源清单；② 可表达"一个物理子系统包含多个部署单元"；③ 数据库/MQ/共享存储可作为特殊部署单元纳入统一管理；④ 可维护类型/形态/资源规格/边车/数据库/中间件/操作系统信息；⑤ 提供导入模板可导入现有信息表；⑥ 可完成新增、变更、扩容、下线等申请流程；⑦ 可支持项目组申请、管理员审核、架构审核、资源管理员实施、运维确认；⑧ 可按环境、申请类型、部署单元类型、资源阈值定制流程；⑨ 可查看历史版本、审批记录、实施记录和字段级变更记录；⑩ 可按环境/物理子系统/部署单元类型/服务器类型输出资源统计报表；⑪ 可维护架构基线（设计态）；⑫ 环境部署单元可绑定基线版本；⑬ 可基于基线或既有环境一键新建环境；⑭ 可按子系统/部署单元批量选择新建范围；⑮ 可对新建环境资源批量编辑；⑯ 可导出离线表格并批量导入回系统；⑰ 可追踪基线、环境、版本和差异关系。

> 待确认：客户字段是否保留（建议保留）；流程定制的平台能力边界（Flowable 动态流程版本）；字段映射与现有表格的最终口径（§10-2）。

## 五、网络管理域（D4）

### 5.1 网络规划方案文档管理

发布整体网络规划（主要核心网络，不写骨干网和广域网），以 PDF 承载：

- 网络规划：整体网络规划。
- 分区划分：互联 DMZ 区、核心开发区（容器应用和虚机应用）、P5 外联区、办公区。
- 域名命名规则：分段规则及各段含义（如 sys/com/net 结尾）。
- 各区 IP 段与掩码。

功能：① 文档上传——上传者角色控制为**网络架构师**，格式 PDF；② 文档阅读展示——所有技术人员可读，业务人员和其他人员不可见，**不支持下载**。

### 5.2 网络访问关系基线

以"网络访问关系"为颗粒度维护基线：源物理子系统、源系统部署单元（源地址）、目的物理子系统、目的系统部署单元（目的地址、目的端口）、协议、NAT 映射地址、映射端口、用途。数据落地存储不冗余，保证一致性。

### 5.3 网络权限管理（申请→实施→反馈闭环）

**背景痛点**：网络权限申请（内网打通、内外网互通、外网域名、CLB 负载均衡）通过 ITSM 工单分散提交，无统一流程，实施记录不完整，无法追溯审计，到期后无人回收。

**目标**：建设统一网络权限管理平台，实现"申请→实施→反馈"全生命周期闭环，标准化流程、全链路可追溯、支持合规审计，到期自动回收。

**菜单**：「系统管理」下新增「网络权限管理」子菜单。

**功能要求**

1. 四种申请类型（内网打通、内外网互通、外网域名、CLB），每种展示不同动态表单（内网打通：源/目标 VPC、网段、端口、协议；CLB：监听端口、后端服务、负载策略等）。所有申请单含基础数据字段：所属事业群、物理子系统名称、物理子系统编号（自动读取）。
2. 支持草稿保存、提交、撤回、退回后修改重提、复制历史申请；支持上传架构图等附件。
3. 提交后自动生成实施工单，按申请类型和所属事业群自动分配对应网络工程师，支持手动转派和接单。
4. 工程师接单后执行配置变更，记录变更前配置、变更操作、变更后配置和回滚方案。
5. 申请人验证连通性后关闭工单；验证不通过退回实施重新处理；关闭时记录满意度评价。
6. 有效期管理：到期前 7 天自动提醒；到期后自动生成回收工单走实施流程回收权限；支持续期申请。
7. 实施超时催办（默认 24h 超时，3 次催办无响应自动转办上级）；站内消息通知。
8. 统计：按类型、部门、时间维度统计申请量和实施工单；网络权限全景图展示当前生效的所有网络策略；可导出 Excel/PDF。

**流程**：申请提交 → 待实施 → 实施中 → 待验证 → 已关闭；退回后可修改重提，验证不通过退回实施，到期后自动生成回收工单。共 7 个状态节点。

**留痕**：每条申请完整操作链（操作人/动作/时间）、实施变更记录（变更前/后配置、操作命令、回滚方案）、验证结果和满意度评价；全量操作日志保留 1 年，审计员可只读查看并导出报表。

**验收**

① 申请人可按四种类型提交，系统按类型展示对应动态表单并校验必填项；② 申请单自动读取事业群/物理子系统等基础数据；③ 提交后自动生成实施工单，工程师可接单、记录变更、标记完成；④ 申请人可验证连通性，通过则关闭归档，不通过退回实施并附问题描述；⑤ 到期前 7 天自动提醒申请人和实施工程师，到期后自动生成回收工单；⑥ 审计员可只读查看全部申请和实施记录，可按时间范围导出审计报表；⑦ 普通用户只能查看维护本人申请，管理员可查看全部。

> 待确认：到期"自动回收"边界（自动生成回收工单 vs 仅提醒）；SSL 证书等敏感信息加密存储方案；角色清单（申请人/网络工程师/网络管理员/系统管理员/审计员）中"提出人/部门待确认"（§10-3）。
>
> 附（D1 预留项，后续需求）：微隔离特殊处理（盛赛荣）、CLB 管理（李彪）、DNS 域名管理（李彪）、SSL 证书管理（张恒）、外联证书管理（张恒）。

## 六、环境管理域

### 6.1 环境整体规划与使用情况（D5）

**环境整体规划**

- 环境基础信息：架构资产按多套系统的实例化信息；多套环境的名称、环境用途（SIT、UAT、非功能、数据线、账务线、某某专题环境）、每套环境使用方信息。
- 计算和存储：物理机型号、规格、台数、存储；汇总后的资源总数（CPU、MEM、存储）。
- 数据库：物理机、存储，以及上层搭建的集群信息。

**环境使用情况**

- 计算和存储：按系统维度已使用的资源总数和详细清单。
- 数据库：按系统维度已分配的实例、资源、数据库链接、用户名。

### 6.2 测试环境搭建跟踪（D6）

**背景痛点**：测试环境搭建涉及底座搭建、基础技术组件部署、网络访问关系开通、应用部署等多环节，环节间存在复杂依赖（加密组件部署依赖加密机就绪，应用部署依赖网络策略开通和基础组件部署完成）。当前线下文档 + 会议跟踪，存在：进度分散无法一站式查看；依赖缺乏结构化表达，前置未完成后续盲目启动；阻塞/延期/变更缺乏系统记录追溯；多轮搭建缺模板复用和历史对比；例会依赖人工汇报时效差。

**目标**：在平台内建立搭建全流程结构化跟踪机制，实现创建、依赖管理、进度更新到验收关闭的闭环；进度可视化、依赖自动校验、阻塞预警、记录可追溯。

**菜单位置**：建议"版本概览"或"测试管理"菜单下（待确认）；关联投产点、版本需求、工单等现有模块。

**功能要求**

1. 按环境类型（SIT/UAT/性能测试等）新建、编辑、复制、归档搭建计划；计划可另存为模板复用。
2. 多级任务分解（如底座搭建 → 操作系统安装 → 中间件部署），任务含名称、责任人、计划开始/结束时间、实际开始/结束时间、状态、备注。
3. 前置依赖配置；前置任务未完成时后续任务状态不可置为"进行中/已完成"，界面给出依赖未满足提示。
4. 搭建进度看板（按环节分组）和甘特图视图；按状态、责任人、环节、依赖关系筛选。
5. 阻塞/问题登记：每条关联具体任务，含阻塞描述、影响范围、责任人、预计解决时间。
6. 整体进度自动计算（基于子任务完成情况）和关键路径标识。
7. 导出搭建进度报告（PDF/Excel），内容与页面筛选结果一致。
8. 任务状态变更消息通知（站内/邮件，待确认），通知责任人和搭建负责人。

**流程**：搭建计划创建后"草稿"→ 负责人确认清单和依赖后提交 → "搭建中"；任务状态：待开始 → 进行中 → 已完成/已阻塞；全部任务完成后发起"搭建完成确认"→ "待验收"；测试经理验收通过 → "已关闭"，不通过退回"搭建中"并记录整改意见。

**审批**：搭建计划提交由搭建负责人确认；搭建完成确认（验收）由测试经理审批；暂不设置多级会签（是否纳入由测试管理部确认）。

**留痕**：计划与每个任务的状态变更历史、操作人、操作时间、备注；阻塞记录保留登记/更新/关闭完整轨迹；验收环节记录审批意见和附件（如环境验证报告）。

**验收**：① 搭建负责人可按环境类型新建计划、配置多级任务和依赖，依赖未满足时明确拦截或提示；② 项目经理和测试经理可在看板/甘特图实时查看整体进度、任务状态和阻塞项；③ 计划关闭前必须完成验收审批，验收需填写意见，未通过可退回并记录整改要求；④ 导出的进度报告与页面数据完全一致，支持按筛选条件导出；⑤ 普通用户只能更新本人负责或被授权范围内的任务，管理员可维护全部。

> 待确认：与工单模块打通（搭建问题转工单）；消息通知渠道；依赖关系需灵活配置而非硬编码；多环境并行资源冲突检测（IP/端口占用）作为后续迭代（§10-4）。

### 6.3 环境变更操作跟踪与审核（D7）

**背景痛点**：测试/生产环境日常频繁涉及跑批执行、数据清理（清数）、数据翻转（翻数）、系统日期调整、清数范围设定、翻数指令配置等变更操作，当前依赖口头沟通、邮件、即时消息、线下文档，存在：信息传递不对等（参数失真遗漏）；操作失误频发（清错数据、翻错范围、日期调整错误）；缺乏审核确认机制（关键操作无二次确认）；操作记录不可追溯；动态调整无管控（临时调整无记录无审批）；多环境并行混乱（环境标识不清、操作对象混淆）。

**目标**：建立环境变更操作全流程闭环管理：申请、参数确认、多级审核、执行、验证到归档端到端跟踪，参数准确、审核到位、执行可追溯、调整有管控。

**菜单**：一级菜单"环境变更管理"或"运维管理/测试管理"下（待确认）；关联投产点、版本需求、工单等现有模块。

**功能要求**

*4.1 变更申请与参数管理*

- 按变更类型（跑批、清数、翻数、日期调整、其他）创建变更申请单，每类型可配置专属参数字段（清数：目标环境、数据库/Schema、清数范围/条件、是否保留基础数据；翻数：翻数指令、源日期、目标日期、影响表范围）。
- 变更类型和参数字段支持管理员动态配置（新增/修改/停用），无需开发介入。
- 关联目标环境（从环境清单选择：SIT1、SIT2、UAT、PRE-PROD、PROD），环境清单由管理员维护。
- 附件上传（变更脚本、SQL 文件、操作手册、审批截图等）。
- 变更申请模板：常用变更保存为模板，一键复用并修改参数。

*4.2 审核与审批流程*

- 可配置多级审核：按环境级别（测试/生产）、变更类型、影响范围自动匹配审核链路（测试环境清数→测试负责人审核；生产环境任何变更→运维主管+DBA主管+变更管理员三级审核）。
- 审核人可执行通过、驳回、要求补充信息，驳回/补充需填写意见。
- 审核时限设置，超时未审核自动提醒或升级（升级机制待确认）。
- 生产环境变更支持变更窗口校验：仅允许在批准的变更窗口期内执行，窗口外提交自动拦截或标记"待窗口开放"。

*4.3 执行与动态调整*

- 审核通过后流转至执行人，执行人确认参数后标记"执行中"，执行完成填写实际执行时间、执行结果、影响说明。
- 执行中调整参数（如清数范围扩大、翻数指令修改）必须发起变更修改申请，修改内容高亮对比展示，经原审核人（或指定审核人）重新审核通过后方可继续执行。
- 变更取消：已审核未执行可由申请人或管理员取消，需填写原因；已执行中取消需触发回滚评估流程。
- 批量变更：一次申请含多个子操作（如同时对 3 个 Schema 清数），每个子操作独立跟踪状态，整体进度自动汇总。

*4.4 验证与关闭*

- 执行完成后流转至验证人（默认为申请人，可指定），验证确认后关闭变更单。
- 验证不通过支持发起回滚/补救，回滚作为新的子变更单跟踪，关联原变更单。
- 变更单关闭后自动归档，状态不可再修改（管理员除外）。

*4.5 查询、统计与通知*

- 变更台账：按环境、变更类型、状态、申请人、执行人、时间范围、关联版本多维度筛选排序。
- 变更日历视图：按日期展示各环境变更计划，便于识别冲突和窗口安排。
- 导出变更台账（Excel/PDF），内容与筛选结果一致。
- 消息通知（站内/邮件/企业微信，待确认）：状态流转通知；审核超时提醒；变更窗口临近提醒。
- 统计看板：按环境、类型、时间段统计变更数量、成功率、平均处理时长、驳回率。

*4.6 权限与安全*

- 申请人只能查看操作自己提交的变更单；执行人只能操作分配给的待执行变更单；审核人只能审核分配给自己的待审核变更单；管理员可管理全部和系统配置。
- 生产环境变更需额外权限校验，仅授权人员可提交和执行。
- 所有操作（创建、审核、执行、修改、取消、关闭）记录完整操作日志：操作人、操作时间、操作内容、变更前后值对比。

**标准流程**：申请人提交（草稿）→ 确认参数提交（待审核）→ 审核（通过/驳回/要求补充；多级则流转下一级）→ 全部通过后执行人确认执行（执行中）→ 执行中调整参数（变更修改申请→重新审核→继续执行）→ 执行完成（待验证）→ 验证人验证（通过则关闭归档；不通过发起回滚/补救关联新变更单）。

**审批规则（建议，待确认）**：

| 场景 | 审核链路 |
|------|----------|
| 测试环境 - 常规跑批 | 测试负责人审核（1 级） |
| 测试环境 - 清数/翻数/日期调整 | 测试负责人 → DBA 确认（2 级） |
| 生产环境 - 任何变更 | 运维主管 → DBA 主管 → 变更管理员（3 级） |
| 生产环境 - 大范围清数/翻数 | 上述基础上增加部门负责人审批（4 级，待确认） |
| 紧急变更（如生产故障修复） | 支持先执行后补审，需限定时间内（如 2 小时）补齐审核记录（待确认） |

**留痕**：全生命周期状态变更记录；参数修改前后对比；审核意见和附件完整保留；执行记录（实际执行时间、脚本/命令摘要、执行结果）；验证记录和回滚记录；所有记录不可删除，仅管理员可标记作废（需填写原因）。

**验收**：① 按变更类型创建申请单，系统按类型展示对应参数字段，参数完整方可提交；② 提交后按预设规则自动匹配审核链路，审核人收到通知并完成审核；生产环境变更必须多级审核，未通过不可进入执行；③ 执行人只能看到已通过且分配给自己的变更单，执行前二次确认参数，完成后填写执行结果；④ 执行中调整参数强制重新审核，修改内容高亮对比，审核人可清晰识别变更点；⑤ 验证人确认后关闭；不通过可发起回滚，回滚作为独立变更单关联原单；⑥ 管理员和项目经理可在台账和日历视图实时查看各环境变更状态，支持多维筛选和导出；⑦ 所有操作留有完整审计日志，可追溯全生命周期；⑧ 变更类型和参数字段支持管理员动态配置，新增场景无需开发介入；⑨ 普通用户只能操作权限范围内变更单，生产环境变更需额外授权。

> 待确认：紧急变更"先执行后补审"适用场景和补审时限；变更窗口规则由谁维护；与工单/投产管理模块打通；多环境并行冲突检测（后续迭代）；与自动化运维平台/调度系统/数据库管理平台对接（后续，待确认）（§10-4）。

## 七、生产运维域（D8 批量作业管理）

**背景痛点**：生产环境大量批量作业分散在鲁班、百川等调度平台，无统一登记入口；跑批问题通过 ITSM 工单或口头沟通处理，缺乏闭环跟踪；慢作业无系统性标记和分析机制。

**目标**：统一登记批量作业（关联事业群、物理子系统、作业名、作业说明、跑批时间、频次、平台），记录执行时长（秒级）并标记慢作业；两类问题（跑批报错、跑批慢）统一登记，项目组分析原因并反馈处理方案，形成闭环跟踪。

**菜单位置**：「生产运维管理」菜单下；关联事业群、物理子系统基础数据、鲁班/百川调度平台。

**功能要求**

1. 批量作业登记：作业名、所属事业群、物理子系统名称、物理子系统编号（自动读取）、作业说明、跑批时间、跑批频次、跑批平台（鲁班/百川）、备注。
2. 执行记录：执行日期、开始时间、结束时间、执行时长（秒级）、执行状态（成功/失败/超时/慢）、错误信息。
3. 慢作业标记：时长超过阈值自动标记"慢"，运维人员也可手动标记；标记后可登记为慢类问题。
4. 问题登记与处理反馈：运维登记两类问题——报错（关联作业、错误描述、发生时间、严重程度）和慢（关联作业、慢现象描述、当前耗时、慢阈值、严重程度）；项目组提交处理反馈（报错：根因分析+修复方案+预防措施；慢：慢因分析+优化方案+目标时长+计划起止日期），可多次补充；慢类支持更新优化进度；运维确认解决后关闭，可重开。
5. 按问题类型（报错/慢）分别统计问题量、解决率、平均解决时长、慢优化完成率。
6. 统计报表：按事业群、子系统、平台、时间维度统计作业量、问题量（报错/慢分类）、解决率、慢优化完成率，支持导出 Excel。
7. 批量导入导出和搜索筛选：按事业群、子系统、平台、频次、状态、是否慢筛选；支持 Excel 批量导入。
8. 站内消息通知：新问题提交后通知对应项目组，处理反馈提交后通知运维人员。

**流程**

- 作业登记：运维登记 → 保存为"正常"状态 →（如需）标记"停用"。
- 问题处理（报错/慢统一）：运维登记问题（选报错或慢）→ 待处理 → 项目组提交处理反馈 → 处理中 → 运维确认解决 → 已解决 → 已关闭；已关闭可重开。共 5 个状态节点，两类问题共用同一状态机。
- 慢类问题在处理中阶段支持更新优化进度（百分比）和计划状态（已出方案/执行中/已完成/已取消）。
- 留痕：每条作业、问题、处理反馈的完整操作链（操作人、动作、时间）；全量操作日志保留 1 年，审计员可只读查看并导出报表。

**验收**

① 运维人员可登记批量作业（含物理子系统编号自动读取）；② 可登记执行记录（执行日期、开始/结束时间、时长秒级、状态），超阈值自动标记"慢"；③ 可登记两类问题，项目组提交对应反馈，运维确认后关闭，可重开；④ 支持按问题类型统计并导出 Excel；⑤ 支持按事业群、子系统、平台、时间维度统计并可导出；⑥ 审计员可只读查看全部作业、问题、处理反馈记录及操作日志。

> 待确认：慢作业阈值配置方式；鲁班/百川无 API 对接（执行记录手动登记）；批量导入单次最大行数；4 角色按 RBAC 控制，项目组按物理子系统做数据权限隔离。

## 八、安全资源域（D9 加密机入池申请线上化）

**背景痛点**：项目组通过 Excel 填写"项目加密需求申请表"线下提交，字段完整性依赖人工检查，申请状态、补充材料、处理意见和历史版本分散，查询统计不便。

**目标**：在管理系统中新增"加密机入池申请"能力，申请信息结构化录入，支持保存草稿、提交、办理、补充、退回、完成、查询、导出和全程留痕，逐步替代 Excel 传递。

**一期边界**：聚焦"申请与办理管理"。自动调用资源池接口、自动创建协同开发任务、自动完成加密机配置或分配**不在本需求默认承诺**，需接口和职责确认后另行纳入。

**菜单**：建议"安全资源管理 > 加密机入池申请"（最终位置待确认）；关联用户、组织、组件/应用主数据（如不具备，一期允许按受控文本或字典录入）。

**主流程**：申请人新建申请并填写组件、节点、交易量、关联机构、存量需求和接口需求等信息 → 保存草稿 / 提交（必填、条件必填、格式、重复申请校验）→ 生成唯一申请单号并通知办理人 → 办理人核验（受理/要求补充/退回）→ 申请人补充后再次提交 → 办理人处理入池并记录处理结果、完成时间和附件 → 已完成。

**功能要求**

1. 新建申请、保存草稿、编辑草稿、删除未提交草稿。
2. 按字段规则校验后提交，提交成功自动生成唯一申请单号，记录申请人、所属部门、提交时间。
3. 申请列表和详情页，按申请单号、组件名称、英文简称、安全节点号、申请人、申请时间、状态、关联机构查询。
4. 办理人受理、要求补充、退回、填写处理意见、上传处理材料、完成申请。
5. 申请人"待补充"状态修改指定内容后重新提交；办理人受理前可撤回，撤回原因留痕。
6. 录入多个接口名称（每接口独立条目保存）；支持上传技术文档或其他附件。
7. 申请详情导出或打印，包含申请信息、接口清单、处理结果和状态记录，与页面权限一致。
8. 站内消息通知申请人和办理人（是否接入邮件/企业消息工具待确认）。
9. 记录创建、提交、补充、受理、退回、完成、撤回等操作历史（操作者、时间、动作、意见）。
10. 基于角色和数据范围访问控制：申请人只能维护本人或本部门授权范围，办理人只能处理授权范围。
11. 管理员维护必要字典和规则：关联机构、业务量周期、申请状态、附件类型及办理人路由配置。

**留痕要求**：申请内容修改、附件变化、处理意见和状态变化均需记录；历史记录仅允许查看，不允许普通用户删除或覆盖。

**验收**

① 申请人能完成现有 Excel 全部字段录入；② 草稿可保存再编辑，提交时必填/条件必填/数值/重复接口校验生效，错误信息定位到具体字段；③ 提交成功生成唯一申请单号，状态变"已提交"，申请人和办理人在各自权限范围可查询；④ 办理人能受理、要求补充、退回和完成，每次动作记录操作者、时间、意见和状态变化；⑤ 申请人在"待补充"可修改再提交，无权限用户无法查看/修改；⑥ 完成时必须填写处理结果，自动记录完成时间，已完成不可由普通用户直接改回办理状态；⑦ 按列表筛选导出的数据与页面一致，申请详情导出含字段、接口清单、处理结果和操作记录；⑧ 系统对相同组件中文名、英文简称、安全节点号的未结束申请给出重复提示（是否禁止重复提交由业务规则配置）；⑨ 附件下载受权限控制并记录操作；申请表不得录入或上传明文密钥、口令等敏感凭据；⑩ 页面响应、并发容量、浏览器兼容性、日志和备份遵循现行非功能标准（如不存在，开发评审时补充量化指标）。

> 待确认：办理角色（开发部门/安全资源管理人员具体角色）；申请单号生成规则；是否自动调用资源池接口（一期不做）；附件规则；是否接入邮件/企业消息；"已退回"是否允许重新发起；是否需要多级审批/会签（§10-6）。

## 九、研发流程管理域（D10 常规投产版本全生命周期流程管控）

**背景**：投产版本管控流程复杂，从需求提出到上线涉及需求分析、开发管理、应用组装测试、用户测试、非功能测试、安全测试、版本评审及上线投产多阶段，各阶段信息传递依赖人工协调，存在信息孤岛、进度不透明、追溯困难。

**目标**：建设"常规投产版本全生命周期流程管控平台"，以投产版本生命周期流转为主线，全流程可追溯、可监控、可度量。系统定位：面向农信联社与金科公司的内部流程管控工具，所有数据为模拟数据，平台定位"流程管控"中枢，不涉及代码编译、自动化部署等 CI/CD 环节。

- 顶置五项原子指标卡：业务需求数、开发任务数、应用组装测试任务数、用户测试任务数、投产系统数（均按当前投产窗口统计）。

### 9.3 版本概览

- 按实施机构（农信联社/金科公司）分组展示当前投产窗口所有需求的当前进展。
- 卡片：需求编号（等宽字体，如 RC_20260612_001）、所属系统（标签样式，如"信贷管理系统"）、当前阶段状态（阶段名-子任务状态，如"应用组装测试-测试执行中"）。
- 进度条：6 个阶段节点（已完成=青绿圆点；当前=冰蓝圆点+环形光晕；未达=浅灰圆点），下方标注阶段名：需求分析、开发管理、应用组装、用户测试、版本评审、上线投产；有非功能/安全测试时增加阶段显示。
- 全流程详情弹窗（层级编号动态计算，非功能/安全测试按需显示，无承接任务不显示该层）：
  - 第 1 层 需求分析：需求编号（等宽）、需求分析状态（徽章）、需求内容简述、业务负责人、需求文档附件（逐个列出可独立下载）。
  - 第 2 层 开发管理：每个开发任务一张卡片——任务编号（等宽，如 RW_RC_20260612_001_001）、所属系统、开发负责人、开发任务状态（徽章）、设计文档/代码走查记录/单元测试报告（逐个列出可下载）。
  - 第 3 层 应用组装测试：每个 SIT 任务一张卡片——任务编号（如 SIT_RC_20260612_001_001）、实施机构、所属系统、测试负责人、测试任务状态（徽章）、测试方案/测试报告（可下载）。非功能测试、安全测试按需为同级层，字段结构相同。
  - 第 4 层 用户测试：UAT 任务，字段结构同应用组装测试。
  - 第 5 层 投产管理：评审会签进度（需求/开发/测试/投产四方签署状态：已签/未签/驳回）、投产负责人、生产上线时间、灾备同步时间、生产状态。

### 9.4 各阶段子任务与字段

通用交互：点击列表中某一条，弹出页面展示当前阶段所有字段（所有子任务信息，所有字段允许修改，修改后留存修改记录）。

**需求分析（2 子任务）**：需求发布——需求编号（手动/自动生成 RC_XX）、需求内容简述、需求提出时间、需求文档附件（上传文件或填写 SVN/云盘路径）；提交瞬间服务器自动生成不可篡改的"需求登记时间"并自动绑定操作人员工号。需求分析——主要系统（模糊搜索单选）、协同系统（模糊搜索多选）、业务负责人。

**开发管理（4 子任务）**：开发承接——根据需求分析识别的系统关联方数量拆分派生开发任务编号（RW_需求编号_序号），一个需求可建多个开发任务；开发设计——计划开始/结束时间、设计文档附件（上传或路径），提交时登记时间自动生成；开发实施——实际开始/结束时间，自动演算实际耗时与排期计划耗时的偏差率沉淀为效能参数；单元测试——代码走查记录（强制上传）、单元测试报告（强制上传），登记时间自动生成。

**测试管理（SIT/UAT/NFT/SEC，各 4 子任务，流程一致）**：测试承接——按需求分析识别的系统关联方数量拆分派生测试任务编号（SIT_需求编号_序号等），一个需求可建多个测试任务；测试方案——计划开始/结束时间、测试方案文档；测试执行——实际开始/结束时间，自动演算排期偏差率；测试报告——测试报告附件（上传或路径），登记时间自动生成。UAT 额外：1 个测试任务可关联多个需求，执行人增加农信业务/金科业务。

**投产管理（2 子任务）**：版本评审——自动调取聚合该常规投产单在全部阶段沉淀的记录、时间轴、操作工号与文件（或路径），生成紧凑电子评审视图；六方并行会签（农信业务代表、金科业务代表、农信开发代表、金科开发代表、农信测试代表、金科测试代表依次填写评审意见）；页面提示当前会签进度（已签/未签/驳回）。上线情况登记——前置条件为六方评审一致通过；运维值班代表认领单据登记线上生产上线情况、灾备中心同步时间；登记时间自动生成。

**人员管理**：字段——手机号（唯一标识）、姓名、所属机构（从配置表获取）、角色（一人多角色，从角色配置表获取：农信业务/金科业务/金科开发/农信开发/金科测试/农信测试/管理员）。操作——Excel/CSV 批量导入、xlsx 导出、全局模糊搜索、多字段排序、按机构/部门/角色筛选。

**系统设置**（Tab 页 + 紧凑列表布局）：

- 基础配置：平台信息（平台名称/描述/版权可配置）；编号规则（需求/开发/测试各类型编号规则可配置，默认见 §2.9）。
- 参数配置：流程阶段（阶段/子任务的新增、编辑、启用/禁用，子任务可展开折叠；初始阶段配置见 §9.1 表格）；投产日历（投产日期、投产类型、备注，列表展示）；阶段状态（各阶段任务状态取值配置）。
- 机构系统配置：实施机构（初始 11 个，见 §2.2，支持增删改）；业务板块（初始 7 个，支持排序）；所属系统（系统编号/名称/所属实施机构/所属业务板块，内联搜索、批量导入导出、增删改；初始值：W01812 存款-对公 上海事业群 对公金融板块；YN0060 理财平台 云南农信 技术系统）。
- 人员配置：组织机构（列表展示部门及层级关系，初始同实施机构）；角色配置（角色及默认打开系统的默认页；初始：农信业务、金科业务、金科开发、农信开发、金科测试、农信测试、金科运维、农信运维、管理员、超级管理员）；权限矩阵（矩阵形式展示各角色对各模块/操作的访问权限，复选框配置）。

### 9.5 状态枚举
