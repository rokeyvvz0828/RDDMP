# **一、项目概述**

## **1.1 项目背景**

随着金融信息化的持续深化，投产版本的管控流程日益复杂。当前版本从需求提出到最终上线涉及需求分析、开发管理、应用组装测试、用户测试、非功能测试、安全测试、版本评审及上线投产等多个阶段，各阶段间信息传递依赖人工协调，存在信息孤岛、进度不透明、追溯困难等问题。

为解决上述问题，建设"常规投产版本全生命周期流程管控平台"，以投产版本的生命周期流转为主线，提供数字化管控能力，实现全流程可追溯、可监控、可度量。

## **1.2 建设目标**

● 以投产版本为维度，实现从需求到上线的全流程数字化管控

● 各阶段子任务状态实时透明，进度可视化展示

● 自动演算效能参数（排期偏差率），为管理决策提供数据支撑

● 四方并行会签机制，确保版本评审质量

● 统一附件管理，文件可追溯、可下载

● 灵活配置流程阶段、编号规则、机构系统、角色权限

## **1.3 系统定位**

本平台为面向农信联社与金科公司的内部流程管控工具，所有数据为模拟数据，用于展示完整生命周期流程。平台定位为"流程管控"中枢，不涉及代码编译、自动化部署等CI/CD环节。

# **三、效能仪表盘**

## **3.1 顶置原子指标卡**

最上方置顶固定五项极简原子指标卡：

● 业务需求数 — 当前投产窗口下所有业务需求的总数

● 开发任务数 — 当前投产窗口下所有开发任务的总数

● 应用组装测试任务数 — 当前投产窗口下所有SIT测试任务的总数

● 用户测试任务数 — 当前投产窗口下所有UAT测试任务的总数

● 投产系统数 — 当前投产窗口涉及的目标系统总数

## **3.2 自定义绘制矩阵**

仪表盘下方的分析图表支持由用户自行配置与绘制，支持以下图表类型：

● 柱状图 — 适合对比各维度数量分布

● 面积图 — 适合展示趋势变化

● 饼图 — 适合展示占比分布

● 表格 — 适合精确数据展示

支持的维度包括：

● 事业群（农信/金科）

● 业务需求状态

● 开发任务状态

● 应用组装测试任务状态

● 用户测试任务状态

  

# **四、版本概览**

## **4.1 功能描述**

按实施机构（农信联社/金科公司）分组展示当前投产窗口下所有需求的当前进展状态。

## **4.2 卡片显示内容**

每张需求卡片精简显示以下信息：

● 需求编号（等宽字体，如 RC_20260612_001）

● 所属系统（标签样式，如"信贷管理系统"）

● 当前阶段状态（格式：阶段名-子任务状态，如"应用组装测试-测试执行中""用户测试-测试报告中""投产管理-投产评审中"）

## **4.3 进度条**

卡片下方显示一条水平进度线，连接6个阶段节点。节点含义：

● 已完成阶段 — 青绿色圆点

● 当前阶段 — 冰蓝色圆点 + 环形光晕

● 未达阶段 — 浅灰色圆点

进度线下方标注完整的阶段名称：需求分析、开发管理、应用组装、用户测试、版本评审、上线投产

如果有非功能测试、安全测试，则要相应的增加阶段显示。

## **4.4 全流程详情弹窗（****5****层结构）**

点击需求卡片，弹出全流程详情弹窗。弹窗分为5层，层级编号动态计算（非功能测试/安全测试按需显示，无承接任务时不显示该层）：

### **第1层：需求分析**

**需求编号：**等宽字体展示（如 RC_20260612_001）

**需求分析状态：**状态徽章展示

**需求内容简述：**文本展示

**业务负责人：**人员姓名

**需求文档附件：**逐个列出，每个附件可独立点击下载

### **第2层：开发管理**

展示所有关联的开发任务，每个任务独占一个卡片，逐行列出：

**任务编号：**等宽字体（如 RW_RC_20260612_001_001）

**所属系统：**系统名称

**开发负责人：**

**开发任务状态：**状态徽章

**设计文档：**逐个列出附件或路径，附件可下载

**代码走查记录：**逐个列出附件或路径，附件可下载

**单元测试报告：**逐个列出附件或路径，附件可下载

### **第3层：应用组装测试**

展示所有关联的SIT测试任务，每个任务独占一个卡片：

**任务编号：**如 SIT_RC_20260612_001_001

**实施机构：** 

**所属系统：**系统名称

**测试负责人：**

**测试任务状态：**状态徽章

**测试方案：**逐个列出，可下载

**测试报告：**逐个列出，可下载

### **第****3****层：非功能测试（按需显示）**

仅当存在NFT测试任务承接时显示该层，字段结构同应用组装测试。无承接任务时不显示。

### **第****3****层：安全测试（按需显示）**

仅当存在SEC测试任务承接时显示该层，字段结构同应用组装测试。无承接任务时不显示。

### **第4层：用户测试**

展示所有关联的UAT测试任务，字段结构同应用组装测试。

### **第****5****层：投产管理**

展示投产评审会签进度与上线登记信息：

**评审会签进度：**签署状态标记（需求、开发、测试、投产），已签/未签/驳回三种状态

**投产负责人：**

**生产上线时间：**实际生产上线时间

**灾备同步时间：**灾备中心同步上线时间

**生产状态：**上线后运行状态

  

# **五、需求分析**

## **5.1 功能描述**

用户录入需求，生成或手填需求编号（规范格式：RC_投产版本_序号，如RC_20260612_001）。需求分析阶段包含2个子任务：需求发布、需求分析。点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

## **5.2 子任务：需求发布**

**执行人：**农信业务、金科业务、管理员

**需求编号：**手动填写或点击自动生成，规范格式 RC_XX

**需求内容简述：**文本输入

**需求提出时间：**日期选择

**需求文档附件：**必须关联需求文档附件（可上传文件，也可填写SVN或云盘路径）

**系统行为：**点击提交瞬间，服务器自动生成不可篡改的"需求登记时间"并自动绑定当前操作人员账号工号

## **5.3 子任务：需求分析**

**执行人：**农信业务、金科业务、管理员

**主要系统：**模糊搜索，单选

**协同系统：**模糊搜索，多选

**业务负责人：**人员选择

## **5.4 列表功能**

需求分析列表以需求编号为维度，支持：

● 字段搜索

● 筛选（按状态、实施机构、投产窗口等）

● 排序（支持列头点击排序）

● 导入/导出

● 默认自动过滤当前投产窗口期

  

# **六、开发管理**

## **6.1 功能描述**

根据需求建立1个或多个开发任务，生成开发任务编号（格式默认为RW_需求编号_序号，可在系统配置中配置）。开发管理阶段包含4个子任务：开发承接、开发设计、开发实施、单元测试。点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

## **6.2 子任务：开发承接**

**执行人：**金科开发、农信开发、管理员

**业务功能：**根据"需求分析"中识别生成的系统关联方数量，拆分并派生出开发任务编号（如RW_RC_20260612_001_001），与需求编号对应。根据需求建立1个或多个开发任务

## **6.3 子任务：开发设计**

**执行人：**金科开发、农信开发、管理员

**计划开始时间：**日期选择

**计划结束时间：**日期选择

**设计文档附件：**上传文件组件，可上传附件，也可填写路径

**系统行为：**点击提交保存，登记时间由系统自动生成

## **6.4 子任务：开发实施**

**执行人：**金科开发、农信开发、管理员

**实际开始时间：**日期选择

**实际结束时间：**日期选择

**系统行为：**自动演算实际耗时与排期计划耗时的偏差率，作为效能参数沉淀

## **6.5 子任务：单元测试**

**执行人：**金科开发、农信开发、管理员

**代码走查记录：**上传文件组件（系统强制要求上传）

**单元测试报告：**上传文件组件（系统强制要求上传）

**系统行为：**登记时间由系统自动生成

  

# **七、测试管理**

## **7.1 总体说明**

测试管理分为4个独立子模块：应用组装测试(SIT)、用户测试(UAT)、非功能测试(NFT)、安全测试(SEC)。每个子模块均遵循4个子任务阶段的统一流程：测试承接、测试方案、测试执行、测试报告。

## **7.2 应用组装测试(SIT)**

点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

### **7.2.1 子任务：测试承接**

**执行人：**金科测试、农信测试、管理员

**业务功能：**根据"需求分析"中识别生成的系统关联方数量，拆分并派生出测试任务编号（格式默认为SIT_需求编号_序号），与需求编号对应。允许根据需求建立1个或多个测试任务。

### **7.2.2 子任务：测试方案**

**执行人：**金科测试、农信测试、管理员

**计划开始时间：**日期选择

**计划结束时间：**日期选择

**测试方案文档：**上传文件组件，可上传附件，也可填写路径

**系统行为：**点击提交保存，登记时间由系统填写

### **7.2.3 子任务：测试执行**

**执行人：**金科测试、农信测试、管理员

**实际开始时间：**日期选择

**实际结束时间：**日期选择

**系统行为：**自动演算实际耗时与排期计划耗时的偏差率，作为效能参数沉淀

### **7.2.4 子任务：测试报告**

**执行人：**金科测试、农信测试、管理员

**测试报告附件：**上传文件组件，可上传附件，也可填写路径

**系统行为：**登记时间由系统自动生成

## **7.3 用户测试(UAT)**

点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

流程与SIT一致，4个子任务：测试承接、测试方案、测试执行、测试报告。

额外说明：用户测试也可以1个测试任务关联多个需求。执行人增加农信业务、金科业务。

## **7.4 非功能测试(NFT)**

点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

流程与SIT一致。按需进行，需求可以不进行非功能测试，未关联时默认无此阶段。

## **7.5 安全测试(SEC)**

点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

流程与SIT一致。按需进行，需求可以不进行安全测试，未关联时默认无此阶段。

## **7.6 通用列表功能**

各测试管理列表均以需求编号为维度，支持：

● 字段搜索

● 筛选（按状态、实施机构、测试类型、投产窗口等）

● 排序（支持列头点击排序）

● 导入/导出

● 默认自动过滤当前投产窗口期

  

# **八、投产管理**

## **8.1 功能描述**

管理四方并行会签表单评审意见、线上生产情况登记与灾备中心上线登记。包含2个子任务：版本评审、上线情况登记。点击列表中某一条后，要展示当前阶段的所有字段（所有子任务的信息，所有字段都允许修改。修改后要留存修改记录）。所有子任务的填写，都在这个弹出的页面中维护。

## **8.2 子任务：版本评审**

**执行人：**所有人员

**业务功能：**按照需求，自动调取聚合该常规投产单在上述所有阶段中沉淀的全部记录、时间轴、操作工号与文件（或文件路径），在页面中生成紧凑的电子评审视图

六方并行会签机制，相关人员依次在表单中填写各自的会签评审意见：

● 农信业务代表签署

● 金科业务代表签署

● 农信开发代表签署

● 金科开发代表签署

● 农信测试代表签署

● 金科测试代表签署

**系统行为：**登记时间为系统自动生成。页面提示当前会签进度（已签/未签/驳回状态标记）

## **8.3 子任务：上线情况登记**

**执行人：**所有人员

**前置条件：**六方评审一致通过后

**线上生产上线情况：**运维值班代表认领单据，线上登记实际生产上线情况

**灾备中心同步时间：**登记灾备中心的实际同步上线时间

**系统行为：**登记时间由系统自动生成

## **9.2 字段明细**

● 手机号 — 唯一标识，如13800010000

● 姓名 — 真实姓名

● 所属机构 — 从所属机构配置表获取

● 角色 — 支持一人关联多个角色（农信业务/金科业务/金科开发/农信开发/金科测试/农信测试/管理员）角色信息从角色配置表获取。

## **9.3 操作功能**

# **十三、编号规则说明**

## **13.1 需求编号**

格式：RC_投产窗口_序号

示例：RC_20260612_001

说明：RC为Requirement的缩写，投产窗口采用8位日期格式(YYYYMMDD)，序号为3位数字。

## **13.2 开发任务编号**

格式：RW_需求编号_序号

示例：RW_RC_20260612_001_001

说明：RW为Rework/Task的缩写，关联对应需求编号，末尾3位为该需求下的开发任务序号。

## **13.3 测试任务编号**

格式：测试类型_需求编号_序号

示例：SIT_RC_20260612_001_001 / UAT_RC_20260612_002_001

说明：测试类型前缀为SIT(应用组装测试)、UAT(用户测试)、NFT(非功能测试)、SEC(安全测试)。以上编号规则均可在系统设置中自定义配置。

# **十五、界面设计规范**

## **15.1 设计风格**

钢蓝治理风格 — 金融级流程管控平台，如同精密仪表盘与冰蓝色钢板的结合。意象锚点：银行金库门后的中央监控室，深色钢质面板上嵌着冷光指示灯，每个数字都经过严格审计。

|   |   |   |
|---|---|---|
|**用途**|**色彩描述**|**OKLCH色值**|
|主色|深钢蓝(银行安全门的深蓝钢质)|oklch(0.35 0.03 250)|
|强调色|冰蓝(监控室指示灯的冷光)|oklch(0.65 0.15 230)|

|侧边栏|深靛蓝(金库深处的厚重感)|oklch(0.2 0.04 260)|

## **15.3 字体排版**

● 字体族： Microsoft YaHei

● 标题：18-24px，font-weight 600，letter-spacing 紧凑

● 正文：14px，font-weight 400

● 数据/编号：等宽字体 tabular-nums，12-13px

● 排版节奏：紧凑密集，减少留白，增加信息密度

## **15.4 页面布局**

● 左侧固定侧边栏(240px)，深靛蓝背景，白色文字

● 顶部标题栏(56px)，显示当前模块名、投产窗口筛选器、用户信息

● 内容区白底，紧凑卡片布局

● 列表页：顶部筛选栏 + 数据表格

● 详情页：弹窗形式展示

## **15.5 设计禁忌**

● 禁止使用渐变色背景（纯色体现严谨）

● 禁止使用圆角大于8px的卡片（过度圆润失去专业感）

● 禁止使用装饰性插图或emoji（信息优先）

● 禁止大面积留白（金融管控平台需高信息密度）

● 禁止使用科技蓝+紫色渐变（落入俗套）
