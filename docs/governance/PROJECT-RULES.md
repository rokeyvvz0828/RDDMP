# RDDMP 项目研发规约总则

## 架构与依赖

RDDMP 是 Java 17、Spring Boot 3.4.4 与 Vue 3 组成的模块化单体。现有 Java 包名 `com.ccb.*` 是兼容边界，普通需求不得修改。

- `server/src/modules/*` 拥有各自业务规则、服务、接口与测试。
- `server/src/platform/*` 提供启动装配、系统管理、工作流、安全、持久化、迁移和对象存储等平台能力；除所属平台任务或批准的公共能力任务外，对业务模块只读。
- `server/src/shared/common` 提供无业务数据所有权的通用响应、异常、分页与追踪能力。
- `web/src/components/ui`、通用 stores、router、HTTP 和主题属于前端公共能力；业务页面优先复用，不建立平行组件。
- Maven 模块只依赖 `governance/modules.yaml` 的 `allowed_dependencies`。`boot` 是组合根，可装配平台与业务模块；其他平台和 shared 模块不得反向依赖业务模块。
- 跨模块新增调用应通过已登记的公开 Java 包、API DTO 或前端 API 封装。需要暴露新能力时，先更新契约和模块清单，再实现调用方。
- 新增模块或调整模块边界必须更新 `governance/modules.yaml`、`docs/architecture/MODULES.md`、CODEOWNERS 和测试，不以目录移动替代架构决策。

## API、权限与审计

- 后端接口统一使用 `/api` 前缀和 `{ code, data, message }` 响应；对外 DTO 使用字段白名单。
- 受保护接口必须在服务端校验身份、RBAC、数据范围和实体权限；前端仅负责体验层显隐。
- 写操作应记录操作人、对象、动作、结果和 trace ID。日志不得记录密码、Token、密钥和不必要的敏感字段。
- 附件通过 MinIO 平台服务和受控 URL 访问，业务代码不得暴露底层存储路径或持久凭据。

## 数据库与配置

- MySQL 8.4 是当前正式数据库目标。字符集、时区、索引和事务行为必须明确。
- Flyway 迁移只追加；已发布的 `V*__*.sql` 不修改、不重排。变更需说明存量数据兼容、校验、补偿或回退。
- 不在源码、镜像、提交记录和普通日志中保存环境口令、JWT 密钥、对象存储密钥或内网地址。
- 测试和演示数据必须虚构或脱敏，不得从生产直接复制。

## 前端交付

- 页面必须覆盖加载、空数据、失败、无权限、提交中、只读和重复提交状态。
- 有限选项使用选择器、开关等受控组件；人员、机构、角色、菜单和参数等平台数据不得硬编码为自由文本选项。
- 列表采用服务端分页/筛选，关键操作保留上下文；桌面和移动端不得出现遮挡、溢出或不可达操作。
- 所有业务功能开发必须先参考 `web/src/modules/delivery-showcase` 的前端设计，优先复用其页面结构、组件组合、交互状态和语义主题样式；仅当示范中心无法覆盖目标业务形态时，才允许新增样式，并在需求设计或当前 `.ai-control` 任务记录中说明例外原因、复用能力、适用边界和回归范围。
- 新页面复用现有 `web/src/components/ui`、语义主题变量、API 错误处理和权限模型；新增样式不得成为绕过公共组件和全状态要求的理由。

## 质量与发布

每项变更必须有 ready 需求、任务范围、测试证据和回退说明。普通变更至少覆盖正常、异常、权限与边界；认证、安全、公共能力、数据库迁移和发布属于高风险变更，必须由 Owner 专项复核。只有实际通过的检查才能写入完成报告。
