# RDDMP Codex Coding 与数据边界规约

## 任务准入

Codex 任务必须关联状态为 `ready` 的 `requirement.md` 和完整的 `codex-task-scope.yaml`。任务范围应声明目标模块、开发者、Owner、独立分支/工作区、可写/只读/禁止路径、风险、测试、数据库、公共能力和外部访问影响。

缺少范围、验收标准、关键产品决策，或规则相互冲突时，Codex 不得开始编码。`.ai-control` 记录任务执行和验证状态，但不能替代需求准入与路径授权。

## 数据与环境边界

- 禁止向 Codex 提供生产数据、真实个人信息、账号口令、Token、Cookie、密钥、证书、内网地址、真实日志、真实附件、签名和未脱敏截图。
- `contains_confidential_information=true` 时，`codex_allowed` 必须为 `false`。
- 禁止访问、连接或修改生产应用、数据库、对象存储和密钥系统。
- 只使用本地、测试、虚构或确认已脱敏的数据；输出同样执行敏感信息检查。

## 修改边界

- 只能写入 `writable_paths`；不得通过重命名、目录搬迁、依赖升级、批量格式化或顺手修复扩大范围。
- `read_only_paths` 只能用于理解上下文；`forbidden_paths` 不得读取或修改。
- 不修改用户或其他开发者的无关改动，不自行回退工作区。
- `.ai-control` 只允许修改 `completion.control_prefix` 对应文件；无前缀历史账本和其他任务前缀只读。
- 跨模块只使用登记的依赖和公开能力；不得直接写其他模块负责的数据表。
- 修改 platform、shared、公共前端组件或公开契约时，必须声明 `public_capability_change`、关联 Issue、Owner 审批、兼容策略和回归测试。
- 数据库、认证、权限、审计、附件、外部接口和供应链变更必须人工专项复核。

## 编码前预检

Codex 应先输出：需求与验收理解、目标模块、拟改文件、只读/禁止路径、复用能力、公共能力/数据库/权限/审计/外部访问影响、测试计划和未决问题。与任务范围不一致时先纠正范围。

## 完成报告

报告实际修改文件、运行过的命令和结果、`.ai-control` 前缀与 phase、数据库影响、浏览器验收路径、已知风险、上线检查及回退方式。明确区分“已实现”“检查通过”“运行可达”和“浏览器已验收”；不得声称未执行的验证已经通过。
