# 投产方案时序与指令分层设计

## 数据模型

`rel_release_plan_timeline` 表表示投产方案内的一个时序节点，字段包括方案、正向/回退类型、序号、名称、说明和 rowVersion。`rel_release_plan_item` 通过 `timeline_id` 归属时序节点，原 `seq_no` 改为该时序内的指令序号。

## 接口和流程

- 方案查询返回 `timelines`，每个时序节点内嵌 `items`。
- 时序节点使用 `/release-plans/{planId}/timelines/{type}` 下的 CRUD 接口。
- 指令使用 `/release-plans/{planId}/timelines/{type}/{timelineId}/items` 下的 CRUD 接口。
- 服务端继续执行项目成员、方案归属、负责人项目成员和 rowVersion 校验；删除时序在同一事务中软删除其指令。

## 页面结构

时序抽屉上方保留时序类型和自定义正向/回退组名称；主体使用横向阶段列，每列头部显示 P 编号、时序名称、指令数量和时序编辑/删除动作；列内显示多条指令及其时间范围、负责人、状态、说明和维护动作。P 节点之间使用连接关系表达顺序，不根据指令时间绘制位置。底部时间线全部移除。新增/编辑时序使用轻量表单弹窗，新增/编辑指令继续使用抽屉。

## 兼容与迁移

V129 先从现有方案指令按 `plan_id/item_type/seq_no` 生成时序节点，再回填 `timeline_id`，将历史指令序号设为 1，并替换原唯一索引为时序内指令序号索引。无后端之外的业务表变更。

## 响应式和状态

桌面端显示完整阶段列；移动端只有图形区域局部横向滚动。阶段列内的文本可换行，编辑/删除按钮保持可达。复用现有 Element Plus、UiEmptyState 和语义主题变量，保留加载、空、失败、无权限、提交中和重复提交保护。
