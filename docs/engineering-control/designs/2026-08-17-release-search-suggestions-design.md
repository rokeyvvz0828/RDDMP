# 配置管理候选式模糊检索工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户于 2026-08-17 确认仅修改配置管理模块，并确认搜索值必须来自模糊匹配下拉候选、空输入获得焦点时展示前 20 条候选，复核落盘设计后明确要求开始执行。

## 目标与成功信号

将配置管理模块中投产窗口、版本申请、投产基线、生产版本四个列表的自由文本搜索框统一为候选式模糊检索控件。用户输入内容只用于缩小真实候选范围，必须选择候选后才改变列表，避免无效自由文本产生无意义查询。

成功信号：四个页面的搜索交互一致；空输入可浏览前 20 条候选；输入编码、名称或版本片段能得到匹配项；未选择的临时文字不触发查询且失焦后清除；清空已选项恢复完整列表。

## 使用者与场景

- 配置管理人员：通过窗口编码或名称定位投产窗口。
- 申请人和审批相关人员：通过申请单号或物理子系统定位版本申请。
- 投产管理人员：通过物理子系统、交付单元、版本或来源申请定位投产基线。
- 运维和查询人员：通过物理子系统、交付单元或版本定位当前生产版本。

## 必须需求与验收条件

### R1 四个页面统一为候选选择检索

- 覆盖投产窗口、版本申请、投产基线、生产版本四个现有搜索框。
- 控件外观和基本行为统一，保留搜索图标、清空能力和现有工具栏布局。
- 候选项由主标题和辅助信息组成，能够区分同名记录。
- 验收：四个页面均不再以普通 `el-input` 承载列表检索，且键盘和鼠标均可完成候选选择。
- 反例：只有投产基线支持下拉，或同名候选无法辨认。

### R2 模糊匹配和空输入候选

- 搜索框获得焦点且没有输入时展示当前范围内前 20 条候选。
- 输入后进行不区分大小写的包含匹配，最多展示 20 条。
- 投产窗口匹配编码和名称；版本申请匹配申请单号和物理子系统；投产基线匹配物理子系统、交付单元、制品版本和来源申请；生产版本匹配物理子系统、交付单元和制品版本。
- 候选按现有列表或接口返回顺序展示，不引入新的业务排序规则。
- 验收：输入字段任意连续片段均可找到对应候选；超过 20 条时稳定截断为 20 条。
- 反例：仅前缀匹配，或大小写不同导致编码无法找到。

### R3 只有已选候选才能查询

- 用户输入的临时文字只筛选下拉候选，不直接修改主列表查询条件。
- 只有选择真实候选后才更新列表；未选择时失焦清除临时文字并保持原列表状态。
- 清空已选候选后恢复该页面其他过滤条件下的完整列表。
- 候选刷新后若已选记录仍有效则保持；项目、投产窗口等上级范围变化导致候选失效时自动清空。
- 验收：输入不存在的文本不会使主列表变空；选择候选后列表只显示对应记录；清空后恢复。
- 反例：按回车可提交任意文本，或临时输入触发后端分页查询并改变主列表。

### R4 使用真实且完整的数据范围

- 投产窗口候选来自当前项目已加载的窗口记录。
- 版本申请候选通过现有版本申请分页接口按当前项目远程模糊查询，使用约 300ms 防抖，最多请求 20 条，不新增专用后端接口。
- 投产基线候选来自当前选中投产窗口的完整基线明细。
- 生产版本候选来自当前项目已加载的生产版本明细。
- 项目切换、投产窗口切换和数据刷新后重建候选并校验当前选择。
- 验收：版本申请候选不局限于主表当前分页；其他三个页面不产生额外无意义请求；候选不跨项目或跨窗口。
- 反例：版本申请只能联想当前页记录，或切换项目后仍显示旧项目候选。

### R5 错误状态与可用性

- 远程候选加载显示局部加载状态，不阻塞主表已有内容。
- 远程候选失败时显示明确的加载失败空态或提示，允许重新输入重试，不把失败当作“无匹配项”。
- 下拉无匹配项时显示“无匹配选项”；控件支持清空、方向键浏览和回车选择。
- 候选文本超长时截断但提供完整辅助信息展示能力，控件宽度不挤压工具栏操作按钮。
- 验收：前端构建通过；桌面常用分辨率下搜索框、下拉和工具栏无重叠；请求失败后可恢复。
- 反例：远程失败静默显示空列表，或下拉内容撑破页面宽度。

## 不变量与约束

- 搜索选择只改变展示和查询条件，不修改任何业务数据。
- 项目和投产窗口数据范围仍由现有上下文与接口决定。
- 版本申请主列表继续使用现有服务端分页接口；选择候选后使用其申请单号作为精确稳定的查询值。
- 不新增数据库表、迁移或权限。
- 保护 `rokey` 工作区现有未提交修改，不进行无关格式化和重构。
- 首期仅覆盖桌面端，移动端不在本次范围。

## 非目标

- 不推广到配置管理之外的全平台页面。
- 不建设全平台统一搜索中心或全文索引。
- 不允许创建新候选、自由文本搜索或搜索历史。
- 不改变状态、制品类型等现有独立筛选器。
- 不调整后端列表排序和业务数据范围规则。

## 方案比较与选择

| 方案 | 优点 | 代价与风险 | 结论 |
| --- | --- | --- | --- |
| 公共候选选择组件，按页面注入本地或远程候选 | 四处行为一致；复用现有接口；改动边界清晰 | 需要定义统一候选模型和选择失效规则 | 选择 |
| 四个页面分别实现 | 单页改动直接 | 逻辑重复，清空和失焦行为容易不一致 | 不选 |
| 新增统一后端联想接口 | 服务端模型统一，适合全平台扩展 | 当前仅一个页面需要远程候选，接口和维护成本过高 | 不选 |

## 架构边界与组件职责

- `ReleaseSearchSelect`：配置管理模块内部公共候选选择组件，只负责候选展示、临时输入、选择、清空、加载和无结果状态，不理解具体业务字段。
- `ReleaseSearchOption`：统一候选模型，包含稳定 `value`、主标题 `label`、辅助文本 `description` 和可选检索文本 `keywords`。
- 四个列表页面：负责把业务记录映射成候选、保存已选稳定标识，并按已选记录过滤或查询。
- `ReleaseManagementPrototype`：为版本申请页面提供当前项目范围的远程候选查询，复用 `listReleaseApplications`。
- `web/src/api/release.ts`：继续使用现有列表接口，不增加公共搜索 API。

## 接口、数据和状态流

公共组件输入：

- `modelValue?: string | number`：已选择候选的稳定值。
- `options: ReleaseSearchOption[]`：本地或远程候选，最多 20 条。
- `loading?: boolean`、`placeholder: string`、`noMatchText?: string`。
- 可选 `remoteMethod(query: string)`：由页面提供远程候选刷新函数。

公共组件输出：

- `update:modelValue`：仅在选择或清空真实候选时发出。
- `search`：远程模式下传递临时输入，不代表主列表查询条件变化。

状态流：

```text
获得焦点
  -> 空输入加载/展示前 20 条候选
  -> 输入临时文字
  -> 本地过滤或防抖远程获取候选
  -> 选择候选
  -> 更新稳定选择值
  -> 页面过滤或请求主列表

未选择直接失焦
  -> 丢弃临时文字
  -> 保持原选择和主列表

点击清空
  -> 清除稳定选择
  -> 恢复其他筛选条件下的完整列表
```

## 错误、降级与恢复

- 版本申请候选请求失败：保留主列表和原有已选项，候选区提示加载失败；再次输入重试。
- 本地候选数据尚未加载：显示加载状态，不产生空选择事件。
- 项目或窗口切换：先清空不再有效的选择，再加载新范围候选，防止旧值过滤新数据。
- 已选记录因刷新消失：自动清空并恢复列表，同时不显示错误消息。
- 快速连续输入：只接纳最后一次远程候选响应，避免旧请求覆盖新结果。

## 安全、性能、兼容性与运维

- 候选接口继续走现有认证、租户和项目数据范围，不在前端扩大权限。
- 本地候选去重和过滤为线性处理，最多渲染 20 条。
- 远程查询防抖约 300ms，并通过请求序号或取消机制忽略过期响应。
- 公共组件限定在配置管理模块内部，避免在需求未确认时形成平台公共契约。
- 不改变现有 API 请求和响应结构，后端无需重新部署也可兼容。

## 验证策略

- 组件测试：空输入前 20 条、包含匹配、选择后发值、自由文本失焦不发值、清空恢复、加载和无结果状态。
- 页面测试：四个页面候选字段、同名辅助信息、项目/窗口切换失效处理。
- 版本申请远程测试：防抖、项目参数、非当前分页候选、过期响应忽略和失败恢复。
- 构建检查：`vue-tsc --noEmit` 与 Vite 生产构建。
- 浏览器验证：四个页面逐一测试焦点、输入、选择、清空和布局；确认主列表不会被未选择文本改变。

## 假设、未知项与决策记录

- 假设：投产窗口单次加载上限 200 足以代表当前原型项目的完整可选窗口；若后续超过上限，再将该页面切换为远程候选。
- 假设：投产基线和生产版本接口当前返回对应范围完整明细。
- 未知项：无阻塞未知项。
- 决策 D1：本次只覆盖配置管理模块四个列表搜索框。
- 决策 D2：不允许自由文本查询，必须选择真实候选。
- 决策 D3：空输入获得焦点时展示前 20 条候选。
- 决策 D4：采用配置管理内部公共组件，版本申请远程、其他页面本地候选。

## 风险与回退原则

- 版本申请候选与主列表请求并发可能出现顺序错乱：分别维护候选和主列表请求状态，并忽略过期候选响应。
- 候选以记录为单位时，同一子系统可能出现多条申请：辅助信息包含申请单号、子系统和状态，选择后使用唯一申请单号查询。
- 上游接口改为分页后本地候选可能不完整：通过页面数据来源契约和测试暴露，必要时单独演进为远程模式。
- 回退时恢复四个原普通输入框及页面原过滤逻辑，不涉及数据补偿或数据库回滚。
