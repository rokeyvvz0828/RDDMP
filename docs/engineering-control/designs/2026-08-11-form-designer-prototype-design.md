# 表单设计器平台原型设计

**状态：** approved-by-user-request

## 目标

验证“平台自有 DSL + form-create 作为拖拽设计器 + 平台自有渲染器”的交互方向，为后续统一业务表单、详情、审批和列表设计提供可见的工作区原型。

## 原型范围

- 左侧：基础组件目录，展示文本、数字、选择、日期、人员、附件等可拖拽组件。
- 中间：表单画布，支持示例字段、拖入新增、字段排序、选中态和删除。
- 右侧：属性面板，编辑字段编码、名称、控件类型、栅格宽度、提示语和必填状态。
- 顶部：设计、预览、Schema 三种视图，以及重置原型状态的操作。
- 预览：使用当前 DSL 映射为 Element Plus 表单控件，不向后端提交。

## DSL 原型

```json
{
  "schemaVersion": 1,
  "scopeKey": "delivery.work-order",
  "mode": "create",
  "layout": {"columns": 24, "mobileColumns": 1},
  "fields": [
    {"id": "field_1", "key": "work_order_no", "type": "text", "label": "工单编号", "span": 12, "required": true}
  ]
}
```

DSL 只作为原型展示。正式实现时由平台拥有稳定字段 ID、组件白名单、数据源、规则、权限、版本和发布快照，不能把第三方设计器的原始 JSON 直接作为长期契约。

## 边界与不变量

1. 原型不调用业务表单元数据 API，不写入 `biz_form_*`。
2. 既有输入项配置页、业务模块和后端逻辑保持不变。
3. 设计状态只保存在浏览器内存，刷新后恢复示例数据。
4. 手机视口下组件区、画布和属性区按单列顺序排列，不产生横向页面溢出。
5. 后续 form-create 接入应通过适配层产生平台 DSL，平台渲染器不直接依赖设计器内部对象。

## 验证

- `npm --prefix web run build`。
- 治理检查通过。
- 浏览器验证拖入新增、画布排序、属性更新、预览和 Schema 同步。
- 以 390px 宽度检查单列布局、操作按钮和属性输入项不重叠。
