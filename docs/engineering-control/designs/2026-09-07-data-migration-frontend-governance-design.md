# 数据迁移前端规范与上传样式统一设计

## 状态

- 设计修订：1
- 状态：approved
- 用户确认：2026-09-07 用户要求按已列计划逐项执行。

## 目标

修复数据迁移模块当前源码中违反项目上下文展示规范的页面，并将文件上传区域收敛为可复用、响应式、主题兼容的模块级视觉规范。

## 需求

1. 页面、列表、详情、弹层和确认文案不得展示“所属项目”“项目名称”或动态项目名称；项目仍由顶部全局项目切换器提供并参与接口请求。
2. Excel 导入和主要源文件选择使用全宽拖拽区域；附件追加或替换使用按钮入口与统一文件列表。两种形态共享间距、主题色、文件名截断和移动端约束。
3. 使用自定义文件列表时关闭 Element Plus 默认文件列表，避免重复文件名和重复移除操作。
4. 上传相关业务样式使用 `--panel-bg`、`--line`、`--text`、`--muted`、`--brand`、`--warning` 等语义变量，不保留业务页内联十六进制颜色。
5. 桌面 `1280x800` 与移动 `375x812`、`390x844`、`430x932` 下上传区域不得造成页面级横向溢出。

## 方案

在 `web/src/modules/data-migration/data-migration.css` 建立模块级上传与附件列表样式原语，不增加运行时依赖，也不改变上传 API。各页面继续持有文件校验、上传、重试和提交状态，仅将 DOM 类名与 Element Plus 文件列表行为统一。Excel 导入、主文件与普通附件按两个已确认形态呈现，避免用单一复杂组件强行耦合不同业务流程。

## 边界

- 修改范围限于数据迁移前端、REQ-031 需求文档和当前任务前缀账本。
- 不修改后端、数据库、公共 UI 组件、全局项目切换器和上传 API。
- 目标表模板中的“所属项目编码”是后端文件契约，保留模板列说明，但不回显当前项目名称。
- REQ-061 属于投产模块，只记录为仓库全量治理的外部扰动，不修改也不绕过。

## 验证

- 静态扫描项目字段残留、上传入口配置和硬编码颜色。
- `npm --prefix web run build` 与 `git diff --check`。
- REQ-031 定向任务范围检查。
- 真实浏览器覆盖桌面与三个移动视口，检查上传入口、文件列表和页面横向溢出。
