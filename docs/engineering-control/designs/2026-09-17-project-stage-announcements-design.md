# 项目阶段公告栏工程设计

## 文档状态

- 修订：4
- 状态：已确认
- 用户确认依据：用户确认公告管理页、成员维护权限、富文本、当前日期阶段判定、置顶和并行阶段展示；并于本次修订确认投产日历应选择主题内置色系，且随全局主题切换。

## 目标与成功信号

项目成员可维护阶段公告，进入项目概览即可看到当前日期命中阶段的置顶和最新公告。公告不能跨项目或跨租户读取、写入或渲染不安全内容。

## 使用者与场景

- 项目成员：进入项目概览阅读当前阶段公告；进入公告管理页维护任意本项目公告。
- 项目 Owner：复核阶段判定与概览信息层级。
- 平台系统 Owner：复核富文本安全、成员授权、审计和迁移。

## 必须需求与验收条件

- R1：新增公告管理页签并保持现有 `?tab=` 契约。验收：可通过 `tab=announcements` 直接打开且其他页签保持可用。
- R2：按项目阶段维护标题、富文本正文和置顶标记。验收：成员可创建、编辑、置顶、逻辑删除并在刷新后回显。
- R3：服务端执行成员、租户、项目、阶段和乐观锁校验并记录审计。验收：非成员、跨租户、无效阶段及旧版本写入均被拒绝。
- R4：概览仅显示当前日期命中的顶级项目计划阶段公告。验收：并行阶段均展示，置顶优先；无当前阶段时显示空状态。
- R5：富文本受控渲染且项目概览响应式可读。验收：脚本与危险 URL 不执行，规定桌面和手机视口无页面级横向溢出。

## 不变量与约束

- 公告是项目模块数据，不复用测试管理公告、站内消息或投产窗口。
- 所有项目成员都可维护本项目任意公告，但服务端成员授权不得由前端替代。
- 迁移只追加，删除使用逻辑删除并保留审计；不访问生产数据或密钥。

## 非目标

提醒、邮件、跨项目汇总、附件、审批、定时发布、公告归档页和项目计划规则调整均不在本次范围内。

## 方案比较与选择

- 选择：项目自有公告表和项目详情页签。阶段、成员、租户和概览查询都在项目边界内，回滚和审计可控。
- 备选：复用测试管理公告。拒绝原因：数据 Owner、项目语义和权限边界不同。
- 备选：复用站内消息。拒绝原因：消息投递不支持阶段维护、置顶排序和项目概览查询。

## 架构边界与组件职责

- `ProjectView`：页签路由、公告管理、概览公告栏和响应式状态。
- `project.ts`/`project.ts types`：项目公告 API 与 DTO 契约。
- `ProjectController`：项目公告 HTTP 适配。
- `ProjectService`：成员授权、阶段验证、当前阶段计算、CRUD、乐观锁与审计。
- `V215`：项目公告持久化及项目、阶段、置顶、时间查询索引。

## 接口、数据和状态流

公告包含 `id`、`project_id`、`stage_code`、`title`、`content_html`、`pinned`、审计字段、`deleted` 与 `row_version`。列表接口按项目查询管理页数据；概览接口根据当天命中的顶级计划阶段返回公告。读取或写入前服务端验证项目成员及阶段属于项目；写入使用版本号，失败返回可恢复冲突语义。

## 错误、降级与恢复

加载失败提供重试；无当前阶段或无公告显示空状态；无权限显示拒绝状态；保存期间禁用重复提交；乐观锁冲突提示刷新。富文本净化失败时拒绝保存，不降级渲染原始 HTML。

## 安全、性能、兼容性与运维

富文本使用现有编辑器依赖并在渲染前净化，禁止脚本、事件属性与危险 URL。当前阶段查询仅扫描当日有效的顶级计划并使用索引限定项目、租户和逻辑删除。保持已有项目 Tabs、主题变量、路由和计划行为不变。上线前以成员和非成员身份验证读写边界。

## 验证策略

执行项目服务及迁移测试、公告 CRUD/成员/跨租户/阶段/乐观锁 API 测试、前端生产构建、范围与治理检查，并在桌面、375x812、390x844、430x932 验收概览和管理路径。

## 假设、未知项与决策记录

- 假设：顶级项目计划的计划日期与阶段能够表达当前实施阶段；若无命中阶段则不展示历史或未来公告。
- D1：所有项目成员维护任意本项目公告，来自用户确认。
- D2：公告使用标题、富文本正文、阶段和置顶，来自用户确认。
- D3：并行当前阶段均展示，按置顶、阶段顺序、发布时间排序，来自用户确认。

## 风险与回退原则

主要风险是富文本安全、成员授权遗漏和并行阶段排序。通过服务端授权、净化测试、API 负向测试和浏览器验收缓解。回退应用代码时保留追加表和公告数据；不得回滚已发布迁移。

## D5：概览布局与投产日历

- 桌面概览上半区为“精简项目信息、当前阶段公告、投产日历”三列等高布局；主计划排期移至下半区并横跨全部列。
- 项目信息只保留项目身份、状态、负责人、周期、进度和必要统计，降低视觉权重；公告与日历使用独立且等高的面板。
- 日历复用现有项目投产日历月查询，不新增数据或接口。默认显示当月，可在当前自然年内前后切换；有投产安排的日期只显示语义品牌色圆点，不显示投产标题或备注。
- 移动端按照项目信息、公告、日历、主计划排期顺序纵向排列；日历保持局部七列网格，禁止页面级横向溢出。
- 用户确认依据：用户确认默认当月、允许切换但仅限当年，并确认上述布局设计。

## D7：投产日历主题内置色系

- 投产安排维护不再选择海湾蓝、科技蓝等全局主题方案，也不向用户展示“主色、成功、警告、危险、信息”等语义名称；改为显示当前主题的五个带色块色系选项“主题色系一”至“主题色系五”。
- 每个色系保存稳定键 `tone-1` 至 `tone-5`，分别映射当前主题的品牌、辅助、强调、提醒和风险色调。概览日期格只引用这些语义 CSS 变量，因此更换全局主题方案或浅深模式后，维护选项和已保存日期格的背景、边框及文字都会即时切换到对应主题的色调。
- `system`、`ocean`、`emerald`、`sunset`、`graphite`、`tech-blue`、`violet`、`amber` 以及 `primary`、`success`、`warning`、`danger`、`info` 为历史兼容值：读取时均按“主题色系一”渲染；编辑并保存后写入当前稳定色系键。维护弹框不再显示这些旧值。
- 不新增表字段、接口、权限、审计或 Flyway 迁移；`theme_key VARCHAR(16)` 已可容纳稳定色系键。
- 用户确认依据：用户明确要求“主题内置色系”，并确认切换全局主题时已维护日期的颜色也必须同步变化。
