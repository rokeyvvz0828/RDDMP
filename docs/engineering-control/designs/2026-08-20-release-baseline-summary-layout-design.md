# 投产基线汇总区分层布局工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户查看现状截图后选择方案 2，并明确回复“确认并实施”。

## 目标与成功信号

修复投产基线汇总区因六项数据落在五列网格中造成的异常换行和大块留白，并通过上下两层结构突出当前投产窗口。桌面端应表现为一条窗口信息栏和一行五项指标，窄屏下指标稳定换行且无横向溢出。

## 使用者与场景

配置管理用户进入投产基线页面、选择投产窗口后，快速确认当前窗口及其中的物理子系统、交付单元、文件介质、投产成功和制品准出数量。

## 必须需求与验收条件

- R1：当前投产窗口必须在汇总区上层独立展示窗口编码、窗口名称和状态，不再与数量指标竞争同一网格轨道。
- R2：五项数量指标在桌面端必须等宽单行排列，不得出现孤立换行或空白第二行。
- R3：窄屏下指标按两列排列，手机端按单列排列；文本和数值不得溢出或遮挡。
- R4：仅调整汇总区模板和样式，不改变窗口选择、数据统计、权限、接口或业务状态。

## 不变量与约束

- 沿用 Vue 3、Element Plus、现有设计变量和 6px 容器圆角。
- 不新增卡片嵌套；窗口信息栏和指标行属于同一汇总容器。
- 不修改 `summary` 计算逻辑、投产窗口接口或后端数据。
- 保护 `rokey` 工作区内其他未提交修改。

## 非目标

- 不重构投产基线工具栏、告警、表格或维护结果弹窗。
- 不改变指标名称、排序和统计口径。
- 不调整其他配置管理页面的汇总组件。

## 方案比较与选择

选择方案 2“窗口信息栏 + 五项指标行”。它能明确区分筛选上下文与统计结果，同时彻底消除六项挤入五列造成的错位。

- 方案 1“六项单行”改动更小，但窗口上下文和统计数字仍处于同一层级。
- 自适应卡片流可减少断点规则，但中间宽度下换行位置不稳定，不适合固定五项指标。

## 架构边界与组件职责

- `ReleaseBaselineView.vue`：为汇总区提供窗口信息层和指标层的语义结构，继续消费现有 `selectedWindow` 与 `summary`。
- `release-prototype.css`：定义两层布局、分隔、稳定尺寸和桌面/窄屏响应式规则。

## 接口、数据和状态流

`selectedWindow` 提供窗口编码、名称和状态；`summary` 继续提供五项计数。模板仅重新分组展示这些现有数据，不增加状态、事件或网络请求。

## 错误、降级与恢复

未选择窗口时继续不展示汇总区。名称过长时允许信息区收缩并截断辅助文本；窄屏按既定断点换列。若样式回归，可独立回退汇总区模板和对应 CSS。

## 安全、性能、兼容性与运维

无权限、接口、数据库或运行配置变化。静态模板与 CSS 调整不产生可感知性能开销，现有数据和浏览器行为保持兼容。

## 验证策略

- 运行 `npm run build` 与 `git diff --check`。
- 在桌面视口确认窗口信息占上层、五项指标等宽单行且无多余留白。
- 在约 760px 和 430px 宽度检查两列/单列布局、边框分隔和无横向溢出。
- 检查空窗口状态仍不显示汇总区，表格加载和筛选行为不变。

## 假设、未知项与决策记录

- 假设：截图红框指向的是汇总区错位与视觉层级问题。
- 未知项：无阻塞未知项。
- D1：采用方案 2，上层展示窗口上下文，下层展示五项统计。
- D2：保持一个汇总容器，不引入嵌套卡片。
- D3：桌面五列、窄屏两列、手机单列。

## 风险与回退原则

主要风险是长窗口名称挤压状态标签，以及断点处边框分隔不连贯。通过可收缩文本容器、溢出省略和断点专用边框规则控制；回退范围仅限两个前端文件。
