# 数据迁移内容 checksum_md5 移除工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认“完整移除并关闭 MD5 查重”，并回复“执行”批准按本设计实施

## 目标与成功信号

从 data-migration 内容模型中移除 `checksum_md5` 的持久化和业务契约，关闭 MD5 查重。成功标准是 7 张文件型内容表不再包含该列或 MD5 索引，创建/替换/报告上传不再接收或计算 MD5，两个 `check-md5` 接口不再可用，附件绑定和文件存储仍可正常工作。

## 使用者与场景

- 数据迁移管理员或普通人员上传计划、映射文档、依赖、脚本、主题、发布演练和汇报材料。
- 用户替换文件或编辑汇报材料时，按记录 `id` 定位，系统不再执行同内容文件查重。
- 回收站、详情、导出和审计继续展示文件名、大小、业务编号和附件关系，不展示 MD5。

## 必须需求与验收条件

### R1 数据模型移除

`dm_plan`、`dm_mapping_doc`、`dm_dependency`、`dm_script`、`dm_topic`、`dm_release_drill`、`dm_report` 不再有 `checksum_md5` 列及 `idx_*_md5` 索引。

验收：在从头执行迁移后的 MySQL 8.4 数据库中，7 张表的 `information_schema.columns` 和 `statistics` 均查不到该列/索引；文档公共列和各表列清单不再描述该字段。

### R2 服务端契约移除

文件内容创建、按 `id` 替换、报告单条/批量上传和报告更新不再接收、校验、写入或返回 MD5；`GET /content/check-md5` 和 `GET /reports/check-md5` 被移除。

验收：Controller、Service、DTO/SQL 和接口测试中不存在 MD5 参数、查重查询或 `checksum_md5` 投影；携带历史 `md5`/`checksumMd5` 参数不会改变写入结果。

### R3 前端契约移除

前端不再计算文件 MD5、不再发送 `md5`/`checksumMd5`，上传、批量上传、替换和回收站页面不展示 MD5。

验收：静态搜索无业务 MD5 计算、查重 API 调用、上传 MD5 字段或 MD5 列表展示；Vue 构建通过，上传流程可完成。

### R4 附件能力保持

`att_file` 创建、下载、绑定、替换、删除和回收逻辑保持不变；文件名、内容类型、大小、对象存储和权限/审计契约不因移除 MD5 改变。相同内容文件允许在同一项目内重复入库。

验收：运行时完成一次新增和一次按 `id` 替换，附件关系和对象可达，重复内容不返回 MD5 冲突。

## 不变量与约束

- `id`、`doc_code`、`active_doc_code`、`attachment_id` 和项目/租户隔离语义不变。
- 只修改当前需求 `writable_paths` 覆盖的 data-migration、需求设计、追加迁移和当前前缀账本文件。
- Flyway 迁移只追加，不修改已发布脚本；新增迁移必须幂等处理列和索引不存在的情况。
- 不修改 `att_file` 平台表，不修改 platform/shared Java 能力，不连接生产环境。
- 当前模块尚未投产，允许移除既有 MD5 HTTP 契约，不提供历史客户端兼容层。

## 非目标

- 不删除附件绑定、对象存储、文件名、内容类型、文件大小或上传审计。
- 不引入新的内容查重算法（SHA-256、ETag 或对象键查重）。
- 不治理 `att_file` 或其他业务模块中的 `checksum`/校验和字段。
- 不修改已发布 V90、V160、V162、V163、V170 等历史迁移脚本；不处理生产历史数据。

## 方案比较与选择

### 已选择：完整移除持久化字段并关闭查重

删除业务字段、索引、查重接口、服务端校验和前端计算；通过新增迁移清理已创建的列和索引。该方案使数据模型、接口和用户行为一致，消除无实际业务价值的计算、索引和维护成本。

### 未选择：仅删除列，保留临时 MD5 查重

需要继续计算和传输一个不落库的隐藏契约，无法跨请求稳定查重，也会保留前后端接口复杂度。

### 未选择：改用其他摘要字段

用户当前目标是取消该能力，不新增等价的隐式查重机制；如未来需要，应另立需求评估摘要算法、唯一性和隐私影响。

## 架构边界与组件职责

- `ContentFileAssetService`：移除 MD5 参数、规范化和查重 SQL；仅负责内容行、附件关系、权限和审计。
- `PlanService`、`ReportService`：创建/更新 SQL 和查询投影移除 MD5；报告 Controller 删除查重及 MD5 参数。
- `ContentAssetTables`：删除 MD5 UNION SQL 和参数构造，仅保留内容表注册与统计能力。
- 前端 API/页面：删除 MD5 类型、计算、查重调用和展示；保留文件上传和按 `id` 替换。
- 新增 Flyway 迁移：按 7 张文件型内容表逐表删除 `idx_*_md5`（存在时）及 `checksum_md5`（存在时），不触碰 `att_file`。

## 接口、数据和状态流

1. 客户端提交项目、元数据和附件 ID；服务端执行认证、项目/实体授权和附件校验。
2. 服务端直接创建或按 `id` 替换内容行，不读取 MD5，也不发起跨表查重查询。
3. 数据库保存内容元数据、`doc_code`、`attachment_id` 和审计字段；不保存摘要字段。
4. 相同内容文件按普通文件处理，可形成多条内容记录；附件生命周期按现有绑定逻辑执行。
5. 查询、回收站和导出返回现有非 MD5 字段；旧客户端附带的未知 MD5 参数被忽略，不影响写入。

## 错误、降级与恢复

- 不再产生 MD5 冲突错误；文件重复只受现有业务编号、项目权限和数据库其他约束影响。
- 缺少附件、跨租户/项目或无权限仍沿用现有错误码和审计行为。
- 旧客户端调用 `check-md5` 返回既有未找到/不支持接口语义；不保留兼容代理。
- 应用回退可恢复旧代码，但已执行的追加迁移不会恢复列；恢复列需要单独批准的前向补偿迁移和备份，当前不执行数据库反向迁移。

## 安全、性能、兼容性与运维

- 移除客户端摘要上传，减少文件内容派生信息暴露和请求体字段。
- 上传路径减少文件读取、摘要计算、跨 7 表查询和索引维护；重复文件占用的对象存储治理不在本次范围。
- 同版本前后端一起发布；模块未投产，允许删除 `check-md5` 和 MD5 参数契约。
- 迁移采用条件删除，可在已无列/索引的环境安全重放；发布前需在隔离 MySQL 8.4 验证完整迁移链。

## 验证策略

- 静态检查：全仓 data-migration 业务代码、API、页面和当前需求文档无 `checksum_md5`、`check-md5`、`computeFileMd5` 或 MD5 上传参数（历史迁移注释/测试夹具需同步收敛）。
- 后端测试：内容和报告创建/替换/查询不含摘要；重复内容可创建；旧参数不会覆盖任何字段；接口不再注册查重路由。
- 数据库测试：隔离 MySQL 8.4 从现有迁移链执行到新迁移，确认 7 张表列和索引已删除、其他列和附件绑定仍在。
- 前端测试：`npm --prefix web run build`，浏览器验证上传、替换、报告批量上传和回收站在桌面及 `390x844` 视口无 MD5 控件、无接口错误、无溢出。
- 工程检查：运行当前模块 Maven 测试、前端构建、治理检查、范围检查和 `git diff --check`；治理/范围基线失败须按无关工作树改动归因。

## 假设、未知项与决策记录

- 假设：数据迁移模块尚未投产，现有客户端可与后端同步升级；依据用户确认。
- D1：完整移除 `checksum_md5` 持久化字段及所有 MD5 查重能力；来源：用户确认“完整移除并关闭 MD5 查重”。
- D2：附件平台能力不变；依据现有 `att_file` 绑定契约和本次非目标。
- D3：历史 Flyway 只追加不改写；新增清理迁移的具体版本号在实施计划中确定。

## 风险与回退原则

- 风险：旧页面或脚本仍调用 `check-md5`，会在升级后得到 404；通过前后端同版本发布和静态契约搜索降低风险。
- 风险：迁移链中历史脚本仍引用该列；必须保证清理迁移排在所有回填/索引脚本之后，并用隔离数据库跑完整链路。
- 风险：关闭查重可能增加重复对象存储；本次不引入替代算法，需由后续容量治理需求单独处理。
- 回退：代码可回退到本次变更前；数据库不执行反向迁移，若需恢复字段必须走独立补偿迁移。
