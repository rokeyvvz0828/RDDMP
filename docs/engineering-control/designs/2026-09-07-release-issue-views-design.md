# 投产问题页面设计

## 状态与目标

修订 1，设计已确认。确认依据：用户对详情抽屉、新增/编辑抽屉、卡片/列表切换及原数据权限保持不变的方案回复“确认”。实施计划另行待复核。

目标是让项目成员无需进入编辑即可阅读问题全文，让维护和连续浏览保留当前列表上下文。需求编号 REQ-20260907-066，R1-R5 见需求文档。

## 方案比较

采用详情、新增、编辑均在右侧抽屉的方案：关闭后仍处于原筛选和页码，避免增加路由。另一方案是独立详情页面，适合分享独立链接和大型详情，但会增加返回步骤，本次不采用。

## 页面与控件

- 保留“投产问题分析及跟踪”标题和新增问题主操作，关键词、优先级、状态及查询操作保持原有含义；不增加统计块或介绍文案。
- 工具栏增加列表/卡片图标分段控件，使用 Element Plus 图标、tooltip 和可访问名称；两种视图只改变同一个 `issues` 数组的呈现方式。
- 列表保留当前业务列，问题标题可点击，操作列包含详情以及按权限显示的编辑/删除。
- 卡片为同层重复记录：问题编号/标题、优先级/状态、轮次、负责人、发现时间和分析摘要，正文长文在详情中完整呈现。标题和详情按钮进入详情，编辑/删除按钮不触发详情。手机单列，桌面随容器宽度重排，不使用嵌套卡片。
- 共用服务端分页，切换视图不请求、不重置页码；关键词查询和改变每页条数仍回到第一页。视图偏好仅存于当前组件会话，不引入持久化配置。

## 抽屉

详情为只读排版，不使用禁用输入框冒充详情。基本信息以标签和描述项展示，四个全文字段分为问题描述、分析结论、处理措施和跟踪记录，保留换行并以文本插值渲染，不使用 v-html。

新增/编辑沿用同一套字段和保存流程。分为基本信息、问题描述、分析与处理、跟踪记录，手机全部单列。抽屉最大宽 760px，宽度不超过视口，正文内部纵向滚动，头尾操作可达。从详情点击编辑使用同一抽屉切换模式，避免叠加两个维护抽屉；取消或保存后回到原筛选/分页位置。

维护表单发生改动后关闭时提示是否放弃；取消放弃确认继续编辑，保存失败保留输入。保存中禁重并阻止关闭。编号、标题和关闭时间规则不变，不增加业务字段或改变 payload。新增和编辑的保存结果仍以服务端响应及原刷新流程为准。

## 状态、数据与权限

复用现有 ReleaseIssueDto/Write、listReleaseOperationsIssues、create/update/deleteReleaseOperationsIssue、项目成员和演练轮次选项。列表响应已包含详情全文，不创建平行详情数据源，不新增后端调用。

查看入口不依赖 canManage，写入口继续依赖原管理权限。403、加载错误、空结果、保存中和删除取消使用现有语义；项目切换由父组件 key 重建问题组件，清除当前抽屉数据。详情记录与编辑表单分离，取消不得改动原记录。

## 复用与样式边界

参考交付示范中心 DeliveryProjectList 的操作层级、列表/卡片字段优先级和状态反馈，复用 UiPageHeader、UiToolbar、UiStatusTag、UiEmptyState 及 Element Plus 表格/抽屉/表单。

现有 UiFormDrawer 未直接暴露保存禁用状态，优先使用现有 Element Plus drawer 并沿用共享抽屉布局约定，不修改公共组件。问题全文详情与手动双视图是业务组合，必要样式仅在 ReleaseIssueTrackingView 内生效；teleport 内部样式使用问题抽屉专用类限定，不影响其他页面。

## 响应式与验收

以 760px 作为首次进入的手机默认视图判断边界，采用已有依赖或浏览器 matchMedia，不新增依赖。布局变化不自动覆盖用户已选择模式。表格局部横滚，分页控件在手机端使用可容纳的布局，不隐藏总数与翻页能力。

验证 375x812、390x844、430x932、1280px 以上以及浅深主题。分别检查详情全文、双视图数据一致性、筛选和分页保持、抽屉取消与保存、只读/403、空/失败/加载、长文本、重复提交、项目切换及滚动边界。

## 风险与回退

主要风险是表格和卡片状态漂移、详情与编辑表单互相污染、teleport 样式失效和移动端表单 footer 不可达。通过单一 records/分页状态、表单副本、抽屉专用选择器和真实浏览器交互验收控制。

不读取生产或敏感数据；不改 API/权限/审计/数据库。缺少角色、写入夹具或工具时如实记录测量缺口。回退仅撤销本组件专项改动，无迁移和数据补偿。无未决产品范围问题。
