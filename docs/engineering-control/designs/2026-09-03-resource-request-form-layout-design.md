## 目标与成功信号

在不改变资源申请业务契约的前提下，降低多明细登记时的纵向滚动和定位成本。成功信号是用户可在稳定主从工作区中维护基础信息和多条申请项，切换不丢内容，错误能定位到具体申请项，最终请求仍为现有 `items[]`。

## 使用者与场景

资源申请人在资源申请页面新建或编辑草稿。用户先在左侧确定物理子系统、联系人、环境、类型和原因，再在右侧列表中新增、删除或选择申请项，并在当前项表单内选择部署单元和填写资源规格。

## 必须需求与验收条件

| ID | 必须需求 | 验收条件 |
| --- | --- | --- |
| R1 | 外层分为基础信息和登记表两栏。 | 桌面两栏稳定；申请级字段和物理摘要在左侧；登记行为在右侧。 |
| R2 | 登记表使用申请项列表与当前项表单的主从布局。 | 左列可新增、删除、切换；右列只显示当前项；切换不丢数据。 |
| R3 | 保留重复部署单元多规格。 | 部署单元在当前项表单选择；不同申请项可选择相同部署单元并提交不同规格。 |
| R4 | 申请项具有状态和错误定位。 | 显示未选择、待完善、已填写；保存校验失败自动选中首个错误项。 |
| R5 | 物理子系统切换保护已有申请项。 | 有内容时确认；确认后清空、重建空项并刷新候选；取消恢复原状态。 |
| R6 | API、字段分流和校验语义兼容。 | `items[]` 结构和顺序、DB/非 DB 表单、计算和服务端校验不变。 |
| R7 | 全状态和响应式体验可用。 | 加载、失败、无权限、提交中、脏表单保护可见；四视口和明暗主题无页面级横向溢出。 |

## 不变量与约束

- 只修改 `ResourceRequestPage.vue` 和架构模块局部样式，不修改公共 UI。
- 不改变资源申请 API、类型、数据库、权限、审计、工作流和后端逻辑。
- `items[]` 顺序由列表顺序决定，重复 `deploymentUnitId` 合法。
- 固定强类型表单，不接入动态表单元数据。
- 手机端不使用整页横向滚动或缩小字号解决布局。

## 非目标

- 不实现自动保存、拖拽排序、复制申请项或批量套用规格。
- 不改变列表、详情、审批、下发和环境实例功能。
- 不新增接口、持久化字段或迁移。
- 不重构架构模块或公共组件。

## 方案比较与选择

### 已选：两级主从申请项编辑

外层为基础信息和登记表，内层为申请项列表和当前项表单。该方案在申请项增长时仍可扫描、切换和定位，同时保持现有数据契约。

### 未选：申请项标签页

标签较多时不易扫描，横向拥挤，手机端处理成本较高。

### 未选：纵向折叠全部明细

仍会形成长页面，不能解决定位和切换成本。

## 架构边界与组件职责

- 基础信息栏：维护申请级字段、物理子系统摘要和切换保护。
- 申请项列表：维护当前临时 ID，展示顺序、部署单元摘要和完成状态，提供新增删除。
- 当前项编辑器：复用现有 DB/非 DB 字段模板、计算和同步逻辑。
- 表单状态适配：为申请项生成前端临时 ID，编辑回显时补齐，提交时剥离，校验时返回错误项。
- 响应式样式：桌面双层分栏，中等宽度登记区改为上下布局，手机端外层和字段单列。

## 接口、数据和状态流

新建时创建一个带临时 ID 的 `blankItem()` 并选中。新增后立即选中新项；删除当前项后优先选择下一项，否则选择上一项；只有一项时禁用删除。编辑时按服务端 `items[]` 原顺序映射并默认选中第一项。

物理子系统变更前保存旧值。若申请项仍为单个空项，可直接重建和加载候选；否则显示确认。确认后清空旧项、创建一个空项并加载新候选；取消时恢复旧物理子系统且不刷新候选。

校验先检查申请级字段，再逐项执行现有容量、整数、需求和网络分区规则。列表状态复用相同规则：未选择部署单元为“未选择”，已选择但不完整为“待完善”，满足前端规则为“已填写”。提交仍执行 `form.items.map(requestItemPayload)`。

## 错误、降级与恢复

- 候选加载失败：保留当前项和已有部署单元快照，显示可重试错误。
- 校验失败：显示持续错误并切换到首个错误申请项。
- 保存失败：保留弹窗、顺序、选中项和全部输入。
- 保存中：禁用新增、删除、切换、基础选择和提交。
- 关闭脏表单：拦截关闭并确认，取消关闭时保持上下文。

## 安全、性能、兼容性与运维

安全边界不变，服务端继续负责认证、RBAC、租户、申请人和实体校验。只渲染当前申请项完整字段，列表仅显示摘要，可减少多明细 DOM。提交载荷、字段含义和顺序保持。无数据库或配置变化，回退仅需回退前端提交。

## 验证策略

- R1/R2：桌面检查两级分栏、连续新增、切换和删除相邻选择。
- R3/R6：创建两个相同部署单元的申请项，填写不同规格，检查 Network 请求和编辑回显。
- R4：构造未选择、DB 不完整和非 DB 缺网络分区，检查状态和自动定位。
- R5：验证空项直接切换、有内容确认清空、有内容取消恢复。
- R7：执行构建、治理、scope、diff，并在 1280、375、390、430 视口和明暗主题检查滚动、遮挡、长名称与底部操作。

## 假设、未知项与决策记录

- 假设：申请项列表顺序即提交顺序，不需要拖拽调整。证伪条件是用户要求重排。
- 假设：现有资源申请页面没有可直接复用的组件单测入口；若实施勘察发现，则计划补充聚焦测试。
- D1：保留同一部署单元多规格重复明细。
- D2：左列采用申请项列表，部署单元在右侧表单选择。
- D3：物理子系统变更确认后清空全部申请项，取消则恢复。
- D4：桌面双层分栏、中等宽度登记区上下、手机端单列。
- 当前无阻塞未知项。

## 风险与回退原则

数组索引可能导致切换或删除后内容错位，因此使用稳定临时 ID。状态判定可能与最终校验分叉，因此状态与校验复用相同无副作用规则，服务端仍为最终事实源。双层分栏在窄桌面下可能压缩字段，因此设置明确断点重排，不缩小字号。回退本需求前端提交即可恢复原表单，无数据补偿。
