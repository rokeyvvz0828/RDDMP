# 资源申请表单主从布局工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户于 2026-09-03 回复“可以”，确认落盘设计修订 1。

## 目标与成功信号

在不改变资源申请业务契约的前提下，降低多明细登记时的纵向滚动和定位成本。成功信号是用户可在稳定主从工作区中维护基础信息和多条申请项，切换不丢内容，错误能定位到具体申请项，最终请求仍为现有 `items[]`。

## 使用者与场景

资源申请人在资源申请页面新建或编辑草稿。用户先在左侧确定物理子系统、联系人、环境、类型和原因，再在右侧列表中新增、删除或选择申请项，并在当前项表单内选择部署单元和填写资源规格。

## 必须需求与验收条件

| ID | 必须需求 | 验收条件 |
| --- | --- | --- |
| R1 | 外层分为基础信息和登记表两栏。 | 桌面两栏稳定；申请级字段和物理摘要在左侧；登记行为在右侧。 |
| R2 | 登记表使用申请项列表与当前项表单的主从布局。 | 左列可新增、删除、切换；右列只显示当前项；切换不丢数据。 |
| R3 | 保留重复部署单元多规格。 | 部署单元在当前项表单选择；不同申请项可选择相同部署单元并提交不同规格。 |
| R4 | 申请项具有状态和错误定位。 | 显示未选择、待完善、已填写；保存校验失败自动选中首个错误项。 |
| R5 | 物理子系统切换保护已有申请项。 | 有内容时确认；确认后清空、重建空项并刷新候选；取消恢复原状态。 |
| R6 | API、字段分流和校验语义兼容。 | `items[]` 结构和顺序、DB/非 DB 表单、计算和服务端校验不变。 |
| R7 | 全状态和响应式体验可用。 | 加载、失败、无权限、提交中、脏表单保护可见；四视口和明暗主题无页面级横向溢出。 |

## 不变量与约束

- 只修改 `ResourceRequestPage.vue` 和架构模块局部样式，不修改公共 UI。
- 不改变资源申请 API、类型、数据库、权限、审计、工作流和后端逻辑。
- `items[]` 顺序由列表顺序决定，重复 `deploymentUnitId` 合法。
- 固定强类型表单，不接入动态表单元数据。
- 手机端不使用整页横向滚动或缩小字号解决布局。

## 非目标

- 不实现自动保存、拖拽排序、复制申请项或批量套用规格。
- 不改变列表、详情、审批、下发和环境实例功能。
- 不新增接口、持久化字段或迁移。
- 不重构架构模块或公共组件。

## 方案比较与选择

### 已选：两级主从申请项编辑

外层为基础信息和登记表，内层为申请项列表和当前项表单。该方案在申请项增长时仍可扫描、切换和定位，同时保持现有数据契约。

### 未选：申请项标签页

标签较多时不易扫描，横向拥挤，手机端处理成本较高。

### 未选：纵向折叠全部明细

仍会形成长页面，不能解决定位和切换成本。

## 架构边界与组件职责

- 基础信息栏：维护申请级字段、物理子系统摘要和切换保护。
- 申请项列表：维护当前临时 ID，展示顺序、部署单元摘要和完成状态，提供新增删除。
- 当前项编辑器：复用现有 DB/非 DB 字段模板、计算和同步逻辑。
- 表单状态适配：为申请项生成前端临时 ID，编辑回显时补齐，提交时剥离，校验时返回错误项。
- 响应式样式：桌面双层分栏，中等宽度登记区改为上下布局，手机端外层和字段单列。

## 接口、数据和状态流

新建时创建一个带临时 ID 的 `blankItem()` 并选中。新增后立即选中新项；删除当前项后优先选择下一项，否则选择上一项；只有一项时禁用删除。编辑时按服务端 `items[]` 原顺序映射并默认选中第一项。

物理子系统变更前保存旧值。若申请项仍为单个空项，可直接重建和加载候选；否则显示确认。确认后清空旧项、创建一个空项并加载新候选；取消时恢复旧物理子系统且不刷新候选。

校验先检查申请级字段，再逐项执行现有容量、整数、需求和网络分区规则。列表状态复用相同规则：未选择部署单元为“未选择”，已选择但不完整为“待完善”，满足前端规则为“已填写”。提交仍执行 `form.items.map(requestItemPayload)`。

## 错误、降级与恢复

- 候选加载失败：保留当前项和已有部署单元快照，显示可重试错误。
- 校验失败：显示持续错误并切换到首个错误申请项。
- 保存失败：保留弹窗、顺序、选中项和全部输入。
- 保存中：禁用新增、删除、切换、基础选择和提交。
- 关闭脏表单：拦截关闭并确认，取消关闭时保持上下文。

## 安全、性能、兼容性与运维

安全边界不变，服务端继续负责认证、RBAC、租户、申请人和实体校验。只渲染当前申请项完整字段，列表仅显示摘要，可减少多明细 DOM。提交载荷、字段含义和顺序保持。无数据库或配置变化，回退仅需回退前端提交。

## 验证策略

- R1/R2：桌面检查两级分栏、连续新增、切换和删除相邻选择。
- R3/R6：创建两个相同部署单元的申请项，填写不同规格，检查 Network 请求和编辑回显。
- R4：构造未选择、DB 不完整和非 DB 缺网络分区，检查状态和自动定位。
- R5：验证空项直接切换、有内容确认清空、有内容取消恢复。
- R7：执行构建、治理、scope、diff，并在 1280、375、390、430 视口和明暗主题检查滚动、遮挡、长名称与底部操作。

## 假设、未知项与决策记录

- 假设：申请项列表顺序即提交顺序，不需要拖拽调整。证伪条件是用户要求重排。
- 假设：现有资源申请页面没有可直接复用的组件单测入口；若实施勘察发现，则计划补充聚焦测试。
- D1：保留同一部署单元多规格重复明细。
- D2：左列采用申请项列表，部署单元在右侧表单选择。
- D3：物理子系统变更确认后清空全部申请项，取消则恢复。
- D4：桌面双层分栏、中等宽度登记区上下、手机端单列。
- 当前无阻塞未知项。

## 风险与回退原则

数组索引可能导致切换或删除后内容错位，因此使用稳定临时 ID。状态判定可能与最终校验分叉，因此状态与校验复用相同无副作用规则，服务端仍为最终事实源。双层分栏在窄桌面下可能压缩字段，因此设置明确断点重排，不缩小字号。回退本需求前端提交即可恢复原表单，无数据补偿。

# 修订 2：UAT 紧凑布局调整

## 文档状态

- 修订：2
- 状态：已确认
- 用户确认依据：用户于 2026-09-03 回复“可以”，批准修订 2；此前已确认“固定登记区高度与内部滚动”方案，并选择空申请项标题显示“未选择部署单元”。

## 目标与成功信号

在保持修订 1 主从交互、数据和请求契约不变的前提下，减少基础信息与资源字段的非必要占用，使登记表占满弹窗可用高度并在内部滚动。成功信号是用户在 1920×1080 下同时看到弹窗标题、主要基础信息、登记区和底部操作，并能在 1280×800 下通过登记区内部滚动完成全部填写。

## 必须需求与验收条件

| ID | 必须需求 | 验收条件 |
| --- | --- | --- |
| R8 | 基础信息区减少非必要纵向占用。 | 申请原因桌面端默认 2 行；基础字段和物理摘要保持可读；不隐藏必填信息。 |
| R9 | 登记表占满弹窗可用高度并内部滚动。 | 主从容器拉伸到 body 剩余高度；申请项列表和当前项编辑器独立滚动；标题和 footer 保持可见。 |
| R10 | 数值字段使用短输入框。 | 桌面端数值输入宽约 140–180px；步进按钮和长数值可用；手机端恢复满宽。 |
| R11 | 申请项主标题使用部署单元名称。 | 已选择时列表和编辑器顶部显示部署单元名称；未选择时显示“未选择部署单元”；序号仍用于错误和删除定位。 |
| R12 | 桌面布局优先提高一屏可见信息量。 | 1920×1080 下标题、主要基础信息、登记区和 footer 同时可见；1280×800 下无页面级横向溢出；超高内容在登记区内部访问。 |

## 不变量与非目标

- 不改变 `ResourceRequestPayload`、`items[]` 顺序、重复部署单元、DB/非 DB 字段分流和校验。
- 不修改 API、DTO、后端、数据库、权限、审计、工作流、公共 UI 或应用壳。
- 不通过缩小正文字号、隐藏字段或启用全局高密度模式换取单屏展示。
- 不增加基础信息折叠、自动保存、排序、复制或批量填写。

## 方案比较与选择

选择“固定登记区高度与内部滚动”：弹窗使用视口内稳定高度，外层两栏拉伸至同高；基础信息自然展示，登记表占满剩余高度，列表和编辑器分别滚动。申请原因缩为 2 行，数值字段使用短输入框，部署单元名称成为主标题。

未选择“基础信息自动折叠”，因为会隐藏申请范围上下文并增加展开状态。未选择“全局高密度控件”，因为会影响可读性和触控体验，并扩大影响范围。

## 组件与状态设计

- 弹窗高度链：Dialog body、外层布局、登记表和主从容器均允许收缩，使用明确的 `min-height: 0` 和剩余高度分配。
- 申请项列表：桌面端独立纵向滚动；移动端继续保持局部横向滚动。
- 当前项编辑器：桌面端独立纵向滚动，标题和状态位于编辑器顶部；不把滚动传递到页面根。
- 数值字段：桌面端使用专用短宽样式，选择器和文本字段保持可伸展；手机端覆盖为 `width: 100%`。
- 标题：列表和编辑器主标题读取 `deploymentUnitName || '未选择部署单元'`；状态文字保留；序号只进入错误提示、删除提示和辅助定位。
- 基础信息：申请原因由 4 行改为 2 行，并压缩局部分区间距；物理摘要不删除字段。

## 错误、兼容性与恢复

候选失败、保存失败、物理子系统切换确认、脏表单保护和保存中禁用行为完全沿用修订 1。标题变化只消费已有 `deploymentUnitName`，不进入 HTTP 请求。短输入框只改变呈现宽度，不改变数值范围、精度和提交映射。

## 验证策略

- R8：检查桌面申请原因为 2 行，基础字段和摘要完整可编辑。
- R9/R12：在 1920×1080、1280×800 明暗主题检查 Dialog、body、登记表、列表和编辑器的 `clientHeight/scrollHeight/overflow`，确认 footer 可见且页面根无横向溢出。
- R10：检查所有数字输入桌面计算宽度、步进按钮和长数值；375×812、390×844、430×932 下恢复满宽。
- R11：验证空项、选择部署单元、重复部署单元和切换时，两处标题同步；保存错误仍显示申请项序号。
- 回归：重新执行前端构建、scope、diff、新建/编辑请求和四视口明暗主题验收。

## 风险与回退原则

多层高度和 `overflow` 可能形成错误滚动容器，导致 footer 遮挡或内容不可达，因此必须用真实浏览器计算尺寸验证滚动节点。短数值输入框可能无法容纳极端长值，需保留 140–180px 的可用宽度并在手机端恢复满宽。回退修订 2 的局部模板与 CSS 提交即可恢复修订 1，无数据补偿。

# 修订 3：容量与部署 Flex 布局

## 文档状态

- 修订：3
- 状态：已确认
- 用户确认依据：用户于 2026-09-03 回复“可以”，批准落盘设计修订 3；此前已确认桌面端按可用宽度自动排列，每行尽量展示 3–4 个字段。

## 目标与成功信号

在保持修订 1、修订 2 的主从交互、内部滚动、字段语义和请求契约不变的前提下，将“容量与部署”字段区改为 Flex 自适应换行，减少当前固定两列产生的大面积空白。成功信号是宽桌面下一行可稳定展示 3–4 个字段，中等宽度自然换行，手机端保持单列满宽且无页面级横向溢出。

## 必须需求与验收条件

| ID | 必须需求 | 验收条件 |
| --- | --- | --- |
| R13 | “容量与部署”字段区必须使用 Flex 自适应换行。 | 桌面端按可用宽度排列且每行尽量展示 3–4 项；选择类字段宽于数值字段；计算摘要独占整行；中等宽度自然换行；手机端字段单列满宽。 |

## 不变量与非目标

- 不改变字段顺序、显示条件、必填规则、计算、校验、状态或提交映射。
- 不改变修订 2 的短数值输入宽度、编辑器内部滚动和 footer 可见性。
- 不修改 API、DTO、后端、数据库、权限、审计、工作流、公共 UI 或应用壳。
- 不为每个字段手工拆分固定行，不引入新的公共布局组件或断点体系。

## 方案比较与选择

选择“字段项 Flex 自适应换行”：容量区增加专用局部类，容器使用 `display: flex` 和 `flex-wrap: wrap`。选择器类字段使用较宽的 basis，数值字段使用较窄的 basis，“有边车”按内容需要占位，计算摘要占满整行。该方案直接满足用户指定的 Flex 布局，并能根据编辑器实际宽度自动重排。

未选择“所有字段统一 Flex 宽度”，因为选择器和数值框的信息密度不同，统一宽度仍会浪费空间。未选择“模板拆成固定 Flex 行”，因为字段条件变化和不同视口下容易形成空洞，响应式维护成本更高。

## 组件与响应式设计

- 容量字段容器：仅替换该区域原有固定两列网格，不影响部署单元区和其他表单网格。
- 选择类字段：服务器类型、网络分区等使用约 280–320px 的首选宽度，允许在剩余空间不足时换行。
- 数值字段：字段项使用约 180–220px 的首选宽度，内部 `el-input-number` 继续保持修订 2 的约 160px 短宽。
- 布尔字段：“有边车”按控件和标签所需宽度排列，不拉伸为整列。
- 计算摘要：使用 `flex-basis: 100%` 独占整行，保证总 CPU、总内存和边车内存占比可扫描。
- 手机端：容量字段项统一 `flex-basis: 100%`，输入控件继续满宽；不得产生页面级横向滚动。

## 错误、兼容性与恢复

字段加载、候选失败、校验失败、保存失败和提交中禁用行为均沿用前两轮设计。Flex 只改变布局，不改变 DOM 字段绑定和数据流。若浏览器不满足目标排列，回退修订 3 的容量区专用类和局部 CSS 即可恢复修订 2，无数据补偿。

## 验证策略

- 在 1920×1080 和 1280×800 明暗主题检查容量区字段的计算样式、每行数量、自然换行、摘要整行及 footer 可见性。
- 在 375×812、390×844、430×932 检查容量字段单列满宽、数值输入可操作、页面根无横向溢出。
- 回归 DB 与非 DB 字段分流、有边车开关、自动计算、校验、申请项切换和新建/编辑保存请求。
- 执行前端构建、scope、diff 和治理检查；不把未执行的浏览器验收描述为通过。

## 风险与回退原则

Element Plus 的 `.el-form-item` 和条件字段可能影响 flex basis 或换行，因此必须在真实浏览器中检查计算宽度，而不能只依赖截图。长标签或长选项可能占用额外空间，应通过允许换行和字段最小宽度保持可读，不缩小字号。回退仅涉及 `ResourceRequestPage.vue` 的容量区专用类和 `architecture.css` 的局部 Flex 规则。
