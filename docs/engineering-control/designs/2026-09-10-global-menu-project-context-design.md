# 全局菜单项目上下文工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户复核并确认本落盘修订。

## 目标与成功信号

将项目管理和系统级菜单定义为全局入口。进入这些页面时不要求初始化或选择项目上下文，桌面与移动端都不显示项目选择器；已保存的项目选择在返回项目内业务时仍有效。

认证完成或会话恢复时，如果缺少有效的本地项目 ID，应用壳会复用项目工作台的既有选择逻辑，恢复首个可访问项目并取得其完整项目级菜单；无法取得项目列表时维持已加载的系统级授权快照。

## 使用者与场景

具备系统权限的用户访问 `/system/**`，以及在任一可访问项目具备 `project:project:list` 的用户访问 `/projects`。用户可以从未选择项目的登录状态直接进入这些菜单，也可以从项目内页面返回全局菜单而不丢失已选项目。

## 必须需求与验收条件

| ID | 要求 | 验收 | 反例 |
| --- | --- | --- | --- |
| R1 | 全局路由不初始化项目上下文，也不显示选择器。 | `/projects` 与 `/system/**` 在桌面和 390x844 下均隐藏选择器；已选项目保留。 | 进入系统菜单触发项目加载或显示选择器。 |
| R2 | 项目管理入口由任一可访问项目的项目管理权限决定。 | 有任一 `project:project:list` 时路由含 `/projects`；只有其他项目权限或无此权限时不含。 | 当前项目未选导致有权用户失去入口，或计划权限意外授予入口。 |
| R3 | 项目内业务行为不被放宽。 | 项目业务路由仍初始化上下文；项目 API 仍携带并校验 `X-Project-Id`。 | 全局菜单改动使项目 API 可无上下文访问。 |

## 不变量与非目标

- 不修改 JWT、公开 API、数据库结构、项目业务表或既有 V202 迁移。
- 系统级菜单继续使用系统权限；项目管理不因任意 `project:*` 权限而放宽。
- 项目内路由、数据范围、服务端 RBAC 和实体授权不变。
- 不清除或重写已保存的项目选择。

## 方案比较与选择

1. 路由元数据标注全局路由，并由路由守卫和应用壳层共同消费。推荐：单一且可审查的页面范围，避免路径判断分散。
2. 在 `AppLayout` 维护路径前缀数组，只隐藏选择器。拒绝：不能阻止守卫初始化上下文，不能满足无需限制。
3. 改为所有页面都不初始化项目上下文。拒绝：会破坏项目业务数据范围和权限刷新。

## 架构边界与组件职责

- `web/src/router/index.ts`：为 `/projects` 与 `/system/**` 设置全局上下文元数据，守卫据此跳过项目初始化和按项目刷新授权。
- `web/src/views/AppLayout.vue`：根据匹配路由元数据，统一控制三个选择器（顶部、普通头部、移动抽屉）的渲染。
- `AuthRepository`：仅查询用户在任一可访问项目中持有的 `project:project:list` 权限。
- `AuthService`：在不带项目上下文的动态路由生成中，仅以该聚合权限激活 `/projects`；其他项目菜单保持需要当前项目权限。
- `web/src/stores/auth.ts`：先应用全局授权快照，再在本地项目 ID 缺失时调用 `project-context` store；取得有效项目后重新拉取授权，失败时不清空先前快照或登录态。

## 接口、数据和状态流

全局路由导航不调用项目上下文初始化，且保留 localStorage 中原项目标识。动态菜单在无项目上下文时由系统权限加项目管理聚合权限生成；项目内路由仍按已选项目加载权限。HTTP 拦截器和服务端项目 API 的 `X-Project-Id` 契约不变。

## 错误、兼容性与恢复

全局菜单的项目管理权限查询失败时按失败关闭，不返回 `/projects`；系统菜单仍按已有系统权限生成。若项目上下文在进入全局页面前不存在，返回项目业务页面时沿用现有初始化与错误反馈。回退仅撤销路由元数据、选择器条件和聚合权限逻辑，V202 菜单文本修复保留。

## 验证策略

- Security 单元测试：有任一项目管理权限、仅其他项目权限、无项目权限三种路由结果。
- 前端构建和浏览器：桌面及 390x844 验证 `/projects`、`/system/**` 的选择器隐藏与项目业务页面恢复显示。
- API/权限探针：无 `X-Project-Id` 的全局动态路由结果；项目业务 API 仍拒绝缺失或伪造上下文。

## 风险与决策记录

聚合查询必须绑定租户、有效项目成员关系和项目角色权限，超级管理员维持其既有全权限语义。用户已确认“任一可访问项目的项目管理权限”作为入口规则；仅 `project:project:list` 可激活项目管理，其他项目权限不能替代。
