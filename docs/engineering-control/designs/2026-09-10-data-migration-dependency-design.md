# 迁移过程依赖文件菜单优化工程设计

## 文档状态

- 状态：已确认

## 目标与成功信号

将“迁移过程依赖文件”从附件资产改造成迁移参数与使用方系统的关系管理页。成功信号是用户能按当前项目新增、编辑、导入、查询和删除关系，列表准确展示参数与两侧系统信息，旧文件上传/替换/下载入口消失，数据库和服务端共同拒绝重复或越权关系。

## 使用者与场景

- 迁移配置维护人员选择已有迁移参数和使用方系统，登记或调整依赖关系。
- 批量维护人员下载两列模板，导入多条关系并查看逐行失败原因。
- 查询人员按参数或系统信息筛选并比较提供方、使用方和更新时间。
- 管理员在统一回收站恢复或彻底删除关系。

## 必须需求与验收条件

1. `dm_dependency` 使用 `parameter_id` 关联迁移参数，现有 `system_code` 表示使用方系统；空表迁移删除 `doc_code/doc_name`。
2. 列表展示参数英文名、参数中文名、使用方编号/中文名、提供方编号/中文名、更新时间和更新人。
3. 单条新增和编辑只接受当前租户、项目中的活动参数及启用系统，关系键在租户和项目内唯一。
4. Excel 模板仅含参数英文名和使用方系统编号；合法行部分成功，零命中、多义、无效系统和重复行逐行失败。
5. `DEPENDENCY` 从通用附件 CRUD 和回收站来源剥离，旧上传、替换、下载端点和页面操作下线。
6. 新专属接口执行菜单 750 的查看、新增、编辑、删除权限，并保留项目/实体授权与 `DEPENDENCY` 审计。
7. 逻辑删除、恢复和彻底删除由统一回收站承接；活动依赖阻止删除对应参数。
8. 看板 DEPENDENCY 计数和下钻不再引用已删除列，页面在桌面和手机视口覆盖完整异步状态。

## 不变量与约束

- 数据 Owner 保持 `business/data-migration`，路由和菜单 750 不变。
- 提供方编号固定来自 `dm_parameter.system_code`；使用方编号固定来自 `dm_dependency.system_code`。
- 两侧系统名称只做当前租户/项目的只读投影，不在依赖表冗余保存。
- 迁移参数英文名唯一范围保持“租户 + 项目 + 提供方系统”，本需求不扩大该约束。
- Flyway 只追加 V199，不修改 V162、V182、V190、V197 或 V198。
- `dm_dependency.component_id` 保留为未使用兼容列；不处理历史附件，因为空表门禁保证不存在待转换业务行。
- 不连接生产系统，不使用真实生产数据或附件。

## 非目标

- 不提供依赖关系导出，不重构其他文件资产服务。
- 不修改迁移参数字段、系统/组件清单或系统参数管理。
- 不新建公共 UI 组件、主题或路由。
- 不自动选择多义参数，不覆盖重复关系。

## 方案比较与选择

选择方案 A：新增 `DependencyService`、`DependencyController`、`DependencyRecycleBinSource` 和专属页面，并将 DEPENDENCY 从通用文件资产链路剥离。该方案与迁移参数、检核规则的域化范式一致，能从路由和服务边界彻底取消附件行为。

未选择在 `ContentFileAssetService` 中按类型分支，因为参数关系、Excel 和附件生命周期会混在同一服务，容易保留误用入口。未选择新建并行关系表，因为它违背改造 `dm_dependency` 和删除旧字段的明确要求，还会产生重复数据 Owner。

## 架构边界与组件职责

- `V199__data_migration_dependency_domain.sql`：空表断言、增加 `parameter_id`、删除旧列/索引、建立唯一键与查询索引、补充菜单 750 细粒度权限。
- `DependencyService`：列表/详情、参数选项、CRUD、Excel 模板与导入、判重、关联投影、审计和回收站行为。
- `DependencyController`：保持 `/api/data-migration/dependencies` 前缀，定义专属 HTTP 与权限契约。
- `DependencyRecycleBinSource`：向统一回收站注册 `DEPENDENCY`，不再经过附件来源。
- `ContentFileAssetService`、`ContentAssetController`、`ContentAssetRecycleBinSource`：移除 DEPENDENCY 直接管理和旧端点，保留其他专属服务仍复用的附件辅助能力。
- `ParameterService`：参数逻辑删除前检查活动依赖，彻底删除前检查所有依赖记录。
- `DashboardMetricDefinition`：用关联参数的中英文名构造 DEPENDENCY 下钻标识，不再读取 `doc_code/doc_name`。
- `web/src/api/data-migration.ts`、`DependenciesPage.vue`：专属类型/API、桌面表格、移动卡片、表单与导入状态。

## 接口、数据和状态流

列表 `GET /dependencies` 接受 `projectId`、`consumerSystemCode`、`keyword`、`page`、`size`。关键字匹配参数中英文名和提供方/使用方系统编号及中文名。响应至少包含 `id/project_id/parameter_id/parameter_name_en/parameter_name/provider_system_code/provider_system_name/consumer_system_code/consumer_system_name/updated_at/updated_by/updated_by_name`。

`GET /dependencies/options/parameters` 在当前项目内按关键字返回活动参数选项，标签为“英文名 / 中文名 · 提供方编号 - 名称”。使用方继续复用 `/components/options/systems`，需让依赖菜单查看权限能够访问该公共选项端点。

新增 `POST /dependencies` 使用 `projectId/parameterId/consumerSystemCode`；更新 `PUT /dependencies/{id}` 不允许改变记录所属项目，只接受 `parameterId/consumerSystemCode`。删除 `DELETE /dependencies` 接收 ID 数组并逻辑删除。写入前服务校验租户、项目、参数、启用系统、Owner/管理员权限和唯一性，数据库唯一键兜住并发。

模板 `GET /dependencies/template` 固定两列。导入 `POST /dependencies/import?projectId=...` 只接受 `.xlsx`、最大 50 MB 和 5000 行。参数英文名在当前项目做不区分大小写精确查询：一条命中则取 ID，零条或多条失败。文件内和数据库按 `parameter_id + consumer_system_code` 判重。每个合法行持久化并审计，响应返回 `rows/accepted/failed/errors`。

## 错误、降级与恢复

- 参数或系统缺失、跨项目、已删除/停用：400，明确指出字段原因。
- 重复关系或并发唯一键冲突：409，不覆盖原记录。
- 导入文件类型、大小、行数或表头非法：拒绝整个文件；业务行错误只跳过该行。
- 参数英文名多义：该行失败并提示先调整参数数据，不任取一条。
- 迁移发现历史行：V199 在结构修改前失败，旧列和数据保持原状。
- 恢复时重新校验参数活动状态和使用方系统；不满足时拒绝恢复并保留回收站记录。

## 安全、性能、兼容性与运维

- 安全：Controller 和 Service 双层落实认证、RBAC、项目范围与实体写权限；请求中的项目和身份均不可信任。
- 性能：列表服务端分页；关系唯一键和项目/使用方/更新时间索引支持判重与筛选；参数选项返回有界结果。
- 兼容性：查询前缀保留但响应语义变化，旧上传/下载客户端不兼容，需前后端和 V199 同批发布。
- 运维：上线门禁是目标表为空；应用启动前执行 V199。若 V199 已生效，旧应用因缺少旧列不可直接回滚。

## 风险与回退原则

- 最大风险是破坏性结构变更导致旧应用不可运行；通过空表门禁、同批发布和上线前检查降低风险。
- 参数英文名跨提供方重复会使两列模板无法唯一解析；按确认规则将该行失败并要求先治理参数数据。
- 当前工作区已有 REQ-067 未提交改动，后续实施不得覆盖或将其误计入本任务证据。
- V199 未执行时可直接回退本任务代码。已执行且未写新关系时只能使用经 Owner 审批的前向补偿迁移恢复旧列；已有新关系后修复前进，不直接降级。
