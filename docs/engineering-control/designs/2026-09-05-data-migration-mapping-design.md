# 数据迁移“迁移映射”优化工程设计

## 文档状态

- 修订：2
- 状态：已确认
- 需求：`REQ-20260820-031` 数迁资产内容增量
- 控制前缀：`req-20260820-031-data-migration-asset-library-v3`
- 用户确认依据：2026-09-06 确认采用独立迁移映射服务和页面；一条记录绑定多个文件；当前无历史数据；确认数据、接口、权限、页面状态与验收设计。

## 目标与成功信号

将“数迁资产内容 / 迁移映射”升级为独立文件业务域。每条迁移映射具有一个文件编号、文件名称、映射类型和系统编号，可绑定多个普通文件或压缩包；提供组合筛选、分页、附件维护、单文件/打包下载、逻辑删除及统一回收站能力。

成功信号：必填和 50MB 边界由服务端强制执行；类型与系统均来自受控数据；所有接口受权限、项目和实体授权保护；桌面与三个手机视口可以完成完整用户路径且无页面级横向溢出。

## 使用者与场景

- 数据迁移管理员：维护当前项目全部迁移映射，执行新增、编辑、删除、下载、恢复和彻底清理。
- 普通数据迁移人员：查看和下载当前项目映射；具有写权限时新增映射，只能编辑或删除本人创建的映射。
- 用户从顶部全局项目切换器确定当前项目，在迁移映射菜单中筛选、分页、维护和下载；回收站管理继续从统一回收站入口完成。

## 必须需求与验收条件

1. 映射类型、系统编号、文件名称必填；文件名称最多 200 字符，文件编号由服务端生成且不可编辑。
2. 映射类型来自参数管理 `DM_MAPPING_TYPE`，预置 `MIGRATE_OUT=迁出程序`、`MIGRATE_IN=迁入程序`；停用或未知编码禁止写入，前端不硬编码显示值。
3. 系统编号单选，只能取当前项目 `dm_component` 中启用的系统；选项展示“编号 - 名称”并支持前端本地筛选。
4. 一条映射记录绑定多个附件；新增至少一个附件，普通文件和压缩包均按原文件保存且不解压，每个附件独立校验不超过 50MB。
5. 列表按映射类型、系统编号和文件名称组合筛选并执行服务端分页，展示系统、映射类型、文件编号和文件名称。
6. 编辑可修改元数据，并通过附件列表保留、追加或移除文件；支持指定附件下载和全部附件 ZIP 下载。
7. 删除进入统一回收站；恢复保留全部附件；彻底清理解绑并删除全部附件和业务记录，审计记录保留。
8. 查看、下载、上传新增、编辑、删除和回收站管理全部纳入服务端权限体系，并执行租户、项目、实体和附件归属校验以及写操作审计。
9. 页面覆盖项目未选择、加载、空列表、筛选无结果、失败可重试、无权限、提交中、部分上传失败和重复提交状态；桌面及 `375x812`、`390x844`、`430x932` 可完成核心流程。

## 不变量与约束

- 当前 `dm_mapping_doc` 无历史业务数据；本次不设计回填、兼容默认值或历史数据补偿。
- Flyway 只追加，不修改已发布脚本；业务关联继续使用 `(project_id, system_code)`。
- 附件继续通过平台附件能力和 `dm_content_attachment` 管理，业务表不保存对象存储路径或凭据。
- 全局项目切换器、参数管理实现、公共附件表结构、公共权限实现和其他内容菜单不在修改范围。
- 文件大小必须同时在前端预检和后端附件元数据校验；服务端结果是最终判定。
- 不限制业务文件扩展名，不在本服务解压压缩包；附件平台既有安全策略继续生效。

## 非目标

- 不实现文件内容解析、压缩包展开、病毒扫描、文件版本历史或内容查重。
- 不把多个上传文件拆成多条 `dm_mapping_doc` 记录。
- 不新建映射类型业务字典表，不修改系统管理参数模块。
- 不重构迁移程序、依赖文件或其他通用文件资产链路。

## 方案比较与选择

采用“独立 `MappingService` / `MappingController` / `MappingRecycleBinSource` 和独立页面，复用公共能力”。它将映射字段、多附件、权限和审计收敛在单一业务边界内，同时继续复用附件、参数、项目权限和统一回收站。

未选择继续扩展 `ContentFileAssetService` / `AssetListView`，因为条件分支会把映射专属规则带入其他文件菜单并扩大回归面。未选择抽象迁移程序与迁移映射的统一领域服务，因为当前两个领域字段和演进节奏不同，抽象会形成超出本需求的跨菜单重构。

## 架构边界与组件职责

- `MappingService`：列表、详情、创建、编辑、删除、附件维护、下载、码值与系统校验、项目/实体授权、审计和回收站业务。
- `MappingController`：暴露 `/api/data-migration/mappings*`，完成 HTTP 参数适配和方法级 RBAC。
- `MappingRecycleBinSource`：作为 `MAPPING_DOC` 的唯一统一回收站来源，委托专属服务执行查询、恢复和彻底清理。
- `DataMigrationCodeValueService`：通过平台参数表只读获得启用的 `DM_MAPPING_TYPE`，不修改参数管理实现。
- `ContentAttachmentService` 与附件平台公开能力：维护临时附件校验、业务绑定、下载和清理。
- `MappingsPage.vue` 与 `web/src/api/data-migration.ts`：承载筛选、桌面表格、移动卡片、表单抽屉、多文件状态和 API 契约。

## 接口、数据和状态流

### 数据

- `dm_mapping_doc` 新增非空 `mapping_type`；沿用 `system_code`、`doc_code`、`doc_name`、所有者、审计时间和软删字段。
- `dm_content_attachment(business_type='MAPPING_DOC', business_id=<mapping-id>)` 保存一条映射记录到多条附件的有序关系。
- 追加 Flyway 迁移创建映射类型/系统组合查询索引，并幂等初始化 `DM_MAPPING_TYPE` 及两个初始项；由于当前无历史数据，不执行旧行回填。

### 接口

- `GET /api/data-migration/mappings`：按 `projectId/mappingType/systemCode/keyword/page/size` 分页查询，`keyword` 只模糊匹配文件名称。
- `GET /api/data-migration/mappings/{id}`：读取当前项目活动记录及附件。
- `POST /api/data-migration/mappings`：接收 `projectId/mappingType/systemCode/fileName/files[]`，新增至少一个附件。
- `PUT /api/data-migration/mappings/{id}`：项目与文件编号不可改；更新元数据，传入 `files` 时按完整附件集合维护绑定。
- `DELETE /api/data-migration/mappings`：批量逻辑删除。
- `GET /api/data-migration/mappings/{id}/download?attachmentId=`：下载指定附件；省略附件 ID 时只允许在契约明确的首附件场景使用。
- `GET /api/data-migration/mappings/{id}/download-all`：流式生成全部附件 ZIP；无附件或读取失败时不返回空 ZIP。
- `GET /api/data-migration/mappings/options/types` 与 `/options/systems`：返回启用类型和当前项目系统选项。
- 统一回收站继续使用 `/api/data-migration/recycle-bin`，`MAPPING_DOC` 仅由 `MappingRecycleBinSource` 认领。

### 页面状态流

进入页面先等待全局项目上下文就绪，再并行加载列表、类型和系统选项。切换项目时立即关闭抽屉，清空旧列表、筛选、分页和附件状态，再加载新项目数据。

新增或编辑时，附件项维护待上传、上传中、成功和失败状态。保存期间禁用重复提交；部分上传失败时保留表单和成功项，只允许重试失败项。业务创建/更新失败时保留当前输入，临时附件由附件平台既有生命周期清理。

## 错误、降级与恢复

- 必填缺失、文件名超长、文件为空或超过 50MB、停用/未知类型、项目外或停用系统：返回可读的 400，页面保留表单并定位问题。
- 无访问权限、普通人员修改他人记录、附件不属于当前用户或业务记录：返回 403，前端展示无权限或操作失败状态。
- 记录并发变化、编号或恢复冲突：返回 409，提示刷新后重试，不写成功审计。
- 单个附件上传失败：其他附件状态保持可见，允许仅重试失败项。
- ZIP 读取任一附件失败：终止打包并返回明确错误，不生成内容不完整的成功响应。
- 列表失败保留筛选条件并提供重试；切换项目失败时不回显上一项目数据。

## 安全、性能、兼容性与运维

- 类级访问权限保护查询和下载；创建、编辑、删除使用对应动作权限；统一回收站恢复和彻底清理由 `data-migration:manage` 或 `system:admin` 执行。
- 后端从认证主体取得租户和操作者，不信任前端提交的身份字段；所有数据访问带租户与项目条件。
- 系统选项按项目一次加载并在浏览器本地过滤；列表使用服务端分页和组合索引。
- `MAPPING_DOC` 从通用服务和通用回收站来源摘除，但类型标识保留供看板和既有附件关系识别，避免重复认领。
- 应用回退时保留已执行的追加迁移和附件数据；结构撤销只能通过另行审批的前向补偿迁移。

- 服务测试：覆盖必填、200 字符边界、单/多附件、50MB 边界、停用类型、项目外系统、附件归属、组合筛选、编辑附件集合、下载、逻辑删除、恢复、彻底清理和审计。
- Controller 权限测试：覆盖查看/下载、创建、编辑、删除以及无权限响应；统一回收站测试覆盖管理员门禁和唯一来源。

## 假设、未知项与决策记录

- D1：一条迁移映射记录绑定多个文件，文件名称是映射记录名称，附件各自保留原始文件名。
- D2：采用独立迁移映射服务和页面，只复用公共附件、参数管理、权限校验和统一回收站。
- D3：当前无历史 `dm_mapping_doc` 数据，不设计回填和历史兼容。
- D4：映射类型使用 `DM_MAPPING_TYPE`，系统编号来自当前项目启用组件。
- D5：多文件上传需要逐文件状态和部分失败重试，不能用一次总提示隐藏失败项。
- 当前无阻塞未知项。

## 风险与回退原则

- 多附件完整集合更新可能误解绑附件：通过归属校验、事务和保留/追加/移除测试控制。
- 专属来源与通用来源并存可能导致回收站重复：在注册测试中断言 `MAPPING_DOC` 只有一个来源。
- 多个 50MB 文件连续上传可能造成长时间提交：采用逐文件状态、禁用重复提交和流式 ZIP，运行验收观察内存及响应。
- 回退应用提交，不回写或修改已发布 Flyway；若追加迁移已执行则保留新增列、索引和参数项，结构撤销另行立项。
