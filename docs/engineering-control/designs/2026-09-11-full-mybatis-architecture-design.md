# 全量 MyBatis 分层迁移设计

## 目标

在不改变外部行为的前提下，将服务端数据库访问统一到 MyBatis Repository/Mapper 层。

## 架构

Controller 只负责协议适配和身份上下文传递；Service 负责授权、事务和业务编排；Repository 负责面向领域的持久化接口；MyBatis Mapper/XML 负责参数绑定、SQL 和结果映射。已有 Mapper 可逐步收敛到 Repository 适配器，不修改包名和模块公开契约。

## 迁移顺序

先建立扫描基线和公共 MyBatis 配置，再按 `platform/system`、`platform/workflow`、`platform/attachment`、其他平台模块、业务模块顺序迁移。每个模块完成后独立运行测试和接口回归，再进入下一模块。

## 关键不变量

租户条件、项目数据范围、实体授权、写审计、事务边界、分页排序、空值语义和异常映射必须保持等价。SQL 只允许参数绑定，不允许把用户输入拼接进语句。

## 回滚

每个迁移批次保留原 Service 行为的可恢复提交点；若测试或验收发现偏差，仅回滚当前模块，不回退其他模块和用户改动。

## 风险

全量迁移涉及约 168 个 SQL 访问文件，存在隐式事务、动态条件、结果类型、权限前置顺序和数据库方言差异风险。任何无法由现有测试覆盖的行为必须新增测试后才能迁移。
