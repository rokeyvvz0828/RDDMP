# 数据迁移内容编号治理工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认采用 9 张内容表全部由服务端生成 `doc_code`，并确认 UUID 不含连字符。

## 目标与成功信号

治理数据迁移模块 9 张内容表中 `id` 与 `doc_code` 的职责边界：`id` 仅作为技术主键，`doc_code` 作为独立的业务编号。成功标准是新建、更新、文件替换和 Excel 导入均不再从客户端取得或由 `id` 推导 `doc_code`；列表、详情、回收站和导出仍能稳定展示业务编号。

## 使用者与场景

- 数据迁移管理员或普通人员在内容页面新增文件、迁移方案、汇报材料、规则和参数。
- 用户编辑既有内容或替换文件时按记录 `id` 定位，业务编号不变。
- 管理员或用户查询、回收、恢复和导出时使用服务端返回的 `doc_code`。

## 必须需求与验收条件

### R1 编号职责

`id` 只用于技术定位、数据库关联、审计和附件绑定；任何业务展示、搜索和导出编号使用 `doc_code`。

验收：代码和页面不再把 `id` 拼接为 `doc_code`，技术 `id` 不作为业务编号展示。

### R2 服务端生成

`dm_plan`、`dm_mapping_doc`、`dm_dependency`、`dm_script`、`dm_topic`、`dm_release_drill`、`dm_report`、`dm_rule`、`dm_parameter` 的新增记录均由服务端生成 `doc_code`。格式为 `<TYPE_PREFIX>-<32 位小写十六进制 UUID>`，UUID 部分不含 `-`。

验收：9 种类型均满足格式；请求体、multipart 参数和 Excel 导入不再成为编号来源；数据库活动唯一约束继续有效。

### R3 编号稳定

更新、文件替换、软删除恢复和回收站操作不得重算或修改 `doc_code`；更新通过 `id` 或内部记录定位。

验收：更新前后 `doc_code` 相等，恢复时仍按原编号执行活动唯一性校验。

### R4 文件替换

文件型内容的 POST 上传语义为新增；文件替换通过按 `id` 定位的 PUT 接口完成，并保留原 `doc_code`、权限、MD5 查重、附件生命周期和审计语义。

验收：新增不会因缺少客户端编号失败；按 `id` 替换只改变文件关系及允许的元数据，不生成新业务编号。

### R5 前端与 Excel 契约

前端表单不提供编号输入；列表、详情、回收站和导出可以显示服务端生成的 `asset_code`/`doc_code`。结构化 Excel 导入模板删除编号输入列，导出保留编号作为只读结果。

验收：前端构建通过；导入每行都得到服务端生成编号；非法或旧客户端携带的 `assetCode` 不会覆盖服务端编号。

## 不变量与约束

- `doc_code` 创建后不可编辑，且不包含或编码 `id`。
- 活动唯一键仍为 `(tenant_id, project_id, active_doc_code)`，其中 `active_doc_code` 由 `doc_code` 和 `deleted` 生成。
- 只修改当前需求 `writable_paths` 覆盖的 data-migration、需求设计和当前前缀账本文件。
- 不修改已发布 Flyway 脚本，不连接生产环境，不改变平台安全、附件和共享模块。
- 现有开发环境尚未投产，允许采用破坏性接口契约收敛；仍不回写或删除已有本地测试数据脚本中的历史样例。

## 非目标

- 不删除 `id` 或 `doc_code` 列，不改变 `active_doc_code` 生成列和活动唯一索引。
- 不治理会议 `meeting_code`、问题 `issue_code`、目标表 `table_code`、字段 `field_code` 或项目/组件编号。
- 不新增跨模块编号服务、数据库序列表或生产数据迁移。

## 方案比较与选择

### 已选择：类型前缀 + 无连字符 UUID

示例：`PLAN-550e8400e29b41d4a716446655440000`。生成逻辑集中在 data-migration 模块内部，随机性和并发安全性足够，长度远小于 `VARCHAR(96)`，不需要额外表或迁移。

### 未选择：时间戳 + 随机后缀

可读性更高，但需要额外碰撞检测和重试，且容易被误解为时间业务含义。

### 未选择：独立数据库序列

编号更短，但需要新的分配状态、事务锁和迁移，超出本次编号职责治理的必要范围。

## 架构边界与组件职责

- `ContentDocCodeGenerator`：维护 9 种类型到前缀的白名单映射，生成无连字符 UUID，不访问数据库。
- `PlanService`、`ReportService`：创建时调用生成器；更新只使用记录 `id`，不改变编号。
- `ContentFileAssetService`：POST 创建时调用生成器；新增按 `id` 的 PUT 文件替换路径，保留现有附件、MD5、权限和审计能力。
- `StructuredAssetService`、`ExcelService`：创建和逐行导入调用生成器；更新按 `id` 保留编号。
- Controller/API/页面：移除编号输入契约；继续用 `id` 做内部路由和 `asset_code` 做业务展示。

## 接口、数据和状态流

1. 新增请求通过认证、项目/实体权限、附件或结构化字段校验。
2. 服务端生成类型前缀编号，写入对应内容表；数据库生成 `active_doc_code` 并执行活动唯一约束。
3. 响应返回 `id` 作为技术定位值和 `asset_code`/`doc_code` 作为业务展示值。
4. 文件替换按 `/{resource}/{id}/upload` 定位现有行，执行实体授权、MD5 检查和附件关系替换，编号保持不变。
5. 回收站、恢复、清理和导出继续读取现有 `doc_code` 投影，不改变其排序和查询语义。

## 错误、降级与恢复

- UUID 生成不依赖外部服务；数据库唯一键冲突仍转换为现有冲突响应，调用方可重试。
- 记录不存在、跨租户/项目或无实体权限沿用现有 `BAD_REQUEST`/`FORBIDDEN` 语义。
- 旧客户端提供 `assetCode` 时服务端不读取、不持久化；前端和导入模板不再发送该字段。
- 应用回退可恢复旧代码；不新增数据库对象，数据库回退不需要删除列或索引。

## 安全、性能、兼容性与运维

- 编号生成在服务端完成，客户端不能伪造业务编号或借编号定位其他项目记录。
- UUID 生成是常数时间，不增加数据库查询；唯一键仍提供最终一致性保护。
- 新接口与前端同版本发布；由于模块尚未投产，允许移除 `assetCode` 输入契约。
- 审计继续记录技术 `entity_id`，审计详情或展示需要业务编号时从记录查询，不把 `id` 当作业务编号。

## 验证策略

- 单元测试：9 种前缀、UUID 32 位无连字符、小写格式、生成值不依赖 `id`。
- 服务测试：9 类新增、更新保号、文件按 `id` 替换、结构化导入逐行生成、旧 `assetCode` 不覆盖。
- 数据测试：活动唯一键、软删后恢复冲突、租户/项目隔离和附件关系不变。
- 工程检查：`mvn -pl :ccb-data-migration -am test`、`mvn test`、`npm --prefix web run build`、治理和范围检查。
- 浏览器验收：内容新增、编号展示、编辑/替换、Excel 导入导出及回收站流程，覆盖桌面和需求规定的移动视口。

## 假设、未知项与决策记录

- 假设：当前数据迁移模块尚未投产，允许前后端同版本破坏性收敛编号输入契约。
- D1：`id` 仅作技术主键；用户确认采用 9 张内容表服务端生成编号。
- D2：UUID 使用小写 32 位十六进制且不含连字符；用户已确认“uuid不用 -”。
- D3：保留数据库 `doc_code` 和活动唯一生成列，不新增 Flyway 迁移。

## 风险与回退原则

- 风险：移除文件上传按编号 upsert 后，若缺少按 `id` 的替换接口会退化为重复新增；实施必须先补齐 PUT 替换契约再移除前端编号输入。
- 风险：旧设计文档与当前实现存在编号规则冲突；本次实施同步修正文档并以生成器为唯一事实源。
- 回退：回退应用代码即可恢复旧接口实现；新增生成器无数据库状态，不需要反向迁移。已生成的测试数据若需清理，使用受控测试清理而非生产操作。
