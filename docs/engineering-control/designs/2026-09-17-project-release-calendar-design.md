# 项目投产日历工程设计

## 文档状态

- 修订：4
- 状态：已确认
- 用户确认依据：用户确认独立维护、开始日期/结束日期范围、同一日期最多一条安排但项目允许多条不重叠安排、范围内每日标识、项目全体成员可编辑、项目详情独立日历页签方案，以及固定六类公告和概览筛选规则。

## 目标与成功信号

在项目详情中提供独立维护的投产日历。项目成员能按月查看并维护本项目多条不重叠安排，安排可覆盖开始日期至结束日期，范围内每一天都可见；同一日期最多一条有效安排；刷新后数据一致；非成员无法跨项目访问；项目现有页签路由和配置管理投产窗口互不受影响。

## 使用者与场景

项目成员从项目详情切换至“投产日历”，查看所选月份的投产安排。可通过工具栏或空日期格新增安排，填写标题、投产日期范围和备注；已有安排可编辑或删除，操作后即时刷新当前月份；服务端拒绝与已有安排重叠的日期范围。手机端将范围内日期重排为日期分组列表，同一条跨日安排可出现在多个日期组。

## 必须需求与验收条件

- R1：增加 `release-calendar` 项目详情页签，保留 URL 查询参数和既有页签行为。验收：直接访问及切换均正确加载。
- R2：多条不重叠安排独立持久化，包含标题、开始日期、结束日期和备注；同日表示单日安排。验收：CRUD 后刷新回显，不重叠的第二条安排可保存，重叠范围被服务端拒绝，配置管理窗口无变化。
- R3：项目成员可维护，非成员及跨租户请求由服务端拒绝。验收：权限测试覆盖读取和写入。
- R4：桌面月历与移动日期列表可用，当前月份内每一天都标识相交的范围记录；项目概览日期框直接显示投产标题，不依赖悬浮详情。验收：跨月范围在两个相邻月份均可见，规定四种视口无页面级横向溢出。
- R5：页签视觉借鉴配置管理投产窗口导航，同时保持项目模块语义主题。验收：现有页签可用且明暗主题可读。

## 不变量与约束

- 不修改或读取配置管理投产窗口业务数据。
- 所有写入服务端验证认证、项目成员关系、租户、实体归属和版本号，并写操作审计。
- Flyway 仅追加 `V218__project_release_calendar_date_range.sql`；既有 `release_date` 数据回填为同日范围，所有删除为逻辑删除。

## 非目标

不支持时间段、状态、重复、提醒、附件、审批、外部同步和跨项目汇总；不调整项目计划或项目角色规则。

## 方案比较与选择

选择“项目详情独立页签和独立表”。它将投产安排与项目计划、配置管理窗口分开，同时保留项目上下文与最小权限范围。

- 合并到项目计划页签：减少导航，但混淆计划排期和投产安排，未采用。
- 新建跨项目全局页面：便于汇总，但扩大查询、权限和导航范围，未采用。

## 架构边界与组件职责

- `ProjectView.vue`：路由页签、数据加载、桌面月历、移动列表、范围表单和反馈状态。
- `project.ts` 与 `project.ts` 类型：封装项目日历 DTO 和 HTTP 调用。
- `ProjectController` / `ProjectService`：提供项目范围 CRUD、成员授权、乐观锁和审计。
- Flyway：创建 `pm_project_release_calendar` 及项目月份查询索引。

## 接口、数据和状态流

接口为 `GET/POST /api/projects/{projectId}/release-calendar` 与 `PUT/DELETE /api/projects/{projectId}/release-calendar/{calendarId}`。列表接收年月；写入返回当前条目与版本号。表保存 `tenant_id`、`project_id`、`title`、`release_start_date`、`release_end_date`、`remark`、审计字段、`deleted` 和 `row_version`；旧 `release_date` 仅作为迁移来源保留。列表按 `start_date <= month_end AND end_date >= month_start` 查询。页面切换项目或月份时取消过期请求；保存成功后刷新当前月。

## 错误、降级与恢复

首次加载显示骨架或加载态；空月显示明确空状态；请求失败保留重试入口；403 显示无权限；409 提示刷新后重试；提交中禁用重复操作；删除提示对象和不可恢复后果。

## 安全、性能、兼容性与运维

服务端以认证用户、租户和项目成员表校验，审计动作包含创建、更新和删除。按 `(tenant_id, project_id, release_start_date, release_end_date, deleted)` 建索引，按月份重叠查询。既有项目页签、API 与配置管理窗口保持兼容。

## 验证策略

聚焦系统项目服务、MySQL 迁移和成员授权测试；执行前端构建、治理与范围检查；使用桌面和三种手机视口验证项目成员维护、非成员拒绝、空月、失败、长文本和主题。

## 假设、未知项与决策记录

- 假设：项目成员关系是“项目所有人”的授权依据；推翻条件是 Owner 指定额外角色限制。
- D1：日历独立维护，不依赖配置管理投产窗口。
- D2：项目只保存一条安排，包含标题、开始日期、结束日期和备注，同日表示单日安排，范围内每天都标识该安排。
- D3：项目所有成员均可编辑。

## 风险与回退原则

主要风险是成员授权遗漏、跨月范围边界和项目页签回归。通过服务端读写权限测试、日期边界/跨月查询、审计断言和浏览器回归降低风险。回退只撤销本需求应用和前端改动，保留追加迁移和历史记录。

## 公告管理扩展（修订 4）

### 目标与范围

公告不再关联项目计划阶段，改为项目内固定的六个公告栏位：`PROJECT`（项目公告）、`REQUIREMENT`（需求公告）、`DEVELOPMENT`（开发公告）、`TEST`（测试公告）、`PRODUCTION`（投产公告）、`DATA_MIGRATION`（数据迁移公告）。公告继续使用现有项目公告表和 CRUD 接口，服务端以固定编码校验，保留项目成员授权、租户隔离、审计和乐观锁。

### 用户流程

公告管理页签显示六个栏位 tabs；切换栏位只加载该栏位公告，并使用当前栏位的发布、编辑、删除和置顶字段。发布表单由当前 tab 预填，不再读取项目计划阶段。HTTP 接口继续使用 `stageCode` 参数名以保持兼容，但其值只接受六个公告栏位编码。

项目概览从六类公告统一读取，按 `pinned DESC, created_at DESC, id DESC` 排序，展示全部置顶公告和最新 3 条非置顶公告；点击条目打开已有详情弹窗。概览不再根据当前日期或计划阶段过滤公告。

### 验收条件

- A1：公告管理显示六个固定栏位，切换后只展示当前栏位，发布和置顶状态在栏位之间相互独立。
- A2：服务端只接受六个公告栏位编码；非项目成员、跨租户、实体不归属和乐观锁冲突仍按现有规则拒绝并记录写操作审计。
- A3：项目概览展示全部置顶公告和最新 3 条非置顶公告，置顶公告始终优先；不再关联计划阶段。
- A4：既有公告 API 路径、项目公告详情弹窗、删除和编辑流程保持可用；无公告、加载失败和提交中状态可恢复。

### 非目标与回退

本修订不新增数据库迁移、不修改项目阶段表、不迁移或删除历史公告数据；旧的非六类编码公告继续保留，但不作为新栏位的有效发布编码。回退应用代码即可恢复原有阶段公告校验和查询行为。
