# 项目投产日历工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认独立维护、单个投产日期、仅标题/日期/备注、项目全体成员可编辑、项目详情独立日历页签方案，以及本修订落盘设计。

## 目标与成功信号

在项目详情中提供独立维护的投产日历。项目成员能按月查看并维护本项目条目，刷新后数据一致；非成员无法跨项目访问；项目现有页签路由和配置管理投产窗口互不受影响。

## 使用者与场景

项目成员从项目详情切换至“投产日历”，查看所选月份的投产安排。成员点击日期或新增入口，填写标题、投产日期和备注；编辑、删除在确认后即时刷新当前月份。手机端将相同数据重排为日期分组列表。

## 必须需求与验收条件

- R1：增加 `release-calendar` 项目详情页签，保留 URL 查询参数和既有页签行为。验收：直接访问及切换均正确加载。
- R2：条目独立持久化，仅有标题、投产日期和备注。验收：CRUD 后刷新回显，配置管理窗口无变化。
- R3：项目成员可维护，非成员及跨租户请求由服务端拒绝。验收：权限测试覆盖读取和写入。
- R4：桌面月历与移动日期列表可用。验收：规定四种视口无页面级横向溢出。
- R5：页签视觉借鉴配置管理投产窗口导航，同时保持项目模块语义主题。验收：现有页签可用且明暗主题可读。

## 不变量与约束

- 不修改或读取配置管理投产窗口业务数据。
- 所有写入服务端验证认证、项目成员关系、租户、实体归属和版本号，并写操作审计。
- Flyway 仅追加 `V214__project_release_calendar.sql`；所有删除为逻辑删除。

## 非目标

不支持时间段、状态、重复、提醒、附件、审批、外部同步和跨项目汇总；不调整项目计划或项目角色规则。

## 方案比较与选择

选择“项目详情独立页签和独立表”。它将投产安排与项目计划、配置管理窗口分开，同时保留项目上下文与最小权限范围。

- 合并到项目计划页签：减少导航，但混淆计划排期和投产安排，未采用。
- 新建跨项目全局页面：便于汇总，但扩大查询、权限和导航范围，未采用。

## 架构边界与组件职责

- `ProjectView.vue`：路由页签、数据加载、桌面月历、移动列表、表单和反馈状态。
- `project.ts` 与 `project.ts` 类型：封装项目日历 DTO 和 HTTP 调用。
- `ProjectController` / `ProjectService`：提供项目范围 CRUD、成员授权、乐观锁和审计。
- Flyway：创建 `pm_project_release_calendar` 及项目月份查询索引。

## 接口、数据和状态流

接口为 `GET/POST /api/projects/{projectId}/release-calendar` 与 `PUT/DELETE /api/projects/{projectId}/release-calendar/{calendarId}`。列表接收年月；写入返回当前条目与版本号。表保存 `tenant_id`、`project_id`、`title`、`release_date`、`remark`、审计字段、`deleted` 和 `row_version`。页面切换项目或月份时取消过期请求；保存成功后刷新当前月。

## 错误、降级与恢复

首次加载显示骨架或加载态；空月显示明确空状态；请求失败保留重试入口；403 显示无权限；409 提示刷新后重试；提交中禁用重复操作；删除提示对象和不可恢复后果。

## 安全、性能、兼容性与运维

服务端以认证用户、租户和项目成员表校验，审计动作包含创建、更新和删除。按 `(tenant_id, project_id, release_date, deleted)` 建索引，只查询单月。既有项目页签、API 与配置管理窗口保持兼容。

## 验证策略

聚焦系统项目服务、MySQL 迁移和成员授权测试；执行前端构建、治理与范围检查；使用桌面和三种手机视口验证项目成员维护、非成员拒绝、空月、失败、长文本和主题。

## 假设、未知项与决策记录

- 假设：项目成员关系是“项目所有人”的授权依据；推翻条件是 Owner 指定额外角色限制。
- D1：日历独立维护，不依赖配置管理投产窗口。
- D2：条目仅保存标题、单个投产日期和备注。
- D3：项目所有成员均可编辑。

## 风险与回退原则

主要风险是成员授权遗漏和项目页签回归。通过服务端读写权限测试、审计断言和浏览器回归降低风险。回退只撤销本需求应用和前端改动，保留追加表和历史记录。
