# 配置管理项目维度隔离工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 需求编号：REQ-20260831-057
- 用户确认依据：用户确认采用“显式项目参数 + 后端统一项目访问校验”，并确认直接链接有权时自动切换项目、无权时拒绝访问。

## 目标与成功信号

配置管理六个菜单以顶部当前项目为唯一展示和操作范围，同时由服务端对列表范围与目标实体执行项目成员校验。成功信号是正常切换不串数据、伪造项目参数不能越权、直接链接能正确同步项目上下文，并且现有菜单 RBAC 与审批状态机保持不变。

## 使用者与场景

- 项目成员在顶部切换项目后查看和维护当前项目的配置管理数据。
- 审核人通过版本申请固定链接进入其他有权项目，页面自动切换到该项目并继续展示或审批。
- 无目标项目成员关系的普通用户，即使知道业务编号或记录 ID 也不能读取或修改数据。
- 超级管理员继续访问租户内有效项目，但仍受配置管理菜单和操作权限约束。

## 必须需求与验收条件

### R1 顶部项目驱动六菜单

投产窗口、版本申请、投产基线、生产版本、统计分析和审批流程配置的列表请求必须携带当前项目编码；后端缺少项目编码时返回 400，不能查询租户全量。切换项目后旧数据立即清空，旧弹层关闭，慢响应不得覆盖新项目结果。

### R2 服务端项目访问门禁

新增 `com.ccb.system.capability.ProjectAccessService`，按 `project_code + tenant_id` 解析未删除项目并校验成员关系有效；`SUPER_ADMIN` 维持豁免。项目 `PLANNING/RUNNING/COMPLETED/SUSPENDED` 状态与顶部列表保持一致，不额外限制。无权访问返回 403，项目不存在或已删除返回稳定中文业务错误。

### R3 实体所属项目校验

详情、历史、冲突、附件、提交、撤回、取消、投产结果和流程配置等接口不能信任前端项目字段。服务层先按租户读取目标记录，再以记录中的 `project_id` 执行项目访问校验；创建或更新同时校验请求项目、投产窗口和目标记录属于同一项目。

### R4 直接链接项目同步

版本申请详情页先读取申请基本信息并获取所属 `projectId`。项目 Store 已初始化且目标项目在可访问列表中时调用现有 `select(projectRef)` 自动切换，再加载审批轮次、附件、历史和流程；目标项目不在列表时显示“无该项目访问权限”，不继续发起后续敏感请求。服务端详情接口仍执行最终授权，前端判断只负责体验。

### R5 兼容现有权限与业务

现有 `release:*` 菜单和动作权限、审批流程、状态机、附件规则、投产窗口规则和数据库模型不变。项目成员校验是附加的数据范围门禁，不替代 RBAC。

## 不变量与约束

- 租户 ID 和当前用户只能来自 `AuthUser`，不得接受请求体注入。
- 业务实体的所属项目只能来自服务端存量记录或经统一项目服务解析的项目。
- 前端顶部项目不是安全边界；所有受保护接口必须在后端校验。
- 不修改现有未提交文件，不新增 Flyway 迁移，不连接生产环境。
- platform/system 公共能力仅新增独立服务，不改动现有大型 `ProjectService` 的行为。

## 非目标

- 不增加全局 `X-Project-Ref` 请求头或后端过滤器。
- 不重构为项目化 URL 路由。
- 不统一改造配置管理之外的业务模块。
- 不新增项目角色模型或调整菜单权限种子。

## 方案比较与选择

### 已选：显式项目参数 + 后端统一访问服务

沿用现有 API 形态，列表显式传 `projectRef`，实体操作反查所属项目，统一服务提供相同项目成员语义。它对审批外链和内部工作流事件边界最清楚，能渐进改造且回退简单。

### 未选：全局 `X-Project-Ref` 请求头

请求注入简单，但审批外链、后台工作流回调和非项目页面容易误用同一上下文；请求头也不能替代目标实体反查，收益不足以覆盖全局过滤器风险。

### 未选：项目化 URL `/projects/{projectRef}/release/...`

资源边界最直观，但会同时改动前端路由、分享链接和全部 API，兼容成本和回归范围超出本次需求。

## 架构边界与组件职责

- `ProjectAccess` 与 `ProjectAccessService`：平台公开只读契约；业务模块只依赖项目引用和访问方法。
- `JdbcProjectAccessService`：位于 system `internal` 包，解析项目编码并执行成员/超级管理员访问判断，不向消费者暴露数据库实现。
- 配置管理各 Service：在业务操作入口调用项目访问能力；列表使用显式项目，实体操作使用存量实体所属项目。
- `web/src/api/release.ts`：使项目范围参数在类型上必填，避免调用方遗漏。
- `project-context` Store：继续维护用户可访问项目列表和唯一当前项目；直接链接复用 `select`，不另建第二套项目状态。
- 配置管理页面组件：项目变更时清理局部状态并用请求代次或捕获项目编码拒绝过期响应。

## 接口、数据和状态流

### 项目访问接口

候选公开模型：

```java
public record ProjectAccess(long id, String projectRef, String projectName) {}

public interface ProjectAccessService {
    ProjectAccess requireAccessible(String projectRef, AuthUser user);
}
```

`projectRef` 对应 `pm_project.project_code`。服务查询当前租户的未删除项目，再检查 `pm_project_member.status = 1`；失败分别映射项目不存在和 403。

### 列表流

```text
顶部项目 -> API 必填 projectRef -> Controller 参数校验
-> ProjectAccessService -> 业务 Store 按 tenant + projectRef 查询 -> 当前项目结果
```

### 实体操作流

```text
业务编号/记录 ID -> Store 按 tenant 读取目标 -> 取目标 project_id
-> ProjectAccessService -> 校验请求其余关联实体属于同项目 -> 读写或拒绝
```

### 直接链接流

```text
申请固定链接 -> 初始化可访问项目 -> 调用受保护详情接口
-> 详情返回 projectId -> Store 中存在则 select(projectId)
-> 再并行加载轮次/附件/历史/工作流
-> 不存在或接口 403 则展示无权访问并停止
```

## 错误、降级与恢复

- 缺少项目编码：400，提示“请选择项目后重试”。
- 项目不存在或已删除：400/业务错误，清空当前视图数据，不保留旧项目内容；成员关系停用按 403 处理。
- 非成员：403，直接链接显示无权访问；不自动退到另一个项目造成误解。
- 项目切换中的旧响应：按捕获的 `projectRef` 或请求代次丢弃，不显示错误到新项目。
- 某一菜单加载失败：保留该菜单自己的重试入口，不回显其他项目缓存。

## 安全、性能、兼容性与运维

- 安全：后端统一执行租户、项目状态、成员关系和实体所属项目校验；覆盖参数伪造和 ID 枚举。
- 性能：每个业务请求增加至多一次项目/成员存在性查询；使用现有项目编码与成员索引，不引入跨页全量加载。
- 兼容性：公开 API 仅将原可选项目参数收紧为必填；现有前端调用已经大多携带项目，内部事件不走面向用户的项目门禁。
- 运维：无迁移和配置项；可通过 400/403 日志区分缺参和越权，不记录敏感请求内容。

## 验证策略

- 平台单测：成员、超级管理员、非成员、停用/删除/不存在项目。
- 业务单测：六域列表缺参、跨项目实体、伪造请求项目、同项目正常路径。
- 前端构建与静态验证：API 必填项目类型，项目切换清理状态，详情链接自动选择。
- 浏览器验证：桌面与 `390x844` 下切换两个项目、直接打开有权/无权链接、快速连续切换项目。
- 回归：`mvn -pl :ccb-system,:ccb-release -am test`、`npm --prefix web run build`、治理检查和 `git diff --check`。

## 假设、未知项与决策记录

- 已确认 `rel_*` 表中的 `project_id` 存储 `pm_project.project_code`，与顶部 `ProjectContextItem.ref` 一致。
- 已确认项目工作台列表仅返回普通用户的有效成员项目，超级管理员返回租户项目。
- 无阻塞未知项；若实现发现存量配置管理记录的 `project_id` 无法解析到 `pm_project.project_code`，必须停止并单独决定数据修复方案。
- D1：采用显式项目参数和统一服务，不采用全局请求头。
- D2：直接链接有权时自动切换项目，无权时拒绝。

## 风险与回退原则

- 存量脏项目编码可能导致原本可见数据被拒绝；实施前用只读查询/测试确认映射，发现异常立即停止。
- 服务构造函数变化会影响较多单测；逐域接入并在每个任务后运行聚焦测试。
- 异步竞态可能只在快速切换时出现；每个独立加载组件都必须保存请求项目并在赋值前比较。
- 无数据库变更，按任务提交回退即可；公共服务和 release 依赖必须同一任务回退。
