# 顶部栏与页签合并工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认采用“桌面端页签并入顶部栏，移动端保留独立紧凑页签栏”的方案 1，并明确要求直接开发。

## 目标与成功信号

消除桌面端顶部面包屑与页签重复展示当前页面的问题，减少一整行壳层高度，让业务内容更靠上。成功信号是桌面端只在页签中出现当前页面标题，顶部栏保持项目切换、侧栏折叠、页签切换和账号操作；移动端行为不退化。

## 使用者与场景

面向需要在工作台、系统管理、工作流和配置管理页面间频繁切换的桌面端用户。用户打开多个页面后，通过顶部栏内的页签切换、关闭、刷新或右键关闭其他页签。

## 必须需求与验收条件

1. 桌面端移除“控制中心 / 当前页面”的重复面包屑，将 `UiTabs` 放入 `app-header` 中部。
2. 桌面端不再渲染独立页签行，业务内容区相应上移；项目选择器、折叠按钮和右侧全局操作保持可用。
3. 页签区域使用弹性宽度，页签较多时由 Element Plus 页签导航处理横向溢出，不挤压项目选择器和账号操作。
4. 关闭、关闭其他、关闭全部、刷新和工作台不可关闭规则保持不变。
5. `760px` 及以下继续使用现有独立粘性页签栏和当前页面标题，不把多页签塞入移动端主标题栏。
6. 桌面常用宽度与 `375x812`、`390x844`、`430x932` 不出现控件重叠或页面级横向溢出。

## 不变量与约束

- 沿用 Vue 3、Element Plus、`UiTabs` 和 `tabsStore`，不增加依赖。
- 项目上下文仍在页面顶级切换，不能因页签合并被隐藏或压缩到不可用。
- 顶部右侧通知、主题、打印和用户菜单保持原位置与功能。
- 顶部栏与移动页签的粘性层级不能遮挡业务内容。

## 非目标

- 不修改页签持久化、路由缓存和业务页面标题来源。
- 不重做侧栏、顶部导航模式或主题设置。
- 不取消多页签能力，也不调整业务页面内部布局。

## 方案比较与选择

- 选择：桌面端页签并入顶部栏。直接消除信息重复和额外高度，同时保留多任务切换。
- 未选择：保留两行并弱化面包屑。风险较低，但仍浪费垂直空间。
- 未选择：取消页签只保留面包屑。界面最简，但会破坏已存在的多页面工作流。

## 架构边界与组件职责

- `AppLayout.vue`：根据桌面/移动状态决定 `UiTabs` 的挂载位置；桌面挂入 `app-header`，移动端挂在 header 之后。
- `UiTabs.vue`：继续负责页签切换、关闭和右键菜单，不感知壳层模式。
- `styles.css`：定义桌面内联页签弹性、紧凑高度和溢出约束；保留移动端独立粘性页签样式。

## 接口、数据和状态流

路由变化仍由 `AppLayout` 调用 `tabsStore.open`。`UiTabs` 接收同一个 `route.fullPath`，无论挂载位置如何都使用同一份 `tabsStore.tabs`，不产生第二份状态。

## 错误、降级与恢复

页签过多时允许页签导航滚动，不允许覆盖右侧操作。小屏幕命中移动断点后恢复独立页签行。若合并布局产生不可接受回归，可仅回退模板挂载位置和相关 CSS，不影响页签数据。

## 安全、性能、兼容性与运维

本变更不涉及接口和权限。只调整 DOM 布局，不增加请求或持久状态。兼容现有布局模式；移动端保持原行为。

## 验证策略

- 运行 `npm run build` 和 `git diff --check`。
- 桌面端打开至少工作台和用户管理两个页签，验证切换、关闭、刷新、右键菜单和内容区上移。
- 验证页签较多时项目选择器和右侧操作不被挤出。
- 在 `375x812`、`390x844`、`430x932` 验证标题、独立页签和页面宽度。

## 假设、未知项与决策记录

- 假设 Element Plus 的页签导航可处理内联区域溢出；若实际无法限宽，将补充 `min-width: 0` 和导航滚动约束。
- 决策 D1：桌面端合并，移动端不合并，来源为用户确认方案 1。

## 风险与回退原则

主要风险是中等宽度下项目选择器、页签和右侧操作争抢空间。通过固定两侧、页签中部弹性收缩和移动断点降级控制。回退只恢复独立页签挂载，不改变数据或业务行为。
