# 业务对象页面设计器重构设计

**状态：** approved-by-user-request

## 1. 页面模型

```text
业务对象
  └── 页面集合
      ├── 列表页（业务入口）
      ├── 详情页
      ├── 新建页：单页表单 / 分步表单
      ├── 编辑页：单页表单 / 分步表单
      └── 审批页
```

`form/detail/list/approval/wizard` 仅作为历史兼容值。新配置使用 `view_role` 表达页面职责，使用 `form_mode` 表达新建或编辑页面的表单形态。

## 2. 配置职责

- 业务对象页面树：选择业务范围和页面角色。
- 字段主列表：维护字段编码、类型、数据来源和通用校验。
- 列表页：维护列顺序、宽度、固定、筛选、排序和移动端卡片模式。
- 详情页：维护只读字段顺序、分区和展示格式。
- 新建/编辑页：维护分区、栅格、字段顺序和必填/编辑状态；`form_mode=wizard` 时维护步骤。
- 审批页：维护只读业务字段和审批上下文，审批动作仍由 workflow 模块负责。

所有页面引用同一业务对象字段集合，不允许页面创建临时字段。列表字段必须是字段主列表中 `form_available=1` 且已启用的字段。

## 3. 后端契约

`biz_form_view` 追加：

- `view_group_key`：业务对象页面集合编码，默认 scope 的 `scope_key`。
- `view_role`：`list/detail/create/edit/approval`。
- `form_mode`：`single/wizard`，仅 create/edit 使用，其他页面为 `none`。

读取时保留 `view_type`，并根据历史值归一化：`form -> create/single`、`wizard -> create/wizard`、其余值按同名角色映射。保存时服务端校验组合和页面集合唯一性，不让前端绕过约束。

## 4. 前端工作区

顶部选择业务对象，左侧显示页面集合树，中间是当前页面的布局画布，右侧显示页面属性或字段属性。新建/编辑页面在页面属性中选择单页/分步模式；列表页切换到列配置，移动端显示卡片预览。所有视图继续复用现有字段 API、视图 API、Element Plus 控件和交付示范中心的列表/表单布局语言。

移动端将页面树变为横向可滚动的紧凑导航，字段画布单列显示，属性面板进入页面底部；不让设计器根页面横向滚动。

## 5. 风险与回退

历史视图可能没有页面角色，因此读取必须归一化而不能要求一次性数据修复。V37 只追加列和索引，回退时停止使用新列即可，不删除 V35/V36 表和数据。
