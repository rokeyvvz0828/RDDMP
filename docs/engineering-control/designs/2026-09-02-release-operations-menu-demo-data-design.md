# 投产管理独立菜单与测试数据设计

## 1. 已确认决策

用户确认保留“投产管理”父级目录，五项功能作为独立子菜单；用户确认至少两个测试项目且每个项目覆盖五项功能。

## 2. 方案比较

### 方案 A：保留页面壳，按路由渲染单个业务组件（采用）

继续复用 `ReleaseOperationsManagement.vue` 处理当前项目解析、项目切换、公共加载/错误/无项目状态；根据当前路由只渲染一个业务组件，删除壳内导航。优点是改动小、项目切换逻辑只有一份、五个现有业务组件无需重复处理项目上下文；左侧动态菜单负责页面切换。

### 方案 B：五个路由直接挂载五个业务组件

每个组件各自解析当前项目并处理公共状态。页面视觉上同样没有 Tabs，但会复制项目加载和错误处理逻辑，项目切换时容易出现行为不一致，不适合当前需求的最小变更边界。

### 方案 C：嵌套路由父页面加 `<router-view>`

把父级页面改为嵌套路由布局，由子路由承载业务页面。结构表达清晰，但需要同时调整现有路由匹配、菜单跳转和项目上下文生命周期，改动面大于本需求收益。

## 3. 页面与路由行为

- 保留五条现有路由、菜单路径和权限编码。
- `ReleaseOperationsManagement.vue` 删除 `visibleNavItems`、`navigate` 及对应 `<nav>`，根据 `route.path` 映射到一个业务组件。
- `/release-operations` 保留为父级入口，初始化后跳转到当前用户有权限的第一个子菜单。
- 子菜单仍由动态菜单系统从 V123 种子读取，因此左侧导航中只有一份五项菜单。
- `projectStore.currentRef` 变化时递增请求代次，清空旧项目 ID 并使用组件 key 重新挂载当前业务组件，避免旧请求或编辑状态覆盖新项目。

## 4. 测试数据与数据流

新增 V124，不改变 V123 表结构。V124 使用固定测试项目编码 `REL-DEMO-ALPHA`、`REL-DEMO-BETA` 和高位固定主键；项目成员引用仓库 V71 已建立的演示用户，不新增真实用户信息。由于后端投产接口还要求当前登录用户是项目成员，追加 V125 将本地测试登录用户 `admin` 加入两个测试项目；由于 V124 的问题状态值与后端枚举不一致，追加 V126 修正两个固定演示问题记录。V125/V126 不修改已发布迁移。

每个项目补齐：

- 一条演练计划、三条轮次；
- 一条 `NORMAL` 时序及四条明细；
- 一条 `ROLLBACK` 时序及三条明细；
- 三条不同优先级/状态的问题记录，带分析、处理和跟踪内容；
- 两个投产组，每组至少两名项目成员。

各业务行使用固定 ID，采用 `INSERT ... SELECT ... WHERE NOT EXISTS` 或等价幂等写入，仅补齐本任务预留的测试记录，不按项目删除数据，不覆盖用户手工新增记录。所有记录固定 `tenant_id=1`、`project_id` 为两个演示项目，且 `created_by/updated_by=1`。

## 5. 权限、错误与兼容性

不新增权限编码或公共契约。路由 meta 权限、左侧菜单权限和后端已有权限保持一致。V124 只追加测试数据，应用回退保留迁移和数据，关闭菜单或回退应用入口即可恢复旧入口。

## 6. 响应式与验证

本次不引入新页面样式，复用现有投产业务组件和 `release-operations.css`。桌面端验证左侧五项菜单与内容层级，手机端验证页面没有因删除内部导航而产生异常空白或横向溢出。验证视口为 `375x812`、`390x844`、`430x932`、`1280x800`，并检查切换项目、刷新、控制台错误和页面级 `scrollWidth`。

## 7. 风险与回退

- 如果本地数据库缺少 V71 演示用户，V124 的成员引用会被条件查询跳过；如果本地数据库缺少 `admin`，V125 会跳过成员写入；V126 仅更新存在的固定测试问题记录；部署检查必须报告数据缺口，不能写入孤立成员。
- 如果固定测试主键已被占用，迁移不覆盖既有记录，需在迁移检查中报告冲突。
- 菜单缓存可能使新结构短暂不可见，重启后刷新动态菜单即可恢复。
