# 参数、角色权限、页签与会话改造设计

## 目标

在单租户基础上统一参数管理、建立用户角色与菜单动作权限模型、提供可选页签工作区，并让登录失效可恢复到原操作页面。

## 已确认设计

- “字典管理”和“系统配置”从前端菜单移除，合并为“参数管理”。参数管理包含参数类别和参数明细，类别支持系统参数、流程参数、AI 参数等。
- 保留现有 `sys_dict_type` 与 `sys_config` 数据表兼容性，新增参数类别与参数关联字段；旧资源不再暴露为独立菜单。
- 角色继续通过 `sys_user_role` 关联用户；菜单可见性继续通过 `sys_role_menu` 控制。
- 新增菜单动作权限表和角色动作权限关联表。每个菜单默认提供“查看、新增、修改、删除”四种动作，角色矩阵按菜单树勾选。
- 用户拥有多个角色时，后端权限查询使用 `DISTINCT` 取并集。前端只负责显示控制，后端服务接口强制校验动作权限。
- 主题设置增加“页签模式”开关。启用后保留已访问路由，支持切换、关闭当前、关闭其他、关闭全部；工作台作为不可关闭页签。
- Axios 收到 401 时先单次刷新令牌；刷新失败清理会话、保存当前完整路由并跳转登录页；登录成功后回到保存路由。
- 登录访问时效从参数表读取，参数变更后对下一次登录/刷新令牌生效；环境配置作为无数据库可用时的兜底。

## 接口与行为契约

- 参数类别：查询、创建、修改、停用/启用。
- 参数明细：按类别查询、创建、修改、停用/启用。
- 角色：查询角色、查询角色权限、保存角色权限、查询角色用户关联。
- 用户：查询可用角色、保存用户角色关联。
- 权限动作码采用 `<菜单权限编码>:<动作>`，例如 `system:user:create`；查询动作兼容已有菜单列表权限编码。
- 系统接口对列表/详情使用查看权限，对创建使用新增权限，对更新使用修改权限，对删除/停用使用删除权限；系统根访问权限仍作为模块入口权限。
- 参数键 `security.jwt.access-ttl-millis` 和 `security.jwt.refresh-ttl-millis` 由参数管理维护，单位为毫秒，范围由后端校验。

## 不变量与非目标

- 不改变单租户边界，不引入租户切换。
- 不删除旧表；旧字典/配置数据通过迁移兼容，旧菜单和旧资源入口移除。
- 没有角色动作权限时不得因前端隐藏按钮而绕过后端鉴权。
- 刷新令牌失败后不得保留旧访问令牌或继续重试原请求。
