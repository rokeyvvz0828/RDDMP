# 测试执行与测试缺陷工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户于 2026-09-01 明确要求“测试执行是新的菜单，测试缺陷也新增了一些页面。请你都严格按照需求实施。确认实施。”

## 目标与成功信号

在四个测试大类中交付完整的执行与缺陷闭环。测试人员能导入案例并记录可追溯结果；失败记录必须有缺陷；缺陷可按角色受控流转、关联多个执行记录，且解除/移除关联后仍保留业务快照。

## 必须需求与验收条件

| ID | 必须行为 | 可观察验收 |
|---|---|---|
| R1 | 四大类均有独立“测试执行”菜单，执行树只读引用项目、参测系统、轮次、周期并维护执行目录。 | 菜单和路由可达；无项目时不请求；轮次/周期不能在执行页增删。 |
| R2 | 执行页支持范围、案例树、粘贴编号三种预览导入，阻止无效或同目录重复案例。 | 预览列出有效、重复、无效项；确认只写入有效且不重复记录。 |
| R3 | 执行记录实时引用案例，支持筛选、导出、详情填写、附件和轨迹。 | 案例修改后列表/详情读取新值；无效/阻塞备注必填；保存更新执行人、时间和轨迹。 |
| R4 | 失败及批量失败必须至少关联一个缺陷；批量处理、移动和移除遵循权限及未解决缺陷阻断。 | 无缺陷不能保存失败；移除时返回被阻断项，其余项可移除并转关联快照。 |
| R5 | 缺陷支持新建、列表、默认排除已解决、快捷筛选、导出、详情编辑和附件。 | 缺陷编号为 BUG+系统编码+流水号且系统变更不改号；全部筛选可复现。 |
| R6 | 缺陷状态机、处理人、执行关联与快照按角色在服务端校验。 | 无权流转被拒绝；处理人仅目标系统开发人员；解除关联或执行移除后显示快照而非死链。 |
| R7 | 所有写入具备大类/项目/系统边界、RBAC、审计与软删除恢复。 | 跨域/跨项目/跨系统请求被拒绝；删除保护和 30 天恢复可验证。 |
| R8 | 前端复用现有全局项目、紧凑左树、居中弹窗、通用可调列宽表格和成熟富文本。 | 不出现第二个项目下拉或抽屉；桌面/移动均无页面横向溢出。 |

## 不变量与约束

- 执行、缺陷数据归测试管理模块所有；项目、用户、系统、轮次、周期、案例和附件平台均只读复用已有契约。
- 缺陷与执行记录为无主次的 1:N 关联；缺陷编号永不因范围、案例或系统字段更新而变化。
- 执行记录移除不得删除缺陷；关联转为代码、名称、范围序号的快照。
- 所有弹出表单使用居中弹窗，不使用抽屉；不修改 `web/src/components/ui` 或平台附件实现。
- 新表仅以 V141 追加；应用回退保留本地测试数据。

## 方案比较与选择

选择“独立执行/缺陷归一化表 + 关联快照表 + 领域服务”的方案。它可保证多关联、软删、轨迹和实时案例引用的正确性。

- 不采用把执行结果写回 `tm_test_case`：同一案例可在不同目录重复执行，无法表示结果、轨迹或缺陷关联。
- 不采用在缺陷表直接以 JSON 存执行记录：无法为解除关系后的快照、权限筛选、删除保护和导出建立可查询约束。

## 架构与数据流

`TestExecutionService` 拥有执行树、导入、状态、批量、附件绑定和轨迹；`TestDefectService` 拥有缺陷、状态流转、关联、快照、附件、回收和轨迹。两者通过同模块事务与 `tm_test_defect_execution` 关联表协作。

执行列表通过 JOIN 案例、范围和系统实时展示案例内容；缺陷列表通过关联表计算有效关联数。所有详情写入先加载 tenant/domain/project/system 边界实体，再检查系统角色和菜单权限。附件只通过模块内 `AttachmentAccessPolicy` 及平台 AttachmentGateway 访问。

## 错误、恢复与验证

失败保存无缺陷、无效/阻塞无备注、非法角色流转、跨范围记录、非参测系统、目录删除有记录、未解决缺陷的执行移除均返回明确业务错误。导入预览不写库；确认在一个事务中执行。前端保留加载、空、失败、只读、提交中、确认和移动端状态。

验证使用测试管理 Maven 测试、Flyway/治理检查、Vite 构建、认证 API 数据断言和浏览器桌面/手机路径。风险集中在附件平台、既有角色配置和本地环境数据；任一公共能力需要修改时停止并升级。
