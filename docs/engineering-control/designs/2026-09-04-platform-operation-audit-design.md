# 平台全局操作审计日志设计

## 目标与边界

平台统一记录新增、修改、删除、审批、导入导出、登录和敏感查询。普通列表、统计、健康检查、轮询和选项查询不记录。日志只保存操作元数据，不保存请求体、响应体、密码、Token、文件、签名 URL、审批意见正文或字段值。

## 方案选择

采用“全局拦截器 + 集中审计策略 + 请求级语义上下文”。单纯按 HTTP 方法无法准确识别审批、导入导出和敏感 GET；逐控制器手工记录又会产生大量重复实现。组合根在请求结束后统一写一条日志，业务已有 `SystemOperationAudit` 只向请求上下文补充操作码；非 HTTP 调用仍直接落库。

领域专用审计表继续保留，它们回答领域状态变化；`sys_operation_log` 回答平台访问和操作追踪，二者不互相替代。

## 采集流程

1. 拦截器只处理已认证请求。`POST/PUT/PATCH/DELETE` 默认纳入；登录由 `sys_login_log` 负责；预览、校验、轮询、内部回调等集中排除。
2. `GET` 仅在敏感路径策略中纳入，包括系统用户角色权限、组织成员、参数配置、工作流审批详情、附件预览下载、迁移失败结果以及日志查询。
3. 请求开始建立 shared/common 中无业务数据的 `OperationAuditContext`。原有手工审计写入操作码、业务对象和错误语义；更新请求的反序列化 Advice 只提取字段名，不读取或序列化字段值。
4. 请求完成后根据响应状态写入一条日志。异常信息只保存异常类别或 HTTP 状态，不保存可能含业务值的原始消息。
5. 项目从可信路径变量、查询参数或服务端语义上下文解析，并从 `pm_project` 获取名称快照；不能确认时保持空值。
6. 日志写入独立事务，写入失败只输出受控系统错误及 Trace ID，不覆盖业务响应。

## 数据模型

`V156` 为 `sys_operation_log` 追加：操作者名称快照、模块编码/名称、操作类型、业务对象类型/标识、项目 ID/名称快照、HTTP 状态、耗时、User-Agent 和修改字段名 JSON。所有新列允许为空以兼容存量数据，并增加项目时间、类型时间索引。

`sys_login_log` 结构保持不变。两张日志表均保留 180 天；每天执行批量删除。清理完成后只向操作日志写一条 `audit:retention:cleanup` 汇总记录，记录删除数量的字段名/结果元数据，不为每一行生成日志。

## 权限与菜单

- `SUPER_ADMIN`：查询本租户全部操作日志和登录日志。
- 项目负责人或有效项目角色 `PM`：查询其负责项目的操作日志，不显示登录页签。
- 其他用户：不返回审计菜单，接口返回 403。

菜单为“系统管理 > 审计日志”。认证路由查询在用户拥有任一可管理项目时动态补入系统目录和审计菜单；后端查询仍独立执行数据范围校验，前端显隐不作为授权。

查询范围始终限制在最近 30 天。即使客户端传入更早日期，服务端也将开始时间截断至当前时间前 30 天。项目管理员的 SQL 必须带 `owner_id` 或 `PM` 角色存在条件，不能先查全量后在内存过滤。

## 页面设计

页面包含操作日志与登录日志页签；登录页签仅超级管理员可见。筛选区提供日期、模块、操作类型、结果、项目和关键字，默认最近 30 天。桌面使用 `UiDataTable`；移动端改为卡片，身份区展示操作与结果，事实区展示用户、模块、项目、对象和耗时，详情折叠区展示路径、IP、Trace ID、User-Agent 和修改字段。

加载、空数据、失败、无权限和分页状态均明确呈现。页面不提供修改、删除或导出日志的入口，避免审计数据被普通管理操作改变。

## 错误与运行保障

- 审计写失败不影响业务事务；服务端按 Trace ID 记录一次错误。
- 查询参数非法返回 400；无审计权限返回 403；项目筛选超出授权范围返回空结果且不泄露项目存在性。
- 清理任务使用可配置 cron 和 180 天固定下限，单次 SQL 批量删除后记录汇总。
- 反向代理 IP 由 Spring 标准转发头策略解析，部署层只允许可信 Nginx 访问后端端口。

## 验证与回退

验证覆盖采集策略、去重、成功失败、字段名最小化、项目权限、查询上限、清理边界、迁移、前端构建及四个视口。代码回退时保留 V156 可空列和索引；需要物理回退结构时追加补偿迁移，不修改 V156。
