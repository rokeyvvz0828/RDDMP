# 工作流生命周期、编辑器、历史与电子签名工程设计

## 文档状态

- 修订：1
- 状态：已批准
- 用户确认依据：用户确认采用增量闭环方案，逐段确认生命周期、编辑器、历史、电子签名、接口、数据和验收设计，并于 2026-08-17 明确要求“开始实施”。

## 目标与成功信号

在不重构 Flowable 核心架构的前提下，修复流程定义生命周期语义、流程图串行插入、编辑弹窗可达性、版本与更新历史以及平台内部电子签名闭环。

成功信号：已发布流程可安全归档和恢复，运行实例与历史不受影响；管理员能查看版本和变更记录；常见串行节点可自动插入；低分辨率下保存按钮始终可达；需要签名的审批动作不能绕过服务端校验并形成可查询凭据。

## 使用者与场景

- 流程管理员：创建、编辑、发布、取消发布、归档、恢复流程，并查看历史版本与更新记录。
- 审批人：在业务审批或平台审批入口处理任务，在节点要求时使用当前登录身份确认签署。
- 运营与审计人员：查看定义生命周期记录、历史流程图和签署凭据。
- 业务模块：通过现有工作流公开 API 发起和处理流程，不直接操作 Flowable 或工作流业务表。

## 必须需求与验收条件

### R1 流程定义生命周期

- 草稿允许软删除；已发布流程不允许删除，只允许填写原因归档。
- 归档只禁止新实例，不删除部署、版本、运行实例、任务或历史。
- 管理员可填写原因恢复发布，继续使用归档前版本且不生成新版本。
- 验收：归档前启动的实例可继续处理；归档定义可查看详情和历史；恢复后可再次发起。
- 反例：归档后定义详情消失，或运行中任务无法继续审批。

### R2 自动插入节点

- 零出边节点执行“从此处添加节点”时追加用户任务并建立连线。
- 单出边节点执行该操作时删除原边，创建“当前节点 -> 新节点 -> 原后续节点”两条边。
- 多出边网关不猜测分支，要求用户选择具体连线；用户任务和抄送节点继续遵守单入边、单出边约束。
- 验收：插入后的模型可通过后端校验、保存和发布，原后续节点不丢失。
- 反例：用户必须先删除连线才能插入，或插入后原后续节点成为孤立节点。

### R3 编辑器视口适配

- 设计器弹窗采用视口最大高度和纵向 flex 布局，标题、底部操作栏固定可见，中间区域独立滚动。
- 画布高度使用可用空间，不以固定 `560px` 撑出屏幕；全屏模式保持现有行为。
- 验收：桌面及 375、390、430 像素宽视口中保存或关闭操作可达，页面无整体横向滚动。
- 反例：需要浏览器缩放或滚动页面主体才能找到“保存流程”。

### R4 版本历史和更新记录

- 定义详情提供“当前设计 / 历史版本 / 更新记录”。
- 历史版本展示版本号、状态、模型版本和创建时间，并可只读查看对应流程图。
- 更新记录覆盖创建、修改、发布、取消发布、归档和恢复，展示操作人、时间、原因和版本号。
- 验收：同一定义的多个版本和生命周期事件可按时间追溯。
- 反例：只能看到当前版本，或更新记录无法说明谁在何时执行了什么操作。

### R5 平台内部电子签名

- 用户任务配置明确展示“需要电子签名：是/否”，默认“否”，并随发布版本冻结。
- 需要签名时，同意、拒绝、退回必须由当前登录人确认签署；加签、转办、委托和抄送不要求签名。
- 后端从实例绑定版本的节点配置判断签名要求，不信任前端显隐或请求中的身份。
- 签署凭据保存签署人身份快照、定义版本、实例、任务、动作、签署时间和审批内容摘要哈希。
- 验收：缺少签署确认的受控动作被拒绝；成功审批与签署记录在同一事务中落库并可审计。
- 反例：前端隐藏签署区域后仍能通过直接调用 API 完成受控审批。

### R6 schema 元数据一致性

- 保持已执行 V34 不变，追加迁移再次修复 JSON schema 与定义、版本元数据。
- 修正本地演示数据同步源，避免应用启动后重新写回错误值。
- 验收：迁移和 Mock 同步后，所有 JSON `schemaVersion=2` 的记录元数据均为 2。
- 反例：Flyway 显示 V34 成功，但应用启动后不一致数量重新大于零。

## 不变量与约束

- 已启动实例始终绑定原 `definition_id + version_no + deployment_id`，定义生命周期操作不得改变其实例执行图。
- 所有查询和写入带租户范围，审批身份来自服务端认证上下文。
- Flowable `ACT_*` 表不由前端或业务模块直接操作。
- Flyway 迁移只追加，不修改 V34 或其他已发布脚本。
- 保持 Spring Boot 3.4.4、Java 17、MySQL 8.4、Vue 3、TypeScript、Element Plus 和现有统一响应模型。
- 只修改最新 `origin/main` 基线可见的工作流能力，不带入 `rokey` 未提交或未合并的业务代码。

## 非目标

- 不实现第三方 CA、证书链、印章图片、短信确认或外部签名平台。
- 不重写工作流设计器、BPMN 编译器或 Flowable 运行引擎。
- 不实现多出边网关的自动分支猜测。
- 不改造配置管理业务模块的审批页面；平台 API 提供签名要求和签署能力供其后续接入。
- 不恢复已下线的输入项配置或依赖 `biz_form_*`。

## 方案比较与选择

| 方案 | 能力覆盖 | 代价与风险 | 结论 |
| --- | --- | --- | --- |
| 仅前端优化 | 可改善插入、弹窗和开关展示 | 无法保证生命周期、历史和签名留痕 | 不选 |
| 增量闭环改造 | 复用现有 Flowable、`wf_version`、`wf_audit_event`，补齐前后端和迁移 | 需要公共平台与数据库专项回归 | 选择 |
| 重构设计器和版本模型 | 长期模型可重新统一 | 范围大、回归风险高，不适合本次修复 | 不选 |

## 架构边界与组件职责

- `WorkflowDesigner`：处理节点追加、单边插入和图模型同步，不承担发布校验。
- `WorkflowNodeInspector`：配置用户任务属性，将现有签名开关改为明确的“是/否”。
- `WorkflowView`：承载生命周期操作、历史页签、历史流程图、响应式弹窗和平台审批签署交互。
- `web/src/api/workflow.ts`：维护生命周期、历史、审批和签署的类型与请求契约。
- `WorkflowController`：提供租户认证后的 HTTP 接口和归档权限门禁。
- `WorkflowService` / `FlowableWorkflowService`：执行状态约束、版本历史、定义事件、任务签名要求和事务编排。
- `WorkflowAuditService`：统一记录定义生命周期与任务动作事件。
- `wf_version`：版本流程图唯一事实源；已发布版本不可变。
- `wf_audit_event`：定义更新和流程动作时间线。
- `wf_signature`：V35 已建立的不可变平台内部签署凭据，本次直接复用。
- V42 Flyway 迁移与 `mock/mock-data.json`：修复存量元数据并防止本地同步回归。

## 接口、数据和状态流

### 生命周期接口

- `DELETE /api/workflows/definitions/{id}`：只允许 `DRAFT`，软删除后不展示。
- `POST /api/workflows/definitions/{id}/archive`：只允许 `PUBLISHED`，请求体包含必填 `reason`，状态变为 `ARCHIVED`。
- `POST /api/workflows/definitions/{id}/restore`：只允许 `ARCHIVED`，请求体包含必填 `reason`，状态恢复为 `PUBLISHED`。
- 定义列表和详情保留 `ARCHIVED` 数据的可见性；发起接口仍只接受 `PUBLISHED`。

状态流：

```text
DRAFT --发布--> PUBLISHED --归档--> ARCHIVED --恢复发布--> PUBLISHED
  |                    |
  +--删除--> hidden    +--取消发布--> DRAFT(新草稿版本)
```

### 历史接口

- `GET /api/workflows/definitions/{id}/versions`：返回定义全部版本摘要。
- `GET /api/workflows/definitions/{id}/versions/{versionNo}`：返回指定版本及 `definition_json`。
- `GET /api/workflows/definitions/{id}/events`：返回定义级审计事件，不混入实例任务事件。

### 签名接口和事务

- 用户任务配置复用已有布尔字段 `signatureRequired`，前端由文本开关改为明确的是/否选项。
- 待办和任务详情返回服务端计算的 `signature_required`。
- 审批动作请求复用已有布尔字段 `signatureConfirmed`。
- 后端读取实例绑定版本和任务 `node_id`，判断该动作是否需要签名；需要但未确认时返回冲突类业务错误。
- 受控审批继续复用现有事务写 `wf_task_action`、`wf_audit_event` 和 `wf_signature`，本次增加回归测试，不新建签署表。
- `wf_signature.data_digest` 继续使用业务接入时生成的规范化数据摘要；签署记录不接受前端传入签署人。

## 错误、降级与恢复

- 删除非草稿：返回“只有草稿流程可以删除”。
- 归档非已发布或恢复非已归档：返回当前状态不支持该操作，不修改数据。
- 归档/恢复原因为空：返回参数错误。
- 历史版本不存在或跨租户：统一返回流程版本不存在。
- 多出边节点右键添加：不修改图，提示选择具体连线；单边插入失败时保持原图不变。
- 需要签名但未确认：不推进 Flowable、不更新任务、不写部分签署记录。
- 签署持久化失败：审批事务整体回滚。
- 历史或签署数据加载失败：当前流程设计仍可查看，失败区域给出明确错误并支持重试。

## 安全、性能、兼容性与运维

- 删除、归档、恢复使用服务端 RBAC；恢复与归档至少沿用流程定义删除/管理权限，不以按钮显隐替代授权。
- 版本、事件和签署查询均校验租户及定义实体归属。
- 签署人、账号和显示名来自认证与用户表快照，不接收客户端身份字段。
- 历史版本和事件分页或受控返回，索引覆盖租户、定义、版本和创建时间。
- 现有未配置 `signatureRequired` 的版本按 `false` 处理，保持兼容。
- 现有 `PUBLISHED` 和 `DRAFT` 数据无需重建；新增 `ARCHIVED` 为字符串状态扩展。
- 归档不删除 Flowable deployment，避免影响运行实例；恢复不重复部署。
- 监控新增迁移后 schema 元数据不一致数量，发现回归时检查本地 Mock 数据源和人工导入路径。

## 验证策略

- 生命周期服务测试：草稿删除、发布归档、归档恢复、非法状态、原因必填、运行实例不受影响。
- 历史服务测试：版本排序、指定版本、定义事件过滤、租户隔离和归档可见。
- 编辑器验证：零边追加、单边插入、原目标保留、多边不修改、保存模型可通过后端校验。
- 签名服务测试：版本配置判断、三个受控动作、非受控动作、身份不可伪造、事务回滚和签署记录内容。
- 迁移验证：V42 在 MySQL 8.4 执行，V34、V35 校验和不变，不一致计数为零。
- 前端构建与浏览器：桌面和 375x812、390x844、430x932 视口检查弹窗、操作可达、历史和签署；明暗主题可读。
- 完整门禁：JDK 17 聚焦测试、`mvn test`、前端构建、治理检查、任务范围检查和 `git diff --check`。

## 假设、未知项与决策记录

- 假设：`wf_definition.status` 为可扩展字符串，无需修改列类型；现有查询只将 `PUBLISHED` 视为可发起状态。
- 假设：平台当前登录身份足以构成内部确认签署，用户已明确不要求外部 CA。
- 假设：历史事件以定义生命周期和更新行为为粒度，不要求流程图逐字段可视化 diff。
- 未知项：无阻塞未知项。
- 决策 D1：选择增量闭环改造，不重构工作流引擎。
- 决策 D2：已发布流程使用可恢复的归档，不使用删除。
- 决策 D3：签名属于用户任务节点配置，并对同意、拒绝、退回生效。
- 决策 D4：V34 保持不变，使用后续迁移修复。

## 风险与回退原则

- 生命周期状态遗漏可能导致归档流程仍可发起：所有发起入口统一复用已发布定义查询，并增加服务测试。
- 插入边处理错误可能破坏流程图：图变更一次性构造后提交，失败不修改原数组，并以模型校验作传感器。
- 签名要求读取错误版本可能误放行：只读取实例固化版本，不读取定义当前版本。
- 签名记录与审批状态不一致：使用同一 Spring 事务，任一写入失败整体回滚。
- 新迁移与本地已执行版本冲突：本地数据库已有 V40/V41 历史，因此本次从 V42 追加；后续集成由 Owner 保持版本唯一，禁止修改已执行迁移。
- 应用回退时保留已执行迁移、已修复元数据和 V35 既有签署记录，不执行破坏性数据库回滚。
