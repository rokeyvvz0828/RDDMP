# 审批中重复申请门禁工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认创建前预检方案，并要求直接实施；明确保存草稿同样不得绕过审批中旧申请。

## 目标与成功信号

同窗口、同交付内容存在审批中申请时，禁止新申请保存草稿或提交审批。冲突弹框展示旧申请详情；当前用户创建的审批中旧申请可在卡片右下角快捷撤销；全部旧申请退出审批中状态后才允许继续原操作。

## 使用者与场景

版本申请人在保存草稿或提交审批时遇到同窗口、同交付内容的历史申请，其中至少一张仍在审批中。

## 必须需求与验收条件

- R1：保存草稿和提交审批前均执行冲突预检；存在审批中冲突时不插入、不更新新申请。
- R2：创建、更新和提交后端接口均独立强制检查审批中冲突，不能通过跳过预检、冲突令牌或并发请求绕过。
- R3：弹框完整展示旧申请信息，审批中且由当前用户创建、当前用户有撤回权限时，在卡片右下角显示“撤销申请”。
- R4：撤销必须填写原因；提交后显示处理中并每 2 秒刷新，任意旧申请仍审批中时底部“继续申请”禁用并提示原因。
- R5：全部审批中冲突变为已撤回后，“继续申请”恢复原始动作；原操作为保存草稿则此时创建/更新草稿，原操作为提交则创建/更新后提交审批。
- R6：底部固定显示“取消”和“继续申请”；取消返回原表单并保留前端数据，数据库不产生新草稿。

## 不变量与约束

- 复用现有撤回接口、工作流终止回调和冲突详情结构。
- 仅 `IN_REVIEW` 是本门禁的阻塞状态；`WITHDRAWN`、`CANCELLED`、`RELEASED` 不阻塞继续申请。
- 追加申请判定仍只基于已准出历史版本及制品变化。
- 不新增数据库字段或迁移，不改变工作流撤回状态机。
- 保护 `rokey` 工作区其他未提交修改，不提交、不推送、不清理。

## 非目标

- 不自动替其他用户撤销申请。
- 不改变草稿、退回、已撤回旧申请的既有取消/编辑处理规则。
- 不改变冲突匹配范围、版本类型判定或审批流程配置。

## 方案比较与选择

选择“前后端双重门禁 + 创建前预检”。前端预检避免产生无效草稿并提供交互，后端三处检查保证不能绕过。仅前端禁用按钮无法抵御直接 API 调用；先落库再弹框违反用户明确要求。

## 架构边界与组件职责

- `ReleaseApplicationService`：根据未持久化写入请求生成冲突预览，并在创建、更新时拦截审批中冲突。
- `ReleaseSubmissionService`：提交时再次拦截审批中冲突。
- `ReleaseApplicationController`：提供创建和更新两种冲突预检入口。
- `ReleaseManagementPrototype.vue`：暂存原操作、调用预检、发起撤回、轮询状态并恢复操作。
- `ReleaseConflictDialog.vue`：展示卡片级撤销操作和底部门禁状态。

## 接口、数据和状态流

- `POST /api/release/applications/conflicts/preview`：接收创建请求，返回未落库冲突报告。
- `POST /api/release/applications/{code}/conflicts/preview`：接收更新请求，校验所有权、可编辑状态和行版本后返回冲突报告。
- 保存或提交先预检；阻塞时保存 `{payload, mode, attachments, edit identity}` 于前端内存并打开弹框。
- 撤回成功后轮询同一预检接口；无审批中冲突时启用继续按钮；继续时重新执行完整预检与后端持久化检查。

## 错误、降级与恢复

- 撤回失败：保持继续禁用，显示接口错误并允许再次撤回。
- 轮询失败：保持继续禁用，下次轮询继续尝试并显示状态刷新错误。
- 状态竞态：创建、更新或提交返回 409，前端重新预检并回到阻塞弹框。
- 弹框关闭：停止轮询，清理暂存操作；抽屉内表单数据保持。

## 安全、性能、兼容性与运维

预检和轮询沿用当前认证、租户隔离、所有权及权限校验。轮询仅在阻塞弹框打开时每 2 秒进行，关闭即停止。无迁移和运维配置变化。

## 验证策略

- 后端单元测试覆盖预检不落库、创建/更新门禁、提交令牌无法绕过、撤回后可继续。
- 前端构建检查类型和模板契约。
- 浏览器验证同用户、其他用户、撤回处理中、撤回完成、取消保留表单和继续恢复两种原始操作。
- 运行 release 模块测试、前端生产构建和 `git diff --check`。

## 假设、未知项与决策记录

- D1：只将审批中状态作为新门禁阻塞条件。
- D2：第二张申请在门禁解除前完全不落库。
- D3：撤回原因必填，状态刷新周期为 2 秒。
- D4：多张冲突申请时，全部退出审批中状态后才能继续。
- 未知项：无阻塞未知项。

## 风险与回退原则

主要风险是异步工作流终止存在延迟，以及预检与最终写入之间的竞态。通过轮询、最终后端复检和 409 回退控制。回退时同时恢复预检接口、三处门禁和前端状态机，避免只回退一侧造成行为不一致。
