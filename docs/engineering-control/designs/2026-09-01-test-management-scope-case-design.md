## 不变量与约束

- 不重复实现全局项目选择器；页面只消费现有项目上下文。
- 项目、人员、物理子系统、平台附件与文件预览均只复用，不在测试管理模块维护。
- 不修改平台附件、文件预览、公共 UI 或执行/缺陷/报告模块；后者尚未实现时状态按“未执行”派生。
- 仅追加 `V126__test_management_scope_case.sql`，不修改 V123-V125；回退代码时保留新增数据。
- 所有富文本服务端净化并复用公告板已采用的编辑器/上传路径；单附件不超过 50MB。

## 方案比较与选择

1. **推荐：同一迁移、两个领域服务、共享最小支持代码。** `TestScopeService` 专注范围和范围目录，`TestCaseService` 专注案例和案例目录；两者通过同一模块内的编号联动事务协作。页面分别实现，复用一个紧凑工作台骨架、通用列表和公共附件能力。这样保持模块边界清晰，也能在一次敏捷迭代内完成依赖链。
2. 单一巨型“范围案例服务/页面”。实现快但会把目录、导入、编号、附件和批量行为混在一起，后续执行模块无法稳定消费，未采用。
3. 提前实现执行/缺陷快照来计算最终状态。会越过当前模块边界且显著扩大范围，未采用；本次预留基于未来执行表的派生查询，缺表时明确返回未执行。

## 架构边界与组件职责

- `V126`：新增范围目录、范围、案例目录、案例、案例附件与统一审计表；均带租户、大类、项目、系统、软删除和时间字段。
- `TestScopeService` / `TestScopeController`：范围树、目录与范围 CRUD、编号预览/校验、置无效、软删除/恢复预留、筛选分页、导入预校验与提交、导出；修改序号时事务内调用案例编号前缀同步。
- `TestCaseService` / `TestCaseController`：案例树、案例 CRUD、案例范围迁移、目录移动、批量调整、置无效/删除分支、核算核对、附件绑定、导入预校验与提交、导出。
- `ScopeCaseWorkbookService`：使用既有工作簿依赖生成模板/导出，并处理范围与案例的预导入；不把 xlsx 解析放进 Controller。
- 前端 `scope/` 与 `case/`：各自为“左树 + 右侧筛选/工具栏/通用数据表”的紧凑页面；移动端将树切换为上方可展开选择区、列表切换信息卡片，表格只在其自身容器横向滚动。

## 接口、数据与状态流

- 接口前缀：`/api/test-management/scopes/{domain}` 与 `/api/test-management/cases/{domain}`；项目 ID 从当前全局上下文显式传入，服务端验证项目与大类范围。
- 范围接口提供树、目录 CRUD、范围分页/详情/保存/置无效/删除、导入模板/预校验/提交和导出。范围保存返回需确认的编号变更影响摘要；前端确认后才提交原子变更。
- 案例接口提供树、目录 CRUD、案例分页/详情/保存/移动/批量调整/置无效/删除、核算核对、附件绑定、模板/预校验/提交和导出。范围变更返回编号前缀影响摘要。
- 编号：范围为 `系统编码-流水号`；案例为 `范围序号-四位流水号`。流水号从历史最大值递增，软删除记录也占用编号以保证恢复无冲突。
- 状态：范围手工无效优先，否则按未来最新执行记录聚合；案例手工无效优先，否则按未来最新执行记录。当前执行表不存在时均为未执行，不伪造执行结果。
- 列偏好只保存前端本地、按登录用户/测试大类/项目和模块键分区；表格继续复用交付示范中心列表的排序和列宽能力。

## 错误、降级与恢复

- 未选项目、无参测系统、空目录、筛选无结果、加载失败、无权限和提交中均有明确页面状态。
- 序号格式/唯一性、目录层级、范围不可见、字典停用值、附件大小和富文本必填项在服务端校验；前端就近提示并保留输入。
- 导入先返回行级结果、重复处理和自动建目录清单；存在任一失败行时确认按钮禁用，提交阶段再次校验避免并发覆盖。
- 已被未来执行记录引用的案例删除返回“只能置无效”；目录删除在事务中先移动子数据再软删除目录。
- 富文本或附件预览失败不丢失已保存案例，保留下载和重新打开操作。

## 安全、性能、兼容性与运维

- 后端从认证用户获取租户与操作人，使用既有测试管理菜单权限并在实体查询中限制大类、项目和参测系统；前端显隐仅改善体验。
- 所有分页、筛选和排序均在服务端执行；导入单批限定现有 50MB 文件限制且采用一次事务。
- 使用现有数据字典选项和附件公开契约，避免新增平台公共依赖；已发布配置、公告和方案数据不受影响。
- 审计表只保存变更摘要与标识，不存储附件内容、密钥或未净化 HTML。
