# 字段治理与视图设计器基础能力设计

**状态：** approved-by-user-request

## 1. 设计结论

采用模块独立、平台能力复用的模式：字段和视图配置遵循统一协议，但每个业务模块自己维护菜单、路由、页面、API、业务服务、主表和验收。平台不实现跨业务的万能动态 CRUD 或任意组件加载。

## 2. 配置层级

```text
biz_form_scope
  └── biz_form_field_definition  (业务表单字段集合)
       ├── biz_form_view_field    (表单/列表/详情视图引用)
       └── biz_form_view_step_field (分步视图引用)

biz_form_view
  ├── form / detail / list / approval / wizard
  ├── biz_form_view_field
  └── biz_form_view_step

biz_form_page
  └── biz_form_page_block
```

`field_definition` 是字段主列表在当前业务范围内的可用集合。视图只能引用集合中的字段；列表字段必须引用 `form_available=1` 的业务字段。只读状态、创建人和创建时间也可以登记为业务字段，但不必在新建页面可编辑。

字段核心属性由字段元数据维护：编码、类型、值类型、数据来源、通用校验、组件白名单和启用状态。页面视图只维护分区、顺序、栅格、列宽、筛选、排序、移动端展示和动作规则。

系统设置中的“输入项配置”作为字段主数据审阅和发布入口，不再编辑分区与布局；历史 `biz_form_section` 数据保持兼容读取。分区标题、布局模式、字段归属和视图预览由视图设计器维护，并保存在现有视图 `layout_json` 与 `view_section_key` 中，避免字段主数据和视图配置出现两套可编辑来源。

## 3. 数据模型

- `biz_form_view`：一个业务范围下的可发布视图，视图类型受白名单限制。
- `biz_form_view_field`：视图到字段定义的引用和视图级展示属性。
- `biz_form_view_step`：分步表单步骤；`biz_form_view_step_field` 将步骤绑定到同一视图中的字段。
- `biz_form_page`：模块拥有的页面编排定义。
- `biz_form_page_block`：页面中引用的模块 Block，保存类型、引用编码、布局、权限和受控配置。

不使用数据库中的组件路径动态加载 Vue 文件。页面 Block 只能使用平台或业务模块登记的 `block_type` 和 `ref_key`，前端路由仍由业务模块明确声明。

## 4. 服务边界

`BusinessFormMetadataService` 负责元数据读写、引用校验、发布快照和审计；业务模块负责核心数据服务、跨表规则、状态流转和特殊动作。公共设计器只消费稳定 DTO，不直接写业务主表。

视图保存时服务端检查：租户、scope 归属、字段启用状态、列表字段可用标记、视图类型、步骤归属、页面 Block 白名单和权限前缀。前端隐藏字段和按钮不替代后端校验。

## 5. 设计器边界

1. 字段属性中心先登记字段集合。
2. 表单设计器从字段集合选择和布局。
3. 列表设计器从业务表单字段集合选择列、筛选和排序字段。
4. 分步设计器编排表单字段集合中的字段。
5. 页面 Block 设计器只编排已登记 Block，不承担业务代码和任意脚本。

本次先交付元数据底层和基础视图配置能力；具体列表设计器、分步设计器和页面 Block 可视化交互在同一契约上分阶段补齐。

## 6. 版本与回退

发布视图时生成完整快照，历史业务数据保存字段定义 ID 和配置版本。字段编码不可变；字段类型、值类型和已发布引用变更必须通过兼容性校验。回退通过切换应用/配置版本，不删除 V35 表或历史快照。

## 7. 验收与风险

- 必须验证跨 scope 字段引用失败、列表引用不可用字段失败、步骤引用外部字段失败和 Block 未登记失败。
- 必须验证旧 V32/V33/V34 配置仍可读取，现有输入项配置页不回归。
- 风险：当前已有字段定义同时承载部分默认布局属性；本次保留兼容字段，新增视图属性优先使用引用表，后续逐步减少视图对全局布局字段的依赖。
