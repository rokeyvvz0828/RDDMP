# 投产基线维护时间限制工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认未结束窗口采用“可查看、不可维护”，要求窗口下拉选项展示不可维护原因，并在复核落盘设计后明确要求开发。

## 目标与成功信号

投产管理人员在窗口结束前仍可查看完整基线，但无法提前维护最终投产结果。窗口下拉、页面状态和服务端错误使用同一 `productionEnd` 规则；当前时间达到结束时间后开放维护。

## 使用者与场景

投产管理人员在“配置管理 / 投产基线”选择窗口，查看物理子系统、交付单元、准出版本及投产结果。未结束窗口用于过程核对，结束后才进入结果维护阶段。

## 必须需求与验收条件

- R1：窗口下拉项展示编码、名称、状态、投产结束时间；未结束时展示不可维护原因，但仍可选择。
- R2：选中未结束窗口后，基线数据正常可见，行选择、单条维护和批量维护均不可操作，页面有明确原因。
- R3：前后端都以 `now >= productionEnd` 为开放边界；前端定时更新时间，后端使用 `Asia/Shanghai` 业务时区。
- R4：单条和批量接口均从基线明细的 `windowId` 查询租户内窗口并校验；提前调用不产生结果写入和审计日志。
- R5：限制统一适用于常规、紧急和应急版本，且不改变已维护不可重复维护、乐观锁、结果字段校验和审计行为。

## 不变量与约束

- `productionEnd` 的权威来源是现有投产窗口记录，不接受客户端传入维护资格。
- 窗口和基线明细均按当前租户查询。
- 不修改公开 API DTO、数据库结构、窗口状态算法或版本归窗规则。
- 批量接口保持事务原子性；任何明细不满足窗口时间条件时整批回滚。
- 保留 `rokey` 工作区中所有其他未提交修改。

## 非目标

- 不阻止查看未结束窗口。
- 不允许人工绕过、管理员特权或应急版本例外。
- 不重构投产基线 API 为新的聚合响应。
- 不修改移动端布局。

## 方案比较与选择

选择前后端双重校验。前端通过现有 `ReleaseWindowDto.productionEnd` 提供即时反馈；后端通过 `ReleaseWindowStore` 根据每条基线的 `windowId` 强制校验。仅前端方案可被接口绕过；改造基线接口返回维护资格会扩大公开契约，当前没有必要。

## 架构边界与组件职责

- `ReleaseBaselineView.vue`：维护当前时间、派生窗口维护资格和原因；定制窗口选项；统一控制选择框、单条和批量入口。
- `ReleaseProductionService.java`：在任何结果语义校验和写入前，锁定/读取基线明细后查询租户窗口，校验当前时间不早于 `productionEnd`。
- `ReleaseProductionServiceTest.java`：使用固定 `Clock` 覆盖结束前、边界时刻、批量拒绝和原有结果规则。
- `ReleaseWindowStore`、`ReleaseWindowDto` 和现有 REST 接口只被复用，不修改。

## 接口、数据和状态流

前端加载窗口列表后，以业务当前时间比较 `productionEnd`。未结束选项显示“不可维护：投产窗口将于 YYYY-MM-DD HH:mm 结束”，选中后显示相同页面提示并禁用所有维护入口。计时器按分钟更新当前时间，到达边界后重新计算资格。

服务端单条维护先锁定基线明细，再按 `before.windowId + user.tenantId` 查询窗口。窗口不存在返回业务错误；`now.isBefore(productionEnd)` 返回冲突错误。批量接口继续在同一事务内逐条调用内部方法，因此任一失败会回滚整批。

## 错误、降级与恢复

- 窗口未结束：返回 `CONFLICT`，消息为“投产窗口尚未结束，结束时间为 YYYY-MM-DD HH:mm，不能提前维护投产结果”。
- 窗口不存在：返回业务错误，不尝试更新基线。
- 前端本地时间与服务端不一致：服务端结果权威；前端展示接口错误并可刷新窗口。
- 窗口结束时间被管理员调整：下一次窗口刷新更新提示，服务端立即按最新记录校验。

## 安全、性能、兼容性与运维

校验使用当前租户和服务端业务时钟，不扩大权限。单条维护增加一次按主键查询；批量最多 200 条，沿用现有限额和事务。API 请求与响应结构保持兼容。无需迁移、配置或数据补偿。

## 验证策略

后端测试覆盖结束前拒绝且无写入、结束时允许、批量含未结束窗口时回滚意图及原有结果规则。运行发布模块完整测试。前端运行 TypeScript/Vite 生产构建，并在桌面浏览器验证下拉双行提示、可查看不可维护、禁用状态、时间边界和控制台错误。最后运行治理、范围和 diff 检查。

## 假设、未知项与决策记录

- 假设：浏览器时间与服务端业务时间通常同步；即使偏差，后端仍保证规则正确。
- 未知项：无阻塞未知项。
- D1：所有版本类型统一受窗口结束时间限制。
- D2：未结束窗口保持可选择，以满足过程查看需求。
- D3：开放边界为当前时间达到结束时间，而不是依赖 `CLOSED` 状态。

## 风险与回退原则

主要风险是前后端时钟短暂不一致和批量跨窗口数据异常。通过服务端权威校验、固定时钟测试和事务回滚控制。回退只涉及本需求的三份产品/测试文件，不需要数据库回滚。
