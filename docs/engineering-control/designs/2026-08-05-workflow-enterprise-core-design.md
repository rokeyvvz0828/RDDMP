# 企业级流程核心能力设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认采用“自定义中文流程设计器 + Flowable 运行引擎”，并选择首期核心企业级流程范围。

## 目标与成功信号

将当前仅支持线性审批的流程模块升级为可落地的企业级审批基础设施。流程设计使用中文业务模型，运行时转换为标准 BPMN 并交由 Flowable 执行，同时保留现有 `definitionJson` 接口兼容性。

成功信号：

1. 管理员可以创建草稿、绘制流程、校验、发布版本和停用流程；已发布实例始终绑定发布时的版本。
2. 流程可以表达条件分支、并行分支、汇聚、会签、抄送和退回等企业审批行为。
3. 审批人可以来自用户、角色、组织负责人、发起人、表单字段或流程表达式，并在运行时解析。
4. 运行人员可以查看待办、已办、流程轨迹、节点耗时和审批审计；异常实例可以被授权管理员标记、重试或终止。
5. 旧版线性 `definitionJson` 能被读取和迁移，不影响已存在的流程定义数据。

## 用户与场景

- 流程管理员：维护流程、审批人规则、表单字段、版本和发布状态。
- 业务发起人：选择已发布流程，提交业务单据和流程变量。
- 审批人：处理待办，执行同意、拒绝、退回、转交、委托、加签、减签和抄送。
- 组织管理员：维护角色、组织和人员关系，为审批人解析提供数据。
- 运营审计人员：查询实例、节点、动作、耗时和异常记录。

## 必须需求与验收条件

### R1 流程版本与发布

- 草稿、已发布、停用状态分离；同一流程可存在多个版本，但只能有一个当前发布版本。
- 发布前必须校验开始节点、结束节点、连接完整性、网关条件、审批人配置和变量引用。
- 已启动实例固化 `definition_id + version_no + BPMN deployment id`，后续编辑不改变实例执行图。
- 反例：发布后编辑流程，历史实例的审批节点或审批人规则不能被悄然改变。

### R2 中文可视化设计器

- 提供节点面板、画布、连线、属性面板、缩放、自动布局、撤销重做和校验结果定位。
- 首期节点包括开始、人工审批、抄送、条件网关、并行网关、汇聚网关、结束。
- 自定义业务模型编译为 BPMN 2.0；前端不直接编辑 Flowable 内部表。
- 反例：保存一个只能由前端显示、Flowable 无法执行的节点配置。

### R3 审批人和审批策略

- 审批人来源支持指定用户、角色、组织负责人、发起人、表单字段和表达式。
- 支持或签（任一通过）、会签（全部通过）、比例通过；同一审批节点允许配置去重、空审批人处理和审批顺序。
- 角色和组织解析必须受当前单租户边界约束。
- 反例：角色中没有有效用户时流程进入无审批人节点且没有明确失败状态。

### R4 网关、会签与审批动作

- 条件网关支持基于流程变量的比较、布尔组合和默认分支；表达式执行必须使用受限表达式上下文。
- 并行网关支持分支创建和汇聚；会签使用 Flowable 多实例任务或等价标准 BPMN 语义。
- 首期审批动作支持同意、拒绝、退回、转交、委托、加签、减签、抄送。
- 每个动作记录操作人、目标人、意见、来源任务、时间和结构化参数。
- 反例：分支条件均不满足且没有默认路径时，流程必须进入可观测的异常状态，而不是静默结束。

### R5 变量和表单绑定

- 流程定义声明变量名称、类型、是否必填、默认值和可见范围。
- 发起实例时提交变量，节点条件只能引用已声明且类型匹配的变量。
- 审批节点可以绑定动态表单字段；首期表单以字段元数据和 JSON 数据为边界，不重做完整表单设计器。
- 反例：条件表达式引用不存在变量时，发布校验失败并指出节点和变量名。

### R6 监控与审计

- 提供实例列表、实例详情、流程图高亮、待办/已办、节点时间线、动作审计和异常状态。
- 管理员干预需要单独权限，并记录原因；普通审批人不能修改其他人的任务状态。
- 查询按租户、流程、业务单号、状态、发起人、时间范围分页。
- 反例：管理员终止流程但审计记录无法说明谁在何时以什么理由操作。

## 不变量与约束

- 单租户：所有流程定义、部署、实例、任务、变量和审计查询必须带 `tenant_id`，Flowable 业务键不得绕过租户校验。
- 技术基线：Spring Boot 3.x、JDK 17、MySQL、MyBatis-Plus；前后端分离，前端 Vue 3 + TypeScript + Element Plus。
- `definitionJson` 保持现有接口字段名，旧版 schema 可由适配器转换为内部业务模型。
- 流程定义和执行数据不能通过前端直接写入 Flowable 表。
- 所有用户可见页面使用中文；接口时间按 `yyyy-MM-dd HH:mm:ss` 返回，页面按既有约定展示日期。
- 不允许删除已经被实例引用的已发布版本；停用只阻止新实例发起，不影响运行中实例。

## 非目标

- 首期不实现服务任务、HTTP/Webhook、消息事件、补偿事件和复杂子流程编排。
- 首期不实现通用低代码表单设计器，只定义流程变量和字段绑定契约。
- 首期不做跨租户流程共享和多租户管理。
- 不替换现有组织、用户、角色和权限模块。

## 方案比较与选择

| 方案 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 继续自研状态机 | 复用当前代码，短期改动小 | 网关、会签、变量、定时、历史和异常恢复均需自行实现 | 不选，长期风险高 |
| 直接暴露 Flowable BPMN 编辑 | 标准能力完整 | 业务人员面对 XML/BPMN 概念，中文业务配置体验差 | 不选，前端体验不符合平台定位 |
| 自定义中文设计器 + Flowable 运行引擎 | 保留业务配置体验，运行时复用成熟引擎能力 | 需要维护业务模型到 BPMN 的编译和映射 | 选择 |

## 架构边界与组件职责

### 前端

- `WorkflowDesigner`：维护节点、连线、布局、撤销重做和选择状态。
- 节点属性面板：配置审批人、审批模式、条件、变量、表单绑定、超时和动作权限。
- `WorkflowCompilerPreview`：调用后端校验和 BPMN 预览，不在浏览器自行判定可发布性。
- 流程监控视图：展示实例、任务、轨迹、图形高亮和审计；复用现有通用表格、抽屉、状态标签和用户选择组件。

### 后端

- `WorkflowDefinitionService`：管理业务定义、草稿、版本、发布和停用。
- `WorkflowModelValidator`：校验业务模型的图结构、节点配置、条件和变量引用。
- `BpmnModelCompiler`：将业务模型转换为 BPMN 2.0，并生成节点映射、部署元数据和兼容信息。
- `FlowableRuntimeService`：封装启动实例、任务查询、完成任务、转交、委托、加签和管理员干预。
- `WorkflowAssigneeResolver`：在租户范围内解析用户、角色、组织负责人、发起人和表达式。
- `WorkflowAuditService`：记录动作、状态变化、发布、干预和异常。
- `WorkflowMonitorService`：组合 Flowable 历史数据和业务表，提供分页监控查询。

### 数据边界

- 业务表继续保存流程编码、名称、版本、业务模型、BPMN XML、部署 ID 和状态。
- Flowable 表保存引擎执行状态、运行时任务、历史任务、执行、变量和定时信息。
- 业务审计表保存租户、实例、任务、动作、操作人、目标人、意见和结构化参数。
- 旧 `wf_*` 表保留兼容读取；新运行链路以 Flowable 运行数据为准，迁移策略在实施计划阶段确定。

## 核心模型与状态流

业务定义状态：`DRAFT -> PUBLISHED -> DISABLED`。发布产生不可变版本和 Flowable deployment；新建修订从当前版本复制为草稿。

实例状态：`RUNNING -> APPROVED | REJECTED | RETURNED | TERMINATED | ERROR`。任务状态由 Flowable 管理，业务审计记录动作和状态变化。

启动流程：

```text
提交业务数据
  -> 租户与权限校验
  -> 读取当前发布版本
  -> 校验变量和表单数据
  -> 部署版本对应的 Flowable 流程
  -> 创建实例和首批任务
  -> 记录启动审计
```

任务处理：

```text
查询待办
  -> 校验任务归属或管理员权限
  -> 校验动作与节点策略
  -> 完成/转交/委托/加签任务
  -> 由 Flowable 推进网关、多实例和汇聚
  -> 同步业务实例状态与审计
```

## 接口契约

保留现有接口并逐步扩展：

- `GET /api/workflow/definitions`：分页查询定义和版本摘要。
- `POST /api/workflow/definitions`：创建定义，继续接收 `code`、`name`、`definitionJson`。
- `POST /api/workflow/definitions/{id}/draft`：基于版本创建草稿。
- `POST /api/workflow/definitions/{id}/validate`：返回节点级、边级和变量级校验错误。
- `POST /api/workflow/definitions/{id}/publish`：校验、编译、部署并发布版本。
- `POST /api/workflow/definitions/{id}/disable`：停用新实例发起。
- `POST /api/workflow/instances`：使用发布版本启动实例，提交业务键、变量和表单数据。
- `GET /api/workflow/tasks/inbox`：分页查询当前用户待办。
- `POST /api/workflow/tasks/{taskId}/actions`：提交审批动作及结构化参数。
- `GET /api/workflow/instances/{id}/timeline`：查询流程图状态、任务时间线和动作审计。
- `GET /api/workflow/monitor/instances`：管理员分页查询实例并按权限提供终止、重试等干预操作。

动作参数统一使用 `actionCode`、`comment`、`targetUserId`、`targetUserIds`、`reason` 和 `payload`，不破坏现有同意、拒绝、加签、抄送字段。

## 错误、降级与恢复

- 发布校验失败：返回结构化错误，包含 `nodeId`、`edgeId`、`field`、中文消息和错误级别，不创建部署。
- 审批人解析为空：实例进入 `ERROR` 或待配置状态，禁止静默跳过，并记录解析快照和错误原因。
- Flowable 部署失败：事务回滚业务发布状态，保留可重试的发布审计。
- 引擎推进成功、业务同步失败：使用事务边界和补偿任务重试；重复处理以实例、任务和动作幂等键去重。
- 管理员终止、重试或修复：必须校验权限、要求操作原因并写入审计。

## 安全、性能、兼容性与运维

- 所有接口复用现有认证和权限体系，新增权限粒度至少包括流程定义查看、编辑、发布、实例查看、任务代办和实例干预。
- 表达式只允许访问白名单变量、只读函数和当前用户/组织上下文，禁止任意 Java 方法调用。
- 待办和监控查询分页，常用索引覆盖租户、用户、流程定义、状态、业务键和创建时间。
- 发布与启动建立指标：发布耗时、校验失败数、任务创建数、实例异常数和引擎推进延迟。
- Flowable 数据库表由独立迁移初始化；生产环境不允许使用自动建表覆盖已有数据。
- 先完成旧流程只读兼容和新流程双轨验证，再切换新运行链路；无法转换的旧定义保持原执行路径并明确标记。

## 验证策略

- 模型验证：覆盖孤立节点、循环、多个开始/结束、网关无默认分支、条件变量不存在、会签空审批人和跨租户引用。
- 编译验证：随机组合节点编译为 BPMN，并由 Flowable 部署校验；检查节点映射可反向定位到中文设计器节点。
- 运行验证：串行、任一通过、全部通过、比例会签、条件分支、并行汇聚、退回、加签、抄送和版本固化。
- 权限验证：普通用户只能处理本人任务；管理员干预需要专有权限；所有数据按租户隔离。
- 回归验证：现有 `definitionJson` 创建、发布、启动、待办和审批接口行为保持兼容。
- 浏览器验证：中文设计器的节点添加、连线、属性配置、校验提示、流程图高亮和移动端基本布局。

## 假设、未知项与决策记录

- 假设：当前 MySQL 实例允许增加 Flowable 标准表和流程业务扩展表。
- 假设：现有用户、角色、组织数据可以通过统一服务或受控 SQL 查询读取。
- 未知项：Flowable 具体版本和 starter 组合，需要在依赖基线与 Boot 3.x 兼容性验证后固定；不阻塞本设计。
- 未知项：历史 `wf_instance/wf_task` 数据量和是否存在运行中实例，需要实施前迁移盘点；不阻塞设计，但影响切换策略。
- 决策 D1：采用自定义中文设计器与 Flowable 运行引擎的混合方案。
- 决策 D2：首期实现核心企业审批能力，服务任务、消息事件和复杂子流程后置。

用户已确认按本设计实施，服务任务和消息事件暂不纳入首期范围。

## 风险与回退

- BPMN 编译语义与业务模型不一致：通过节点映射、编译快照和部署前运行测试降低风险；失败时不发布。
- 直接切换旧运行链路造成历史任务异常：保留旧定义兼容执行，按版本选择运行适配器。
- Flowable 表和业务表事务边界不一致：统一由后端事务服务编排，并增加失败重试和一致性检查。
- 复杂表达式导致安全或性能问题：首期限定表达式语法和变量类型，禁止任意脚本执行。
