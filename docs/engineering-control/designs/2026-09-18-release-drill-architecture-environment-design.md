# 投产演练复用架构环境管理工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认移除私有投产演练环境，演练改用架构环境管理数据，并明确旧数据无需兼容、可清空。

## 目标与成功信号

投产演练不再维护重复环境。项目成员从架构管理已维护且有效的环境中选择演练环境；私有环境菜单、代码和数据均被移除。

## 必须需求与验收条件

- R1：移除私有演练环境入口与 CRUD。验收：菜单、路由、页面、权限、后端端点及私有模型均不再可用。
- R2：演练轮次使用架构项目环境。验收：只列出同项目 ACTIVE 环境，保存时服务端复核租户、项目和状态。
- R3：清空旧数据，不保留兼容层。验收：迁移删除私有环境、旧轮次、步骤与关联问题，再删除私有表。
- R4：架构环境引用受保护。验收：演练引用后删除环境返回冲突，停用环境不能用于新演练。
- R5：跨模块边界和现有授权保持。验收：投产模块只调用架构公开契约，不直连 `arch_` 表，成员授权与审计仍有效。

## 不变量与约束

- 仅追加 V217，不修改历史 Flyway。
- 用户确认数据删除不可逆；回退代码不能恢复历史数据。
- `environmentId` 保持 HTTP 字段名，但语义变为 `arch_environment.id`。
- 改动限于任务范围，禁止读取 `.env`、访问生产或修改共享 UI。

## 方案比较与选择

1. 迁移私有环境到架构环境：会产生名称匹配歧义且保留冗余历史，已拒绝。
2. 仅隐藏私有菜单：遗留并行数据源和无入口维护的数据，已拒绝。
3. 选择方案：删除私有环境与旧依赖记录，演练改用架构环境。符合用户明确的清空与不兼容要求。

## 架构边界与组件职责

- 架构模块：在 `ReleaseMasterDataQuery` 提供 ACTIVE 项目环境查询/解析；环境删除检查投产演练引用。
- 投产模块：通过 `ReleaseArchitectureDirectory` 转发公开投影，验证演练请求并读取环境显示字段。
- Boot 适配器：将两个公开接口隔离连接，不使投产模块依赖架构实现。
- 前端：移除私有环境页；演练表单加载架构环境选择项。
- Flyway：执行不可逆旧数据清理、表删除及菜单权限逻辑下线。

## 接口、数据和状态流

演练页加载 -> 投产 API -> 投产服务 -> `ReleaseArchitectureDirectory` -> 架构公开查询 -> 返回 `{id,code,name,typeName}`。保存时再解析所选 ID，失败时拒绝跨项目、不存在或非 ACTIVE 环境。演练轮次仍存 `environment_id`，但引用 `arch_environment.id`；读取回显环境投影。

## 错误、降级与恢复

- 没有有效架构环境：明确提示并禁用新建轮次。
- 环境跨项目、停用或已删除：服务端返回业务错误，前端提示刷新环境选择。
- 被演练引用的架构环境删除：返回冲突，不删除。
- V217 执行后无数据级回退；仅能从迁移前备份恢复。

## 安全、性能、兼容性与运维

沿用架构环境的租户与项目边界、投产成员授权、RBAC、审计和乐观锁。环境查询只投影所需字段，按项目和 ACTIVE 条件索引查询。旧 `/release-operations/environments` 不保留兼容端点或数据。

## 验证策略

聚焦 Java 测试验证公开契约、权限、环境状态、引用删除与 V217 清理；前端类型检查/构建验证路由和表单；浏览器验证架构环境创建到投产演练选择的桌面与移动路径。

## 假设、未知项与决策记录

- 假设：`arch_environment` 现有项目、租户、状态字段及索引可支撑投产选择，已由现有环境服务验证。
- D1：不迁移旧数据，用户确认。
- D2：保留 `environmentId` HTTP 名称，降低客户端轮次接口字段变更风险。
- D3：扩展既有架构公开契约，而非投产直查架构表。

## 风险与回退原则

V217 删除数据不可恢复，执行前必须完成备份与 MySQL 迁移验证；上线失败只可回退应用代码，数据恢复依赖迁移前备份。
