# 迁移参数英文名工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：2026-09-09，用户确认参数英文名只允许字母、数字和下划线，在租户、项目、系统编号范围内不区分大小写唯一，纳入关键字搜索；已有数据不处理；随后确认完整设计方案并要求执行。

## 目标与成功信号

在现有“数据迁移 > 数迁资产内容 > 迁移参数”专属管理页增加必填的参数英文名，并贯通数据库、REST、单条维护、Excel 导入导出、列表详情、回收站和关键字搜索。成功信号是合法英文名可创建和回显，非法或重复值在服务端被拒绝，`ABC_01` 与 `abc_01` 不能在同一租户、项目和系统编号下同时存在。

## 使用者与场景

- 迁移参数维护人员通过当前项目下的新增或编辑抽屉填写参数名称与参数英文名。
- 批量维护人员使用迁移参数 Excel 模板导入，并从条件导出中取得参数英文名。
- 查询人员可用中文名称、英文名或参数说明作为关键字检索活动记录；管理员在统一回收站中使用同一关键字语义。

## 必须需求与验收条件

1. 参数英文名在新增、编辑和 Excel 导入时必填，最大 255 字符，只允许正则 `[A-Za-z0-9_]+`；前后端均提供字段级提示，服务端为最终校验点。
2. 参数英文名在 `tenant_id + project_id + system_code` 范围内不区分大小写唯一；`ABC_01` 与 `abc_01` 视为重复，应用预检和数据库唯一索引共同防止并发写入绕过。
3. 列表、详情、REST 响应、回收站详情、模板和导出均包含参数英文名；创建和更新请求字段为 `parameterNameEn`，响应字段为 `parameter_name_en`。
4. 活动列表和回收站的关键字筛选同时匹配参数名称、参数英文名和参数说明。
5. 追加 Flyway `V198`，不修改已发布的 `V197`，不为已有参数记录生成、推导或回填英文名。
6. 沿用既有项目范围、RBAC、记录 Owner、审计和逻辑删除规则，不改变其他数据迁移内容类型。

## 不变量与约束

- 数据 Owner 保持为 `business/data-migration`，页面入口、菜单 752 和权限码不变。
- 所属项目仍来自全局项目上下文，关联系统仍来自当前项目启用组件。
- `parameter_name` 的现有必填和唯一规则保持不变，参数英文名是独立字段和独立唯一约束。
- MySQL 8.4 Flyway 迁移只追加；`V197` 不得修改。
- 只修改当前任务范围授权的参数服务、接口、测试、迁移、前端 API/页面、需求和当前前缀账本。
- 不连接生产环境，不使用真实生产数据。

## 非目标

- 不处理、转换或保留已有 `dm_parameter` 数据。
- 不改造系统管理/参数管理，不新增码值或权限节点。
- 不增加模糊匹配之外的新筛选项，不改变排序、分页、删除和审计语义。
- 不新建公共组件或样式体系，不改动其他数据迁移页面。

## 方案比较与选择

选择“独立字段 + 大小写不敏感列排序规则 + 独立唯一索引”。`parameter_name_en` 使用仅容纳 ASCII 规则字符的列定义和大小写不敏感排序规则，服务层执行格式与重复预检，数据库索引兜住并发竞争。该方案保留用户录入的字母大小写，同时最直接满足不区分大小写唯一。

未选择生成小写辅助列方案，因为它会增加一列、一套生成表达式和迁移复杂度，而当前值域只有 ASCII 字母、数字和下划线。未选择统一转大写后存储方案，因为它会改变用户输入的展示形式。

## 架构边界与组件职责

- `V198__data_migration_parameter_english_name.sql`：增加 `parameter_name_en` 非空列和 `tenant_id + project_id + system_code + parameter_name_en` 唯一索引；迁移前断言 `dm_parameter` 无记录，非空时失败关闭。
- `ParameterService`：统一负责英文名格式校验、大小写不敏感重复预检、SQL 读写、导入导出、关键字查询、回收站和审计衔接。
- `ParameterController`：保持现有路由和 RBAC，仅透传扩展后的请求与响应契约。
- `web/src/api/data-migration.ts`：为 `ParameterRecord`、`ParameterFormData` 和更新类型增加稳定字段。
- `ParametersPage.vue`：在表格、详情和表单中呈现英文名，并在提交前给出就近校验；复用现有 `UiDataTable`、`UiFormDrawer`、导入对话框和项目范围状态。

## 接口、数据和状态流

单条新增/编辑流程为：用户填写 `parameterNameEn`，前端先检查必填与 `[A-Za-z0-9_]+`，服务端重新校验并在当前租户、项目、系统编号内执行不区分大小写重复检查，数据库唯一索引完成最终并发保护，成功后沿用现有审计并返回 `parameter_name_en`。

Excel 模板列调整为“参数类型、参数范围分类、系统编号、参数名称、参数英文名、参数说明”。每行独立检查英文名格式、文件内不区分大小写重复和数据库重复；失败行跳过并返回行号错误，其余行继续。条件导出在参数名称后增加参数英文名列。

关键字查询继续使用单个 `keyword` 参数，SQL 匹配范围从参数名称和说明扩展为参数名称、参数英文名和说明；回收站采用相同匹配范围。桌面表格新增参数英文名列，移动端保持表格容器内局部滚动，不允许页面级横向溢出；抽屉维持单列字段和可达的底部操作。

## 错误、降级与恢复

- 空值返回“参数英文名不能为空”；包含空格、中文或符号时返回“参数英文名只允许字母、数字和下划线”。
- 超过 255 字符时返回明确长度错误。
- 同范围内大小写不同但规范值相同，或并发写入触发唯一索引时，统一返回冲突错误“参数英文名在同一项目同一系统下已存在”。
- Excel 错误包含实际行号，单行失败不回滚其他合法行。
- 迁移检测到已有参数记录时直接失败，不删除记录、不填充占位值；由发布负责人确认环境符合“已有数据不处理”的前提后重试。

## 安全、性能、兼容性与运维

- 安全：后端继续执行认证、既有 RBAC、项目范围和记录 Owner 校验；前端校验不替代服务端校验。
- 性能：唯一索引支持精确判重；关键字仍是现有分页查询中的 `LIKE`，增加一个 OR 条件，不引入新全文索引。
- 兼容性：请求新增必填字段，因此旧客户端创建或更新会收到可解释的 400；查询响应为加字段兼容扩展。Excel 模板版本同步变更，旧五列模板会按缺少英文名逐行失败。
- 运维：部署顺序为先执行 V198 再启动新应用；迁移失败时保持旧应用和 V197 数据结构，不允许绕过空表断言。

## 验证策略

1. `ParameterServiceTest` 覆盖合法值、空值、非法字符、大小写重复、跨项目或跨系统可复用、创建/编辑、Excel 文件内重复、数据库重复、导出列和关键字 SQL。
2. 数据迁移注册测试与 MySQL 迁移测试覆盖 V198 存在、列非空、大小写不敏感唯一索引、空表成功和非空表失败关闭。
3. `npm --prefix web run build` 验证前端类型与构建；静态契约检查表格、详情、表单、模板说明和搜索占位均包含参数英文名。
4. 运行 `mvn -pl :ccb-data-migration -am test`、Flyway 检查、治理检查、任务范围检查和 `git diff --check`。
5. 真实浏览器在 `1280x800`、`375x812`、`390x844`、`430x932` 验收新增、编辑、查询、导入部分失败、详情、删除和回收站；检查无页面级横向溢出、提交防重复、错误就近可见及明暗主题可读。

## 假设、未知项与决策记录

- 假设：执行 V198 的环境中 `dm_parameter` 没有需要保留的记录。依据是用户明确确认“已有数据不用处理”。推翻证据是迁移前查询存在任意记录，此时迁移失败且禁止实施。
- 未知项：无阻塞产品决策。
- D1：字符规则为仅字母、数字和下划线，允许数字或下划线开头。
- D2：唯一范围为租户、项目、系统编号，比较不区分大小写。
- D3：英文名贯通页面、接口、Excel、回收站并纳入关键字搜索。
- D4：不处理已有数据，采用空表前置断言而不是自动生成英文名。

## 风险与回退原则

- 主要风险是目标环境已有数据导致 V198 失败。该失败是预期保护，不能改成静默默认值；需由需求负责人重新决定数据处置后另行修订设计。
- 旧客户端没有必填字段会失败，应与前端同批发布。
- 回退应用时保留已执行的 V198，不在生产环境删除列或索引；关闭迁移参数写入口并恢复旧应用只读能力。未执行成功的 V198 不产生结构变化。
