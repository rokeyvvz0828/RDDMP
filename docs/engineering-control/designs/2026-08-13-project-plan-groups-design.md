# 项目计划分组工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户确认“项目级平面分组 + group_id 字段”方案，并要求添加“可以拖动主计划进行分组”提示。

## 目标与成功信号

项目计划页能够持久化项目级分组，主计划拖入分组后其后代计划保持同组；刷新和重新登录后分组关系不丢失。

## 使用者与场景

项目负责人在桌面端维护计划分组，移动端通过操作菜单选择目标分组。超级管理员和有项目计划修改权限且具备项目实体授权的用户可执行写操作。

## 必须需求与验收条件

- R1：分组属于项目且可新建、重命名、删除；验收为 CRUD API 成功、刷新后数据保持，删除分组不删除计划。
- R2：主计划移动到分组时，主计划和所有后代计划的 `group_id` 在一个事务内同步更新；验收为多层子计划移动后全部同组。
- R3：计划树呈现分组、主计划、子计划三级层级；验收为已有计划出现在未分组，分组和层级名称可区分。
- R4：桌面端拖拽、移动端菜单均可移动主计划，并显示中文操作提示；验收为两种入口都能完成同一后端移动操作。
- R5：后端执行租户、项目访问、计划修改权限和计划归属校验；验收为跨项目、子计划移动和无权请求被拒绝。

## 不变量与约束

- 保留 `parent_id`、计划编号和计划排序逻辑。
- Flyway 只新增 V40，不修改 V35-V39。
- 单租户现有 `tenant_id` 约束继续生效。
- 不新增前端专用权限码。
- 中文界面，复用 `UiDataTable`、Element Plus 和现有语义主题变量。

## 非目标

- 分组不支持嵌套。
- 不做跨项目计划移动。
- 不重新设计项目详情页和项目计划表单。

## 方案比较与选择

选择项目分组表加计划 `group_id` 字段：关系清晰、查询简单、已有计划可默认未分组，且移动后代可以事务性批量更新。拒绝把分组伪装成计划节点，因为会污染 `parent_id` 语义；拒绝单独关联表，因为每个计划只有一个项目分组时会增加约束和查询复杂度。

## 架构边界与组件职责

- `pm_project_plan_group`：持有项目分组名称、说明、排序和删除状态。
- `pm_project_plan.group_id`：持有计划当前分组，允许为空表示未分组。
- `ProjectService`：负责项目访问、权限、分组 CRUD 和后代计划事务性移动。
- `ProjectController`：暴露分组查询、CRUD、移动主计划接口。
- `ProjectView.vue`：构建分组树、拖拽交互、移动端选择和中文提示。

## 接口、数据和状态流

- `GET /api/project/{projectId}/plan-groups` 返回当前项目未删除分组。
- `POST /api/project/{projectId}/plan-groups` 输入 `{group_name, description?, sort_no?}`。
- `PUT /api/project/{projectId}/plan-groups/{groupId}` 输入分组名称、说明、排序。
- `DELETE /api/project/{projectId}/plan-groups/{groupId}` 软删除分组并将其计划置为未分组。
- `PUT /api/project/{projectId}/plans/{planId}/group` 输入 `{group_id: number|null}`，只允许 `parent_id=0` 主计划；服务端查询后代并批量更新。
- 计划查询返回 `group_id`、`group_name`，前端按 `group_id` 先分组再构建 `parent_id` 树。

## 错误、降级与恢复

- 分组名称为空、重复、目标分组不属于项目时返回中文 400。
- 子计划作为移动源、计划不属于项目或用户无权时返回中文业务错误/403。
- 分组删除失败不修改计划；成功后计划统一回到未分组。
- 前端 API 失败保留当前数据并提示错误，成功后刷新项目详情。

## 安全、性能、兼容性与运维

- 所有写接口调用 `requireAction("plan", "update", user)` 与 `requireProjectAccess`。
- 移动操作使用事务和项目/主计划行锁，避免并发移动产生半树状态。
- 现有数据通过可空字段兼容，V40 增加项目和分组索引。
- 数据回退使用数据库备份或回滚新代码；不删除历史迁移。

## 验证策略

- 后端单元测试验证分组权限、主计划身份和后代批量更新 SQL 调用。
- 前端构建、静态检查和源代码交互检查。
- 浏览器验收新建分组、拖动、刷新、删除分组、移动端操作和错误提示。

## 假设、未知项与决策记录

- 假设：项目计划页已有 `UiDataTable` 可承载树形行和原生拖拽事件；若浏览器实测不可靠，保留移动菜单作为可操作入口。
- 决策：分组删除采用移入未分组，不提供删除计划的快捷选项。

## 风险与回退原则

主要风险是 Element Plus 树表格拖拽事件在不同浏览器下的命中区域差异。通过整行拖拽源标识、分组行高亮和移动端菜单降低风险；后端移动接口是唯一事实来源，失败时不更新本地状态。
