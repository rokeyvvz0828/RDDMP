# 工作流按项目维度管理工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户在讨论工作流与项目、组织、成员和业务权限边界后确认采用“全局模板 + 项目流程”的混合方案，并于 2026-09-01 明确要求“按此执行”。

## 目标与成功信号

流程定义、业务启动、实例、待办和人员解析形成一致的项目边界。项目成员能使用本项目流程，项目管理员能维护本项目流程，跨项目读取、配置和审批均被服务端阻断。

## 选择方案

采用混合范围：`GLOBAL` 是租户级可复用模板，`PROJECT` 是归属于单一项目的可执行流程。项目数据仍由 system 模块拥有，workflow 通过接口访问，由 boot 完成组合；不让 workflow 直接依赖 system 或直接维护项目表。

## 数据设计

- `wf_definition.scope_type VARCHAR(16) NOT NULL DEFAULT 'GLOBAL'`
- `wf_definition.project_id BIGINT NULL`
- 定义编码唯一性调整为租户、范围、项目、编码和删除状态。
- `wf_instance.project_id BIGINT NULL`，`project_ref/project_name` 保留为启动时快照。
- 新增 `wf_business_binding`，唯一键为租户、项目、模块、业务场景；绑定已发布定义及版本策略，供业务场景逐步接入。
- 存量定义统一回填 `GLOBAL`；存量实例仅在项目编号唯一匹配时回填真实项目主键。

## 模块职责

- workflow：定义范围、实例授权、人员解析、待办授权、项目业务绑定契约。
- system：项目访问、项目负责人、项目成员与角色目录；成员停用/移除前调用守卫。
- boot：实现 workflow 与 system 的双向桥接，不产生 Maven 循环依赖。
- frontend：读取顶层项目上下文，在工作流定义页展示范围并加载当前项目人员、角色。

## 权限模型

- 查看项目流程/实例：超级管理员或项目有效成员。
- 维护项目流程：超级管理员、项目负责人或有效 `PM` 项目角色成员。
- 审批：任务办理人匹配且仍有项目访问权限。
- 全局定义：沿用现有平台工作流 RBAC。
- 项目成员移除/停用：若该成员在项目实例中存在待办任务则阻断。

## 启动与人员解析

业务启动先校验项目编号并获得真实 `project_id`，再校验定义范围；创建实例时一次写入业务上下文和项目上下文，然后才推进到首个审批节点。传统执行器和 Flowable 执行器都从实例读取 `project_id`：`PROJECT_MEMBER` 校验有效项目成员，`PROJECT_ROLE` 从项目角色成员关系解析有效用户。项目流程的抄送用户也执行同一成员校验。

## 前端交互

- 新建流程先选择“当前项目流程”或“全局模板”，默认当前项目流程。
- 当前项目流程显示项目名称标签，人员来源提供“项目成员”“项目角色”“发起人”。
- 全局模板保留现有“指定用户”“指定角色”“发起人”。
- 项目切换后重载列表和候选项；编辑已打开时依赖现有项目切换整页刷新保护。
- 手机端单列排列范围、基本信息和节点属性，选择器不超出弹层宽度。

## 错误与兼容

- 缺少项目上下文、项目无权访问、人员不属于项目、角色不属于项目或成员仍有待办时返回明确业务错误。
- 存量全局定义及 USER/ROLE 节点不自动改写。
- 无法回填项目的历史实例继续作为租户级历史记录，避免错误归属。
- 数据库只追加 V134；代码回退保留新增可空字段和绑定表。

## 验证策略

- 迁移验证字段、索引、唯一性、GLOBAL 回填和实例匹配回填。
- workflow 测试两种定义范围、两套人员解析路径、跨项目拒绝、任务审批二次校验。
- system/boot 测试项目目录桥接、项目管理权限和成员待办守卫。
- 前端构建和浏览器验证桌面及三个手机视口。
- 全量 Maven、治理、范围和差异检查作为收敛门禁。

## 风险与回退

- 最大风险是实例创建与首批任务之间的时序；通过单事务先写上下文再推进节点消除窗口。
- 项目成员状态变化可能使运行任务失去办理人；通过移除守卫阻断，并保留转交、撤销、终止的恢复路径。
- 项目接口和流程接口互相调用可能形成模块循环；通过 boot 桥接隔离。
- 回退应用代码时保留 V134，旧应用忽略新增列；不得回改已执行迁移。
