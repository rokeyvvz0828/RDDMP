# 菜单折叠对齐与用户角色维护设计

## 目标

修复收缩菜单时各层级图标垂直错位的问题，并将用户角色维护从用户资料编辑抽屉中拆出，提供独立、可单独保存的角色维护入口。

## 已确认设计

- 折叠菜单使用固定宽度和固定高度的菜单项，菜单项及图标采用 Flex 居中布局；覆盖 Element Plus 的默认内边距、图标外边距和子菜单标题布局。
- 用户列表操作列增加“角色”按钮，打开独立角色维护弹窗。
- 角色弹窗显示目标用户身份和可选角色，支持多选；保存时只调用用户角色关联接口，不提交用户资料、组织或头像。
- 用户新增/编辑抽屉移除“关联角色”字段；用户资料保存与角色授权保存相互独立。

## 范围与约束

- 单租户保持不变，不新增后端接口。
- 继续复用现有 `getRoleOptions`、`getUserRoles` 和 `saveUserRoles` 接口。
- 页面和操作文案全部使用中文。
- 保留现有用户编辑、头像上传、组织选择和权限校验行为。

## 验收标准

1. 菜单收缩后，一级菜单项和一级子菜单标题的图标在同一条垂直中心线上，图标不因选中状态或层级发生偏移。
2. 用户编辑抽屉中不存在角色选择字段。
3. 用户列表每行可以通过“角色”按钮打开角色维护弹窗。
4. 打开角色弹窗会加载当前角色，保存角色只触发角色关联保存；资料字段未修改也能完成角色保存。
5. 角色加载或保存失败时显示中文错误提示，弹窗不会误报用户资料保存成功。

## 验证策略

- 使用 `npm run build` 验证 TypeScript 和 Vue 模板编译。
- 使用浏览器检查收缩菜单的 DOM 几何尺寸和用户角色弹窗流程。
- 使用现有接口调用记录确认角色保存请求独立于用户资料更新请求。

## 风险与回滚

- 风险：Element Plus 在不同菜单状态下仍可能注入默认样式；通过组件作用域外的全局选择器统一覆盖。
- 回滚：恢复 `ModuleView.vue` 的角色入口与抽屉字段、移除本次折叠菜单样式覆盖，不涉及数据库变更。

## 批准
