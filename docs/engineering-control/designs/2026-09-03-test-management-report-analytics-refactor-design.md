# 测试报告与分析统计重构工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户已逐项确认全量交付、责任团队组织归集、执行中口径、16 张图表、质量阈值与启停、测试大类由入口固定，以及本设计的四个分段方案，并于 2026-09-03 明确指示“开始实施”。

## 目标与成功信号

在不破坏 V1 历史数据的前提下，交付中文化、可版本化的八章节测试报告，以及与报告同口径的 26 张固定报表、16 张固定图表和自定义分析。所有结果可按项目、责任团队组织、系统、范围、案例和时间层级追踪，并在权限、导出与移动端中保持一致。

成功信号是：六种报告组合可生成；目录中的 RPT-001~026 和 CHT-001~016 可访问；指标验证显示执行中未计入已执行；停用阈值不显示且不影响质量结论；历史 V1 数据仍能读取或导出。

## 使用者与场景

- 测试经理：维护项目级质量阈值，查看项目或机构质量，生成、重生成和导出正式报告。
- 测试负责人：通过轮次、周期和系统统计跟踪执行、缺陷、风险并下钻问题明细。
- 测试人员与相关成员：在已授权项目及测试大类内查看报告、统计和共享分析。

## 必须需求与验收条件

| ID | 必须行为 | 可观察验收 |
| --- | --- | --- |
| R1 | 入口固定测试大类 | 应用组装测试入口的所有查询只能返回应用组装数据；其他三类同理。 |
| R2 | 六种中文报告组合与八章节 | 项目/机构/系统 × 全周期/轮次均能生成版本，章节、导出和补充为中文。 |
| R3 | 统一指标口径 | 有效案例排除无效；执行中独立显示；已执行仅为成功、失败、阻塞。 |
| R4 | 全目录固定分析 | RPT-001~026、CHT-001~016 可被目录解析，并显示数据、空态或失败态。 |
| R5 | 自定义分析 | 用户可选择允许的中文维度、指标和筛选，保存/共享/下钻/导出均继承入口与项目边界。 |
| R6 | 质量阈值 | 项目加测试大类级阈值支持启停和审计；仅生效指标参与并显示在报告快照。 |
| R7 | 历史兼容与安全 | V1 可读/可导出；迁移追加；所有读取和写入在服务端校验认证、RBAC、租户、项目与实体范围。 |
| R8 | 多端与状态 | 桌面及三种手机视口可完成主路径，且涵盖加载、空、失败、无权限、只读、提交中与重复提交状态。 |
| R9 | 本地模拟数据 | 幂等脚本在至少 3 个系统、2 个机构主数据存在时写入 60 个以上虚构案例及完整统计样本；不足时零写入失败。 |

## 不变量与约束

- 测试管理模块拥有本需求新增的报告、统计、阈值和审计数据，但不拥有项目、组织、物理子系统、案例、执行或缺陷主数据。
- 机构只按物理子系统的责任团队组织聚集，不新增参测系统到项目组织的映射。
- 所有面向用户的文本为中文；代码标识、表名和已有 API 字段为兼容可保持既有命名。
- 不修改 V142~V146 或其他已发布迁移；通过 V147 追加兼容结构。
- 新增业务表单由本模块 DTO、校验和表结构维护，不依赖已下线的 biz_form 元数据能力。

## 非目标

- 不变更测试大类、项目、组织或物理子系统主数据。
- 不提供跨测试大类的统一筛选或聚合。
- 不删除或主动迁移掉 V1 周期级、专项级等历史对象。

## 方案比较与选择

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 一次性替换 V1 表与接口 | 查询模型最简单，但会破坏历史版本和回退 | 不采用。 |
| 在 V142 上修补并继续堆叠页面特例 | 改动小，但继续造成口径分散且无法稳定覆盖全目录 | 不采用。 |
| 追加 V2 语义、统一指标目录与兼容适配层 | 保留历史、统一服务端计算，可分任务验证并回退应用代码 | 采用。 |

## 架构边界与组件职责

1. 指标目录与计算引擎：定义中文维度、指标、状态映射、聚合和比率计算；报告、固定分析和自定义分析只能调用此层。
2. 报告编排器：接收六种组合、时间范围和章节选择，生成八章节事实快照，计算质量结论并维护版本、补充和轨迹。
3. 统计目录与查询规划器：将 RPT/CHT 编号映射为允许的维度、指标、筛选、表格、图表和下钻协议，拒绝无效组合。
4. 自定义分析服务：验证拖拽配置，保存个人/共享配置与快照，并复用查询规划器，不执行任意 SQL 或任意字段访问。
5. 质量阈值服务：维护固定指标的项目加测试大类阈值、生效状态和审计；报告生成时读取并固化结果。
6. 导出适配器：从同一快照/统计结果生成中文 DOCX、PDF、XLSX 和 PNG，记录导出审计。
7. 前端领域页面：复用 UiPageHeader、UiDataTable、TestManagementFormDialog、DeliveryChart 与主题变量；不拼接后端地址或承担授权判断。

## 接口、数据和状态流

1. 路由参数 `domain` 决定测试大类，页面从全局项目上下文取得项目；缺少项目时不请求并显示引导空态。
2. 统计筛选仅包含项目、时间、责任团队组织、系统、范围、案例与缺陷/人员维度；服务端以 domain、tenant、project 共同校验。
3. 指标计算先选择有效案例和最新执行状态，再聚合执行、缺陷与质量数据；统计结果携带完整筛选上下文以支持导出和钻取。
4. 报告生成将范围、事实、阈值、质量结论和章节写入不可变版本快照；人工补充单独按版本和章节保存。
5. V147 为 V2 增加范围/时间语义与兼容标记、质量阈值及所需快照字段；V1 记录以历史适配方式继续读取和导出。

## 错误、降级与恢复

- 未选项目、无数据、无生效阈值、无历史快照和空图表均输出具体中文空态，不展示误导性零值结论。
- 无权限、越项目、越系统或不允许的自定义字段组合由服务端拒绝，前端展示可恢复错误。
- 导出失败保留当前统计上下文，可重试；报告历史版本不因重生成或导出失败被覆盖。
- 迁移后如需回退，只回退应用行为；追加表与数据保留，兼容版本继续可读。

## 安全、性能、兼容性与运维

- 服务端在所有接口校验认证、菜单动作权限、租户、项目和实体范围；写入与导出保留对象、动作、结果和 trace 审计。
- 分页明细和下钻设置上限；图表和固定报表使用已验证的聚合查询，避免自定义分析执行任意表达式。
- 历史 V1 路由和导出保持可用，新 V2 不再暴露周期级、专项级新建选项。
- 中文 PDF/DOCX/XLSX 输出必须以实际文件打开验证，不能以接口状态代替内容验收。
- 本地模拟脚本独立于 Flyway，只读取项目、物理子系统和责任团队组织主数据；依赖不足时事务回滚且不写入任何业务表。

## 验证策略

- 对指标引擎编写状态、分母、时间范围、责任团队组织和阈值启停单元测试。
- 对报告、固定/自定义统计、快照、权限、历史兼容和导出执行模块测试及 API 探测。
- 以独立本地脚本验证模拟数据幂等性、60 个案例覆盖、状态/缺陷/时间/组织分布和零写入失败行为。
- 执行 Flyway、治理、范围、前端构建和完整 Maven 测试；浏览器验收报告和统计的桌面及 375×812、390×844、430×932 视口。

## 假设、未知项与决策记录

- D1：机构维度以物理子系统责任团队组织为准。来源：用户确认。
- D2：执行中为独立状态且不属于已执行。来源：V1.1 与用户确认。
- D3：固定图表按清单实际的 16 项交付。来源：用户确认。
- D4：测试大类由菜单入口固定，而非筛选器。来源：用户确认。
- D5：未配置或没有生效质量指标时，报告总体质量为“未配置”。来源：用户确认。
- D6：本地测试数据以独立幂等脚本生成，至少覆盖 3 个系统、2 个责任团队组织、3 个轮次、6 个周期和 60 个案例。来源：用户确认。
- 未知项：现有依赖是否已具备可验证的中文 PDF 字体/渲染能力。若不存在，实施计划必须在不扩大未授权依赖范围的前提下给出最小兼容方案并先做技术验证。

## 风险与回退原则

- 最大风险是旧数据兼容、统计口径不一致和中文 PDF 输出。所有写入采用追加迁移、快照不可变和逐层测试缓解。
- 浏览器、导出或数据口径出现偏差时，停止扩展目录，先回到统一指标引擎纠正；不得在单页叠加特殊计算。
- 回退应用代码不会回退数据库迁移或删除数据；回退版本必须保有兼容读取路径。
