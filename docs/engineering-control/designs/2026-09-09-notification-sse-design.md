# 通知中心 SSE 设计

## 状态

- 设计修订：1
- 状态：已批准
- 批准证据：用户在确认 SSE 方案后要求“按此调整”

## 设计

通知是单向的服务端到浏览器状态失效信号，因此使用 SSE 而非 WebSocket。认证用户先通过 Bearer JWT 调用 `POST /api/notifications/stream-ticket` 获取 30 秒、单次使用的随机票据，再由原生 `EventSource` 连接 `GET /api/notifications/stream?ticket=...`；URL 中不放 JWT。

服务端以内存表维护票据和按 `(tenantId, userId)` 分组的连接。消息发布或用户状态修改仅在数据库事务成功提交且影响行数大于零后，向对应用户的全部连接发送不含业务数据的 `notification` 失效事件。每 25 秒发送心跳并清理过期票据和失效连接；连接 10 分钟超时后由浏览器重新换票。

前端初始化只查一次未读数。事件到达后刷新未读数，抽屉打开时再刷新列表和模块统计；页面隐藏时关闭连接。连接失败按 `1/2/5/15/30s` 重试，连续失败后并行启用 60 秒兜底轮询，连接恢复即停止轮询。

## 边界

- 保持通知 CRUD、租户/接收人过滤、项目上下文、归档和 UI 样式不变。
- 单实例部署使用内存注册表；未来水平扩容时在广播入口增加 Redis Pub/Sub，不改变浏览器协议。
- Nginx 对精确 SSE 路径关闭响应缓冲和缓存，并把读取超时提高到一小时。
- 不新增数据库迁移，不部署到远程服务器。

## 失败处理

- 无效、过期或复用票据返回 401，且不泄露票据状态细节。
- 单个连接发送失败只清理该连接，不影响其他用户或页签。
- SSE 持续不可达时 60 秒轮询维持最终一致性，不恢复高频轮询。
- 活跃事务没有同步回调时不提前广播，避免回滚产生假事件。
