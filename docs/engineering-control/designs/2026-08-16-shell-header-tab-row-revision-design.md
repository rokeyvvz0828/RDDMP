# 顶部栏与独立页签栏布局修订工程设计

## 文档状态

- 修订：1
- 状态：已确认
- 用户确认依据：用户根据页面截图确认采用方案 A，并在设计落盘后明确要求开始实施。

## 目标与成功信号

调整桌面端应用壳层的信息层级：顶部栏只承载全局控制，页签在其下方形成独立导航栏。成功信号是桌面端从左到右呈现“收缩按钮、项目选择器、弹性空白、全局操作”，下一行完整呈现页签；不恢复重复面包屑，移动端现有紧凑布局保持不变。

## 使用者与场景

面向在工作台、系统管理、工作流和配置管理之间频繁切换的桌面用户。用户先通过左上角收缩按钮控制侧栏，再切换当前项目；页面页签作为第二层导航独立显示，不与全局控制争抢宽度。

## 必须需求与验收条件

1. 桌面端收缩按钮必须位于项目选择器左侧，两者保持合理间距且均可操作。
2. 桌面端 `UiTabs` 必须从顶部栏中移出，放在顶部栏下方的独立整行栏位。
3. 不恢复“控制中心 / 当前页面”面包屑，当前页面名称只由页签和业务页面自身标题表达。
4. 通知、主题、打印和用户菜单继续位于顶部栏右侧，页签数量不再影响这些全局操作的位置。
5. 页签切换、关闭、刷新、关闭其他、关闭全部和工作台不可关闭规则保持不变。
6. `760px` 及以下保持现有紧凑顶部栏、当前页标题、独立粘性页签和侧滑导航内项目选择器。
7. 桌面常用宽度与 `375x812`、`390x844`、`430x932` 不出现控件重叠或页面级横向溢出。

## 不变量与约束

- 继续使用 Vue 3、Element Plus、`UiTabs` 和 `tabsStore`，不增加依赖。
- `tabsStore` 仍是页签状态唯一来源，`UiTabs` 仍负责全部页签命令。
- 项目上下文、侧栏状态和全局操作行为不改变。
- 保留当前工作区的其它未提交改动，不修改业务页面和后端。

## 非目标

- 不恢复面包屑或重新设计业务页面标题。
- 不修改页签持久化、路由缓存和右键菜单语义。
- 不调整侧栏菜单、顶部导航模式、主题系统或配置管理业务页面。

## 方案比较与选择

- 选择：顶部栏与页签栏拆成两个同级行。结构清晰，页签不会挤压全局控制，完全符合用户截图标注。
- 未选择：在同一个 `app-header` 内换行展示页签。视觉上接近两行，但会把顶部栏高度、粘性定位和响应式规则耦合在一个容器中。
- 未选择：继续保留内联页签，仅把收缩按钮移到项目左侧。改动最小，但不满足用户要求的独立页签栏。

## 架构边界与组件职责

- `AppLayout.vue`：桌面顶部栏按“收缩按钮、项目选择器、全局操作”组合；`UiTabs` 在顶部栏后独立挂载。移动端继续使用现有标题和页签挂载逻辑。
- `UiTabs.vue`：保持现状，不感知桌面或移动端挂载位置。
- `styles.css`：恢复独立页签栏视觉和宽度约束，移除桌面内联页签样式，保留移动端粘性规则。

## 接口、数据和状态流

路由变化继续更新 `tabsStore`。`AppLayout` 始终向唯一的 `UiTabs` 实例传入 `route.fullPath`；桌面和移动端都在顶部栏后方显示页签，只是移动端额外使用现有粘性定位。收缩按钮仅修改 `theme.sidebarCollapsed`，项目选择器仅修改 `projectContext`，两者状态互不影响。

## 错误、降级与恢复

页签过多时继续由 Element Plus 页签导航处理横向溢出，不允许产生页面级横向滚动。移动端继续命中现有断点规则。若独立页签栏造成壳层高度异常，可回退模板挂载和对应样式，不触碰页签数据。

## 安全、性能、兼容性与运维

本修订不涉及接口、权限、数据库和网络请求。只改变壳层 DOM 顺序与 CSS，不增加运行时状态。需要兼容现有侧边、顶部和混合布局，移动端行为不得退化。

## 验证策略

- 运行 `npm --prefix web run build` 和目标文件 `git diff --check`。
- 桌面端验证收缩按钮位于项目选择器左侧，页签为下方独立整行，面包屑不存在。
- 打开多个页签，验证切换、关闭、刷新、关闭其他和关闭全部。
- 测量顶部栏、页签栏和主内容区域矩形，确认无重叠且页面宽度不溢出。
- 在 `375x812`、`390x844`、`430x932` 复验当前页标题、移动页签和项目选择器入口。

## 假设、未知项与决策记录

- 假设独立页签栏沿用现有 `.ui-tabs-bar` 即可满足视觉和交互要求；浏览器几何检查将验证该假设。
- 未知项：无阻塞未知项。
- 决策 D1：桌面收缩按钮置于项目选择器左侧，来源为用户截图标注和明确要求。
- 决策 D2：桌面页签恢复独立栏，不恢复面包屑，来源为用户确认方案 A。
- 决策 D3：移动端保持上一修订已验收行为，避免扩大变更范围。

## 风险与回退原则

主要风险是独立页签栏增加约 44px 壳层高度，但这是用户明确选择的信息层级。另一个风险是顶部或混合布局中收缩按钮条件不同，实施时必须按真实布局模式验证。回退仅涉及 `AppLayout.vue` 的元素顺序和 `styles.css` 的壳层规则。
