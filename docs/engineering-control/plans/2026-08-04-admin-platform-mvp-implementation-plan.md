# 管理平台一期基础能力实施计划

> 执行要求：使用 `control-engineering` 按任务实施。当前计划已写成可执行版本，等待用户复核后导入控制账本。

## 状态与来源

- 计划修订：1
- 设计修订：1
- 设计文档：`docs/engineering-control/designs/2026-08-04-admin-platform-mvp-design.md`
- 计划状态：待用户确认
- 目标：交付可启动、可验证的单租户前后端分离管理平台一期基础能力

## 全局约束

- 后端 Spring Boot 3.x、JDK 17、Maven、MyBatis-Plus、MySQL 8。
- 前端 Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router。
- 每次修改使用最小文件边界；不引入工作流、AI 调用和微服务基础设施。
- 所有新路径在空仓库中均按 `candidate-new` 处理，不能声称为已有文件。
- 后端权限必须在接口层执行，不能把前端隐藏菜单当作安全控制。
- 数据库迁移必须可重复验证，失败时停止，不删除已有业务数据。

## 任务依赖与并行策略

```text
T1 工程骨架与基础契约
  -> T2 数据库迁移与基础设施
  -> T3 认证与权限闭环
  -> T4 系统管理领域 API
  -> T5 前端壳、动态路由与主题
```

T1 和文档目录可先串行完成。T2 完成后才能验证 T3/T4。T5 可在 T3 的接口契约确定后实施，T6 依赖 T4 和 T5。T7 必须串行收尾。

## T1：建立工程骨架与公共契约

**需求映射：** R1, R3, R8

**前置任务：** 无

**文件范围：** 创建 `pom.xml`、各 Maven 模块的 `pom.xml`、公共包目录、统一响应类、错误码、分页 DTO、traceId 过滤器接口和接入文档骨架；创建 `ccb-boot` 启动类和基础配置模板。

**接口：** 输出 `{ code, message, data, traceId }` 响应契约、统一异常处理扩展点和权限注解名称；不实现数据库业务。

**步骤与验证：**

- [ ] 运行 `java -version` 和 `mvn -version`，预期 JDK 17 且 Maven 可用；保存版本输出。
- [ ] 创建模块和最小启动类，运行 `mvn -DskipTests compile`，预期所有模块编译通过。
- [ ] 添加统一响应和异常单测，运行 `mvn test`，预期测试通过。
- [ ] 检查模块依赖方向，预期 `ccb-common` 不依赖业务模块，领域模块不循环依赖。

**验收：** 空配置下后端可编译；公共契约单测通过；接入文档能说明新模块的 Controller、Service、Mapper 和权限标识边界。

**回滚：** 删除本任务新增模块目录和父工程文件，不触碰用户已有文件。

**停止条件：** JDK 低于 17、Maven 无法解析依赖或出现循环依赖时停止并重新建模。

**升级条件：** 若本机无法使用 Maven Central，需要用户提供可用镜像或允许配置内部仓库。

## T2：建立数据库迁移与基础设施

**需求映射：** R1, R2, R5, R7

**前置任务：** T1

**文件范围：** 创建 `ccb-infrastructure` 的数据源、MyBatis-Plus 配置、Flyway 迁移脚本、实体基类和 `application.yml`/`.env.example`；创建用户、角色、组织、菜单、字典、配置、登录日志、操作日志及关系表。

**接口：** 提供事务、分页、审计落库和实体映射约定；表字段包含 `id`、`tenant_id`、状态、创建/更新时间、逻辑删除字段。

**步骤与验证：**

- [ ] 运行 `mvn -DskipTests compile`，预期实体和 Mapper 编译通过。
- [ ] 使用本地 MySQL 执行 Flyway 迁移，预期所有表和索引创建成功。
- [ ] 运行迁移重复启动验证，预期不重复创建、不破坏数据。
- [ ] 插入初始化角色、菜单和管理员账号脚本，预期密码为 BCrypt 哈希而非明文。

**验收：** MySQL 迁移可重复执行；所有一期领域表存在；组织和菜单具备树结构字段；审计表可写入。

**回滚：** 仅回退未应用的迁移文件；已应用迁移通过新增修复迁移处理，不执行自动删表。

**停止条件：** MySQL 版本不兼容、迁移破坏已有表或凭证需要写入仓库时停止。

**升级条件：** 若缺少本地 MySQL，先报告环境阻断，不用内存数据库替代真实迁移验证。

## T3：实现认证与权限闭环

**需求映射：** R1, R3, R7

**前置任务：** T2

**文件范围：** 创建 `ccb-security` 的密码服务、JWT 服务、登录/刷新/注销 Controller、认证过滤器、当前用户上下文、权限注解、角色/菜单权限查询和登录日志服务；补充相关测试。

**接口：** `POST /api/auth/login`、`POST /api/auth/refresh`、`POST /api/auth/logout`、`GET /api/auth/me`、`GET /api/auth/routes`；未认证返回 401，未授权返回 403。

**步骤与验证：**

- [ ] 先编写密码哈希、Token 过期和错误凭证测试，预期初始失败。
- [ ] 实现 BCrypt、短期 Access Token、长期 Refresh Token 和密钥环境变量读取。
- [ ] 实现过滤器和接口鉴权，运行 `mvn test`，预期认证单测通过。
- [ ] 启动后端执行正确登录、错误密码、禁用账号、Token 刷新和 403 接口流程，预期分别得到 200、认证失败、认证失败、200、403。

**验收：** 认证流程可重复；后端权限拒绝有效；登录成功/失败均写入审计；不记录密码和 Token。

**回滚：** 回退 `ccb-security` 新增实现并保留公共契约；数据库日志表通过迁移保留。

**停止条件：** Token 密钥无法从外部配置读取、接口鉴权可绕过或登录日志泄露敏感值时停止。

**升级条件：** 发现需要 OAuth2、LDAP 等第三方身份源时回到设计阶段，不在本任务内临时扩展。

## T4：实现系统管理领域 API

**需求映射：** R2, R3, R4, R5, R7, R8

**前置任务：** T3

**文件范围：** 创建 `ccb-system` 的用户、角色、组织、菜单、字典、配置、登录日志和操作日志实体、Mapper、Service、Controller、DTO、校验和测试；创建模块接入规范文档。

**接口：** `/api/system/users`、`/api/system/roles`、`/api/system/orgs`、`/api/system/menus`、`/api/system/dicts`、`/api/system/configs`、`/api/system/logs`；写接口使用事务和权限标识。

**步骤与验证：**

- [ ] 为每个领域先写 CRUD、引用冲突、树环路和分页测试，预期未实现时失败。
- [ ] 实现组织树、菜单树和角色菜单授权，预期父子关系和引用校验有效。
- [ ] 实现用户启停用、重置密码、角色授权和菜单权限查询，预期影响认证链路。
- [ ] 实现字典和配置按编码查询，预期统一响应和分页契约保持一致。
- [ ] 运行 `mvn test` 与接口集成流程，预期所有系统管理测试通过。

**验收：** 管理员可维护全部一期数据；非管理员无权写入；树结构无环；删除引用对象被拒绝；操作日志完整。

**回滚：** 代码按模块回退；数据库不删除已存在数据，修复通过新迁移或数据修复脚本处理。

**停止条件：** 任一领域直接访问其他模块 Mapper、越权写接口或树结构允许环路时停止。

**升级条件：** 如果业务要求数据范围权限、字段级权限或多租户隔离，需新增设计修订。

## T5：实现前端壳、动态路由与主题

**需求映射：** R1, R3, R4, R6

**前置任务：** T3

**文件范围：** 创建 `ccb-web` 的 Vite 工程、HTTP 客户端、认证 Store、权限 Store、主题 Store、静态登录路由、动态路由转换、应用布局、主题变量和基础组件。

**接口：** 消费 `/api/auth/login`、`/api/auth/refresh`、`/api/auth/me`、`/api/auth/routes`；统一处理 401、403 和 traceId。

**步骤与验证：**

- [ ] 运行 `npm install` 和 `npm run build`，预期前端生产构建通过。
- [ ] 为 Token 注入、401 刷新一次、刷新失败退出、动态路由转换和主题 Store 编写单测。
- [ ] 实现登录页、布局、菜单和路由守卫，预期未授权路由不可进入。
- [ ] 实现浅色、深色、跟随系统和 localStorage 持久化，预期刷新后保持。

**验收：** 前端可独立启动；登录后只显示授权菜单；非法路由回退；主题切换无页面跳动和布局破坏。

**回滚：** 删除前端新增目录和依赖，不改后端模块。

**停止条件：** 动态组件路径无法安全限制、Token 被写入日志或刷新请求循环时停止。

**升级条件：** 需要 SSR、移动端适配或复杂可视化设计时另立前端设计任务。

## T6：实现系统管理页面

**需求映射：** R2, R3, R4, R5, R6

**前置任务：** T4, T5

**文件范围：** 创建 `src/views/system` 下用户、角色、组织、菜单、字典、配置和日志页面；创建表格、搜索、分页、表单、树选择和权限按钮组件。

**接口：** 消费 T4 的系统管理 REST API；页面操作必须显示成功/失败反馈并支持加载、空数据、校验错误和冲突错误状态。

**步骤与验证：**

- [ ] 为用户、角色、组织、菜单、字典和配置页面建立页面级测试数据与最小交互测试。
- [ ] 实现用户和角色 CRUD、组织和菜单树维护、字典/配置维护及日志查询。
- [ ] 接入按钮权限指令，预期无权限按钮不渲染且后端拒绝仍可正确提示。
- [ ] 运行 `npm run build` 和前端测试，预期构建及测试通过。

**验收：** 管理员可以完成一期维护流程；普通用户无法看到或访问未授权页面；错误状态可理解且不丢失表单数据。

**回滚：** 页面级回退，不删除后端接口和数据库数据。

**停止条件：** 页面出现横向溢出、关键文字重叠、表单提交重复或无权限按钮仍可触发时停止。

**升级条件：** 需要复杂拖拽式菜单设计器时独立拆分交互设计，不在本任务隐式加入。

## T7：集成验证与接入文档

**需求映射：** R1-R8

**前置任务：** T1, T2, T3, T4, T5, T6

**文件范围：** `README.md`、`.env.example`、启动脚本、接入规范、接口文档、后端集成测试和前端端到端/流程测试配置。

**步骤与验证：**

- [ ] 启动 MySQL、后端和前端，记录端口、健康检查和构建输出。
- [ ] 执行管理员登录 -> 动态菜单 -> 用户/角色/组织维护 -> 权限拒绝 -> 主题切换完整流程。
- [ ] 运行 `mvn test`、`mvn package`、`npm test`、`npm run build`，预期全部通过。
- [ ] 检查文档中的环境变量、初始化账号、接口错误码和新模块接入步骤，预期无占位符和敏感凭证。

**验收：** R1-R8 均有可重复证据；启动说明可由新环境执行；残余风险明确记录。

**回滚：** 保留验证产物和日志；代码回退遵循任务边界，不执行破坏性数据库操作。

**停止条件：** 任一 must 需求无验证证据、生产构建失败或存在高优先级权限问题时不能宣布完成。

**升级条件：** 外部环境缺失导致无法验证时报告具体阻断项，不用未等价的替代环境宣称通过。

## 控制模型种子

- 被控对象候选：空仓库中的一期管理平台代码、数据库迁移和前端构建产物。
- 状态变量候选：模块构建状态、迁移版本、认证流程状态、权限校验结果、页面构建状态。
- 接口候选：REST API、数据库迁移、前端 API Client、动态路由契约。
- 传感器候选：编译/测试退出码、MySQL 迁移结果、HTTP 状态码、前端构建输出、页面流程结果。
- 执行器候选：文件修改、依赖配置、迁移脚本、测试命令和启动命令。
- 扰动候选：本地 JDK/Node/MySQL 版本、依赖网络、端口占用、环境变量缺失。
- 延迟候选：数据库迁移失败反馈、前后端接口契约不一致、浏览器页面验证。
- 所有候选均为 `hypotheses-only`，须在建模和执行阶段用证据验证。
