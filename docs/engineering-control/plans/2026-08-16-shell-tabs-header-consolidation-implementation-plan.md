# 顶部栏与页签合并实施计划

> 执行要求：使用 `$control-engineering` 逐任务实施。开发前计划是候选控制输入，必须先完成需求基准复核和系统建模，不得直接跳到执行阶段。

**目标：** 在桌面端将现有路由页签并入应用顶部栏，移除重复面包屑和独立页签行，同时保持移动端和所有页签操作不变。

**架构：** `AppLayout` 根据 `mobileView` 互斥挂载同一个 `UiTabs`：桌面放入 `app-header` 中部，移动端继续放在 header 下方。`tabsStore`、`UiTabs` 接口和业务页面不变，`styles.css` 只负责中部弹性、紧凑页签和断点降级。

**技术栈：** Vue 3、TypeScript、Element Plus、现有 Pinia `tabsStore`、CSS 响应式断点。

## 全局约束

- 不增加依赖，不修改后端、路由契约、页签状态或业务页面。
- 保留当前工作区中与本任务无关的所有修改。
- 项目选择器、侧栏折叠、通知、主题、打印和用户菜单必须保持可用。
- 移动端继续显示当前页标题和独立粘性页签栏。
- 禁止页面级横向溢出和顶部控件重叠。

### T1：桌面内联页签与移动端降级

**需求映射：** R1, R2, R3, R4

**前置任务：** 无

**文件：**

- 修改：`web/src/views/AppLayout.vue`
- 修改：`web/src/styles.css`
- 测试：浏览器桌面与 `375x812`、`390x844`、`430x932` 视口

**接口：**

- 消费：`UiTabs(currentPath: string)`、`tabsStore.tabs`、`mobileView`
- 产出：桌面 `.app-header__tabs` 内联挂载点、移动端 `.app-mobile-tabs` 独立挂载点

- [ ] **步骤 1：建立当前布局基准**

  运行当前页面 DOM/几何检查，记录桌面同时存在 `.breadcrumb` 和独立 `.ui-tabs-bar`，移动端独立页签正常。

  预期：桌面当前页面标题重复，独立页签行占用额外高度。

  证据：桌面 DOM 快照和关键元素边界。

- [ ] **步骤 2：实施互斥挂载**

  在 `AppLayout.vue` 中移除桌面面包屑，将 `UiTabs` 放入 `app-header` 中部；仅当 `mobileView && theme.tabsEnabled` 时在 header 下方渲染移动页签。

  预期：任何视口只渲染一个 `UiTabs`，`currentPath` 与原实现一致。

  证据：模板差异和浏览器 DOM 数量检查。

- [ ] **步骤 3：实施桌面弹性和紧凑样式**

  在 `styles.css` 中让项目选择器、折叠按钮和右侧操作固定收缩行为，让 `.app-header__tabs` 使用 `flex: 1 1 auto; min-width: 0`；桌面页签去除独立行背景和底边，移动端恢复现有粘性页签条。

  预期：中等桌面宽度和多页签状态无重叠，内容区上移。

  证据：元素边界、页面 scrollWidth 与截图。

- [ ] **步骤 4：运行局部与回归检查**

  运行：`npm --prefix web run build`

  预期：`vue-tsc --noEmit` 和 Vite 构建退出码为 0。

  运行：`git diff --check -- web/src/views/AppLayout.vue web/src/styles.css`

  预期：退出码为 0，无空白错误。

- [ ] **步骤 5：执行浏览器验收**

  在桌面打开工作台、用户管理及多个页签，检查切换、关闭、刷新和右键菜单；在 `375x812`、`390x844`、`430x932` 检查标题、独立页签和 `scrollWidth`。

  预期：桌面标题不重复且无独立页签行；页签操作不变；三个手机视口无页面横向溢出。

  证据：DOM 快照、交互结果、控制台日志和几何值。

**回滚：** 恢复 `AppLayout.vue` 中独立 `UiTabs` 挂载和原 `.ui-tabs-bar` 桌面样式；不回滚 `tabsStore` 或任何业务状态。

**停止条件：** 需要修改 `tabsStore`、路由或公共 `UiTabs` 行为；中等桌面宽度无法同时保留项目选择器和全局操作；移动端产生不可消除的页面级溢出。

**升级条件：** 必须改变用户确认的移动端独立页签规则，或需要重新设计全局导航结构。

## 控制模型种子

- 被控边界候选：`AppLayout` 壳层布局与 `UiTabs` 响应式挂载。
- 状态变量候选：`mobileView`、`theme.tabsEnabled`、当前路由、页签集合、元素边界和页面宽度。
- 传感器候选：类型构建、DOM 数量、元素边界、交互结果、console、`scrollWidth`。
- 执行器候选：模板互斥条件和 CSS flex/断点规则。
- 扰动候选：现有脏工作区、多页签宽度、布局模式和视口变化。
- 所有模型信息均为 `hypotheses-only`，由执行前建模验证。

## 风险与用户批准

最高风险是中等桌面宽度下三个区域争抢空间。通过固定两侧、弹性中部和移动断点降级处理。用户已确认方案 1 并明确要求直接开发，计划修订 1 可移交执行。
