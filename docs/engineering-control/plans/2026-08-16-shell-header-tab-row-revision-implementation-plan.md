# 顶部栏与独立页签栏布局修订实施计划

> 执行要求：使用 `$control-engineering` 逐任务实施。开发前计划是候选控制输入，必须先完成需求基准复核和系统建模，不得直接跳到执行阶段。

**目标：** 将桌面端收缩按钮放到项目选择器左侧，并把路由页签恢复为全局顶部栏下方的独立整行栏位。

**架构：** `AppLayout` 继续拥有应用壳层组合，但将全局控制和路由页签拆成两个同级行。`UiTabs`、`tabsStore` 和业务路由契约不变；CSS 只负责顶部栏顺序、独立页签栏和现有移动断点。

**技术栈：** Vue 3、TypeScript、Element Plus、Pinia、Vite、现有全局 CSS。

## 全局约束

- 只修改 `web/src/views/AppLayout.vue` 和 `web/src/styles.css` 的壳层布局相关部分。
- 不修改 `UiTabs.vue`、`tabsStore`、路由元数据、业务页面、后端和依赖。
- 不恢复桌面面包屑。
- 保留移动端当前页标题、粘性页签和侧滑导航中的项目选择器。
- 保留工作区现有未提交改动，不提交或推送代码。

---

## 文件职责地图

- `web/src/views/AppLayout.vue`（existing）：组合顶部/侧边/混合布局中的收缩按钮、项目选择器、全局操作和唯一 `UiTabs` 挂载点。
- `web/src/styles.css`（existing）：定义顶部栏顺序、间距、独立页签栏、移动端粘性定位和溢出约束。

## 任务依赖图与并行策略

### T1：重排全局控制并恢复独立页签栏

**需求映射：** R1、R2、R3、R4、R5

**前置任务：** 无

**文件：**
- 修改：`web/src/views/AppLayout.vue:160`
- 修改：`web/src/styles.css:120`
- 测试：现有前端构建与浏览器运行时验收，不新建测试文件

**接口：**
- 消费：`theme.layout`、`theme.sidebarCollapsed`、`projectContext.currentRef`、`mobileView`、`route.fullPath`、`tabsStore.tabs`
- 产出：桌面全局控制顺序、唯一独立 `UiTabs(currentPath=route.fullPath)` 挂载点、保持不变的移动端壳层

- [ ] **步骤 1：建立当前失败基线**

  检查 `AppLayout.vue` 当前模板和浏览器 DOM。预期当前失败信号为：项目选择器先于收缩按钮，且桌面 `UiTabs` 是 `.app-header` 的后代。

  证据：模板行号、DOM 父子关系和元素矩形。

- [ ] **步骤 2：重排 AppLayout 壳层组合**

  在侧边布局的桌面顶部栏中先渲染收缩按钮，再渲染项目选择器；在混合布局的顶部导航中同样把可用的侧栏收缩按钮放到项目选择器前。顶部布局没有侧栏时不渲染无意义的收缩按钮。

  将 `UiTabs` 从 `.app-header` 内移出，在顶部栏之后只挂载一次。顶部模式不得留下空白的第二顶部栏；移动端继续保留当前页标题和侧滑导航项目选择器。

  预期：桌面 DOM 顺序符合方案 A，任一视口只有一个 `.ui-tabs-bar`。

- [ ] **步骤 3：恢复独立页签栏样式并移除内联样式**

  删除 `.app-header__tabs` 及其内联覆盖；保持 `.ui-tabs-bar` 的整行背景、下边框和最小高度。调整顶部栏 `flex` 顺序和间距，使右侧全局操作仍由 `margin-left:auto` 对齐。

  预期：页签栏独占一行，多个页签不挤压项目选择器和账号区域。

- [ ] **步骤 4：运行编译与目标差异检查**

  运行：

  ```bash
  npm --prefix web run build
  git diff --check -- web/src/views/AppLayout.vue web/src/styles.css
  ```

  预期：两条命令退出码均为 `0`；允许保留项目已有的 Vite 大分块警告。

- [ ] **步骤 5：执行桌面运行时验收**

  在侧边布局打开至少四个页签，检查收缩按钮矩形位于项目选择器左侧，`.ui-tabs-bar` 不是 `.app-header` 后代，右侧操作不重叠，`scrollWidth === clientWidth`。

  依次验证页签切换、直接关闭、刷新、关闭其他和关闭全部。对顶部、混合布局各做一次壳层 DOM 和空白栏检查。

  预期：R1、R2、R3、R5 全部通过。

- [ ] **步骤 6：执行移动端回归验收**

  在 `375x812`、`390x844`、`430x932` 检查当前页标题、独立粘性页签、导航抽屉项目选择器和文档宽度；最终重新加载页面并检查最新控制台错误。

  预期：每个视口只有一个页签栏，标题可读，项目选择器入口存在，`scrollWidth === clientWidth`，最终重新加载后无新增错误日志。

**验收、证据与回滚：**

- 验收：R1-R5 的 DOM、几何、交互、构建和移动端检查全部通过。
- 证据：实际 diff、命令退出码、桌面/移动元素矩形、页签交互结果和控制台日志。
- 回滚：仅恢复本任务开始前 `AppLayout.vue` 的元素顺序、`UiTabs` 挂载条件和对应壳层 CSS，不触碰其它工作区改动。

**停止条件：**

- 必须修改 `UiTabs.vue`、`tabsStore`、路由或业务页面才能完成布局。
- 顶部、混合布局需要重新定义产品行为，而不是仅调整壳层组合。
- 移动端回归无法在两个批准文件内修复。

**升级条件：**

- 用户要求恢复面包屑或改变移动端已确认布局。
- 必须取消某个现有布局模式或改变项目上下文位置。

## 集成检查

完成 T1 后执行前端生产构建、目标 diff 检查、侧边/顶部/混合桌面布局检查和三个移动视口检查。只有最新页面控制台无新增错误且全部 must 需求有运行证据时才能收敛。

## 控制模型种子

- 候选被控边界：`AppLayout` 壳层 DOM、顶部栏控制顺序、`UiTabs` 挂载点、相关 CSS。
- 候选状态：`theme.layout`、`theme.sidebarCollapsed`、`mobileView`、`tabsStore.tabs`、元素矩形和页面宽度。
- 候选传感器：Vue/TypeScript 构建、目标 diff、DOM 父子关系、元素矩形、页签交互、移动视口、控制台日志。
- 候选执行器：模板元素顺序与条件、独立页签挂载、壳层 flex 和媒体查询规则。
- 候选扰动：脏工作区、多个页签、三种布局模式、视口切换和 HMR 延迟。
- 所有候选均为 `hypotheses-only`，导入后由系统建模阶段验证。

## 风险与用户批准

最高风险是顶部/混合模式在移出内联页签后留下空白顶部栏，计划要求专门检查并在模板条件中消除。用户已批准设计和当前计划修订 1，并明确要求开始开发，可移交闭环执行。
