# 通知中心 SSE 实施计划

> 执行要求：使用 `$control-engineering` 逐任务实施。开发前计划是候选控制输入，必须先完成需求基准复核和系统建模，不得直接跳到执行阶段。

**目标：** 用安全的一次性票据 SSE 替代通知中心每秒轮询，并保留断线降级能力。

**架构：** system 模块持有票据、连接和事务后广播；security 只精确放行票据兑换 GET；前端 EventSource 负责可见性、重连和 60 秒兜底；Nginx 禁止流缓冲。

**技术栈：** Java 17、Spring Boot 3.4.4、SseEmitter、Spring Security、Vue 3、TypeScript、Vite、Nginx。

## 全局约束

- 不修改数据库、通知业务规则、JWT 存储方式或 UI 样式。
- 不将 JWT、用户信息或通知正文放入 SSE URL/事件。
- 广播必须在事务提交后且数据实际变化时发生。
- 保留 `rokey` 工作树现有未提交修改，所有实现位于隔离分支。

### T1：后端安全 SSE 通道

**需求映射：** R2 安全换票与用户隔离，R3 事务后广播与连接维护

**前置任务：** 无

**文件：** 新建票据 DTO、SSE 服务、流控制器和聚焦测试；修改通知控制器、通知服务及 Security 配置。

**接口：** 产出 `POST /api/notifications/stream-ticket` 与 `GET /api/notifications/stream?ticket=...`；事件名为 `notification` 和 `heartbeat`。

- [ ] 建立票据单次消费、过期拒绝、隔离和事务回滚测试，确认当前无实现。
- [ ] 实现票据、连接注册、25 秒心跳、10 分钟连接和 after-commit 广播。
- [ ] 将六类通知变化接入广播，并仅在影响行数大于零时触发。
- [ ] 精确放行 SSE GET，运行 `mvn -pl :ccb-system,:ccb-security,:ccb-boot -am test`。

**回滚：** 回退 T1 Java 变更即可，未产生持久数据。

**停止条件：** 必须把 JWT 放入 URL、修改数据库或突破租户/用户边界才能实现。

**升级条件：** 发现当前运行环境已是多后端实例，需要引入跨实例广播。

### T2：前端事件驱动与降级

**需求映射：** R1 消除每秒轮询并事件刷新，R4 重连、可见性与降级

**前置任务：** T1

**文件：** 修改 `web/src/api/notifications.ts` 和 `web/src/components/ui/UiNotificationCenter.vue`。

**接口：** 消费 T1 票据和 SSE 事件；保留现有通知列表 API。

- [ ] 新增票据 API 类型和调用。
- [ ] 将轮询生命周期替换为 EventSource 生命周期、可见性管理和 `1/2/5/15/30s` 重连。
- [ ] 连续失败后启用 60 秒轮询，SSE 恢复后停止。
- [ ] 运行 `npm --prefix web run build` 并检查组件无一秒定时器。

**回滚：** 回退 T2 两个前端文件恢复旧轮询。

**停止条件：** 浏览器必须暴露 JWT 或降级逻辑恢复为秒级请求。

**升级条件：** EventSource 在目标浏览器不受支持且无法使用当前构建目标兼容。

### T3：代理配置与组合验收

**需求映射：** R3 连接维护，R4 代理与端到端恢复

**前置任务：** T1、T2

**文件：** 修改两份 Nginx 配置和通知集成契约，写执行、观测与收敛证据。

**接口：** 精确 `/api/notifications/stream` 位置先于通用 API/站点代理。

- [ ] 对 SSE 路径配置 HTTP/1.1、关闭 buffering/cache、读取超时 1 小时。
- [ ] 更新通知契约，运行治理、后端测试、前端构建与 `git diff --check`。
- [ ] 启动本地服务，检查 SSE 心跳、事件触发刷新、隐藏重连和无每秒轮询。
- [ ] 记录实际证据并完成收敛检查。

**回滚：** 回退 T3 配置和文档；应用回退按 T1/T2 执行。

**停止条件：** Nginx 仍缓冲事件、连接泄漏或浏览器出现持续错误。

**升级条件：** 本地代理行为与目标 Nginx 不一致，需部署环境专项验证。

## 依赖与覆盖

- 串行执行 `T1 -> T2 -> T3`，因为前端消费后端契约，组合验收依赖二者。
- 所有 must 需求由 T1-T3 覆盖；后端单元测试、前端构建、浏览器网络面板和 Nginx 配置是互补传感器。
