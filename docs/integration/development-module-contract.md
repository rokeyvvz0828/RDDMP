# 开发任务模块接入契约

日期：2026-09-09；当前移植需求：REQ-20260909-072；原实现需求：REQ-20260908-071。以下业务规则保持，当前测试与运行证据以本次控制前缀为准。

## 依赖与数据归属

`ccb-development` 不依赖其他业务模块。它只持有 `DevelopmentSourceDirectory`、`DevelopmentSystemDirectory` 端口，boot 分别调用 requirement 和 architecture 的公开 `integration` 查询并转换 DTO。来源、系统和平台私有服务不得被开发域直接调用。

## 需求来源

`search(actor, SourceQuery(projectRef, systemCodes, keyword, page))` 在平台项目授权后，按同租户项目编码解析需求域项目，查询主责或协同改造/测试相关的有效 legacy 需求。`systemCodes` 只能由后端已授权的系统范围派生，不允许直接从 HTTP 请求透传。空集合直接返回空页，不执行全租户来源查询。

`requireCurrent(actor, projectRef, requirementId)` 每次重新校验平台项目，按需求域项目和租户查询。终止、删除或项目内不存在的需求不可承接。不存在同编码需求项目、重复编码、空系统编码或未知关联角色返回 `CONFLICT`，不隐式猜测或降级。

需求生产者返回的 `projectId` 是 `req_project.id`；boot 返回开发域前替换为经过授权的 `pm_project.id`，两个数值允许不同。系统映射仍由后续 `DevelopmentSettings` 以参数 `DEVELOPMENT_SYSTEM_MAPPING` 显式解析，不能假设需求系统编码等于物理系统编码。

角色为 `LEAD`、`CHANGE`、`TEST`，同一系统归并为集合。仅 `TEST` 才能认定纯测试；空集合不能获得豁免。负责人候选不一致时不任意挑选；它仅是建议，不替代物理系统 Owner 默认值。编号、正文、项目和规范化角色/负责人集合产生 SHA-256 来源版本，关联行顺序与重复行不导致版本变化。

## 系统投影

`searchManageable(actor, projectId, page, keyword)` 只查询当前已授权项目、当前租户、未删除且 `ACTIVE` 的系统。默认按物理子系统 `owner_user_id` 过滤；只有当前认证主体匹配 actor 且具有明确 `development:admin` 权限才可扩大到该项目内系统，不能跨项目。计数和分页共用相同谓词。

`find(actor, projectId, systemId)` 是内部租户及项目隔离的当前主数据投影，保留状态和行版本供消费者失败关闭；不授予管理权限、不直接公开成全量 HTTP 接口。项目 ID 来自已验证的 ProjectAccess 或已验证任务，不能使用浏览器声明替代。详情、创建、选项与待承接均应用该边界，不缓存 Owner。

## 任务接口

任务列表、承接、自主创建、详情、更新、修改记录和人员/系统选项已按 C3/C4/C8 提供。创建以请求摘要和请求标识幂等，编号、任务、来源绑定和历史在同一事务；新任务工作项为零。更新必须显式提交非空行版本，额外字段（包括租户、状态、编号、登记时间）被拒绝。

待承接在同一授权集合中扣除已承接系统；映射改绑与已有来源编码绑定冲突时明确返回 409，不能显示为仍可承接。指定人员只能读取自己参与任务，摘要工作项计数也只统计自己的工作项。不写需求或架构数据。

## 工作项执行

`GET/POST /api/development/work-items`、`GET/PUT /work-items/{id}` 和 `POST /work-items/{id}/actions` 共用同一服务。可选 `taskId` 只限制任务范围，不改变授权；返回 `records,total,page,size,counts`，列计数在相同业务筛选下计算，不受当前选择状态列影响。指定人员仅看到自己的工作项，负责人可看到所管理任务内的全部工作项。

动作仅允许 START、SUBMIT、ACCEPT、RETURN、REOPEN。执行和提交由指定人员完成，验收、退回和重开要求负责人与验收权限，兼任角色按实际权限处理。退回与重开必须提供原因，写入先锁父任务再检查工作项版本。父任务完成/取消后执行只读；工作项全部完成不自动关闭父任务。

指定人员仅可编辑实际日期和阻塞信息，负责人还可维护内容、计划和人员。字段更新不能写状态。任务修改记录同步过滤非本人工作项事件，不保留派生权限、警告或跨范围计数作为历史业务字段。

## 阶段与工作日

`GET/PUT /api/development/tasks/{id}/stages` 维护设计计划、设计附件/路径、实施实际日期、代码走查和可选测试报告。阶段版本与任务版本均受保护：资料保存推进任务行版本，阻止基于旧资料执行完成动作。设计与测试资料登记时间由服务端生成。

`POST /tasks/{id}/actions` 接收 START、COMPLETE、CANCEL、REOPEN、RESTORE；取消、重开和恢复需说明原因。取消保留任务、编号、来源与取消前状态，恢复沿用原记录。完成前工作项必须全部 DONE，开发类必须有本任务、本项目有效 BOUND 代码走查文件。纯 TEST 关联来源可豁免，来源角色在保存和完成时重验；测试报告不作为完成门槛。

工作日按首尾计入的日期跨度统计，完整周直接计数并应用维护的日期覆盖。缺日期或计划为零返回 `unavailable`，不填充虚假零偏差。`duration` 同时返回计划/实际工作日、偏差百分比、日历摘要及基础工作周标识。任务完成和工作项验收保存日历快照，已验收工作项改期追加快照，历史口径不随参数变更漂移。

资料保存只追加版本引用，不删除旧附件绑定。附件读取必须经过父任务权限，历史绑定资料禁止直接删除。

## 前端与演示

`/development/tasks` 为主入口，`/development/tasks/:taskId` 集中维护任务、工作项、阶段与变更，`/development/work-items/board` 是次级跨任务入口。任务内看板固定 `taskId`，看板和列表使用同一 API。每列独立有界分页、计数、失败重试和滚动；手机使用状态分段控件及显式动作，不要求拖动。

筛选、呈现模式、页码与滚动位置按用户/项目/任务保存在会话存储中，不缓存业务记录。切用户、项目、任务或筛选会使旧查询及旧确认失效；写操作仅在服务端成功后更新确认状态。表单离开保护覆盖取消、路由切换和浏览器关闭，409 保留草稿并提供重新读取。

本地 Mock 的 `development` 目录项说明四个既有虚构用户的分工；数据涵盖待承接、已承接、自主、纯测试、混合角色、阻塞和完成，不生成假附件。开发类完成必须实际上传并绑定文件。Mock 仅在 `local` 且显式启用时执行，重复同步会将演示记录恢复为种子状态，不用于保留手工验收数据。
